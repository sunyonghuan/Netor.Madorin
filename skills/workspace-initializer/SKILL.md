# Workspace Initializer - 工作目录初始化

## Overview

本技能用于**空工作目录的初始化**，是一个需要用户配合的工作流。当用户切换到一个新的、空的工作目录时，AI 需要：

1. 判断当前工作目录**是否已经初始化**。
2. 若未初始化，**向用户提问收集完整信息**后，为其建立文件夹结构。
3. 把工作目录的**结构、各目录用途、使用规则**简洁地写入**项目记忆**，让后续会话的 AI 能快速理解并遵循该工作目录的架构。

**核心原则**：初始化必须由用户配合完成。AI 先提问、收集齐信息，才可以执行建立目录的操作。

## Scope

本技能涵盖以下功能：

1. **初始化状态检测** - 依据上下文中的项目记忆判断工作目录是否已初始化
2. **空目录判断** - 列出工作目录内容，确认是否为空
3. **信息收集流程** - 向用户提问，收集初始化所需的完整信息
4. **目录结构建立** - 根据用户要求建立文件夹和 README
5. **基础目录保证** - 确保 README、临时数据目录、日志目录等最基本要素存在
6. **中英文目录命名** - 让用户选择采用中文目录还是英文目录
7. **项目记忆写入** - 把工作目录结构、用途、使用规则简洁地写入项目记忆
8. **一致性维护** - 当实际目录与记忆不匹配时，提醒用户并在确认后更新记忆

## 判定标准：是否已初始化

**每个工作目录都有独立的项目记忆，其内容会随每次会话自动进入 AI 上下文。因此判断"是否已初始化"无需调用任何读取工具，直接看当前上下文中是否存在初始化标记即可。**

初始化标记为项目记忆中的这一行：

```
- 初始化状态: 已初始化
```

- **上下文中存在该标记** → 视为已初始化。
- **上下文中不存在该标记** → 视为未初始化，需**主动提醒用户**（见下文）。

## 主动提醒初始化

当判定为**未初始化**，或用户切换到一个**空工作目录**时，AI 应**主动提醒**用户，而不是被动等待指令：

> 当前工作目录尚未初始化（或为空）。是否需要我帮你初始化目录结构？

- 用户**同意** → 进入下方初始化工作流（从阶段二收集信息开始）。
- 用户**拒绝或暂不需要** → 不做任何创建操作，正常继续当前任务。
- 提醒只需一次，用户明确拒绝后本次会话内不再重复打扰。

## 可用工具

直接调用真实工具名，路径使用相对工作目录的相对路径，不要手写绝对路径。

| 用途 | 工具 |
|------|------|
| 获取当前工作目录路径 | `sys_get_workspace_directory` |
| 列出目录内容（判断是否为空 / 与记忆比对） | `sys_list_directory` |
| 创建目录（含父级） | `sys_create_directory` |
| 记录初始化信息到项目记忆 | `sys_write_settings` |

> README 等文本文件用标准文件写入能力创建即可。所有操作都被系统强制限定在当前工作目录内。

## 初始化工作流

### 阶段一：检测状态（先判断，不要直接建目录）

1. 查看当前上下文中的项目记忆，按上文判定标准确认是否已初始化。
   - **已初始化** → 告知用户"当前工作目录已初始化"，并按记忆简述已有结构与使用规则。除非用户明确要求"重新初始化"，否则**结束流程**。
2. 未初始化时，调用 `sys_get_workspace_directory` 取路径，再调用 `sys_list_directory` 确认目录内容。
   - 目录**为空** → 按"主动提醒初始化"提醒用户；用户同意后进入阶段二。
   - 目录**非空** → 提示用户该目录已有内容，询问是否仍要初始化，避免覆盖既有文件；得到确认后再继续。

### 阶段二：收集信息（必须提问，信息不全不得执行）

向用户提问，收集初始化所需信息。至少需要明确：

1. **目录命名语言**：采用**中文目录**还是**英文目录**？（必答）
2. **行业 / 用途**：这个工作目录主要用来做什么？（决定要建立哪些业务目录）
3. **自定义目录**：除基础目录外，是否还需要其他文件夹？
4. **工作习惯 / 约定**：有没有希望 AI 在此目录下遵循的规则（如命名规范、文件归档方式）？

> 用户的行业和习惯各不相同，目录结构没有统一规范。以提问澄清为准，不要臆测。信息收集齐全前，不要调用任何创建工具。

### 阶段三：确定结构

无论用户如何定制，**必须包含以下最基本要素**：

- **README 说明文档** - 描述该工作目录的用途和结构。
- **临时数据目录** - 存放临时/中间文件，以及 AI 为完成任务临时编写的脚本（见"临时目录使用约定"）。
- **日志目录** - 存放运行/操作日志。

根据语言选择套用命名（示例，可按用户要求调整）：

| 要素 | 英文命名 | 中文命名 |
|------|----------|----------|
| 说明文档 | `README.md` | `说明.md` |
| 临时数据 | `temp/` | `临时数据/` |
| 日志 | `logs/` | `日志/` |

在此基础上叠加用户要求的业务目录（如 `docs/`、`data/`、`output/`、`资料/`、`成果/` 等）。

### 阶段四：执行建立

1. 对每个目录调用 `sys_create_directory`。
2. 写入 README，内容简要说明：目录用途、各文件夹作用、命名与归档约定。
3. 每一步执行后确认成功，回显实际创建的路径。

### 阶段五：写入项目记忆（关键，简洁明了）

用 `sys_write_settings` 把工作目录的结构与使用规则记录进项目记忆。**内容务必简洁**，让后续 AI 能一眼看懂并遵循。必须包含初始化标记与日期。建议格式：

```markdown
## 工作目录说明

- 初始化状态: 已初始化
- 初始化日期: {YYYY-MM-DD}
- 目录用途: {一句话说明}
- 命名语言: {中文/英文}

### 目录结构
- {README} — 工作目录说明
- {temp/临时数据} — 临时/中间文件与 AI 临时脚本
- {logs/日志} — 运行与操作日志
- {自定义目录} — {用途}

### 使用规则
- 新建文件按 {约定} 归档到对应目录。
- 所有临时产物（临时脚本、临时文档、临时数据/素材、一次性日志）一律放入临时目录，禁止散落根目录或另建新目录。
- 业务成果归入对应业务目录，勿与临时产物混放。
- {其他用户约定}
```

写入后告知用户初始化完成，并简述已建立的结构。

## 临时目录使用约定（强制）

AI 在工作中会频繁产生各种临时文件——尤其是为完成没有对应内置工具的功能而临时编写的脚本。**所有临时产物一律存放到临时目录**（`temp/` 或 `临时数据/`），严禁在工作目录根部或业务目录里随意新建文件或文件夹。这是防止目录被污染的硬性规则。

**必须放入临时目录的内容（包括但不限于）**：

- 临时脚本：为完成任务临时编写的 `.ps1`、`.py`、`.sh`、`.js`、`.bat` 等任何脚本。
- 临时文本文档：草稿、笔记、中间说明、待整理的 `.md`/`.txt` 等。
- 临时数据：中间数据、下载缓存、解压产物、转换过程文件。
- 临时素材：临时下载或生成的图片、音视频等待处理素材。
- 临时日志：脚本运行产生的一次性日志、调试输出（长期运行日志归入日志目录）。
- 任何一次性、可丢弃、非最终成果的文件。

**硬性规则**：

- **先建目录，再落文件**：需要放临时文件时，若临时目录不存在，先确认/创建它，再写入，绝不在根目录就地生成。
- **禁止自建新目录**：不要为临时用途在根目录另建 `tmp2/`、`scripts/`、`downloads/` 等目录；统一收敛到既有临时目录下（可在其内部分子目录，如 `temp/scripts/`）。
- **成果与临时分离**：业务成果不得放临时目录，应归入对应业务目录；反之临时产物也不得混入业务目录。
- **临时目录可随时清理**：其中文件视为可删除，重要内容务必及时转存到正式目录。
- 该约定必须写入 README 与项目记忆，确保后续会话一致遵循。

## 一致性维护：记忆与实际目录不匹配

用户可能在软件之外手动改动过目录结构。当发现**项目记忆中记录的结构与 `sys_list_directory` 的实际结果不一致**时：

1. 向用户说明差异（例如记忆中有 `drafts/` 但实际已删除，或实际多出记忆里没有的目录）。
2. 对**记忆中没有、用途不明**的目录，先询问用户其用途，不要臆测。
3. 询问用户是否要**更新项目记忆**以反映实际结构。
4. 得到确认后，用 `sys_write_settings` 补写差异，或用 `sys_edit_settings` / `sys_delete_settings` 按行修正对应条目，保持记忆与实际一致。

## Usage Examples

### 示例 1：全新空目录初始化

**用户**："我刚切换了一个新的工作目录，帮我初始化一下。"

**步骤**：

1. 上下文中无初始化标记 → `sys_get_workspace_directory` 取路径 → `sys_list_directory` 确认为空。
2. 提问：中文还是英文目录？用途是什么？是否要额外目录？有无归档约定？
3. 用户答：英文、"个人写作项目"、额外要 `drafts/`、草稿放 drafts。
4. `sys_create_directory` 建立 `temp/`、`logs/`、`drafts/`；写入 `README.md`。
5. `sys_write_settings` 写入结构与规则，含 `初始化状态: 已初始化` 与日期。
6. 回显创建路径，告知完成。

### 示例 2：检测到已初始化

**用户**："这个目录能直接用吗？"

**步骤**：

1. 上下文中已含 `初始化状态: 已初始化`。
2. 直接告知用户"已初始化"，并按记忆简述目录用途与使用规则，不重复建立。

### 示例 3：非空但未初始化

**步骤**：

1. 上下文无标记，但 `sys_list_directory` 显示已有文件。
2. 提示用户目录非空，询问是否仍要初始化（可能与既有文件混合），得到确认后再执行，避免覆盖。

### 示例 4：记忆与实际不匹配，更新记忆

**用户**："我手动删了几个文件夹，你按现在的目录来。"

**步骤**：

1. `sys_list_directory` 得到实际结构，与上下文记忆比对，列出差异。
2. 对记忆里没有、用途不明的目录先问用户用途。
3. 询问是否更新项目记忆。
4. 用户确认后，用 `sys_edit_settings` / `sys_delete_settings` / `sys_write_settings` 修正记忆，使其与实际一致，回显更新结果。

## Best Practices

1. **先判断后动作** - 未确认初始化状态前不建立任何目录。
2. **看上下文，不重复读** - 初始化状态以上下文中的项目记忆为准，不必再调读取工具。
3. **信息不全不执行** - 收集齐用户答复再调用创建工具。
4. **基础三件套必备** - README、临时目录、日志目录始终建立。
5. **记忆要短** - 项目记忆只写结构与规则要点，避免长篇。
6. **临时产物进临时目录** - 临时脚本与中间文件统一放临时目录。
7. **保持一致** - 发现记忆与实际不符，先问用途再经用户确认更新记忆。
8. **回显路径** - 每次创建后回显实际路径，便于用户核对。
