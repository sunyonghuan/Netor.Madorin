# 会议模式动态执行计划

## 背景

会议主题不是固定类型。公司可能召开成本核算会、招聘评审会、市场增长会、产品复盘会、法务风控会等不同会议，因此程序不能把发言顺序写死成某一种业务链路。

会议模式需要固定的是宏流程，而不是具体部门顺序。

## 固定宏流程

程序必须强制执行以下流程：

1. 需求确认：主持人与老板确认目标、范围、约束和成功标准。
2. 主持人开场：需求清晰后，主持人只做一次开场，说明目标和推进方式。
3. 生成执行计划：主持人根据主题和参会者生成结构化会议执行计划。
4. 调度执行：程序按执行计划选择真实参会智能体发言。
5. 阶段纠偏：参会者无效发言、缺关键输入或需要老板决策时，由主持人接管。
6. 总结：议题成熟后，主持人输出会议总结。
7. 征询结束：主持人检查插话后征询老板是否结束，并在确认后归档。

## 动态执行计划

主持人不能直接决定整场会议由谁随意发言。主持人开场后必须形成结构化计划：

```json
{
  "topic": "会议主题",
  "assumptions": ["计划生成时采用的合理假设"],
  "phases": [
    {
      "id": "phase-id",
      "name": "阶段名称",
      "goal": "阶段目标",
      "allowedAgentIds": ["真实参会智能体 ID"],
      "prerequisites": ["进入本阶段前需要满足的前置条件"],
      "completionCriteria": "本阶段完成标准"
    }
  ]
}
```

计划必须满足：

- 每个阶段至少包含一个真实参会智能体，除非该阶段只能由主持人向老板澄清。
- 阶段顺序必须说明业务前置依赖。
- 阶段完成必须以真实 `agent` 发言为依据，主持人的代述不算参会者发言。
- 主持人不能输出“某部门观点如下”并把它当作该部门发言。

## 调度规则

调度阶段的程序硬约束：

- 当前阶段存在可发言智能体时，默认只能从 `allowedAgentIds` 中选择。
- 如果调度模型选择 `HOST`，程序必须检查是否确实存在主持人接管理由。
- 只有以下情况允许主持人接管：
  - 老板刚回复或插话，需要主持人吸收。
  - 当前信息缺口必须由老板确认。
  - 参会者发言无效，需要纠偏。
  - 需要输出总结或征询结束。
  - 当前阶段没有可用真实参会者。
- 主持人代述某部门内容不能推进该部门阶段。

## 流式消息状态

会议流程判断不能被流式草稿状态误导：

- `AgentResponseUpdateEvent` 可以保存草稿。
- 当执行器完成时，必须把已有文本草稿转成完整消息。
- 流程状态判断可以读取有效草稿兜底，但 LLM 历史默认仍优先使用完整消息。
- 如果主持人开场已经输出过，即使消息仍是可恢复草稿，也不能让会议重新从零开始。

## 验收标准

- 主持人可以澄清和开场，但不能替参会者完成正式观点输出。
- UI 和数据库中能看到真实参会智能体独立发言，`SpeakerKind = agent`。
- 不同会议主题能生成不同阶段计划，不依赖写死的成本核算顺序。
- 会议恢复后不会因为主持人开场是草稿而重复开场。
- 总结内容基于真实参会者发言，而不是主持人模拟发言。
