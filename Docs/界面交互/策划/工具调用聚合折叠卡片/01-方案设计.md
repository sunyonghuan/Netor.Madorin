# 工具调用聚合折叠卡片方案设计

## 1. 背景

专家模式和会议模式在复杂任务中会把每一次工具调用都作为独立过程卡片追加到消息流。工具数量较多时，消息流会被大量 `RealtimeProcessCard` 占满，用户需要频繁滚动才能回到 AI 正文。

本方案将同一上下文内的工具调用汇集到一张折叠卡片中，默认收起或在完成后自动收起，保留每个工具的名称、状态、耗时、参数和结果详情。

## 2. 范围

### 2.1 本次修改范围

- 专家模式实时工具调用展示。
- 会议模式实时工具调用展示。
- 会议模式历史回放可顺手复用聚合卡片展示已有 `ToolCallsJson`。
- 公共 UI 控件与轻量聚合状态对象。

### 2.2 不在本次范围

- 工作模式不修改。工作模式当前已经通过时间线、主步骤和子步骤聚合工具过程。
- 专家模式不做历史回放聚合。
- 不调整工具调用协议、AI 历史持久化、数据库结构。
- 不隐藏工具详情，只改变默认呈现层级。

## 3. 当前链路

### 3.1 专家模式

- 工具过程事件来源：`AiChatHostedService.PublishRealtimeProcessEventAsync`，构造 `RealtimeProcessEvent` 时已带 `TurnId`。
- UI 接收入口：`UiChatOutputChannel.OnProcessEventAsync`。
- 当前插入方式：`UiChatOutputChannel.HandleProcessEvent` 以 `ProcessId` 管理单张 `RealtimeProcessCard`。`MainWindow.AddRealtimeProcessCard` 是对外门面，实际由 `ChatView.AddRealtimeProcessCard`（专家模式 ChatView）创建带 `Margin=0,-18,0,0` 的容器后插入 `MessageList`，并返回 `RealtimeProcessCardHandle`。
- 可用聚合键：`RealtimeProcessEvent.TurnId`。
- 注意：插件链路（如 `PowerShellProvider`）会发出 `TurnId = string.Empty` 的过程事件，需要降级策略。

### 3.2 会议模式

- 工具调用事件来源：`MeetingStreamProcessor` 发布 `MeetingToolCallArgs` 和 `MeetingToolResultArgs`。
- UI 接收入口：`MeetingViewController.OnMeetingToolCall` / `OnMeetingToolResult`。
- 当前插入方式：每个工具调用创建独立 `RealtimeProcessCard`，通过 `MeetingView.AddProcessCard` 包一层 `Margin=0,-18,0,0` 容器后插入 `MessageList`。`MeetingViewController` 直接持有 `RealtimeProcessCard` 引用（不经 Handle）。
- 可用聚合键：`MeetingToolCallArgs.MessageId`。
- 历史数据：`MeetingMessageEntity.ToolCallsJson`，内容为 `List<MeetingToolCallRecord>`，记录 `CallId / Name / ArgsJson / ResultText / ExceptionMessage / DurationMs`。
- 注意：实时事件 `MeetingToolResultArgs` 当前不带 `DurationMs`，聚合卡耗时统计需要在 UI 侧用 Stopwatch 估算或扩展事件。

## 4. 目标体验

### 4.1 卡片标题

运行中：

```text
工具调用 3 个
运行中
```

完成后：

```text
工具调用 29 个
成功 28 · 失败 1 · 42.3s
```

总耗时来源：

- 专家模式：`RealtimeProcessEvent.DurationMs` 已由 `AiChatHostedService` 在完成事件中提供，聚合卡累加每个子卡的最终 `DurationMs` 即可。
- 会议模式：`MeetingToolResultArgs` 当前未携带耗时。第一阶段在 `MeetingViewController` 内为每个工具子卡启动 `Stopwatch`，结果到达时停止并写入聚合摘要；后续视情况再扩展 `MeetingToolResultArgs.DurationMs`，并由 `MeetingStreamProcessor` 在发布结果事件时填入实测耗时。

### 4.2 展开内容

聚合卡片展开后，内部按调用顺序展示每个工具子项。子项优先复用现有 `RealtimeProcessCard`，保持当前参数、结果、状态和失败颜色逻辑。

### 4.3 折叠策略

- 聚合卡片创建时默认展开，方便用户观察正在发生的工具调用。
- 全部工具完成后自动折叠。
- 如果存在失败工具，聚合卡片保持展开，便于用户看到错误。
- 如果存在被取消（cancelled）的工具，聚合卡片同样保持展开，便于复盘。`cancelled` 不计入失败计数，单独显示。
- 用户手动展开或收起后，后续状态更新不强制覆盖用户选择，除非当前轮结束且没有失败/取消。

## 5. 设计方案

### 5.1 新增公共控件 `ToolProcessGroupCard`

建议路径：

```text
Src/Netor.Cortana.UI/Controls/Common/ToolProcessGroupCard.axaml
Src/Netor.Cortana.UI/Controls/Common/ToolProcessGroupCard.axaml.cs
```

职责：

- 作为一张外层折叠卡片承载多个工具过程卡。
- 维护工具总数、运行中数量、成功数量、失败数量、取消数量、总耗时展示。
- 提供追加和更新工具子卡的命令式 API。
- 完成时按失败/取消状态决定是否折叠。
- 子卡进入聚合卡时由聚合卡内部清除其 `RootBorder.Margin`（设为 `0,0`），避免双层 `50,0` 缩进。`RealtimeProcessCard` 自身代码保持不变。

建议 API（专家与会议模式共用同一份控件，对外只暴露 Handle 以避免调用方直接持有 `RealtimeProcessCard`）：

```csharp
public sealed partial class ToolProcessGroupCard : UserControl
{
    public string GroupId { get; }

    public RealtimeProcessCardHandle AddTool(RealtimeProcessEvent initial);

    public bool TryGetTool(string processId, out RealtimeProcessCardHandle handle);

    public void UpdateTool(RealtimeProcessEvent evt);

    /// <summary>取消所有仍在运行中的子卡，状态置为 cancelled，但不强制折叠。</summary>
    public void CancelRunningTools(string reason);

    /// <summary>当前轮收口：无运行中工具时按摘要决定是否自动折叠。</summary>
    public void CompleteIfIdle();
}
```

内部结构：

- Header：箭头、标题、状态摘要。
- Body：`StackPanel`，每个子项为 `RealtimeProcessCard`。
- 子卡片由聚合卡内部应用嵌套样式（清掉 `RootBorder.Margin`），不污染 `RealtimeProcessCard` 自身。

### 5.2 专家模式接入

修改点：

- `UiChatOutputChannel` 新增按 `TurnId` 管理的聚合卡字典，并新增 `_currentTurnId` 字段记录当前 UI 输出轮次 ID（首次收到带 TurnId 的事件时落账）。
- 对 `Kind == tool/command/agent` 的过程事件进入聚合卡。
- `thinking` 仍保留独立思考过程卡，不混入工具聚合。
- `OnDoneAsync`、`OnCancelledAsync`、`OnErrorAsync`、`Reset` 收口当前轮聚合卡。
- 在 `ChatView` 上新增 `AddToolProcessGroupCard` 入口，沿用现有 `Margin=0,-18,0,0` 容器策略，由 `UiChatOutputChannel` 通过 `MainWindow` 透传调用，与 `AddRealtimeProcessCard` 保持一致。

建议状态结构：

```csharp
private string? _currentTurnId;
private readonly Dictionary<string, ToolProcessGroupCardHandle> _toolGroupsByTurnId = new(StringComparer.Ordinal);
private readonly Dictionary<string, ToolProcessGroupCardHandle> _toolGroupsByProcessId = new(StringComparer.Ordinal);
```

处理逻辑：

1. 收到 running 工具事件。
2. 取 `evt.TurnId`，为空时退化为 `_currentTurnId`；若两者皆空，再退化为 `evt.ProcessId`（每个工具独立聚合卡，相当于不聚合，仅保证不崩）。
3. 没有聚合卡则创建一张并插入消息流。
4. 没有对应 `ProcessId` 子卡则 `AddTool`，已有则追加内容和更新状态。
5. 收到 success/failed/cancelled 时更新子卡并刷新聚合摘要。
6. 当前 AI 回复完成（`OnDoneAsync`）时，对所有聚合卡调 `CompleteIfIdle`；取消（`OnCancelledAsync`）时先 `CancelRunningTools` 再 `CompleteIfIdle`。

插件链路（无 TurnId）的处理：第一阶段约定其事件走「ProcessId 退化路径」，等同每工具一张独立聚合卡，外观与现状基本一致，不引入新风险。后续如需聚合插件工具，再补 TurnId 透传。

专家模式不需要历史回放聚合，因此不改 `ChatMessageService` 和 `MainWindow.Sessions`。

### 5.3 会议模式接入

修改点：

- `MeetingViewController` 新增按 `MessageId` 管理的工具聚合卡。
- `OnMeetingToolCall` 不再直接 `_view.AddProcessCard(card)`，改为获取或创建该 `MessageId` 的聚合卡后追加工具子卡，并在子卡上启动 `Stopwatch`。
- `OnMeetingToolResult` 更新聚合卡内对应工具子项，停止 Stopwatch，并写入耗时。
- `CompleteProcessCards(messageId)` 同时收口该消息的工具聚合卡。
- `OnMeetingMessageDiscarded` 不仅移除 bubble，还要移除对应的工具聚合卡 UI 元素（修复现存的「丢弃后孤儿过程卡」问题），思考卡同样处理。
- `OnMeetingAskUserRequested`、`OnMeetingPaused` 不收口工具聚合卡（运行中工具会随后续 `OnMeetingToolResult` 自然完成）；若长时间停留可由 `OnMeetingMessageCompleted` / `OnMeetingMessageDiscarded` / `OnMeetingMessagePartialSaved` 收尾。

建议状态结构：

```csharp
private readonly Dictionary<string, ToolProcessGroupCardHandle> _toolGroupsByMessageId = new(StringComparer.Ordinal);
private readonly Dictionary<string, RealtimeProcessCardHandle> _toolHandlesByCallKey = new(StringComparer.Ordinal);
private readonly Dictionary<string, Stopwatch> _toolStopwatches = new(StringComparer.Ordinal);
```

历史回放：

- `RenderHistoryMessage` 遍历 `ToolCallsJson` 时，可创建一张聚合卡并一次性塞入已完成工具，子卡来自 `MeetingToolCallRecord`。
- 历史卡只读，**不写入 `_toolHandlesByCallKey`**，避免与下一次实时调用同 messageId/CallId 撞键（即使概率极低，也消除隐患）。
- 如果希望第一阶段更稳，可以只改实时链路，历史继续使用现状，并在 §7 标注为后续优化。

### 5.4 布局对齐

专家模式和会议模式当前过程卡插入时都使用类似：

```csharp
new Border
{
    Margin = new Thickness(0, -18, 0, 0),
    Child = card,
}
```

聚合卡片沿用这层容器，使它与现有过程卡位置一致。聚合卡外层保持 `RootBorder.Margin=50,0`；内部子卡进入 `AddTool` 时由聚合卡读取 `RootBorder` 并将其 Margin 重置为 `0,0`，避免双层 50 缩进。`RealtimeProcessCard` 控件本身不变。

## 6. 风险与处理

### 6.1 工具结果先于工具调用

少数驱动可能只在最终消息中给出工具结果。处理方式：

- 如果收到完成事件但没有子卡，创建一个占位子卡，再立即完成。

### 6.2 TurnId 为空

专家模式事件理论上已有 `TurnId`，但插件链路（如 `PowerShellProvider`）会发出空 TurnId。处理顺序：

1. 优先用 `evt.TurnId`。
2. 退化为 `UiChatOutputChannel._currentTurnId`（首个带 TurnId 的事件落账）。
3. 仍为空则退化为 `evt.ProcessId`，相当于不聚合，仅保证不崩。

不阻塞 UI 展示。后续如需聚合插件工具，再补 TurnId 透传。

### 6.3 用户手动折叠被覆盖

聚合卡需要记录 `_manualToggled`。自动折叠只在用户未手动操作，或当前轮明确成功结束时执行。

### 6.4 会议消息未产生正文

会议模式里工具调用可能先于正式文本。聚合卡作为消息流独立项插入，不依赖气泡创建，保持当前过程卡行为。

### 6.5 文本与工具时间穿插被打散

专家模式整轮共用一个 AI 气泡（`UiChatOutputChannel._currentPresenter`），所有 token 累积进同一个 `MarkdownRenderer`；正文 token 与工具事件原本按时间在消息流穿插。聚合后该轮所有工具集中到单张聚合卡，**用户失去工具与正文的时间穿插关系**。第一阶段接受这一 trade-off，理由是：

- 复杂任务工具数量远多于正文段落，穿插带来的滚动负担超过时间关系信息收益。
- 聚合卡内部仍按调用顺序展示子卡，时间序仍可追溯。
- 如果未来需要更细粒度，再按 `PublishRealtimeProcessEventsAsync` 发布的批次或正文段落分组。

### 6.6 取消 / 中断 / AskUser 期间运行中的工具

- `OnCancelledAsync`：聚合卡先 `CancelRunningTools`（运行中工具置 cancelled），再 `CompleteIfIdle`。`cancelled` 不计入失败计数，但会让聚合卡保持展开（见 §4.3）。
- `OnDoneAsync` / `OnErrorAsync`：流程同上，差别只在于 `OnDoneAsync` 不主动 cancel 运行中工具（理论不应有未完成工具，若有则保留 running 状态以暴露异常）。
- 会议 `OnMeetingAskUserRequested` / `OnMeetingPaused`：不主动收口工具聚合卡，运行中工具应在恢复后由 `OnMeetingToolResult` 自然完成；若最终走到 `OnMeetingMessageCompleted` / `OnMeetingMessageDiscarded` / `OnMeetingMessagePartialSaved`，再统一收口。

### 6.7 会议消息丢弃后聚合卡残留

`OnMeetingMessageDiscarded` 当前只移除 bubble，未清理已生成的过程卡 UI（既有 bug，聚合后会更明显——一整张工具聚合卡变成孤儿）。本方案顺手处理：

- 维护 `MessageId → 聚合卡 / 思考卡 / UI 容器` 的映射。
- 丢弃时一并 `_view.Messages.Items.Remove(...)` 对应容器，并从字典清理。

## 7. 验收标准

- 专家模式一次复杂任务产生大量工具调用时，消息流中只出现一张工具聚合卡，而不是大量平铺卡片。
- 展开聚合卡后能看到每个工具的原始详情、状态、耗时和失败信息。
- 工具全部成功后聚合卡自动折叠。
- 任一工具失败或被取消时聚合卡保持展开，并显示对应计数（失败 / 取消独立计数）。
- 会议模式同一条发言中的多个工具调用按 `MessageId` 聚合到一张卡。
- 会议消息丢弃时，对应聚合卡和思考卡也从消息流移除，无孤儿卡片。
- 思考过程仍按原逻辑显示，不被混入工具聚合。
- 工作模式展示不变。
- 不影响 AI 工具调用协议和历史上下文。

## 8. 建议验证

- 构造专家模式连续 5 个以上工具调用。
- 构造专家模式工具失败场景。
- 构造专家模式取消场景（运行中工具应记为 cancelled，聚合卡保持展开）。
- 构造插件链路（无 TurnId）调用，确认走 ProcessId 退化路径，不出现异常聚合卡。
- 构造会议模式某个参会者连续调用 3 个以上工具。
- 构造会议模式 `MeetingMessageDiscarded`（如生成中途丢弃），确认聚合卡和思考卡同时被移除。
- 回归会议模式思考卡完成后折叠。
- 回归普通纯文本聊天没有空聚合卡。
