# 模型选择与管理增强方案设计

## 1. 背景

本次涉及三项独立的模型相关交互改进：

1. **对话输入框模型 Popup 搜索**：部分厂商模型数量多（数十甚至上百），当前纯滚动列表难以定位目标模型。
2. **CTX 快捷选择**：设置界面编辑模型时，上下文长度字段需要手动输入，常用值（128K / 512K / 1M）应支持一键填入。
3. **模型可见性开关**：设置中可以管理全部模型，但对话框模型选择器只显示"已开启"的模型。新模型默认开启；关闭模型只从使用侧隐藏，不从设置列表删除。

## 3. 功能 1 — 模型 Popup 搜索框

### 3.1 现状

`InputAreaView.axaml.cs:1256` `FillModelSelectorList` 动态构建按钮填充 `ModelList`（`ItemsControl`），`ModelPopup` 结构为：

```
ModelPopup
└── Border (#181818)
    └── ScrollViewer
        └── ModelList (ItemsControl)
```

### 3.2 交互设计

- 打开 Popup 时，搜索框**自动聚焦**，支持立即键入。
- 搜索框**固定在顶部**，不随 `ScrollViewer` 滚动。
- 输入内容后**实时过滤**，匹配 `DisplayName` 或 `Name`（大小写不敏感）。
- 清空输入框后恢复全量列表。
- 每次打开 Popup 时自动清空上次输入。

**ModelSearchBox.TextChanged** 实时过滤：

```csharp
// 在 InitializeComponent 后订阅
ModelSearchBox.TextChanged += OnModelSearchTextChanged;

private void OnModelSearchTextChanged(object? sender, TextChangedEventArgs e)
{
    var keyword = ModelSearchBox.Text?.Trim() ?? string.Empty;
    var (allModels, activeId) = _inputVm switch
    {
        ChatInputVm cvm => (cvm.AvailableModels.Cast<AiModelEntity>().ToList(), cvm.SelectedModel?.Id),
        MeetingInputVm mvm => (mvm.AvailableModels.Cast<AiModelEntity>().ToList(), mvm.SelectedModel?.Id),
        WorkModeInputVm wvm => (wvm.AvailableModels.Cast<AiModelEntity>().ToList(), wvm.SelectedModel?.Id),
        _ => (new List<AiModelEntity>(), null)
    };

    var filtered = string.IsNullOrEmpty(keyword)
        ? allModels
        : allModels.Where(m =>
            (m.DisplayName?.Contains(keyword, StringComparison.OrdinalIgnoreCase) ?? false) ||
            m.Name.Contains(keyword, StringComparison.OrdinalIgnoreCase)).ToList();

    FillModelSelectorList(filtered, activeId);
}
```

## 5. 功能 3 — 模型列表可见性开关

### 5.1 现状

- `AiModelEntity.IsEnabled` 已存在，注释明确"设为 false 时将在模型选择列表中隐藏"。
- `BuildListItem` 每行只有"编辑"按钮，若要更改 `IsEnabled` 必须进入编辑表单，操作路径长。
- `AiModelService.GetByProviderId` 当前已经使用 `IsEnabled = 1` 过滤，因此对话、会议和工作模式的使用侧查询已经具备隐藏关闭模型的行为。
- **现存问题**：设置页同样调用 `GetByProviderId`，导致关闭模型从设置列表消失，无法重新开启；远程获取模型还会先删除再重建，导致本地状态丢失。
- 需要在 `AiModelService` 增加 `GetAllByProviderId`（不按 `IsEnabled` 过滤），仅供设置页管理全部模型；使用侧继续使用 `GetByProviderId`。

### 5.2 交互设计

- 列表项右侧使用 `ToggleSwitch` 展示启用状态，不再额外显示“开启 / 关闭”状态文字。
- 点击后立即更新 `entity.IsEnabled`，保存并发布事件，**无需打开编辑表单**。
- 设置页始终通过 `GetAllByProviderId` 加载全部本地模型，关闭模型仍保留在列表中，并显示为关闭状态。
- 对话、会议、工作模式的模型下拉列表只使用 `GetByProviderId` 返回的启用模型，关闭模型在这些下拉列表中隐藏。
- 默认模型的“默认”标识放在 `ToggleSwitch` 前面；默认模型的开关不可用且始终保持开启。尝试将关闭模型设为默认时，应先自动开启该模型。
- 关闭当前正在使用的模型时，自动切换到当前提供商下其他启用模型；没有可用模型时清空选择并禁用发送/执行操作。
- 点击后重刷设置列表，并通过现有 `MainWindow` 集中刷新三个输入 ViewModel，使状态即时同步，不在三个 ViewModel 中重复订阅同一事件。

### 5.3 BuildListItem 改动（ModelSettingsPage.axaml.cs）

在 `right` StackPanel 中，编辑按钮前插入开关按钮：

```csharp
private Border BuildListItem(AiModelEntity entity)
{
    // ... 已有代码 ...

    // 开关按钮
    var toggleBtn = new Button
    {
        Content = entity.IsEnabled ? "开启" : "关闭",
        IsEnabled = !entity.IsDefault,
        Padding = new Thickness(10, 3),
        FontSize = 12,
        Foreground = new SolidColorBrush(Color.Parse(entity.IsEnabled ? "#4CAF50" : "#858585")),
    };
    toggleBtn.Classes.Add("btn-secondary");
    if (!entity.IsDefault)
        toggleBtn.Click += (_, _) => ToggleModelEnabled(entity.Id);
    right.Children.Add(toggleBtn);   // 在 editBtn 之前

    // ... editBtn ...
}

private void ToggleModelEnabled(string id)
{
    var entity = ModelService.GetById(id);
    if (entity is null) return;
    if (entity.IsDefault) return;
    entity.IsEnabled = !entity.IsEnabled;
    ModelService.Update(entity);
    Publisher.Publish(Events.OnAiModelChange, new DataChangeArgs(id, ChangeType.Update));
    RefreshList();
}
```

### 5.4 使用侧刷新与状态约束

- 三个 ViewModel 不再自行实现一套过滤规则，统一调用已有的 `GetByProviderId`；该方法只返回 `IsEnabled = 1` 的模型。
- 设置页调用新增的 `GetAllByProviderId`，这样关闭模型仍能被管理和重新开启。
- `OnAiModelChange` 由 `MainWindow` 统一接收并刷新三个输入 ViewModel。刷新后如果当前选择的模型已关闭，按以下顺序选择：当前提供商的默认启用模型、列表第一项；两者都不存在则清空选择并禁用提交。
- 默认模型约束必须在服务层和界面层同时执行，不能只依赖按钮禁用：
  - `IsDefault = 1` 的模型必须 `IsEnabled = 1`；
  - 关闭操作遇到默认模型直接拒绝并保持开启；
  - 设置默认模型时，如果目标模型已关闭，先在同一事务中开启目标模型；
  - 远端删除默认模型前，先从保留模型中选出新的默认模型，再删除旧模型；没有可选模型时允许暂时无默认模型，但后续新增模型默认开启。

模型列表刷新必须区分两个用途：

| 用途 | 查询方法 | `IsEnabled = false` 的模型 |
|------|----------|-----------------------------|
| 设置页管理 | `GetAllByProviderId` | 保留并显示为关闭 |
| 对话/会议/工作模式选择 | `GetByProviderId` | 不返回，不显示 |

## 10. 本次补充：模型列表批量开关与标识顺序

### 10.1 设置页顶部批量开关

- 在模型管理页顶部操作区，将批量开关放在“添加模型”之后。
- 控件必须使用 `ToggleSwitch`，不能使用普通按钮；打开状态表示“批量开启”，关闭状态表示“批量关闭”。
- 该开关仅对当前选中的 AI 厂商生效：批量开启时开启该厂商的全部模型，批量关闭时关闭该厂商的全部普通模型。
- 默认模型受服务层约束，批量关闭时仍保持开启；批量开关状态独立维护，不根据模型行状态计算，也不因单个模型开关变化而改变。
- 切换操作使用一次事务完成，完成后发布模型变更事件并刷新设置列表及使用侧模型选择器，但不得重算或重置批量开关状态。
- 未选择厂商或该厂商没有模型时隐藏批量开关，避免产生无目标操作。

### 10.2 单模型行布局

- 普通模型行右侧只显示无文字 `ToggleSwitch` 和编辑操作。
- 默认模型行顺序为：模型信息 -> “默认”标识 -> 禁用的 `ToggleSwitch` -> 编辑。
- “默认”两个字必须位于开关前面，不能放在开关后面；不新增独立的开启/关闭文字。

## 6. 数据库与模型同步策略

### 6.1 数据库字段与迁移

- `AiModels.IsEnabled` 是模型显示/隐藏状态的唯一持久化字段，类型为 `INTEGER NOT NULL DEFAULT 1`；`AiModelEntity.IsEnabled` 默认值为 `true`。
- 当前建表脚本已经包含该字段，因此新数据库无需增加结构；更新已有数据库时必须通过 `CortanaDbContext.EnsureMigrations()` 增量补列：

```csharp
TryAddColumn("ALTER TABLE AiModels ADD COLUMN IsEnabled INTEGER NOT NULL DEFAULT 1");
```

- 迁移只为缺失字段的旧模型补默认值 `1`，不得把用户已经关闭的模型重新打开。迁移完成后修复历史脏数据：`IsDefault = 1` 的模型必须同步为 `IsEnabled = 1`。
- 开关操作、设置默认模型和远端模型同步使用事务，确保 `IsEnabled`、`IsDefault` 和模型删除不会出现中间状态。
- 不新增第二个“隐藏”字段，不用界面内存状态替代数据库状态。应用重启后，设置页和三个模型选择器必须从数据库重新得到一致结果。

### 6.2 远程模型增量合并

当前 `FetchAndSaveModelsAsync` 会先 `DeleteByProviderId` 再 `BatchInsert`，必须改为按提供商执行增量同步。远端请求失败时不修改本地数据；只有请求成功并拿到权威模型列表后，才执行以下步骤。成功返回的空列表也视为权威结果，此时该提供商下的本地模型均不再存在于远端，应按删除规则处理：

1. 使用 `ProviderId + Name` 匹配已有模型。若远端驱动以后提供稳定模型 ID，应优先使用稳定 ID；当前版本以模型名称作为匹配键。
2. 已存在模型保留原 `Id`、`CreatedTimestamp`、`IsEnabled`、`IsDefault` 以及用户在本地维护的设置，只更新远端元数据（显示名、描述、类型、上下文长度和能力信息）。
3. 远端新出现的模型新增记录，`IsEnabled = true`、`IsDefault = false`，因此新模型默认开启。
4. 本地已有但本次成功获取列表中不存在的模型才删除；不能因为模型仍存在于远端就删除重建。
5. 如果待删除模型是默认模型，先按“同提供商下其他启用模型、其他保留模型”的顺序指定新的默认模型，再删除旧模型；没有候选模型时清除默认标记并允许暂时无默认模型。
6. 同步完成后发布一次模型变更事件，设置页重新读取全部模型，三个使用侧选择器重新读取启用模型。

模型同步服务应提供明确的合并接口（例如 `SyncByProvider`），由数据服务负责事务、匹配、更新和删除；抓取服务只负责获取远端模型并转换为同步输入，避免在抓取层拼接删除再插入逻辑。

### 6.3 状态规则

| 场景 | 处理规则 |
|------|----------|
| 新增或新获取模型 | `IsEnabled = true` |
| 已存在模型再次获取 | 保留本地开启/关闭状态，不删除重建 |
| 远端成功列表中不存在 | 删除本地记录 |
| 关闭普通模型 | 设置页保留；使用侧下拉列表隐藏 |
| 关闭默认模型 | 拒绝操作，默认模型继续开启 |
| 删除默认模型 | 删除前重新指定默认模型 |
| 关闭当前使用模型 | 自动切换到可用模型；无可用模型则禁用提交 |

## 7. 不在本次范围

- 不修改智能体设置页面的模型选择逻辑；如该页面也使用模型下拉列表，应复用同一“仅返回启用模型”的服务方法。
- 不引入新的动画或主题资源，样式完全复用现有资源字典。

## 8. 本次交互修复补充规则

### 8.1 设置页模型状态

- 模型管理列表使用 `ToggleSwitch` 展示并操作 `AiModelEntity.IsEnabled`。
- 默认模型的开关 `IsEnabled = false`，`IsChecked = true`，始终保持开启且不可操作。
- 普通模型切换时调用现有 `AiModelService.SetEnabled`；保存成功后发布 `OnAiModelChange` 并刷新列表。
- 服务层操作失败时重新读取数据库状态，不能让开关停留在未保存状态。

### 8.2 模型选择 Popup

- 搜索框无边框，固定在 Popup 顶部，模型列表单独滚动。
- 搜索框获得焦点后，`Up`/`Down` 在当前过滤结果内循环移动高亮项，`Enter` 确认高亮模型并关闭 Popup，`Escape` 关闭 Popup。
- 搜索过滤同时匹配 `DisplayName` 和 `Name`，不区分大小写；键盘选择范围只包含当前过滤结果。
- 清空搜索内容后恢复全部启用模型；过滤结果为空时忽略 `Enter`，不执行模型切换。
- 对话、会议、工作三种输入模式共用同一套 Popup 键盘交互。
