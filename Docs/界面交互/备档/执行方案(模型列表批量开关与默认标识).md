# 执行方案：模型列表批量开关与默认标识

## 1. 目标

调整模型设置页的状态控件和操作区：

1. 移除单模型 `ToggleSwitch` 内的“开启/关闭”文字。
2. 在“添加模型”之后增加一个批量 `ToggleSwitch`，用于当前厂商的批量开启和批量关闭。
3. 将默认模型的“默认”标识放到单模型开关之前。

## 2. 实现边界

- 设置页仍通过 `GetAllByProviderId` 展示当前厂商的全部模型。
- 普通模型的单项切换继续使用 `AiModelService.SetEnabled`。
- 批量操作新增模型服务层事务接口，批量开启全部模型，批量关闭全部非默认模型。
- 默认模型无论单项操作还是批量关闭都必须保持开启。
- 批量开关只在选中厂商且存在模型时显示；厂商切换或刷新列表只控制显示，不重置批量开关状态。
- 单个模型开关变化不会改变批量开关的 `IsChecked`，两个控件状态相互独立。
- 批量操作完成后发布模型变化事件并刷新列表，失败时重新读取数据库状态。

## 3. 交互规则

| 场景 | 处理 |
| --- | --- |
| 未选择厂商 | 隐藏批量开关，列表显示选择提示 |
| 当前厂商无模型 | 隐藏批量开关，列表显示空状态 |
| 批量开关打开 | 当前厂商全部模型开启 |
| 批量开关关闭 | 当前厂商普通模型关闭，默认模型保持开启 |
| 默认模型 | “默认”在开关前，开关禁用且保持打开 |
| 单模型开关 | 仅显示开关，不显示开启/关闭文字 |

## 4. 技术实现

- `ModelSettingsPage.axaml`：将批量 `ToggleSwitch` 放入顶部操作区，并绑定 `IsCheckedChanged`。
- `ModelSettingsPage.axaml.cs`：维护批量开关的显示和状态，处理厂商切换、刷新、异常恢复及批量操作。
- `AiModelService.cs`：增加按厂商批量更新启用状态的事务方法，批量关闭时排除默认模型。
- `方案设计.md`：保留本次交互约束和验收标准，作为执行依据。

## 5. 验收重点

- 单模型开关视觉上没有“开启/关闭”文字。
- 批量开关紧邻“添加模型”之后，并且确实是 `ToggleSwitch`。
- 批量开启和批量关闭只影响当前厂商。
- 批量关闭不能关闭默认模型。
- 默认标识位于单模型开关前方。
- 切换厂商、刷新列表、操作失败后批量开关保持自身状态；单个模型开关变化不会改变批量开关状态。
