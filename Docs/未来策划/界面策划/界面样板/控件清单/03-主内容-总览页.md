# 03 · 主内容 · 总览页 `#pane-overview`

主内容区 `#content` 里的第一个面板（默认 `.on` 显示），
对应标签栏 `#tab-overview`。整体是一个纵向滚动容器 `.ov-scroll`，从上到下四个板块。

---

## 主内容框架（先了解外壳）

- `#mainarea` — 主内容区，纵向 flex
- `#tabbar` — 顶部标签栏，高 36px，横向可滚动：
  - `.titem` 标签项：26px 高，选中 `.on` 变正文色 + 与内容区同底连成一体
  - 标签内 `.tdot` 模式色圆点、`.tcx` 关闭叉、会议标签额外带绿色呼吸点表示活动
  - `.tadd` — 末尾"＋"新建标签，点 `openNewDialog()`
  - 函数：`switchTab(id)` 切换、`openTask()` 新开、`closeTab()` 关闭
- `#content-row` — 横向 flex，左 `#content`（各 pane），右侧是常驻的项目上下文面板（见 05 文档）
- `.pane` — 每个模式一个面板，`.on` 显示

---

## 1. KPI 行 `.kpi-row`

- **位置** — 总览页顶部
- **风格** — 横向 flex 可换行，每个 `.kpi` 卡片 `--s0` 底 + 边框圆角，最小宽 110px，悬停边框变亮
- **内部** — `.kpi-lbl`（10px 大写标签 + 图标）+ `.kpi-num`（20px 粗体数字）+ `.kpi-trend`（趋势小字）
- **样板 4 项** — 今日订单 184（绿）、待发布商品 27（蓝）、待处理异常 6（黄）、本月净回款 ¥38,624（绿）

> **数据来源：品牌配置驱动。** 样板这 4 项是电商示例，实际 KPI 由当前品牌的
> `Build/brands/{brand}/workbench.json` 的 `overview.kpis` 声明，数值由 Runtime
> 针对当前工作目录 / 平台 API 实时求值。切换品牌即换整组仪表盘，骨架不变。
> 详见 [总览页配置驱动方案](../../总览页配置驱动方案.md)。

## 2. 继续工作卡 `.resume-section` > `.task-card`

总览页的核心区块，展示当前主任务的完整进度，让用户一眼续上工作。

- **区块头** `.sec-hd` — `.sec-hd-title`"继续工作" + 右侧 `.sec-hd-link`"查看全部任务"（点 `switchNav('tasks')`）
- **卡片** `.task-card` — 横向两栏布局，`--s0` 底 + 边框圆角，内边距 14px

### 左栏 `.tc-left`（弹性主体）

- `.tc-header` — 状态行：`.dot.d-wk.pulse` 橙呼吸点 + `.mbadge.mb-wk`"⚡ 工作"徽章 + `.stbadge.st-run`"执行中"状态徽章
- `.tc-name` — 任务名"登录模块重写"（14px 粗体，可点开任务）
- `.tc-desc` — 任务描述段落（次要灰）
- `.tc-meta` — 元信息行：主 Agent、截止时间、产物数（各带图标）
- `.tc-prog-wrap` — 进度条：`.tc-prog-lbl`（"执行进度" + 橙色"38%"）+ `.tc-prog-bg`/`.tc-prog-fg`（5px 高，橙色填充，`transition:width .5s`）
- `.tc-btns` — 按钮组：
  - `.tcbtn.tcbtn-pri` 橙底"继续工作对话"（点 `openTask()`）
  - `.tcbtn.tcbtn-sec` 灰底"暂停"（点 `pauseTask()`）、"···"更多

### 右栏 `.tc-right`（190px，左侧分隔线）

- `.tc-steps-hd` — "业务步骤"小标
- `.tcs` 步骤条目 — `.tcs-num`（圆形序号）+ `.tcs-text`（步骤名）+ `.tcs-tag`（状态）
  - 状态类：`.done`（绿✓）/ `.run`（橙进行中）/ `.warn`（黄需确认）/ `.wait`（灰待执行）
  - 样板 6 步：分析代码结构✓、确认重构方案✓、生成 auth.cs(进行中)、生成单元测试、等待发布确认(需确认)、集成测试验证

## 3. 常用操作 `.qa-section`

- **区块头** — "常用操作" + "管理"链接
- **网格** `.qa-grid` — 3 列网格（`grid-template-columns:1fr 1fr 1fr`），间距 8px
- **`.qa-item` 卡片** — `--s0` 底 + 边框，悬停变强调边 + `--s1` 底
  - `.qa-icon` — 28px 圆角图标块（悬停变 `--acd` 底 + `--ac` 图标）
  - `.qa-name` — 操作名 · `.qa-desc` — 描述
- **样板 6 项** — 新建工作任务、代码分析、发起评审会议、查看历史记录、工作区文件、处理审批（异常项文字标黄）

> **数据来源：通用段 + 品牌段。** 通用段（新建任务/查看历史/工作区文件）骨架固定；
> 品牌段由 `workbench.json` 的 `overview.quickActions` 声明，每项绑定
> `action`（builtin / command / skill）。AI 助理品牌是代码分析/评审会议/运行测试，
> 电商品牌是批量上架/订单同步/异常处理。详见
> [总览页配置驱动方案](../../总览页配置驱动方案.md)。

## 4. 活跃任务表 `.sec` > `table`

- **区块** — `.sec-title`"活跃任务"（顶部有分隔线）
- **表格** — 通用 `table` 样式：`thead th` 弱色小写表头、`tbody td` 12px、行悬停 `--s1` 底可点
- **列** — 标题 / 模式 / 状态 / 进度 / 主 Agent / 耗时
  - 模式列用 `.mbadge` 模式徽章
  - 状态列用 `.sdot`（`.sd-run` 绿 / `.sd-wait` 黄 / `.sd-done` 灰）+ 文字
  - 进度列内嵌 `.prog-bar`/`.prog-fill` 迷你进度条（填充色随模式）
- **样板 3 行** — 登录模块重写(工作)、架构评审会(会议)、代码优化讨论(专家)，点行 `openTask()`
