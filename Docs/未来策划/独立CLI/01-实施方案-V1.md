# 独立 AI CLI / Runtime 实施方案 V1

> 文档状态：待实施
>
> 前置文档：[独立 AI CLI / Runtime 总体方案与总需求](./README.md)
>
> V1 定位：证明独立 Runtime 可以通过稳定协议完成专家、会议、工作三种模式、多任务、流式输出、宿主工具调用、对话持久化和基础故障恢复，不修改当前 Madorin 项目作为实施前提。

## 1. V1 目标

V1 建设一个全新的 .NET 独立解决方案，交付可执行 Runtime、CLI、.NET Client SDK、专家/会议/工作三种模式、两个正式 Provider Adapter、一个 OpenAI Compatible Adapter 和一个参考宿主。

V1 必须闭合以下完整链路：

```text
参考宿主创建任务
-> 启动并连接 Runtime
-> 传入运行模式、Provider、模型和模式专属 Agent 配置
-> Runtime 调用模型并流式输出
-> 总经理或其他 Agent 按需向宿主申请工具权限
-> Runtime 或宿主执行工具并返回结果
-> Runtime 继续推理
-> 形成唯一终态
-> Runtime 持久化对话和恢复状态
-> 宿主确认事件游标并保存业务投影
```

完成这个闭环后，再考虑用户自定义图形化 Workflow、通用 Agent 消息总线、远程部署和强沙箱。

## 2. V1 范围

### 2.1 必须实现

- `serve`、`run`、`doctor`、`providers`、`version` CLI 命令。
- Windows Named Pipe 本地通信。
- 独立控制通道和事件通道。
- 协议版本协商、实例认证和能力查询。
- 多 Run 并发及按 Run 隔离的状态、取消和事件序号。
- 专家模式：宿主传入 Provider、模型和单个 Agent。
- 会议模式：宿主传入参与 Agent 数组和会议策略，Runtime 构建主持人、选择器和参与者。
- 工作模式：宿主传入总经理 Agent、可用子智能体数组和工作策略，Runtime 执行计划、步骤和后台子智能体作业。
- 同一 Session 在当前流结束后直接切换 Provider、模型、Agent 和提示词，不新建或重启对话。
- 文本输入、系统指令、模型参数和文本流式输出。
- 推理增量、工具调用、完成原因、用量和结构化错误事件。
- OpenAI Responses API Adapter。
- Anthropic Messages API Adapter。
- OpenAI Compatible Adapter。
- 版本化宿主工具目录及双向工具 RPC。
- 宿主审批请求和响应。
- 心跳、状态查询、事件确认和有限事件重放。
- URL、路径、Prompt 和结构化数据的无损传递，以及大型文件 Blob 传输。
- 工作区受限的内置文件工具、受控进程工具和默认关闭的 PowerShell 工具。
- 独立配置、数据、日志和工作目录。
- 默认将权威对话记录和恢复状态保存到 `workspaceRoot/.madorin`，并提供分页查询和恢复 API。
- .NET Client SDK 和参考宿主。
- 协议一致性、并发、断线、取消和工具幂等测试。

### 2.2 可以降级但必须显式报告

- Provider 不支持 reasoning 时不产生推理事件。
- Provider 不返回精确用量时，将用量标记为未知或估算，不能伪装成精确值。
- OpenAI Compatible 服务不支持标准工具调用时返回能力不支持错误。
- Provider 不支持服务端取消时，Runtime 停止读取响应并释放本地 Run，同时记录远端取消能力缺失。

### 2.3 V1 不实现

- 不实现对 Claude CLI、Codex CLI 输出的解析和复用。
- 不实现 Gemini 正式 Adapter，放入 V2 前置队列。
- 不实现用户自定义图形化 Workflow 和通用 Agent 间消息总线；会议和工作模式所需的内建多 Agent 编排属于 V1。
- 不实现跨机器 Runtime 和分布式 Worker。
- 不实现完整容器/AppContainer 沙箱。
- 不实现 Provider 程序集运行中原地卸载。
- 不实现音频、视频、Computer Use 和超大文件上传。
- 不承诺 Runtime 崩溃后恢复模型 TCP 流，只保证任务状态可判定并可按策略重试。
- 不接入当前 Madorin 主程序；V1 使用参考宿主验证公开集成能力。
- 不按日期拆分会话数据库，也不让宿主通过扫描目录查找会话。

## 3. V1 技术决策

### 3.1 运行平台

- .NET 10。
- **V1 从第一个版本起要求 Native AOT 兼容和发布**，遵循当前 Madorin 主程序已验证的模式：
  - Release 配置启用 `<PublishAot>true</PublishAot>`
  - `<JsonSerializerIsReflectionEnabledByDefault>false</JsonSerializerIsReflectionEnabledByDefault>`
  - 所有序列化类型注册到 `JsonSerializerContext` source generator，不使用运行时反射序列化
  - MAF（`Microsoft.Agents.AI` 全家桶）通过 `<TrimmerRootAssembly>` + `rd.xml Dynamic="Required All"` 保留反射元数据，与主程序处理方式一致
  - `IlcOptimizationPreference=Speed`，不生成 stack trace data（Release）
- **多平台发布目标**：
  - `win-x64`：V1 首要目标，完整功能
  - `osx-x64` / `osx-arm64`（Apple Silicon）：V1 验证目标
  - `linux-x64` / `linux-arm64`：V1 验证目标
- 传输层和安全层使用 `Transport.Abstractions` 隔离平台差异，核心业务逻辑零平台依赖。

### 3.2 传输和序列化

**IPC 传输**：优先采用跨平台方案。.NET 10 的 `NamedPipeServerStream` / `NamedPipeClientStream` 在所有平台上可用——Windows 使用 `\\.\pipe\...` 命名管道，macOS/Linux 自动映射为 Unix Domain Socket 文件（`/tmp/...`）。V1 直接使用 .NET 跨平台 API，传输层隔离安全逻辑，不在业务层写平台判断。

管道标识规则：

```text
Windows：\\.\pipe\netor.ai.runtime.{instanceId}.control
         \\.\pipe\netor.ai.runtime.{instanceId}.events
Unix：   /tmp/netor.ai.runtime.{instanceId}.control.sock
         /tmp/netor.ai.runtime.{instanceId}.events.sock
```

路径由 `Transport.NamedPipes` 实现层按运行时平台自动生成，对上层暴露统一的 `IControlChannel` 和 `IEventChannel` 接口。

`instanceId` 由宿主生成（UUID v4），通过启动参数 `--instance` 传入；`--pipe-prefix` 可覆盖前缀。认证通过双向挑战响应（见 `02-架构修订 §6`），不使用句柄传递原始令牌。

技术约束：

- JSON 使用 UTF-8 和固定序列化规则。
- 控制通道和事件通道均采用长度前缀帧（4 字节大端 uint32 表示后续字节数），禁止依赖换行或 EOF 分帧。控制通道消息遵循 JSON-RPC 2.0 语义，事件通道消息为单向事件帧。
- 单普通消息设定明确大小上限，超限内容转换为 Blob 引用。
- 高频文本 Delta 可以在不改变语义顺序的前提下短时间批量发送。
- 控制消息优先于事件发送，取消和心跳不得被输出流阻塞。
- 路径、URL、命令和参数使用独立字段；不得按空格拆分或拼接为 Shell 命令。
- 字符串不执行隐式 Trim、URL Decode、路径替换或 Unicode 归一化。

V1 初始默认值如下，并在初始化时协商，最终以双方协商结果为准：

```text
maxControlMessageBytes = 1 MiB
maxEventFrameBytes     = 256 KiB
maxInlineContentBytes  = 256 KiB
blobChunkBytes         = 1 MiB
maxBlobBytes           = 1 GiB
maxBlobBytesPerRun     = 2 GiB
```

大小全部按 UTF-8 字节或原始二进制字节计算。超过内联阈值后使用 Blob Stream 或受控 Staging File；Blob 以 64 位长度和 SHA-256 验证完整性。

### 3.3 进程拓扑

V1 采用单 Runtime 进程、多 Run Scope：

```text
Host Process
  -> AI Runtime Process
       -> Run Scope A
       -> Run Scope B
       -> Run Scope C
```

每个 Run 具有独立依赖作用域、取消源、事件序列、Provider 请求和工具调用表。V1 暂不为每个 Run 启动子进程，但协议中不暴露这一实现细节，以便 V2 增加 Worker 模式。

### 3.4 状态持久化

**设计原则：索引在库、内容在文件**（与 `Docs/未来策划/存储优化/对话记录文件化存储方案.md` 对齐）

`.madorin` 目录布局：

```text
workspaceRoot/
└── .madorin/
    ├── state.db          SQLite + WAL，只存元数据和事务性状态（见下）
    ├── messages/
    │   ├── {sessionId}.jsonl         CanonicalHistory 消息正文，append-only
    │   └── {sessionId}.compact.json  ContextProjection 缓存，可重新生成
    ├── blobs/            大型二进制内容，按 sha256 前缀分片
    ├── checkpoints/      可恢复快照
    ├── staging/          未完成传输的临时文件
    ├── locks/            进程锁文件
    └── logs/
```

**`state.db` 存储范围**（只存可查询/事务性数据）：

| 数据类型 | 存储位置 | 说明 |
|---|---|---|
| Session 元数据（id、mode、status、updatedAt、title） | state.db | 用于列表、过滤、分页 |
| Run / Invocation 状态和快照 | state.db | 状态机、取消、恢复 |
| 工具调用幂等记录（callId、status、argumentsHash） | state.db | 事务性，恢复时查询 |
| NextTurnSelection 版本 | state.db | 乐观并发控制 |
| 会议轮次结构（meeting_sessions/rounds/invocations） | state.db | 结构化查询 |
| 工作步骤图（work_sessions/steps/tool_intents） | state.db | 依赖关系和幂等 |
| Blob 元数据（blobId、contentType、length、sha256） | state.db | 索引和引用 |
| GSN 游标、事件确认位置 | state.db | 断线恢复 |
| 消息正文（Content、ContentsJson） | messages/{sessionId}.jsonl | append-only，不进 SQLite |
| ContextProjection 缓存 | messages/{sessionId}.compact.json | 可重新生成 |
| 大型二进制内容 | blobs/ | 按内容哈希寻址 |

**消息文件格式**（JSONL）：

```jsonl
{"type":"header","schema":1,"sessionId":"ses_xxx","mode":"expert","createdAt":"..."}
{"messageId":"msg_aaa","seq":1,"invocationId":"inv_xxx","agentId":"agent_xxx","role":"user","content":"...","ts":"..."}
{"messageId":"msg_bbb","seq":2,"invocationId":"inv_xxx","agentId":"agent_xxx","role":"assistant","content":"...","tokens":123,"model":"...","ts":"..."}
```

每行必须包含 `messageId`（UUID，写入前在内存生成）。`seq` 从文件而非 SQLite 派生——崩溃后重试不会产生重复序号。

**写入流程（幂等）**：
1. 在内存生成 `messageId`（UUID）和 `seq = lastKnownSeq + 1`；`lastKnownSeq` 在 Session 加载时从 `.jsonl` 末行读取，而非从 `state.db` 读取
2. Append `{messageId, seq, ...}` 到 `.jsonl`（flush 落盘）
3. 更新内存 `lastKnownSeq = seq`
4. 更新 `state.db`：`INSERT OR IGNORE INTO messages(message_id, session_id, sequence, ...)` — `message_id` 为主键，重复插入幂等忽略

**崩溃恢复规则**：
- 步骤 2 之前崩溃：无副作用，重试从同一个 seq 开始
- 步骤 2 成功、步骤 4 失败（最常见崩溃点）：重启时扫描 `.jsonl` 末行，发现 seq=N 已在文件；步骤 4 的 `INSERT OR IGNORE` 补入索引，不产生重复行
- `.jsonl` 末行不完整（写到一半进程被杀）：跳过损坏末行，从上一完整行的 seq 派生下一个序号

**与 `存储优化` 方案的语义差异**：存储优化方案明确接受"崩溃丢最新几条"（低持久性语义）；独立 Runtime 的 `.jsonl` 通过上述幂等写入，保证**已落盘的行永远可重建索引，不出现重复 seq**，满足更严格的权威存储要求。

读取流程：
- 列表/过滤/分页：只读 `state.db` 索引，不碰文件
- 加载对话内容：按 `sessionId` 定位 `.jsonl` 文件，逐行解析
- ContextProjection：先检查 `.compact.json` 是否仍然有效（哈希匹配），有效则直接使用，否则重新从 `.jsonl` 生成

其他持久化规则：
- Blob 传输未完成时文件在 `staging/`，校验通过后原子移入 `blobs/`
- `state.db` 使用 busy timeout、WAL checkpoint；`.jsonl` 使用 append + 末行截断识别
- `state.db` 损坏时可通过扫描 `messages/` 重建 Session 元数据（索引自愈工具）
- 宿主只能通过 Client SDK 查询、分页和恢复会话，不直接读取或修改 `.madorin`

### 3.5 内置工具和权限模式

V1 内置以下工具组：

```text
builtin.fs          文件读写、列表、搜索、补丁（限 workspaceRoot）
builtin.process     受控进程执行（仅白名单程序）
builtin.powershell  显式授权后开放，默认关闭
builtin.content     编码识别、分页读取、哈希、内容类型识别
builtin.http        显式网络策略授权后开放，默认 Deny；见 §7.2 networkPolicy
```

默认使用 `Restricted` 模式：文件读写限制在 `workspaceRoot`，覆盖、移动和删除需要额外权限，工作区外访问、任意进程和 PowerShell 均关闭。Runtime 保留的 `.madorin` 子目录始终从 Agent 文件工具的默认允许范围中排除。

V1 的 `AllowlistedProcess` 只运行宿主 Grant 中允许的程序。`builtin.powershell` 只在显式 `UnrestrictedShell` 授权后开放，使用 `-NoProfile` 和 `-NonInteractive`；V1 不把这种模式描述为工作区隔离。真正受限的 `SandboxedShell` 放入后续版本。

工作模式中，未被现有 Grant 覆盖的工具调用先发送 `tool.permission.request`。子智能体默认不继承总经理权限；只有宿主 Grant 显式允许委派时，才能在更窄或相同作用域内继承。

## 5. V1 公共契约

### 5.1 初始化

宿主创建一次性连接令牌和实例名，通过受控启动参数传给 Runtime。建立控制通道后，宿主发送：

```text
InitializeRequest
- supportedProtocolVersions
- hostInstanceId
- clientVersion
- desiredCapabilities
- eventReplayCursor
  （注：认证通过双向挑战响应完成，不在此消息中传 token，见 02-架构修订 §6.3）
```

Runtime 返回：

```text
InitializeResponse
- selectedProtocolVersion
- runtimeInstanceId
- runtimeVersion
- capabilities
- limits
- eventPipeName
- heartbeatInterval
```

协议版本无交集或认证失败时立即关闭连接。

### 5.2 Run 请求与运行模式

`RunStartRequest` 使用稳定公共字段和 `modeOptions` 鉴别联合，禁止用一个充满可空字段的大 DTO 表达三种模式：

```text
runId
sessionId
taskId
attemptId
idempotencyKey
workspaceRoot
mode                       Expert | Meeting | Work
selectionVersion
defaultSelection
  providerId
  providerProfileId
  modelId
contents
attachments
generationOptions
turnOverride
toolCatalogVersion
timeout
metadata
modeOptions
```

模式专属契约为：

```text
ExpertOptions
  agent

MeetingOptions
  participants[]                 多选，最少 2 人，建议上限 10，硬性上限 20
    agent                        AgentRef（含 promptTemplate、capabilities 等）
    participantId                稳定标识，用于增量更新和会议记录引用
    displayName                  展示名称（可与 agentId 不同）
    joinOrder                    整数，初始发言优先级顺序（值越小越优先）
    status                       Active | Standby
                                 Active：默认，加入会议后按策略调度发言
                                 Standby：预加载但不主动调度，等待 Selector 或主持人激活
    providerOverride?            覆盖 defaultSelection.providerId
    modelOverride?               覆盖 defaultSelection.modelId
  hostAgent?                     主持人 Agent（可空，缺省使用 Runtime 内建主持人）
  selectorPolicy
    type                         RoundRobin | SelectorDriven | HostDriven
                                 RoundRobin：按 joinOrder 轮流，忽略 Selector 调用
                                 SelectorDriven（默认）：每轮由 Selector Agent AI 调用决定下一位
                                 HostDriven：宿主通过协议命令显式指定每轮发言者
    selectorAgent?               SelectorDriven 时使用的 Selector Agent（可空，缺省内建）
    maxRounds?                   会议最大轮次，超出后自动结束（可空=无限制）
    allowStandbyActivation       Selector 是否可以激活 Standby 参与者（默认 true）
  meetingPolicy
    summaryMode                  None | PerRound | FinalOnly
    summaryAgent?                生成摘要的 Agent（可空，缺省内建）
    concludeCondition            MaxRounds | HostDecides | ConsensusReached
    allowLateJoin                会议进行中是否允许通过 selection.update 新增参与者（默认 true）

WorkOptions
  generalManagerAgent
  availableAgents[]
  workflowPolicy
    maxAgentDepth            默认 3，绝对上限 10；超出时返回 DepthLimitExceeded
    maxStepsPerRun           默认 50，绝对上限 500
    maxSubAgentJobs          默认 20
    stepTimeoutSeconds       默认 300
    loopDetection            Strict（默认）| Lenient | Disabled
  toolPermissionPolicy
```

每个 `AgentRef` 至少包含以下字段，并允许覆盖公共的 Provider、模型和生成参数；未覆盖时继承 `defaultSelection`：

```text
agentId
displayName
promptTemplate
  templateId
  templateVersion
  contentHash                sha256 of resolved prompt
  layers[]
    layer                    AgentPrompt | SessionInstructions | RunInstructions
    content                  明文，或 isRedacted=true 时为 null
    isRedacted               true 时 Runtime 只保存哈希，不持久化明文
capabilities[]               text | tool_use | reasoning | ...
providerOverride             可空
modelOverride                可空
generationOptionsOverride    可空
```

Prompt Template 由宿主持有并内联传递，Runtime 不维护模板库，只验证 `contentHash`。宿主查询某 Turn 使用的提示词时，Runtime 返回快照中的 `templateVersion` 和 `contentHash`，不返回明文正文。会议参与者、工作模式子智能体未覆盖时继承 `defaultSelection`。

**Session 创建路径**：`run.start` 支持两种路径，通过 `sessionId` 字段是否存在区分：

- 路径 A（提供 `sessionId`）：必须是已存在的活动 Session；`mode` 与 Session 保存的 `mode` 不一致时返回 `ProtocolConflict` 错误。
- 路径 B（不提供 `sessionId`）：Runtime 自动创建新 Session，在 `RunAccepted` 中返回 `sessionId` 和初始 `selectionVersion=1`。等同于先调 `session.new` 再调 `run.start`，但在一次往返中完成。这是 `ai-runtime run` CLI 的默认路径。

Session 创建后 `mode` 在 V1 中不可隐式修改；Provider、模型、Agent 和提示词仍可按第 5.3 节在相邻 Turn 之间切换。

Runtime 只有在完成格式、能力和资源检查后才返回 `RunAccepted`。相同幂等键不得创建第二个活动 Run。

每个 `AgentInvocation` 开始时产生 `invocation.started` 事件，携带不可变的 `InvocationSnapshot`（详见 `02-架构修订-V1.md §1`）——这是记录实际使用 Provider、模型、Agent、Prompt 和工具目录的权威快照。`RunAccepted` 只返回 Run 级的初始检查结果，不再作为配置权威。

```text
run.start (NewSessionRunRequest 或 ExistingSessionRunRequest)
  -> RunAccepted（Run 接受确认，状态 = Preparing）
  -> [Provider 连接、模型能力校验，构建 AgentInvocation]
  -> invocation.started（InvocationSnapshot，状态 = Running）
  -> output.delta ...
  -> invocation.completed
  -> RunCompleted
```

会议模式每位参与者/主持人一轮 = 一个 `AgentInvocation`；工作模式每个子智能体调度 = 一个 `AgentInvocation`；专家模式每个用户 Turn = 一个 `AgentInvocation`。同一 Run 内多个 Invocation 的 Provider、模型、Prompt 可以不同，各自由 `InvocationSnapshot` 独立记录。

### 5.3 同一 Session 的下一轮实时选择

V1 提供：

```text
session.selection.update
session.selection.get
session.new
```

`session.selection.update` 使用 `expectedSelectionVersion` 更新同一 Session 的 `NextTurnSelection`。Selection 由公共 `defaultSelection` 和模式专属 `modeSelection` 组成：专家模式保存单个 Agent；工作模式保存总经理、可用子智能体数组和 Workflow 策略。版本不匹配时返回冲突，不执行最后写入覆盖。

**会议模式的参与者更新**支持两种路径，通过是否包含 `participantPatches` 字段区分：

```text
路径 A：全量替换（participants 字段存在）
  modeSelection.Meeting
    participants[]           新的完整参与者列表（最少 2 人）
    hostAgent?
    selectorPolicy
    meetingPolicy

路径 B：增量修改（participantPatches 字段存在，participants 不存在）
  modeSelection.Meeting
    participantPatches[]
      op                    Add | Remove | UpdateStatus | Reorder
      participantId         目标参与者的 participantId
      agent?                op=Add 时必须提供 AgentRef
      status?               op=UpdateStatus 时提供新状态（Active | Standby）
      newJoinOrder?         op=Reorder 时提供新的 joinOrder 整数
    hostAgent?              可选，不传则保持不变
    selectorPolicy?         可选，不传则保持不变
    meetingPolicy?          可选，不传则保持不变
```

增量修改的约束：
- `Add`：新参与者 `participantId` 不能与已有参与者重复；`meetingPolicy.allowLateJoin=false` 时拒绝，在已有 AgentInvocation 正在执行期间不影响当前发言
- `Remove`：不能移除唯一的 Active 参与者；被移除但正在发言的 Agent 完成当前 Invocation 后不再调度
- `UpdateStatus`：Active→Standby 的参与者在当前轮次结束后生效；Standby→Active 在下一轮 Selector 调度时生效
- `Reorder`：只影响下一次 Selector 调度，不中断当前发言

无论哪种路径，Runtime 均立即返回 `selection.updated`，生效时机为下一个会议安全点（当前发言者 Invocation 结束后）。

更新操作可以在当前流式输出期间调用。Runtime 验证后立即确认新版本，但不能取消、重启或改变当前流：

```text
Turn A / Selection v20 正在输出
Host -> session.selection.update(expected=20, new=v21)
Runtime -> selection.updated(v21, effective=NextTurn)
Turn A -> RunCompleted
Turn B / 同一 sessionId -> 使用 Selection v21
```

下一轮 Provider、模型、Agent、提示词或生成参数从最新 Selection 解析。`RunStartRequest.turnOverride` 只用于单轮临时覆盖，不修改 Session 后续默认值。

V1 生效规则：

- 当前 `AgentInvocation` 使用不可变的 `InvocationSnapshot`（见 `02-架构修订 §1`），只是为了保护当前发言/步骤不被中途污染。
- Selection 更新在当前 Turn 结束后的下一轮直接生效，不要求取消、不创建新 Session，也不创建新的对话分支。
- 下一轮开始时重新构建 Provider Client、Model Client、AIAgent、提示词和工具上下文，但复用原 `sessionId` 和完整规范化历史。
- 如果更新发生在任务排队期间，以 Turn 真正开始时最新的 Selection 为准，而不是以入队时选择为准。
- Provider 切换后由统一框架和 Adapter 从同一会话历史组装请求；厂商私有 Session/Response ID 不能决定对话是否连续。
- 新模型容量不足时，Runtime 返回上下文调整事件，明确记录裁剪、摘要或拒绝策略。
- Agent 提示词使用版本和哈希标识；临时本轮指令不覆盖 Runtime 安全策略。
- 只有显式 `session.new` 才能创建新对话；普通配置切换不得调用它。

**Selection 冲突重试**：版本不匹配时返回 `SelectionVersionConflict` 错误，不执行覆盖。Client SDK 标准处理：先调 `session.selection.get` 获取最新版本，再重新提交；最多重试 3 次，仍冲突时抛出异常交给调用方。多个界面面板并发更新 Selection 时，冲突重试是预期行为，不视为错误。

会议和工作模式的安全生效点定义为：

- 会议模式：当前参与者或主持人的模型流正常结束后，下一位尚未开始的发言者解析最新 Selection；正在发言的 Agent 不被替换。
- 工作模式：当前模型流正常结束后，下一项尚未开始的步骤或 Agent 调用解析最新 Selection；已经启动的后台子智能体作业继续使用启动快照。
- Agent 集合更新产生新的 `modeConfigurationVersion`；被移除但仍在运行的 Agent 可以完成当前调用，但不得再次被调度。


### 5.6 规范化消息历史

Runtime 内部维护一套与厂商无关的规范化历史，各 Provider Adapter 负责转换，不把厂商私有格式直接存入 `state.db`。

**规范化消息结构**（核心字段）：

```text
messageId
sessionId
sequence
role                user | assistant | tool_result
turnId
content[]           ContentBlock 联合类型（见下）
metadata
  providerId
  modelId
  agentId
  createdAt
  finishReason      end_turn | tool_use | max_tokens | cancelled | error
  usage             inputTokens / outputTokens
```

ContentBlock 联合类型：

```text
{ type: "text",        text }
{ type: "reasoning",   text, signature }
{ type: "tool_call",   callId, toolId, name, arguments }
{ type: "tool_result", callId, toolId, status, content[], error }
{ type: "blob_ref",    blobId, contentType, length, sha256, fileName }
```

**跨 Provider 转换规则**：

- Anthropic：`role=tool_result` 消息和 `role=user` 消息均映射为 Anthropic `role=user`；工具调用块映射为 `tool_use` 内容块；跨 Provider 切换时 reasoning `signature` 失效，Adapter 降级为普通文本块并产生 `history.trimmed` 事件。
- OpenAI（Responses / Chat Completions）：`role=tool_result` 映射为 `role=tool`，`tool_call_id` 使用 `callId`；reasoning 块映射为原生 reasoning summary（如有）或丢弃并产生 `history.trimmed` 事件。

**历史裁剪规则**：新模型上下文窗口不足时，按以下优先级裁剪：reasoning 块 > 早期工具结果内容 > 早期消息（保留最近完整对话轮次）。每次裁剪产生 `history.trimmed` 事件，包含被裁剪消息数、token 估算和裁剪策略名称；不允许静默丢失。

### 5.7 凭据续期

Work 模式和长会话场景下 Provider API Key 可能在执行中途过期。

**宿主主动推送**：宿主可在任意时刻通过控制通道发送 `credentials.update`，包含 `providerId`、`providerProfileId`、凭据类型和值（日志必须脱敏）、`expiresAt`。Runtime 收到后立即替换对应 Profile 凭据，下一次 Provider 请求生效，不中断当前已发出的请求。

**Runtime 主动请求续期**：Provider 返回 `401 Unauthorized` 或凭据距 `expiresAt` 不足 5 分钟时，Runtime 向宿主发送 `credentials.refresh.request`，包含 `providerId`、`providerProfileId`、`reason`（`Expiring | Unauthorized`）、`runId`。宿主通过 `credentials.update` 回应；若超时（默认 30 秒）未收到响应，Runtime 将当前 Run 置为 `WaitingForCredentials` 状态并暂停向 Provider 发出请求，凭据到达后自动恢复。

Run 状态机新增路径：`Running -> WaitingForCredentials -> Running`。

## 6. Provider Adapter V1

### 6.1 统一接口职责

Provider Adapter 接收统一请求并产出统一事件流，负责：

- 能力和模型声明。
- 请求参数映射。
- 流式响应解析。
- 工具调用参数聚合。
- 用量和完成原因归一化。
- Provider 错误转换。
- 取消和超时传播。
- 必要原始扩展数据保留。

### 6.2 V1 Adapter

| Adapter | API 基线 | V1 能力 |
| --- | --- | --- |
| OpenAI | Responses API（`/v1/responses`） | 文本流、reasoning、工具调用、结构化结果、用量 |
| Anthropic Messages | Messages API（`/v1/messages`） | 文本流、thinking、工具调用、用量 |
| OpenAI Compatible | Chat Completions API（`/v1/chat/completions`） | 文本流、标准工具调用、用量；工具调用不支持时返回 `CapabilityNotSupported`，不静默降级；流式不支持时退回非流式并标记 `simulated=true` |

**OpenAI Compatible 选用 Chat Completions 而非 Responses API 的原因**：Ollama、vLLM、Azure OpenAI、LM Studio 等兼容服务目前几乎全部实现了 Chat Completions；Responses API 覆盖率极低，用作 Compatible 基线会大幅降低实际兼容范围。

Provider 能力必须在 Run 接受前检查。缺少必需能力时，返回稳定错误，不在执行中静默改变任务语义。

## 7. 宿主工具与 MCP 对接

### 7.1 工具目录注册

参考宿主通过 `tool.catalog.replace` 发布完整目录。每个工具包含：

```text
toolId
name
description
inputSchema
outputSchema
riskLevel
requiresApproval
timeout
tags
```

V1 使用完整目录替换作为主路径，增量 Patch 可以保留协议但不是强制优化项。

### 7.2 工具调用

Runtime 生成稳定 `callId`，通过控制通道向宿主发起请求。宿主以 `callId` 作为幂等键执行并缓存终态。

未被有效 Grant 覆盖的调用先执行：

```text
Runtime -> tool.permission.request
Host    -> tool.permission.response
```

权限请求至少包含 `taskId`、`sessionId`、`runId`、`mode`、`agentId`、`parentAgentId`、`toolId`、`callId`、`argumentsHash`、`risk`、`requestedScope` 和 `reason`。宿主返回 `Granted`、`Denied` 或 `NeedsUserApproval`，以及可选 `grantId`、实际作用域、有效期和委派规则。

Grant 中的 `networkPolicy` 字段结构：

```text
networkPolicy
  mode                  Deny（默认）| AllowList | AllowAll
  allowedEndpoints[]
    scheme              https | http
    host
    port
    pathPrefix
    methods[]           GET | POST | ...
  maxRequestBodyBytes
  maxResponseBodyBytes
  timeoutSeconds
  followRedirects       默认 false
  allowedContentTypes[]
```

`builtin.http` 工具只在 `mode ≠ Deny` 时可用。`mode=AllowAll` 必须显式授权并在审计日志中标记。Runtime 执行请求前解析 URL 并逐条对比 `allowedEndpoints`，使用解析后的结构比对，不用原始字符串前缀匹配。Provider 自身的 API 调用不经过 `builtin.http`，由 Provider Adapter 的独立凭据配置管理。

获得权限后按工具所有权执行：

- `builtin.*` 由 Runtime 在有效 Grant 和内部安全策略的交集内执行，并产生同样的调用/结果事件。
- 宿主、MCP 和业务工具由 Runtime 发送 `tool.call.request`，宿主执行后返回 `tool.call.response`。
- 权限响应不代表工具已经执行；工具调用和工具结果分别使用稳定 `callId` 幂等。

工具结果分为：

```text
Succeeded
Failed
Rejected
TimedOut
Unavailable
Cancelled
```

断线重连后，Runtime 可以按 `callId` 查询结果，不直接重发有副作用的调用。

### 7.3 审批

需要审批的工具由宿主决定是否弹出 UI、按策略自动批准或拒绝。Runtime 只表达审批上下文和等待状态，不自行绕过宿主权限。

### 7.4 子智能体权限继承

- 总经理、项目负责人和子智能体的每次调用都记录实际 `agentId` 和 `parentAgentId`。
- 子智能体默认没有总经理 Grant；如果没有覆盖自身调用的 Grant，必须重新向宿主申请。
- 只有 `allowDelegation=true` 且 `delegatedAgentIds`、工具集合和作用域全部匹配时，子智能体才可以继承。
- 有效权限取宿主 Grant、父级可委派范围、当前工具目录和 Runtime 策略的最小交集，禁止扩大路径、网络、程序、有效期和风险等级。
- 继承调用保存 `grantId`、`rootGrantId` 和完整委派链；撤销后，尚未开始的调用必须失败为明确权限状态。

## 8. 并发和取消

### 8.1 并发策略

- Runtime 提供可配置的全局最大并发。
- 每个 Provider 可设置独立并发和速率限制。
- 超出容量的任务返回 Busy/Capacity 错误，由宿主决定排队，不在 Runtime 中复制业务队列。
- 相同 Session 是否允许并发由 Session 策略决定，默认串行。

### 8.2 取消语义

取消流程：

```text
Host -> run.cancel
Runtime -> run.cancelAccepted
Runtime -> 取消模型/工具等待
Runtime -> RunCancelled
Host -> events.acknowledge
```

`run.cancelAccepted` 仅表示开始取消，只有 `RunCancelled` 才是终态。若 Run 已经完成，Runtime 返回当前终态，不制造第二个取消终态。

## 9. 断线与恢复

### 9.1 控制通道断开

V1 默认策略：

- 活动 Run 暂时继续执行。
- Runtime 缓冲事件并开始宿主租约倒计时。
- 宿主在租约内使用相同 `hostInstanceId` 重新连接。
- 重连后宿主提交最后确认游标，Runtime 重放后续事件。
- 租约到期后取消仍在等待宿主工具或审批的 Run；纯模型调用可按配置继续或取消。

### 9.2 Runtime 崩溃

- 主程序通过进程退出和心跳超时识别故障。
- 已持久化终态直接恢复。
- 无终态 Run 标记为 Interrupted。
- 主程序根据工具幂等状态和任务策略决定重试或人工介入。
- V1 不尝试继续崩溃前的模型流连接。
- Work 模式步骤级幂等：每个步骤在**执行前**事务性持久化 `stepId`、`stepHash = sha256(invocationId + agentId + toolId + serializedArguments)`（仅含发送前可知字段，不含执行后结果）和状态（`Pending | Running | Completed | Failed | Interrupted`）。恢复时，`Interrupted` 步骤重新执行前先查询 `callId` 幂等记录，已执行的工具调用直接返回缓存结果，不重复产生副作用。

### 9.3 事件缓冲

关键事件（工具调用、错误、终态）必须持久化到 `state.db`，不进入可丢弃缓冲。Delta 使用分级缓冲：

| 缓冲层 | 触发条件 | 容量（初始建议，压测后固化） | 溢出行为 |
|---|---|---|---|
| 内存环形缓冲 | 默认 | 32 MiB / 实例 | 溢出到磁盘缓冲 |
| 磁盘缓冲（`staging/replay/`） | 内存满 | 512 MiB / 实例 | 触发背压，暂停事件写入 |
| 背压后策略 | 磁盘满 | — | 合并连续 Delta；仍不足时旧 Delta 丢弃并产生 `delta.dropped` 事件 |

宿主确认游标后，Runtime 立即释放对应范围的缓冲（内存和磁盘）。`delta.dropped` 事件包含丢弃的 `runId`、`sequence` 范围和字节数；宿主收到后可选择重新请求终态快照（`run.query`）获取完整文本，无需重跑。

### 9.4 会话查询与恢复

V1 提供 `session.list`、`session.get`、`session.messages.list` 和 `session.resume`。列表使用 `(updatedAt, sessionId)` 游标分页，支持模式、状态和更新时间范围过滤；恢复按 `sessionId` 直接查询 SQLite 索引，不扫描文件夹。

恢复快照至少包含模式、规范化消息历史、最新 Selection、模式专属 Agent 快照、附件/Blob 引用、最近安全检查点、未完成 Run 判定和最后事件序号。会议模式恢复参与者和会议轮次，工作模式恢复总经理、步骤、子智能体作业和权限等待状态。

## 10. 配置目录

启动参数至少包含：

```text
--instance
--control-pipe
--auth-token-handle
--config-dir
--data-dir
--log-dir
--workspace
```

配置优先级固定为：

```text
启动参数 > 指定配置文件 > Runtime 内建默认值
```

V1 不自动读取：

- 用户目录中的 Claude/Codex 配置。
- 当前目录中的隐式 AI 配置。
- 主程序配置文件。
- 未显式允许的环境变量。

API Key 由 Runtime 自有密钥配置或宿主短期注入提供，日志必须脱敏。

当未传 `--data-dir` 时，默认使用：

```text
{workspaceRoot}/.madorin/
├── state.db
├── blobs/
├── checkpoints/
├── staging/
├── locks/
└── logs/
```

`.madorin` 是数据目录而不是隐式 Provider 配置目录。V1 不扫描其中的任意配置文件，只读取 Runtime 自己定义并带 Schema 版本的数据；AI 文件工具不能直接访问该目录。

工作区解析规则固定为：

- `ai-runtime run --workspace <path>` 使用显式路径。
- `ai-runtime run` 使用 CLI 启动时当前目录的绝对路径，并在本次 Run 内冻结。
- `ai-runtime serve` 的宿主任务必须在 `RunStartRequest.workspaceRoot` 中显式提供；缺失时拒绝任务。
- 解析工作区并不授权扫描其中的 AI 配置；除 `.madorin` 自有数据外，任何配置读取仍须显式指定。

## 12. V1 验收矩阵

### 12.1 正常流程

- 单 Run 文本流完整、有序且最终快照一致。
- 多 Run 并发输出按 `gsn`（全局序）排列，每个事件的所属 Run 由 `runId` + `runSequence` 标识，宿主可按 `runId` 过滤对应 Run 的事件流。
- 同一 Session 默认串行，不同 Session 可以并行。
- 专家模式使用宿主传入的 Provider、模型和单个 Agent 完成连续多轮对话。
- 会议模式按 `participants[]` 构建全部参与者、主持人和选择器，并按 Agent 覆盖项解析 Provider/模型。
- 工作模式由总经理调度计划、步骤和子智能体作业，宿主只调度任务和处理权限，不代替 Runtime 运行模式内部编排。
- 当前流输出期间切换 Provider、模型、Agent 或提示词，当前流正常完成且内容不被新配置污染。
- 下一轮保持相同 `sessionId`、相同对话记录和附件引用，并直接使用最新 Selection。
- 连续多次切换不触发 `session.new`，不清空历史，也不要求主程序重连 Runtime。
- 单轮 Override 结束后，下一轮自动恢复 Session 的 NextTurnSelection。
- 跨 Provider 切换使用同一规范化历史，新模型发生历史裁剪时产生明确事件。
- OpenAI、Anthropic 和 OpenAI Compatible 完成统一请求。
- 工具调用和审批可以暂停并恢复 Run。

### 12.2 取消和超时

- Preparing、Streaming、WaitingForTool、WaitingForApproval 阶段均可取消。
- 取消一个 Run 不影响其他 Run。
- 超时产生稳定错误和唯一终态。
- Run 完成与取消竞争时仍只有一个终态。

### 12.3 断线和重放

- 事件通道断开后可以从最后确认序号重放。
- 重放可能重复但不会造成宿主重复落库或重复展示。
- 控制通道重连后可以查询活动 Run。
- 宿主租约到期策略按配置执行。

### 12.4 工具幂等

- 同一 `callId` 重复请求只执行一次。
- 工具已执行但响应丢失时，可以查询原结果。
- 工具不存在、下线、超时和拒绝均返回明确状态。
- 未审批工具不能被 Runtime 绕过宿主执行。
- 权限请求可以追溯到实际 `agentId`、`parentAgentId`、参数哈希和请求作用域。
- 子智能体默认无法使用总经理 Grant；显式委派后仍不能扩大工具、路径、网络、程序或有效期。
- 内置工具由 Runtime 执行，宿主/MCP 工具由宿主执行，两种路径共享同一 Grant、事件和审计语义。

### 12.5 故障

- Provider 认证失败、限流、网络异常和协议异常可区分。
- Runtime 意外退出不会导致参考宿主退出。
- Runtime 重启后历史 Run 不会保持虚假 Running。
- 事件缓冲达到限制时不丢失工具和终态事件。

### 12.6 配置隔离

- 未传配置目录时按明确规则失败或使用空配置，不读取第三方 CLI 目录。
- 工作区外路径和非法 Blob 引用被拒绝。
- 路径中的空格、中文、引号和长文件名可以无损读写。
- URL 中的查询字符串、片段和百分号编码可以无损往返，不发生重复解码。
- 超过内联阈值的文件自动使用 Blob，接收后长度和 SHA-256 一致。
- `..`、符号链接、目录联接点、UNC、设备路径和备用数据流不能逃逸允许根目录。
- Restricted 模式不允许任意进程和 PowerShell。
- UnrestrictedShell 必须显式授权，并明确报告不具备操作系统级工作区隔离。
- 日志不包含完整 API Key、认证令牌和敏感请求头。
- 不同 Runtime 实例的数据和 Pipe 名称互不冲突。
- Agent 文件工具不能读取、覆盖、移动或删除 `.madorin` 保留目录。

### 12.7 对话持久化与恢复

- 未传 `--data-dir` 时，数据保存到显式 `workspaceRoot/.madorin`。
- Runtime 重启后，专家、会议和工作模式都能按 `sessionId` 恢复规范化历史、模式快照、Selection、附件引用和最近检查点。
- `session.list` 在大量会话下使用 `(updatedAt, sessionId)` 游标分页，按日期筛选不扫描日期目录。
- 跨日期的长会话只保留一个稳定 `sessionId`，不会因零点或归档动作被拆成多个会话。
- 宿主直接修改 `state.db`、删除 Blob 或扫描目录恢复会话的行为被集成规范禁止。
- Blob 长度或 SHA-256 不一致、数据库版本不兼容和未完成迁移均产生明确诊断，不静默返回空会话。

## 13. V1 性能与质量目标

以下指标作为本机基线目标，最终数值在原型压测后固化：

- IPC 不应成为模型流式输出的主要延迟来源。
- 正常负载下取消命令应在 1 秒内被 Runtime 确认。
- 心跳超时、连接失败和进程退出必须在可配置时间内被宿主感知。
- 高频 Delta 应支持合并发送，且不改变最终文本和事件语义。
- 长时间运行不得出现 Run Registry、事件缓冲和 Session 的无界增长。
- Session 列表和消息列表必须分页；关键查询命中索引，性能不随日期目录数量线性下降。
- SQLite WAL、Blob 写入和检查点不能长期阻塞流式事件；并发写压力在原型压测后固化阈值。
- 所有公共契约启用 Nullable，并保持可序列化兼容测试。
- 所有异步调用必须支持取消和超时，不使用阻塞式等待模拟异步。

## 14. 主要风险和控制措施

| 风险 | 控制措施 |
| --- | --- |
| 统一接口丢失 Provider 特性 | 能力声明、扩展字段、原始事件保留 |
| 多 Run 事件串线 | `runId + sequence`、独立 Run Scope、并发测试 |
| 控制消息被 Token 流阻塞 | 控制/事件双通道、事件批量和背压 |
| 工具重复产生副作用 | `callId` 幂等、结果查询、宿主持久化 |
| 双方状态不一致 | 状态权威表、唯一终态、游标确认和 Query API |
| Runtime 崩溃丢失活状态 | 关键检查点、Interrupted 状态、宿主重试策略 |
| 隐式读取用户配置 | 显式目录、环境变量白名单、隔离测试 |
| 三种模式导致第一版范围失控 | 只实现现有专家/会议/工作语义，排除用户自定义图形 Workflow、通用 Agent 总线、远程 Runtime 和强沙箱 |
| 子智能体越权 | 默认不继承、显式委派、权限交集和完整委派链审计 |
| 会话数量增长导致恢复变慢 | SQLite 索引、游标分页、内容寻址 Blob，禁止目录扫描和按日期拆库 |
| Agent 修改 Runtime 数据 | `.madorin` 保留目录、文件工具强制拒绝、Runtime 管理的归档/删除 API |
| 协议快速变化 | 协议快照、版本协商、兼容性测试 |
| Named Pipe 命名抢占 | 宿主启动前探测同名 Pipe；Runtime 检测 `ERROR_ALREADY_EXISTS` 即退出；一次性令牌通过句柄传递 |
| Provider 凭据中途过期 | `credentials.update` 主动推送 + `credentials.refresh.request` 主动请求；Run 进入 `WaitingForCredentials` 暂停，凭据到达后恢复 |
| Work 模式步骤崩溃后重跑副作用 | 步骤级 `stepId + stepHash` 幂等记录；恢复时先查 `callId` 缓存，不重发有副作用的工具调用 |
| Work 模式无限递归/循环 | `maxAgentDepth`、`maxStepsPerRun`、`loopDetection=Strict`；循环检测触发时产生 `approval.request`，由宿主决定继续 |
| 跨 Provider 历史转换静默丢失内容 | 规范化消息历史格式强制转换；reasoning signature 失效时降级并产生 `history.trimmed` 事件，不静默丢弃 |
| Selection 多面板并发覆盖 | 乐观并发 `expectedSelectionVersion`；冲突返回错误，Client SDK 读取最新版本后重试 |

## 16. V1 完成后的决策点

V1 验收后再根据实测结果决定：

- V2 是否采用 PerRun 或 PerSession Worker 子进程。
- Provider Adapter 使用程序集插件还是独立 Provider Worker。
- 是否增加 Gemini、多模态和 Computer Use。
- 是否增加 Unix Domain Socket、gRPC/TCP 和远程 Runtime。
- Session 检查点是否需要支持跨 Runtime 版本恢复。
