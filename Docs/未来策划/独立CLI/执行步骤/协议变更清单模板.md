# Madorin AI Runtime 协议变更清单模板与兼容规则

> 适用范围：`Madorin.AI.Runtime.Contracts` 的公共 JSON/JSON-RPC 契约、消息类型、鉴别联合、稳定错误码和能力协商。
>
> 当前协议版本：`1.0`。

## 1. 三个版本轴

| 版本 | 责任 | 版本来源 | 变更条件 |
| --- | --- | --- | --- |
| 程序版本 | Runtime、Client 和 CLI 的产品发布版本 | 程序集/发布包 | 任意产品发布均可递增，不代表协议破坏 |
| 协议版本 | Host、Client 与 Runtime 的线协议语义 | `ProtocolVersions.Current` / `Supported` | 线格式或语义兼容边界变化时递增 |
| 数据库 Schema 版本 | Runtime 持久化结构 | `ProtocolVersions.DbSchemaVersion` | 数据库迁移发生时递增，不自动改变协议版本 |

三个版本独立演进。程序升级不得暗示协议或数据库自动升级；协议升级也不得代替数据库迁移。

## 2. 协议协商

1. Host 在 `InitializeRequest.supportedProtocolVersions` 中按自身支持范围声明版本。
2. Runtime 以自身优先级顺序从 `ProtocolVersions.Supported` 选择双方交集中的首个版本，并通过 `selectedProtocolVersion` 返回。
3. 双方必须在初始化完成后固定使用已选择版本，连接存续期间不得切换。
4. 无交集时拒绝初始化并返回 `ProtocolNoIntersection`，不得静默回退到未声明版本。
5. 依赖某项能力的 Host 必须在初始化时声明期望能力；缺失必需能力时拒绝或降级，不能仅凭程序版本推断能力。

## 3. 向后兼容规则

同一协议主版本内只允许接收方可安全忽略、且不改变既有字段语义的追加变更。

| 变更类型 | 同主版本允许 | 要求 |
| --- | :---: | --- |
| 新增可选 JSON 字段 | 是 | 缺失时保持旧行为；默认值不得改变既有语义 |
| 新增可选事件或能力 | 是 | 必须可通过能力协商识别；旧端忽略后仍可保持状态正确 |
| 新增稳定错误码 | 是 | 未识别错误码仍可按 `category`、`isRetryable` 和消息处理 |
| 扩大数值上限 | 是 | 不得超过已协商限制；接收方仍按协商值执行 |
| 收紧数值上限 | 条件允许 | 只能通过新连接重新协商，不得在连接中途生效 |
| 删除或重命名字段 | 否 | 升协议主版本并提供迁移说明 |
| 可选字段改为必填 | 否 | 升协议主版本 |
| 改变字段类型、单位或语义 | 否 | 升协议主版本 |
| 改变枚举字符串值 | 否 | 升协议主版本；旧值在旧主版本内永久保留 |
| 改变消息类型或联合 discriminator | 否 | 升协议主版本 |
| 复用已发布字段、错误码或消息名表达新语义 | 否 | 新增名称或升协议主版本 |
| 改变 GSN、幂等键、确认或终态语义 | 否 | 属于核心协议不变量，必须升主版本并专项评审 |

## 4. 未知内容处理

| 未知内容 | 处理规则 |
| --- | --- |
| JSON 对象中的未知字段 | 忽略并保留已知字段语义；不得因未知可选字段拒绝整个消息 |
| 未知枚举字符串或联合 discriminator | 拒绝该消息；不得映射为默认枚举值或错误模式 |
| 未知事件类型 | 信封、实例 ID、GSN 校验通过后可忽略负载并推进确认游标；不得据此推断 Run 终态 |
| 未知 JSON-RPC 方法 | 返回 JSON-RPC `Method not found`；不得当作成功 |
| 未知可选能力 | 视为未启用；只有显式协商成功后才能使用 |
| 缺失必需能力 | 初始化失败并返回稳定能力错误，或由 Host 显式选择已定义降级路径 |
| 未知稳定错误码 | 保留原始 code，按 `category` 与 `isRetryable` 做通用处理 |

新增事件若会影响 Run 终态、幂等、权限或持久化正确性，不能依赖“旧端忽略”获得兼容性，必须通过新能力门禁或提升协议主版本。

## 5. 快照与验证门禁

1. 所有协议 JSON 必须通过 `RuntimeJsonContext` 的源生成 `JsonTypeInfo` 序列化；禁止反射回退。
2. 新增根类型、联合派生类型、集合或枚举时，同步登记 `RuntimeJsonContext`。
3. 修改公共契约时，同一变更必须更新 `Madorin.AI.Runtime.Protocol.Tests/Snapshots` 中对应版本快照。
4. 快照变更必须逐字段评审；不得通过批量接受快照掩盖删除、改名、类型或枚举值变化。
5. 兼容变更至少验证旧 JSON 可被新代码读取；破坏性变更必须新增协议主版本快照，旧版本快照继续保留到支持期结束。
6. `.received`、临时生成结果或未评审快照不得提交。

## 7. V1 冻结结论

V1 的字段名、消息类型、枚举字符串、联合 discriminator、GSN/确认、幂等和唯一终态语义一经快照提交即视为冻结。后续新增能力优先使用可选字段、可选事件与能力协商；无法满足本文件兼容规则时，必须提升协议主版本。
