## 1. 目标

提供一个轻量的独立 CLI 入口：安装后在 CMD、PowerShell 或终端输入 `madorin` 即可进入交互界面；Windows 用户也可以双击 `madorin.exe` 启动。CLI 自动从当前系统用户主目录下的 `.madorin` 读取配置。

独立 CLI 是备用和调试入口，宿主程序通过 Client SDK/协议调用 Runtime 仍是主要使用方式。独立入口只补齐首次配置、Agent 管理和基本对话能力，不建设第二套 Runtime，也不扩展为复杂的配置平台。

## 2. 现有方案缺口

当前规划已包含通用 Runtime 命令，但尚未明确普通用户直接启动时的最小闭环：

- `madorin` 和双击 `madorin.exe` 的默认行为。
- 用户目录 `.madorin/config.json` 的格式。
- `agents/` 中 Agent JSON 的格式和增删改命令。
- 首次启动时如何引导选择协议、填写 BaseURL、Key 和模型。
- 独立配置如何转换为 Runtime 已有的 Provider、模型和 Agent 选项。
- 独立入口与宿主调用之间的职责边界。

阶段 4A 只解决这些直接使用问题，不引入 Provider Profile、独立模型目录、模式 Profile、远程配置中心和配置热更新。

## 3. 涉及项目

### 4.1 固定配置根目录解析 : 71.4%

独立 CLI 的默认配置目录固定为当前用户主目录下的 `.madorin`：

```text
Windows: %USERPROFILE%\.madorin
macOS:   ~/.madorin
Linux:   ~/.madorin
```

执行要求：

- [√] `madorin` 无参数时进入交互 CLI；配置不存在时自动进入首次配置向导。
- [×] Windows 双击 `madorin.exe` 与无参数启动行为一致，不能打开后立即关闭窗口。
- [×] 安装程序或发布脚本负责把可执行文件目录加入当前用户 PATH，使新终端可以直接输入 `madorin`。
- [√] 独立配置只从用户目录读取，不向上扫描当前工作区，也不读取 Claude、Codex 或其他程序的配置。
- [√] 独立 CLI 的运行数据默认写入 `~/.madorin/data/workspaces/{workspaceKey}`，日志写入该工作区数据目录下按 `runtimeInstanceId` 隔离的子目录，不直接共用全局 `state.db` 或日志文件；宿主模式仍将运行数据写入宿主指定工作区的 `.madorin`。
- [√] `workspaceKey` 由规范化工作区绝对路径稳定派生，跨进程结果一致且不在目录名中暴露原始路径；启动后工作区和数据路径都被冻结。
- [√] 不同工作区的独立 CLI 可以并行启动；同一工作区只允许一个写实例，`--data-dir` 只覆盖存储位置，不能绕过工作区写锁。

### 4.2 固定独立配置目录结构 : 100%

```text
~/.madorin/
├── config.json
├── memory.md              全局记忆，由阶段 4B 定义
├── agents/
│   ├── default.json
│   ├── code-expert.json
│   └── reviewer.json
└── data/
    └── workspaces/
        └── {workspaceKey}/   按工作区隔离的运行数据，运行后按需生成
            └── logs/
                └── {runtimeInstanceId}/
```

目录约束：

- [√] `config.json` 保存公共默认值和 Provider/模型配置。
- [√] `agents/*.json` 每个文件保存一个 Agent，文件名默认与 Agent ID 一致。
- [√] 所有文件统一使用 UTF-8 和标准 JSON，不支持注释、继承和多层覆盖。
- [√] V1 不建立 `providers/`、`models/`、`modes/`、`credentials/` 或 `schemas/` 子目录。
- [√] `data/`（含按工作区和 Runtime 实例隔离的 `logs/`）是 Runtime 生成目录，不属于用户配置，也不能被配置命令当作 Agent 文件扫描。
- [√] `memory.md` 不是 Provider 配置或 Agent 定义，其格式、命令和注入规则由阶段 4B 单独负责。

### 4.3 定义 `config.json` : 100%

`config.json` 使用一个文件保存独立 CLI 所需的公共配置：

```json
{
  "defaultProvider": "openai",
  "defaultModel": "gpt-5",
  "defaultAgent": "default",
  "providers": [
    {
      "name": "openai",
      "protocol": "OpenAI",
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "由配置向导写入",
      "models": ["gpt-5", "gpt-4.1"]
    }
  ]
}
```

要求：

- [√] `protocol` V1 提供明确选项，例如 OpenAI、OpenAI Compatible、Anthropic；Provider Adapter 决定各协议的验证规则。
- [√] 一个 Provider 可以配置多个模型；需要多个 Provider 时继续向 `providers` 数组增加项目，不引入 Profile 概念。
- [√] `defaultProvider`、`defaultModel` 和 `defaultAgent` 必须引用已有配置；缺失时由配置向导要求用户选择。
- [√] `apiKey` 由终端无回显输入。配置文件在支持的平台上限制为当前用户可读，`config show`、日志和错误信息始终脱敏。
- [√] 配置修改先取得当前用户范围的跨进程写锁并重新读取最新内容，再使用临时文件加原子替换；失败时保留原文件。

### 4.4 定义 Agent JSON : 100%

`agents/` 下每个 JSON 文件保存一个 Agent。V1 将 Prompt 直接保存在 JSON 中，不再拆分 Prompt 文件：

```json
{
  "id": "code-expert",
  "name": "代码专家",
  "description": "用于日常代码分析和修改",
  "systemPrompt": "你是一名软件开发专家。",
  "provider": "openai",
  "model": "gpt-5",
  "temperature": 0.2
}
```

要求：

- [√] `id` 在 `agents/` 内唯一，只允许安全文件名字符；默认文件名为 `{id}.json`。
- [√] `provider` 和 `model` 可以省略，省略时使用 `config.json` 默认值。
- [√] Agent 不重复保存 BaseURL 和 Key，也不能扩大 Runtime 的工具权限。
- [√] `systemPrompt` 保持用户输入原文，不 Trim、不自动拼接模板。
- [√] Agent 文件损坏、ID 重复或引用不存在时给出文件路径和字段错误，不静默跳过。

### 4.5 提供交互式配置与 Agent 命令 : 100%

V1 提供以下最小命令：

```text
madorin config init
madorin config edit
madorin config show
madorin config validate

madorin agent list
madorin agent create
madorin agent edit <id>
madorin agent delete <id>
```

交互要求：

- [√] `madorin` 首次启动检测不到有效配置时，自动执行与 `config init` 相同的向导。
- [√] `config init` 依次提示协议、Provider 名称、BaseURL、Key、模型列表和默认模型；没有 Agent 时继续引导创建 `agents/default.json`。
- [√] Key 输入不回显；`config show` 只显示脱敏值。
- [√] `config edit` 先让用户选择要修改的 Provider 或公共默认项，再只询问相关字段，不要求重新填写全部配置。
- [√] `agent create` 依次询问 ID、名称、说明、System Prompt、Provider、模型和温度；Provider 与模型从 `config.json` 中选择。
- [√] `agent edit` 读取原值并允许逐项保留或修改；`agent delete` 删除前明确确认，不能删除当前默认 Agent，除非先选择新的默认项。
- [√] `config init` 不覆盖已有配置；需要重建时必须由用户明确确认并先创建备份。
- [√] `config` 与 `agent` 写命令共用同一用户配置写锁；并发进程等待或返回明确 Busy，不允许以最后写入者覆盖另一进程刚完成的修改。

### 4.6 固定配置加载与 DI 注入顺序 : 100%

启动顺序固定为：


实现约束：

- [√] 使用 `System.Text.Json` 源生成类型读取两个固定结构，不建设通用配置合并框架。
- [√] 配置只在启动或显式执行配置命令时读取；V1 不监视文件，也不实现热更新。
- [√] 配置有错误时进入修复向导或返回配置错误，不能带着半有效配置执行模型请求。
- [√] 独立配置转换为已有 Runtime 输入类型，不能产生只供 CLI 使用的第二套 Provider 或 Agent 执行器。
- [√] 诊断报告文件和字段，但不回显 Key。

### 4.8 固定独立启动与宿主调用边界 : 66.7%

