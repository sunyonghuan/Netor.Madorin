## 1. 目标

建立 V1 可版本化、可序列化、可由测试替身独立验证的公共协议。阶段结束时不接真实 Provider、不启动真实 Named Pipe，也不实现三种模式业务编排。

## 2. 前置门禁

- `Madorin.AI.Runtime.slnx` 中 22 个源码项目、1 个 SampleHost 和 6 个测试项目可构建。
- 正式命名已经统一为 `Madorin.AI.Runtime.*`。
- 已确认架构修订 V1 的 8 项阻断/高风险决策，不再以旧 `RunStartRequest` 或旧事件模型继续设计。

## 3. 涉及项目

| 项目 | 本阶段职责 |
| --- | --- |
| `Madorin.AI.Runtime.Entities` | 稳定领域枚举、值对象和不含传输细节的实体 |
| `Madorin.AI.Runtime.Contracts` | 公共 DTO、消息信封、事件、错误码和协议版本 |
| `Madorin.AI.Runtime.Core` | 状态转换、能力判断和版本兼容纯规则 |
| `Madorin.AI.Runtime.Client` | 只建立公共 Client 接口，不实现真实 IPC |
| `Madorin.AI.Runtime.Protocol.Tests` | JSON 快照、兼容性、无损往返和 Fake 双端测试 |

`Contracts`、`Entities`、`Core` 不得引用 MAF、MEAI、Provider SDK、SQLite、System.CommandLine 或当前 Madorin 内部程序集。

## 4. 执行步骤 : 100%

### 4.1 固化协议版本策略 : 100%

- [√] 定义 `supportedProtocolVersions`、`selectedProtocolVersion` 的协商规则。
- [√] 明确同主版本内允许追加可选字段和事件；删除字段、改变字段语义、改变枚举字符串值属于破坏性变更。
- [√] 为未知字段、未知事件和未知能力定义忽略、拒绝或降级规则。
- [√] 建立[协议变更清单模板与兼容规则](../../执行步骤/协议变更清单模板.md)，记录引入版本、兼容范围和迁移方式。

### 4.2 固化标识与四级层级 : 100%

- [√] 为 `sessionId`、`runId`、`invocationId`、内部 `requestId`、`messageId`、`callId`、`approvalRequestId` 建立生成和作用域规则。
- [√] `runtimeInstanceId` 每次 Runtime 进程启动唯一，`hostInstanceId` 每个宿主进程唯一；初始化完成后连接固定绑定这一对标识。
- [√] 固定 `Session -> Run -> AgentInvocation -> ProviderRequest` 层级。
- [√] 定义 `InvocationSnapshot`，至少包含实际 Agent、Provider、模型、Prompt 哈希、可空的全局/项目记忆哈希、工具目录版本、投影版本和开始时间。
- [√] `ProviderRequest.requestId` 只用于 Provider 内部追踪，不进入稳定宿主协议。
- [√] 所有跨进程 ID 使用字符串表示，禁止依赖 JSON 浮点数传递大整数。

### 4.3 建立初始化与能力契约 : 100%

- [√] 定义双向认证完成后的 `InitializeRequest` 和 `InitializeResponse`。
- [√] 初始化请求包含宿主实例、客户端版本、期望能力和最后确认 GSN，不包含共享密钥或原始令牌。
- [√] 初始化响应包含 Runtime 实例、程序/协议版本、能力、协商限制、事件通道地址和心跳周期。
- [√] 定义协议无交集、认证失败、能力不足和限制不兼容的稳定错误。
- [√] 限制项至少覆盖控制帧、事件帧、内联内容、Blob 分片、单 Blob 和单 Run Blob 总量。

### 4.4 拆分 Run 启动契约 : 100%

- [√] 使用 `NewSessionRunRequest` 表达“创建 Session 并启动 Run”。
- [√] 使用 `ExistingSessionRunRequest` 表达“在已有 Session 中启动下一 Run”。
- [√] 新建请求包含 `sessionIdempotencyKey` 和 `runIdempotencyKey`；续接请求只包含 `runIdempotencyKey`、`sessionId`、输入覆盖和单轮覆盖。
- [√] 续接请求不得重复携带完整 Session 配置；长期配置以 `NextTurnSelection` 为权威。
- [√] 预留可空 `workspaceId` 供 V2 扩展；V1 只校验当前进程绑定工作区。
- [√] 固化 `sessionIdempotencyKey` 7 天、`runIdempotencyKey` 24 小时的默认保留语义。

### 4.5 定义模式与选择契约 : 100%

- [√] 以鉴别联合定义 `ExpertOptions`、`MeetingOptions`、`WorkOptions`，禁止用大量可空字段合并三种模式。
- [√] 定义 `AgentRef` 输入 DTO 和 `AgentSnapshot` 持久化 DTO；快照默认只保存元数据与哈希。
- [√] 定义 `NextTurnSelection`、`selectionVersion`、`expectedSelectionVersion` 和冲突错误。
- [√] 定义 `session.selection.get/update` 和单轮 `turnOverride` 的优先级。
- [√] 定义 `session.resume`、`neededDefinitions`、`session.rehydrate` 及 Prompt 哈希校验响应。
- [√] 禁止在续接 Run 请求中绕过 `session.rehydrate` 注入新的 Agent 定义。

### 4.6 定义事件与状态契约 : 100%

- [√] 事件信封包含 `gsn`、`runId`、`runSequence`、消息类型、时间戳和负载。
- [√] 事件信封同时包含 `runtimeInstanceId`；宿主合并多个 Runtime 事件流时使用 `(runtimeInstanceId, gsn)` 去重并使用 `(runtimeInstanceId, runId)` 路由。
- [√] GSN 是 Runtime 实例级全局连续序号；`runSequence` 只表达 Run 内顺序。
- [√] `events.acknowledge`、重放游标、查询和取消都受当前 Runtime 实例约束；跨实例游标或目标标识返回稳定协议错误。
- [√] 定义 `events.acknowledge(lastConfirmedGsn)`、重放起点和宿主去重规则。
- [√] 定义 `delta.dropped`，只报告未分配 GSN 的 Delta 对应 `runSequence` 范围，自身正常进入 Outbox。
- [√] 统一使用 `invocation.started/completed/failed`，删除模式专属的重复开始/完成事件。
- [√] 固化 Run 状态：`Accepted`、`Preparing`、`Running`、`WaitingForTool`、`WaitingForApproval`、`WaitingForCredentials`、`Persisting`、三个正常终态和恢复态 `Interrupted`。

### 4.7 定义内容、错误与 Blob 契约 : 100%

- [√] 错误模型包含稳定 code、category、message、isRetryable、provider details 和 diagnosticId。
- [√] 明确 Provider 原始错误只能作为受控扩展，不能取代稳定错误码。

- 不得保留旧 `RunStartRequest` 作为并行入口。
