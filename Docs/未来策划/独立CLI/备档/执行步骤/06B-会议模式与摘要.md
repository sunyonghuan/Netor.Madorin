### 4.2 建立会议专属 Schema : 100%

- [√] 建立 `meeting_sessions`，保存主题、状态、当前轮次、选择器状态和策略版本。
- [√] 建立 `meeting_rounds`，保存轮次索引、状态、摘要 messageId 和时间。
- [√] 建立 `meeting_participants`，保存整个 Session 生命周期内的参与者状态变化。
- [√] 建立 `meeting_invocations`，关联 round、participant、agent、角色、顺序、Selector 决策和状态。
- [√] 为 sessionId、当前 round、participant status 和 Scheduled Invocation 建索引。
- [√] 结构表与 JSONL 使用 sessionId、invocationId、messageId 关联，不重复保存消息正文。

### 4.3 实现会议角色构建 : 100%

- [√] Participant、Host、Selector 和 Summarizer 均按 Invocation 创建独立 Agent。
- [√] Participant 使用自身 AgentRef、Provider/模型覆盖和允许工具。
- [√] Host 负责组织议程、HITL 和结束判断，不替代参与者回答。
- [√] Selector 只输出结构化调度决定，不能直接修改数据库或工具权限。
- [√] Summarizer 只接收投影所需历史和摘要策略，输出规范摘要消息。
- [√] 每个角色的 InvocationSnapshot 记录实际配置和上下文投影版本。

### 4.4 实现轮次状态机 : 100%

- [√] 创建 Round 时事务性写入会议状态和初始 Scheduled Invocation。
- [√] SelectorDriven 策略由 Selector 决定下一位 Active 参与者；确定性回退按 joinOrder。
- [√] 一次参与者发言是一个 AgentInvocation；工具续调不拆分 Invocation。
- [√] 每次完成后持久化 Invocation、消息和下一调度决定，再触发下一位。
- [√] 达到轮次/时间/终止条件时进入总结或完成；取消形成唯一 Run 终态。
- [√] 会议内部任一 Agent 失败按策略跳过、重试、暂停或失败，禁止无界循环。

### 4.5 实现 HITL : 100%

- [√] 需要用户确认时 Run 进入 WaitingForApproval，并发布包含会议上下文的审批请求。
- [√] 审批使用稳定 approvalRequestId，支持批准、拒绝、补充输入和取消。
- [√] 断线后恢复未完成审批，不重复创建第二个审批请求。
- [√] HITL 响应作为 CanonicalHistory 记录或明确控制记录持久化，UI 可追溯。

### 4.6 实现参与者增删与状态更新 : 100%

- [√] Add/Update/Remove Patch 使用 expectedSelectionVersion 乐观并发。
- [√] 更新只在当前 Invocation 完成后的安全点生效。
- [√] Remove 将参与者标为 Removed 并记录 removedAt，不删除历史 Invocation 和消息。
- [√] Standby 不进入默认选择，但保留定义和历史；恢复时仍可显示。
- [√] 当前正在执行的参与者被移除时允许本次 Invocation 正常收尾，下一调度不再选择。
- [√] 新参与者需要完整 AgentRef 或按 rehydrate 规则补齐定义。

### 4.7 实现会议 ContextProjection : 100%

- [√] 当前 Round 的发言默认完整保留，`preserveCurrentRound=true`。
- [√] Tail/Sliding 策略以完整 Round 为裁剪单元，不拆散本轮工具调用或参与者发言。
- [√] 为不同角色构建角色适配投影，但都从同一 CanonicalHistory 派生。
- [√] Selector 可使用结构化轮次摘要，Participant 不应看到无关内部决策原文，差异必须在策略中显式定义。
- [√] 投影调整发送 `context.projection.adjusted`，不删除 UI 历史。

### 4.8 实现 PerRound/FinalOnly 摘要 : 100%

- [√] SummaryCompressed 通过 Summarizer Invocation 生成摘要。
- [√] 摘要作为新的 CanonicalHistory 消息追加到文件末尾，禁止插入或覆盖旧行。
- [√] 摘要记录 `summarizesThroughSeq`、summary agent 和生成 Invocation。
- [√] 投影时把摘要放在被替代早期历史之前呈现，再拼接未摘要的新消息。
- [√] PerRound 在轮次完成后生成；FinalOnly 只在会议结束时生成。
- [√] 源历史范围和摘要策略哈希未变化时复用已有摘要，避免重复模型调用。
- [√] 摘要失败不删除原历史；按策略继续 Full/Tail、重试或明确失败。

### 4.9 实现会议恢复 : 100%

- [√] 恢复中 Running Invocation 标记 Interrupted，按会议策略决定重试或跳过。
- [√] 已完成参与者发言、Selector 决策和摘要不得重复生成。
- [√] 恢复后的参与者列表、顺序和 Selection 版本必须与崩溃前一致。
