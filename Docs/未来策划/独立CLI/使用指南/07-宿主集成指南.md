# Madorin Runtime 宿主集成指南

> 适用版本：Madorin.AI.Runtime Client/Contracts V1，协议 1.1

## 1. 依赖边界

宿主项目只引用 `Madorin.AI.Runtime.Client` 和必要的 `Madorin.AI.Runtime.Contracts`。不要引用 Provider 实现、MAF、MEAI、SQLite、Persistence 或 Server 项目，也不要解析 Named Pipe 帧、扫描 Runtime 数据目录或访问内部 DI。

一个宿主进程可以持有多个 `RuntimeClient`，每个句柄固定绑定一个 Runtime 实例。查询、取消、事件游标和回调必须以该绑定为边界，不能只按 `runId` 在多个实例之间查找。

## 2. 启动策略

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| `AttachExisting` | 只连接现有 Runtime，目标不存在时失败 | Runtime 由服务管理器或其他进程拥有 |
| `StartIfMissing` | 优先连接，连接失败时启动新 Runtime | 单实例桌面宿主 |
| `AlwaysStart` | 始终启动新的独立 Runtime | 多工作区、测试和强隔离宿主 |

启动新进程时 SDK 使用 `ProcessStartInfo.ArgumentList` 传递路径与标识，并通过重定向 stdin 传递随机握手 secret。宿主不要把 secret 放入命令行、环境变量、日志或异常消息。

## 3. 创建 Client

```csharp
using Madorin.AI.Runtime.Client;

var options = new RuntimeClientOptions(
    PipeName: "owned-by-create",
    HostInstanceId: Guid.NewGuid().ToString("N"))
{
    RuntimeExecutablePath = @"C:\Program Files\Madorin\madorin.exe",
    WorkspaceDirectory = @"E:\Projects\demo",
    DataDirectory = @"E:\Projects\demo\.madorin",
    LogDirectory = @"E:\Projects\demo\.madorin\logs",
    RuntimeInstanceId = Guid.NewGuid().ToString("N"),
    PipePrefix = "madorin.ai.runtime",
    StartPolicy = RuntimeStartPolicy.AlwaysStart,
    OwnedProcessClosePolicy = OwnedProcessClosePolicy.Shutdown,
    StartupTimeout = TimeSpan.FromSeconds(15)
};

await using var client = await RuntimeClient.CreateAsync(options, cancellationToken);
var binding = client.InstanceBinding;
```

`InstanceBinding` 只在认证、初始化、能力和版本检查完成后可用，公开：

- `HostInstanceId` 和 `RuntimeInstanceId`
- 规范化工作区
- Runtime PID
- 控制与事件端点
- 当前 Client 是否拥有 Runtime 进程

`ExpectedRuntimeVersion`、`ExpectedRuntimeInstanceId` 和 `ExpectedServerProcessId` 可用于加强连接校验。启动或连接失败通过稳定的 `RuntimeClientException` 派生类型报告。

## 4. 启动 Run 与处理事件

新建和继续 Session 分别使用 `NewSessionRunRequest` 与 `ExistingSessionRunRequest`：

```csharp
var runId = await client.StartNewSessionRunAsync(request, cancellationToken);

await foreach (var item in client.ReadEventsAsync(lastConfirmedGsn, cancellationToken))
{
    await durableProjection.ApplyAsync(item, cancellationToken);
    await client.AcknowledgeEventsAsync(item.Gsn, cancellationToken);
}
```

事件显式携带 `runtimeInstanceId`、`runId`、GSN 和 Run 内序号。只有业务投影或其他持久化处理成功后才能调用 `AcknowledgeEventsAsync`；提前确认会让重连后无法重放尚未处理的事件。

每个 Runtime 单独保存 `(runtimeInstanceId, lastConfirmedGsn)`。即使多个实例故意产生相同 `runId` 和相同数值 GSN，也不得合并游标或路由表。

## 5. 宿主回调

```csharp
var callbacks = new RuntimeHostCallbacks
{
    ToolPermissionRequestedAsync = HandlePermissionAsync,
    ApprovalRequestedAsync = HandleApprovalAsync,
    ToolCallRequestedAsync = ExecuteToolAsync,
    ToolResultQueriedAsync = QueryToolResultAsync,
    ToolCallCancelledAsync = CancelToolAsync,
    MaxConcurrency = 4,
    CallbackTimeout = TimeSpan.FromSeconds(30)
};
```

把 `callbacks` 传给 `RuntimeClientOptions.HostCallbacks`。SDK 对回调统一施加有界并发、排队/执行超时和取消映射；单个回调异常会转换为协议错误响应，不会终止事件循环。

工具目录通过 `ReplaceToolCatalogAsync` 或 `PatchToolCatalogAsync` 发布。具有副作用的工具调用按稳定 `callId` 幂等；重连或超时后用 `ToolResultQueriedAsync` 查询持久化结果，不能直接再次执行副作用。权限与审批响应必须保留 Runtime、Run、Agent、Grant 和委派归属。

## 6. Session 与 Selection

Client 高层 API 覆盖：

- `ListSessionsAsync`、`GetSessionAsync`、`ListSessionMessagesAsync`
- `UpdateSessionSelectionAsync`
- `ResumeSessionAsync`、`RehydrateSessionAsync`
- `QueryRunAsync`、`ListRunsAsync`、`CancelRunAsync`
- `ReplaceToolCatalogAsync`、`PatchToolCatalogAsync`、`RevokeGrantAsync`
- `UpdateCredentialsAsync`

Selection 更新只影响下一轮，不改变 `sessionId` 或清空历史。继续对话使用 `ExistingSessionRunRequest`；Runtime 重启后先 rehydrate，再从已确认 GSN 继续事件流。

## 7. 重连与恢复

SDK 在当前 Client 绑定内管理控制/事件通道重连，不会切换到其他 Runtime。宿主仍需持久化：

```text
runtimeInstanceId
lastConfirmedGsn
sessionId
runId
业务任务与 Runtime Run 的映射
```

恢复顺序：

1. 使用原实例信息重新连接，校验 PID、认证、Runtime 实例、协议和能力。
2. 从持久化的 `lastConfirmedGsn` 调用 `ReadEventsAsync`。
3. 对至少送达一次的事件按 `(runtimeInstanceId, gsn)` 去重。
4. 业务处理成功后再推进确认水位。
5. 查询 Run 终态；Runtime 已重启时按 Session 执行 rehydrate/resume。

断线期间不要仅凭本地超时把 Run 判为失败，也不要因重放重复执行工具副作用。

## 8. 生命周期与关闭

`DisposeAsync` 只停止当前句柄的后台循环和连接。`AttachExisting` 连接的进程不归 Client 所有；Client 启动的进程按 `OwnedProcessClosePolicy` 处理：

- `KeepAlive`：释放 Client 后保留 Runtime。
- `Shutdown`：先优雅关闭，超过 `OwnedProcessShutdownTimeout` 后只终止该 Client 拥有的进程。

SDK 不枚举、不附着和不终止其他工作区或其他 Client 拥有的 Runtime。

## 9. 版本升级与回退

1. 停止向旧 Runtime 分配新 Run，等待活动 Run 排空或按业务策略取消。
2. 保留旧二进制和数据恢复点，启动新版本独立实例。
3. 完成 PID、双向认证、协议、能力和 `ExpectedRuntimeVersion` 检查。
4. 对目标 Session 执行 rehydrate，并从旧实例最终确认游标之后建立新实例自己的游标。
5. 冒烟验证新 Run、工具回调、取消和事件确认后再切换业务流量。
6. 失败时关闭新实例并恢复旧版本；不要让两个版本同时写同一规范化工作区。

数据库迁移只允许向前执行。升级前先运行 `madorin db check`、`madorin db backup` 和 `madorin db migrate --dry-run`；不要把复制活动 `state.db` 当作在线备份。

完整的三 Runtime 集成示例位于 `Madorin.AI.Runtime.SampleHost` 的 `reference-host` 入口。
