# Madorin 可配置行业 AI 工作台架构方案

> 状态：产品与架构决策稿 v0.5  
> 日期：2026-07-20  
> 目标读者：产品决策者、架构师、UI、配置平台与执行引擎开发者  
> 替代方案：原“商业级多智能体并行 UI 重构方案”  
> 参考实现：`Stream X` 跨境电商工作台

## 0. 决策摘要

Madorin 不再被定义为一个固定界面的多智能体控制台，而是一套可以按行业、品牌和用户习惯生成实际工作环境的 **AI 工作台内核**。

本方案锁定以下原则：

1. **行业工作台是产品第一层**。用户首先看到项目、业务资产和可直接开始的业务任务，不首先看到 Agent、Run、Token 和事件。
2. **同一内核支持不同发布品牌**。`Stream X`、`Madorin` 和后续垂直产品通过发布配置获得不同名称、图标、默认行业、初始化流程和工作台内容。
3. **首次初始化生成工作台**。用户根据经营领域、工作内容、工作习惯和自动化偏好完成初始化，系统生成当前工作台，而不是加载固定首页。
4. **工作台可继续配置**。用户可以在设置中调整区域、常用操作、顺序、自动化和审批偏好，但看不到按钮背后的技能、Prompt、工作流和 Agent 编排类型。
5. **业务按钮不是 Prompt 快捷方式**。每个按钮引用一个版本化业务动作定义，明确输入、上下文、权限、执行方式、产物和失败处理。
6. **专家、工作、会议是主要三种 AI 协作模式**。用户确定目标并创建工作后，系统建立独立 `WorkSession` 对话页；首页不常驻空白 AI 对话框。
7. **多任务和多智能体仍是核心能力**。顶部工作标签承载并行工作，底部紧凑 Agent 监控栏跨项目显示运行状态，模型、Token、成本和事件仍进入二级执行中心。
8. **配置是声明式数据，不是可执行脚本**。配置只能引用已注册能力，必须具备版本、签名、迁移和权限校验。
9. **数据库存索引与运行态，文件存大正文**。继续采用 SQLite 元数据索引加 JSONL/compact 正文文件的混合存储方案。
10. **重构迁移能力，不迁移旧视图结构**。旧 UI 保留一个发布周期，新工作台独立建立，不复制现有巨型 code-behind。

产品定义：

> 一套可配置、可分行业发布的 AI 工作台内核。用户通过熟悉的项目、资产和业务按钮开展工作，系统在后台组织专家、工作任务、会议、技能、工具和多智能体完成结果交付。

## 1. 对原方案的架构纠正

原方案正确解决了多任务隔离、Agent 状态、审批、事件投影和历史存储，但把系统内部对象放到了用户界面的第一层。

| 原方案主轴 | 新方案主轴 |
| --- | --- |
| 总览首先展示任务数、Agent 数、审批和成本 | 首页首先展示当前行业项目、业务资产、常用任务和继续工作 |
| Agent 定义与运行实例是一级导航 | Agent 运行实例进入执行中心和任务高级详情 |
| 专家、工作、会议是可新建的 WorkItem 类型 | 三种模式成为 `WorkSession` 的协作方式，创建工作后才显示真实对话 |
| 固定工作台 Shell | 根据发布配置、行业包、初始化结果和用户设置生成工作台 |
| 用户需要描述目标后再开始 | 高频业务动作以按钮、表单和业务资产入口直接开始 |
| UI 围绕执行状态组织 | UI 围绕项目、资产、任务、对话和产物闭环组织 |

原有控制面不删除，而是调整到以下位置：

- 工作台底部收起时只显示任务、Agent、等待确认与存储摘要；展开后横向显示跨项目 Agent 运行卡片。
- 任务详情显示业务步骤、输入、产物、审批和异常。
- 展开“执行详情”后显示 Agent、工具、模型、Token 和事件。
- 执行中心统一管理所有 Run、AgentInstance、审批和恢复操作。

## 2. 产品分层

```text
Madorin Workbench Kernel
├── Distribution Profile        发布品牌与产品边界
├── Industry Pack               行业项目、资产、任务和角色
├── Onboarding Definition       首次初始化问题与生成规则
├── Workbench Template          默认区域、导航和常用操作
├── Business Action Catalog     业务按钮与内部能力绑定
├── User Workbench Override     用户个性化覆盖
└── Effective Workbench         合并后供 UI 使用的只读快照
```

### 2.1 发布配置 Distribution Profile

发布配置决定一个可安装产品的外部身份和默认能力，例如：

| 配置 | `Stream X` | `Madorin` |
| --- | --- | --- |
| 产品定位 | 跨境电商工作台 | 单人公司综合工作台 |
| 默认行业 | 跨境电商 | 用户首次选择或组合 |
| 首次初始化 | 经营模式、市场、渠道、商品和运营习惯 | 行业、职责、工作内容和自动化偏好 |
| 默认工作台 | 站点、渠道、商品、营销、订单、客服、结算 | 项目、客户、内容、财务、运营和自定义模块 |
| 可安装扩展 | 跨境电商子行业包 | 多行业包与自定义包 |

发布配置至少包含：

- 稳定 `DistributionId`
- 产品名称、简称、图标、主题与本地化资源
- 默认行业包和允许安装的行业包
- 默认初始化定义和工作台模板
- 更新通道、许可证和功能开关
- 配置签名、公钥标识和最低内核版本

### 2.2 行业包 Industry Pack

行业包定义用户实际工作的业务语言：

- 项目类型
- 业务资产类型
- 业务模块
- 任务模板和常用操作
- 专家角色与会议角色
- 行业知识源
- 工具与外部平台连接要求
- 合规、权限和审批策略
- 业务产物类型和结果呈现组件

行业包不能直接依赖具体发布品牌。`Stream X` 可以加载跨境电商行业包，其他发布版本也可以在允许时复用同一行业包。

### 2.3 初始化定义 Onboarding Definition

初始化定义不是固定问卷，而是声明：

- 问题、选项和条件显示规则
- 选项对业务模块、常用操作和默认设置的映射
- 哪些问题由发布版本预先锁定
- 最少需要完成的步骤
- 允许稍后设置的内容
- 初始化结果的版本和迁移规则

垂直发布版可以锁定行业，只询问行业内部差异；综合发布版可以允许用户选择一个或多个行业。

### 2.4 工作台模板 Workbench Template

工作台模板只定义业务界面：

- 一级导航
- 首页区域及顺序
- 业务模块及入口
- 常用操作
- 继续工作和任务列表规则
- 业务快照和资产摘要
- 工作标签、项目上下文栏和三种协作模式的进入规则
- 窄屏降级策略

模板不包含任意代码，也不直接执行技能。

### 2.5 业务动作 Business Action Definition

业务动作是按钮背后的稳定契约，内部至少包含：

```text
ActionId
Version
DisplayResourceKey
IconKey
RequiredContext
InputSchema
ActionBinding
PermissionPolicy
ApprovalPolicy
ExpectedArtifacts
ResultPresenter
FailurePolicy
TelemetryCategory
```

`ActionBinding` 可以引用：

- 专家对话预设
- 工作任务模板
- 会议模板
- 已注册技能
- 当前任务中的执行步骤
- 业务资产编辑器
- 组合工作流

用户界面只显示业务名称、必要输入、影响范围和预期产物，不显示 `ActionBinding` 的内部类型和引用。

### 2.6 用户覆盖 User Workbench Override

用户设置只能覆盖允许个性化的部分：

- 区域显示、隐藏和顺序
- 常用操作和排序
- 默认工作区和项目
- 默认对话模式
- 自动化、审批和通知偏好
- 列表视图、筛选和密度

产品名称、签名策略、受控权限和被发布版本锁定的行业边界不能被普通用户覆盖。

## 3. 配置组织与解析

### 3.1 建议目录

```text
<Install>/workbench/
├── distributions/
│   └── stream-x/
│       ├── distribution.json
│       ├── branding.json
│       └── signature.json
├── industry-packs/
│   └── cross-border-commerce/
│       ├── industry.json
│       ├── assets.json
│       ├── actions.json
│       ├── roles.json
│       └── knowledge.json
├── onboarding/
│   └── stream-x-onboarding.json
└── templates/
    └── stream-x-default-workbench.json

<UserData>/workbench/
├── profile.json
├── onboarding-result.json
├── overrides/
│   └── <workspaceId>.json
└── snapshots/
    └── <workspaceId>.effective.json
```

生产实现可以按包合并发布，但逻辑边界必须保留，避免形成一个无法独立升级和验证的超大配置文件。

### 3.2 发布清单示意

以下内容只存在于配置与内部策划，不直接展示在消费者界面：

```json
{
  "distributionId": "stream-x",
  "version": "1.0.0",
  "product": {
    "name": "Stream X",
    "icon": "assets/stream-x.png",
    "theme": "stream-x-default"
  },
  "defaultIndustryPack": "cross-border-commerce",
  "onboarding": "stream-x-onboarding-v1",
  "workbenchTemplate": "stream-x-default-v1",
  "minimumKernelVersion": "1.0.0"
}
```

### 3.3 合并优先级

```text
内核安全默认值
  < 发布配置
  < 行业包默认值
  < 初始化结果
  < 用户全局设置
  < 当前工作区设置
```

高优先级覆盖低优先级，但存在三类不可覆盖内容：

1. 安全最小值，例如危险工具不能被配置为无条件自动授权。
2. 发布锁定项，例如 `Stream X` 的主行业边界和品牌身份。
3. 行业合规项，例如外部发布、删除、财务操作的强制审批。

### 3.4 有效工作台快照

UI 不应在每次渲染时读取并合并所有配置。`WorkbenchConfigurationResolver` 负责：

1. 验证签名和版本。
2. 加载发布配置、行业包、初始化结果和用户覆盖。
3. 执行 schema 校验和版本迁移。
4. 解析资源键、功能开关和动作引用。
5. 生成不可变 `EffectiveWorkbenchSnapshot`。
6. 原子替换当前工作区快照并通知 UI。

快照至少包含来源版本和配置哈希，便于诊断、回滚和升级对账。

### 3.5 更新与迁移

- 所有区域、按钮、资产类型和动作必须使用稳定 ID。
- 用户排序保存 ID 序列，不保存整个模板副本。
- 发布升级增加新按钮时合并到默认位置，不覆盖用户已有顺序。
- 被删除动作保留迁移记录，用户快捷入口降级为不可用说明。
- schema 和行业包分别版本化。
- 迁移失败时继续使用上一份有效快照，不加载半完成配置。

## 4. 首次初始化架构

### 4.1 初始化闭环

```text
加载发布配置
  -> 确定可选行业范围
  -> 收集工作领域与经营模式
  -> 收集日常工作内容
  -> 收集工作习惯和审批偏好
  -> 生成初始化结果
  -> 解析有效工作台快照
  -> 创建首个工作区与默认项目
  -> 进入行业工作台
```

### 4.2 初始化原则

- 首次流程最多保留 3 到 5 个主要步骤。
- 垂直产品不重复询问已经确定的行业。
- 先问能够改变工作台结构的问题，连接平台账号可以稍后完成。
- 每一步结果自动保存，关闭后可以继续。
- 提供“查看示例工作台”，但明确示例数据不会提交外部操作。
- 初始化结束后，所有结果都可以在设置中重新调整。

### 4.3 两类发布模式

**垂直发布模式**：

- `Stream X` 固定跨境电商行业。
- 初始化重点是经营模式、市场、渠道、商品规模和工作偏好。
- 只加载跨境电商业务功能及允许的扩展。

**综合发布模式**：

- `Madorin` 允许选择单人公司、程序开发、内容生产等领域。
- 支持组合多个行业包。
- 相同资产或任务冲突时由配置解析器使用命名空间隔离。

## 5. 工作台信息架构

### 5.1 一级结构

建议使用以下稳定入口：

| 入口 | 普通用户看到的内容 |
| --- | --- |
| 工作台 | 当前行业项目、继续工作、常用操作、业务模块和任务 |
| 项目 | 站点、店铺、软件、动漫作品等行业项目 |
| 任务 | 活跃、等待、已完成和定时业务任务 |
| 资产 | 商品、域名、代码、小说、素材、镜头等行业资产 |
| 对话 | 专家、工作、会议三种模式及历史记录 |
| 应用 | 可用业务功能、连接和行业扩展 |
| 执行中心 | 多任务、Agent、审批、资源、异常和恢复 |
| 设置 | 工作台、初始化、连接、模型、存储和系统设置 |

`执行中心` 是高级入口，不作为默认首页。

### 5.2 Shell 布局

```text
顶部：发布品牌 | 全局搜索 | 新建工作 | 通知 | 账户
左侧一级：可展开/收起的主导航轨，承载工作台、项目、任务、资产、对话、应用、执行中心和设置
左侧二级：由当前一级入口驱动的上下文导航，不是固定项目栏
顶部工作标签：全部项目首页 | 多个独立 WorkSession
首页中部：根据 EffectiveWorkbenchSnapshot 渲染的多项目行业工作台，不显示 AI 对话
工作页中部：当前 WorkSession 的真实 AI 对话
工作页右侧：业务步骤 / 产出 / 参与智能体
底部收起态：26px 级紧凑状态条
底部展开态：Agent 监控 | 总数/运行中/需处理 | 跨项目横向 Agent 卡片
```

一级导航在桌面端支持图标收起态和“图标 + 名称 + 数量”展开态，用户选择持久化到本地设置；展开一级导航时只增加整个侧栏宽度，不挤压二级栏。移动端不单独展开一级文字，而是把一级与二级导航作为同一个抽屉打开。

二级导航按一级入口切换信息集合：

| 一级入口 | 二级导航职责 |
| --- | --- |
| 工作台 | 工作台视图、继续工作、项目运行摘要 |
| 经营项目 | 项目搜索、全部项目、当前项目目录树 |
| 业务任务 | 工作搜索、并行工作、当前工作所属项目及其目录树 |
| 业务资产 | 项目选择、项目文件、业务资源与产出目录 |
| 对话记录 | 专家 / 工作 / 会议筛选、最近对话 |
| 应用与连接 | 行业模块、已连接平台 |
| 执行中心 | 全部 / 运行中 / 需处理统计、Agent 实例 |
| 设置 | 工作台、项目文件、对话与存储分类 |

`WorkSession` 工作页归属“业务任务”一级上下文。项目根目录及其文件树只在经营项目、业务任务和业务资产中出现；工作台、对话记录、应用与连接、执行中心和设置不能重复挂载项目目录。

项目不是顶部全局下拉值。在经营项目上下文中可直接扫描和选择全部项目；进入具体工作时，系统自动定位该工作所属项目及其目录。每个工作标签独立保留对话、草稿、步骤、文件引用和页面状态，切换标签不重建全部工作台。

AI 对话只在业务目标已经确定、或新建工作完成必要信息确认后显示。专家、工作、会议不是首页三个常驻空对话标签，而是 `WorkSession.Mode` 的三种值。窄屏中工作页使用“对话 / 详情”切换，任务和项目文件通过左侧导航抽屉访问。

### 5.3 首页优先级

首页内容按以下顺序组织：

1. 当前行业、工作区和全部运行项目。
2. 跨项目继续工作和等待用户处理的业务事项。
3. 常用操作和当前用户选择的业务模块。
4. 项目业务快照，例如站点、商品、订单和渠道数据。
5. 后台运行摘要。

不在首屏显示 AI 对话或完整 Agent 运行矩阵；Agent 摘要固定在底部状态条，需要时再展开监控栏。

## 6. 业务按钮与执行解析

### 6.1 用户交互

用户点击一个业务按钮后，系统执行以下用户可理解流程：

```text
点击业务操作
  -> 检查当前项目和资产上下文
  -> 只询问缺失的必要信息
  -> 显示影响范围、权限和预期产物
  -> 用户确认开始
  -> 进入专家 / 工作 / 会议中的一种
  -> 展示业务步骤与结果
  -> 产物写回项目和资产
```

### 6.2 内部解析

以下内部过程不在消费者界面展示：

```text
BusinessActionId
  -> ActionRegistry.Resolve()
  -> ContextAssembler
  -> PermissionPolicy
  -> ExpertPreset / WorkTemplate / MeetingTemplate / Skill / Step
  -> Agent and Tool Orchestration
  -> ArtifactProjector
```

### 6.3 交互类型一致性

用户不需要知道内部绑定类型，但界面反馈必须可预测：

- 立即完成的操作使用普通按钮并给出结果。
- 需要补充输入的操作打开轻量任务面板。
- 长时间任务创建后台任务并进入工作模式。
- 咨询和诊断切换到专家模式。
- 评审和多角色决策切换到会议模式。
- 高风险操作必须在执行前显示明确作用域和审批。

## 7. 三种主要对话模式

### 7.1 WorkSession 与共享上下文

每次专家咨询、执行任务或会议都创建独立 `WorkSession`：

```text
WorkSession
├── SessionId / ProjectId / Mode
├── ConversationId / TaskId / MeetingId
├── Draft / SelectedFileRefs / ViewState
├── Plan / Outputs / ParticipantAgentIds
└── Status / Progress / UpdatedAt
```

三种模式共享：

- DistributionId 和 IndustryPackId
- WorkspaceId 和 ProjectId
- 当前选中的业务资产
- 来源业务动作与任务
- 用户初始化画像和工作偏好
- 可用技能、工具、知识和权限

模式不是全局开关。创建后由 `WorkSession` 保存模式和来源关系；切换工作标签不复制正文、不停止后台任务，也不丢失项目和文件引用。

### 7.2 对话工作面契约

三种模式都必须提供可以持续工作的实际对话界面：

- 可回放的用户与 AI 消息历史。
- 始终可用的输入框、附件和业务资产引用。
- 停止生成、继续、重新生成和回答询问。
- 明确显示当前项目、项目根目录、所选文件和来源任务。
- 用户切换工作台页面后仍保留当前线程和草稿。
- 不同 `WorkSession` 分别保存线程、焦点、草稿和页面状态。

工作模式必须把对话和执行计划视为同一个任务的两个同步视图：

```text
用户在工作对话中提出修改
  -> AI 生成计划变更建议
  -> 显示受影响步骤、产物和预算
  -> 需要时等待用户确认
  -> 更新步骤树和执行队列
  -> 在对话中回报变更结果
```

“修改方案”“增加步骤”“跳过步骤”“补充输入”和“重新执行”都通过工作对话完成，用户不需要进入 Agent 或工作流编辑器。

### 7.3 专家模式

定位：咨询、诊断、分析、建议和复核。

- 主要是一个主专家持续交流。
- 可以按需委派子智能体和调用工具。
- 支持附件、资产引用、流式响应、停止和会话恢复。
- 结论可以转为工作任务或会议议题。

### 7.4 工作模式

定位：完成明确业务目标并生成产物。

- 由业务按钮或用户对话创建。
- 展示业务步骤、缺失输入、审批、产物和异常。
- 用户可以在任务运行中继续对话，修改方案并重编后续步骤。
- 多智能体、工具和工作流作为内部执行细节。
- 支持后台运行、暂停、恢复、取消和失败重试。

### 7.5 会议模式

定位：多个专业角色讨论、评审和决策。

- 展示议题、参与角色、当前发言、异议、决议和行动项。
- 用户可以插话、追问、调整议题和要求重新讨论某项结论。
- 会议行动项可以批量创建工作任务。
- 会议总结和决策记录写入项目产物。

## 8. 项目、资产、任务和产物闭环

```text
Industry Project
  -> Business Assets
  -> Business Action
  -> Conversation or Task
  -> Artifact
  -> Project Asset / Next Action
```

核心对象：

| 对象 | 说明 |
| --- | --- |
| Workspace | 用户工作边界，承载行业包、配置、连接和存储 |
| Project | 行业项目，例如独立站、软件项目、动漫作品；独占本地根目录和文件索引 |
| BusinessAsset | 商品、域名、代码、小说、素材等业务资产 |
| BusinessAction | 用户可点击的业务操作 |
| Conversation | 专家、工作、会议三模式的对话历史 |
| WorkSession | 一个已明确目标的可交互工作页，绑定一个 Project 和一种协作模式 |
| WorkTask | 可以后台运行的业务任务 |
| Run | 一次实际执行，可恢复、暂停、取消和重试 |
| Artifact | 报告、页面、商品文案、代码、镜头、会议纪要等产物 |
| AgentInstance | Run 中的实际 Agent 实例，仅在高级视图展示 |

业务产物必须成为项目可检索资产，不能只停留在聊天消息中。

### 8.1 项目文件所有权

```text
Workspace
└── Project
    ├── ProjectRootPath
    ├── documents/
    ├── resources/
    ├── inputs/
    ├── outputs/
    ├── WorkSession 1
    │   └── SelectedFileRefs
    ├── WorkSession 2
    │   └── SelectedFileRefs
    └── AgentRunProjection 1..N
```

- 本地根目录、文件树、索引状态和排除规则属于 `Project`，不属于 Agent，也不由每项任务复制。
- 一个项目可以同时运行多个工作和多个 Agent，它们通过文件引用访问同一项目目录。
- 切换项目时只切换左侧项目目录投影；切换同项目内的工作标签不重新扫描目录。
- 工作产出必须记录 `ProjectId / WorkSessionId / RelativePath`，并投影到项目的产出节点。
- UI 正常列表读取文件索引；实时监听、手动刷新和大目录排除由项目索引策略决定。

## 9. 执行中心

执行中心保留原多智能体方案的商业级控制能力：

- 所有活跃和排队任务
- Agent 定义与运行实例
- 审批和用户询问
- 工具调用、异常和恢复
- Provider、Model、Token 和成本
- 事件时间线和心跳
- 文件写入、外部发布和审计记录

任务的普通详情使用业务步骤；高级详情才展示 `TaskId / RunId / AgentInstanceId / CorrelationId`。

所有事件仍需经过统一规范化、状态投影和状态仓库，禁止页面直接依赖“当前任务”全局变量。

## 10. 对话与配置存储

### 10.1 对话正文

继续使用既有目录契约：

```text
<Workspace>/.cortana/conversations/
├── expert/{sessionId}.jsonl
├── expert/{sessionId}.compact.json
├── meeting/{meetingId}.jsonl
├── meeting/{meetingId}.compact.json
├── work/{taskId}.{runId}.jsonl
└── work/{taskId}.{runId}.compact.json
```

- SQLite 保存标题、模式、摘要、时间、状态、Agent、Token 和文件定位。
- JSONL 保存大正文和事件记录。
- compact 文件保存压缩上下文和恢复摘要。
- UI 通过 Repository 加载，不能直接扫描目录作为正常列表流程。

项目业务文件与对话正文分开管理：项目文件位于用户配置的 `ProjectRootPath`；对话正文仍位于工作区 `.cortana/conversations`。SQLite 同时保存项目文件索引、`WorkSession` 索引和对话文件定位，使项目目录迁移不要求搬迁全部历史对话。

### 10.2 工作台配置

- 安装配置只读并经过签名校验。
- 用户覆盖写入用户数据目录，不能修改安装包。
- 有效快照原子写入，保留上一版本。
- 配置中不保存 API Key、密码、Cookie 或访问令牌。
- 外部连接只保存安全存储中的凭据引用。

## 11. 独立解决方案边界

推荐项目名继续使用 `Netor.Madorin.Workbench`，发布品牌由 Distribution Profile 决定，不需要为每个品牌复制完整解决方案。

```text
Src/Netor.Madorin.Workbench/
├── Netor.Madorin.Workbench.slnx
├── Netor.Madorin.Workbench.Entities/
│   └── 配置模型、行业对象、只读快照、状态值对象
├── Netor.Madorin.Workbench.Core/
│   └── 配置解析、动作注册、导航、命令、查询与监控契约
├── Netor.Madorin.Workbench.Services/
│   └── 配置加载、行业包、初始化、执行适配、投影和存储
├── Netor.Madorin.Workbench.Desktop/
│   └── Avalonia Shell、行业工作台、三模式对话和组合根
└── Netor.Madorin.Workbench.Tests/
    └── 配置合并、迁移、动作解析、状态隔离和关键交互测试
```

依赖方向：

```text
Desktop -> Core -> Entities
Desktop -> Services -> Core + Entities
Services -> 现有 AI / Entitys / Store / Plugin / EventHub
```

约束：

- Desktop 不直接读取安装配置、数据库或执行器。
- Core 定义 `IWorkbenchConfigurationResolver`、`IBusinessActionRegistry`、`IWorkbenchQueryService` 等契约。
- Services 负责实际加载、迁移、签名、缓存和旧系统适配。
- Entities 不复制持久化实体的业务职责。
- 发布品牌只提供配置和资源，不复制 Workbench 代码。

## 12. 安全与治理

配置能够间接触发任务，因此必须被视为受控执行入口：

1. 配置只能引用注册表中存在的稳定 ActionId、SkillId 和 TemplateId。
2. 禁止在配置中写 shell 命令、脚本和任意程序集路径。
3. 发布配置和行业包必须签名，用户本地配置只能使用允许覆盖的字段。
4. 动作解析后仍要执行权限、风险、预算和外部发布审批。
5. 高风险操作不能通过工作台设置关闭强制审批。
6. 配置版本、动作版本、用户批准和执行结果进入审计记录。
7. 无效或不兼容配置不得生成部分工作台，必须回退到上一有效快照。

## 15. 验收标准

1. `Stream X` 和 `Madorin` 可以通过不同发布配置显示不同名称、图标、初始化和默认工作台，不复制 Workbench 代码。
2. 首次初始化能够根据选择生成不同业务模块和常用操作。
3. 用户在设置中调整工作台后，升级行业包不会覆盖已有个性化。
4. 任一业务按钮都能追溯到稳定 ActionId、版本、权限、执行模板和产物定义。
5. 用户界面不暴露技能、Prompt、工作流或 Agent 编排类型。
6. 首页不显示 AI 对话；创建或进入已明确目标的工作后，才显示专家、工作或会议真实对话。
7. 一级导航可展开、收起并持久化；切换任一一级入口时，二级栏必须显示对应上下文，而不是始终显示项目和目录。
8. 每个 Project 只有一份根目录和文件索引，同项目多个 WorkSession 与 Agent 通过引用共享文件。
9. 多个 WorkSession 标签可以跨项目并行打开，切换时保留对话、草稿、文件引用和页面状态。
10. 底部状态条保持紧凑；展开 Agent 监控后可横向查看所有项目的运行中、等待和需处理实例。
11. 关闭对话或切换页面不停止后台任务，Agent 卡片能够定位回所属工作。
12. 执行中心能查看模型、Token、成本、事件和异常，但默认首页仍然是行业业务工作台。
13. 配置损坏、签名失败或迁移失败时使用上一份有效快照。
14. 对话历史通过 SQLite 索引和 JSONL 正文文件恢复，文件异常有可理解的降级结果。

## 16. 待产品拍板

以下项目会改变数据契约或核心交互，样板不替代正式决策：

1. **工作标签粒度**：一项任务一个 `WorkSession` 标签，还是一个项目一个标签、项目内再切换多个任务。当前样板采用“一项工作一个标签”。
2. **从项目上下文切换项目后的落点**：进入该项目最后活跃的工作、项目总览，还是仅切换目录树而保持当前工作。当前样板在工作页中定位该项目首个可用工作，在首页只切目录。
3. **项目目录契约**：是否固定 `documents/resources/inputs/outputs`，还是允许行业包定义目录并只要求稳定语义角色。
4. **工作产出位置**：统一写入 `{ProjectRoot}/outputs/{WorkSessionId}/`，还是允许用户把产出写回选定业务目录，同时保留来源索引。
5. **三模式生命周期**：`WorkSession` 创建后锁定专家/工作/会议模式，还是允许在同一线程中转换模式并保留转换记录。
6. **工作标签上限**：允许无限打开，还是达到阈值后提示归档、休眠或关闭较早标签。
7. **Agent 监控偏好**：默认始终折叠，还是记忆上次展开状态；普通卡片是否显示模型、Token 和费用，还是只在执行中心显示。
8. **项目文件索引策略**：实时监听、定时增量刷新或手动刷新；大目录、二进制文件和敏感目录的默认排除规则。
9. **项目根目录迁移**：用户变更 `ProjectRootPath` 时只更新映射、执行文件迁移，还是提供两种显式操作。
10. **一级导航初始状态**：由品牌配置决定首次展开或收起，还是所有品牌统一默认收起。当前样板为首次收起，之后记忆用户选择。
11. **二级上下文状态**：切换一级入口后，搜索词、筛选和展开节点是否分别记忆。当前样板保留关键业务选择，但不承诺所有临时筛选长期持久化。

## 17. 结论

本次重构的核心不是把旧聊天窗口扩大，也不是给 Agent 控制台增加行业按钮，而是建立新的配置驱动产品层：发布版本决定品牌与行业边界，行业包定义业务语言，初始化生成用户工作台，业务按钮封装 AI 执行，三种对话模式承载协作，多任务和多智能体在后台可靠运行并可在执行中心观察。

`Stream X` 是第一套参考发布版，用于验证这套架构能否真正让跨境电商用户通过熟悉的操作方式直接开始工作。
