# 跨平台运行评估

> **目标平台：Windows · macOS · Linux（三端同时支持）**
> 日期：2026-07-21
> 基于：Avalonia 12 + .NET 10 + Native AOT

---

## 一、核心依赖覆盖情况

经过对 NuGet 包内原生库的直接验证，所有关键依赖均覆盖三端。

### SkiaSharp（Avalonia 渲染核心）

| 平台 | RID | 状态 |
|------|-----|------|
| Windows | win-x64, win-arm64, win-x86 | ✅ |
| macOS | osx (universal dylib) | ✅ |
| Linux | linux-x64, linux-arm64, linux-arm, linux-musl-x64, linux-musl-arm64, linux-riscv64, linux-loongarch64 | ✅ |

### HarfBuzzSharp（字体排版）

覆盖情况与 SkiaSharp 完全一致，三端全覆盖 ✅

### Onigwrap（TextMate 语法高亮依赖）

| 平台 | 支持 |
|------|------|
| Windows | win-x64, win-arm64, win-x86 ✅ |
| macOS | osx-x64, osx-arm64, maccatalyst ✅ |
| Linux | linux-x64, linux-arm64, linux-musl-x64, linux-musl-arm64 ✅ |

### LiveMarkdown.Avalonia（Markdown 渲染）

纯托管库，**无原生依赖**，天然跨平台 ✅

### Avalonia 框架本体

官方明确支持 Windows / macOS / Linux / iOS / Android / WebAssembly，三端均为一类平台 ✅

## 二、各平台具体评估

### Windows

| 项目 | 状态 | 说明 |
|------|------|------|
| 运行 | ✅ 完整支持 | x64 / arm64（Surface Pro X 等） |
| Native AOT | ✅ 已验证 | win-x64 编译通过，输出 24MB 单文件 |
| 字体 | ✅ 无需额外处理 | Segoe UI 等系统字体直接可用 |
| 渲染后端 | ✅ Direct2D / OpenGL / Vulkan | 自动选择最佳后端 |
| 分发 | ✅ 成熟 | MSIX / 安装包 / 绿色单文件 |
| 已有代码 | ✅ 现有项目已在生产运行 | — |

**结论：无障碍。**

---

### macOS

| 项目 | 状态 | 说明 |
|------|------|------|
| 运行 | ✅ 支持 | x64（Intel）+ arm64（Apple Silicon M系列） |
| Native AOT | ✅ 支持 | 需在 macOS 机器上编译，不能从 Windows 交叉编译 |
| 字体 | ✅ 无需额外处理 | San Francisco 等系统字体直接可用 |
| 渲染后端 | ✅ Metal（首选）/ OpenGL | Avalonia 12 Metal 后端已稳定 |
| 分发 | ⚠ 需处理 | 需要 Apple Developer 证书签名 + Notarization，否则 Gatekeeper 拦截 |
| 窗口装饰 | ⚠ 需适配 | macOS 标题栏与 Windows 不同，需设置 `ExtendClientAreaToDecorationsHint` |

**关键注意点：**

```xml
<!-- macOS 无边框窗口适配 -->
<Window ExtendClientAreaToDecorationsHint="True"
        ExtendClientAreaChromeHints="NoChrome"
        ExtendClientAreaTitleBarHeightHint="-1">
```

- Apple Silicon 原生运行（非 Rosetta 2）需要 `osx-arm64` 发布目标
- 需要 Universal Binary（同时包含 x64+arm64）或分别发包
- 代码签名命令：`codesign --deep --force --sign "Developer ID" App.app`

**结论：技术可行，需要 Apple Developer 账号（年费 $99）和 macOS 构建机。**

---

### Linux

| 项目 | 状态 | 说明 |
|------|------|------|
| 运行 | ✅ 支持 | x64 / arm64 / musl（Alpine） |
| Native AOT | ✅ 支持 | 需在 Linux 机器上编译 |
| 字体 | ⚠ 需处理 | 依赖 `fontconfig`，用户环境需安装中文字体 |
| 渲染后端 | ⚠ 需处理 | 需要 OpenGL / Vulkan 驱动（mesa），wayland/X11 二选一 |
| 分发 | ⚠ 复杂 | 发行版差异大，推荐 AppImage（免安装） |
| 输入法 | ⚠ 需测试 | IBus / fcitx 输入法与 Avalonia 兼容性需验证 |

**字体依赖处理（必须）：**

```bash
# 用户需要安装字体（或打包时内嵌）
sudo apt install fonts-noto-cjk  # Debian/Ubuntu
sudo dnf install google-noto-cjk-fonts  # Fedora
```

或在应用启动时检测并引导安装：
```csharp
// Avalonia 字体内嵌方案（推荐，无需用户手动安装）
.WithFonts(opts => opts.AddFontFolder("avares://YourApp/Assets/Fonts"))
```

**Wayland vs X11：**

```csharp
// Program.cs 启动时自动检测
builder.UseX11()       // X11（Ubuntu 默认）
       .UseWayland()   // Wayland（GNOME 42+ 默认）
```

Avalonia 12 两者均支持，但 Wayland 下 OpenGL 需要 EGL，需测试目标发行版。

**推荐发行版测试矩阵：**

| 发行版 | 重要性 | 说明 |
|--------|--------|------|
| Ubuntu 22.04 LTS | 🔴 必测 | 最大用户群，apt 包管理 |
| Ubuntu 24.04 LTS | 🔴 必测 | 当前 LTS |
| Debian 12 | 🟡 建议 | 服务器部署场景 |
| Fedora 40+ | 🟡 建议 | Wayland 原生 |
| Alpine Linux | 🟢 可选 | musl libc，容器化场景 |

**结论：技术可行，字体内嵌和 AppImage 打包是关键，需要 Linux CI 构建机。**

## 三、Native AOT 跨平台编译策略

**核心限制：Native AOT 必须在目标平台上编译，不支持完整的跨平台交叉编译。**

```
Windows 机器  → 编译 win-x64 / win-arm64
macOS 机器    → 编译 osx-x64 / osx-arm64
Linux 机器    → 编译 linux-x64 / linux-arm64
```

### 推荐 CI/CD 方案

**GitHub Actions（推荐）：**

```yaml
jobs:
  build-windows:
    runs-on: windows-latest
    steps:
      - run: dotnet publish -r win-x64 -p:PublishAot=true

  build-macos:
    runs-on: macos-latest       # 包含 Apple Silicon
    steps:
      - run: dotnet publish -r osx-arm64 -p:PublishAot=true
      - run: dotnet publish -r osx-x64 -p:PublishAot=true

  build-linux:
    runs-on: ubuntu-latest
    steps:
      - run: dotnet publish -r linux-x64 -p:PublishAot=true
```

GitHub Actions 提供免费的 Windows / macOS / Linux runner，三端 CI 直接可用。

## 四、平台差异处理清单

需要在代码中处理的平台差异：

### 标题栏 / 窗口装饰

```csharp
// 不同平台使用不同策略
if (OperatingSystem.IsWindows())
    // 自定义 Win32 标题栏（已有）
else if (OperatingSystem.IsMacOS())
    // macOS 原生标题栏融合
else
    // Linux 走系统标题栏或自绘
```

### 文件路径

```csharp
// 统一使用 Path.Combine，不手写分隔符
var path = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
    "Madorin", "conversations");
```

### 字体内嵌（解决 Linux 中文字体问题）

在项目中内嵌字体资源，避免依赖系统字体：
```xml
<ItemGroup>
  <AvaloniaResource Include="Assets/Fonts/*.ttf"/>
</ItemGroup>
```

### 托盘图标

- Windows：`NotifyIcon`（Avalonia 有扩展包）
- macOS：`NSStatusItem`（需要 macOS 特定代码）
- Linux：AppIndicator（发行版支持不统一，可选实现）

## 五、已知风险与缓解

| 风险 | 级别 | 缓解方案 |
|------|------|----------|
| macOS Notarization 流程复杂 | 🟡 中 | 提前申请 Developer ID，CI 中集成自动公证 |
| Linux 输入法兼容性 | 🟡 中 | Avalonia 12 已改善 IBus/fcitx 支持，需实机测试 |
| Linux Wayland 渲染问题 | 🟡 中 | 提供 `AVALONIA_BACKEND=x11` 回退选项 |
| HiDPI 缩放（各平台不一致） | 🟢 低 | Avalonia 12 自动处理，少量 UI 需验证 |
| 中文字体在 Linux 缺失 | 🟡 中 | 内嵌 Noto Sans CJK 子集到应用资源 |
| CI macOS runner 费用 | 🟢 低 | GitHub Actions macOS runner 免费（私有库有限额） |

---

## 六、结论

**三端同时支持：完全可行。**

- 框架层（Avalonia + SkiaSharp + HarfBuzzSharp）：原生三端覆盖，无障碍
- Markdown 渲染（LiveMarkdown.Avalonia）：纯托管，三端一致
- Native AOT：三端均支持，需要各平台构建机（CI 可解决）
- 主要工作量：macOS 签名、Linux 字体内嵌 + AppImage 打包、CI 流水线搭建

**开发优先级建议：** Windows → Linux x64 → macOS（按用户群和实施难度排序）
