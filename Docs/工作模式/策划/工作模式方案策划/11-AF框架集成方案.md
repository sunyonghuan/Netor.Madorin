# 11 - AF 框架集成方案

> 工作模式如何使用 Microsoft Agent Framework v1.6.0
>
> **核心决策**：放弃 Magentic，改用 `ChatClientAgent` + 工具调用 + HITL 模式

---

## 一、架构决策：为什么不用 Magentic

### 1.1 Magentic 的特点

Magentic 是 AF 内置的多智能体编排模式（见 [03-编排模式.md](./03-编排模式.md) §六），它的设计目标是：

- Manager **自驱动**：自己制定计划、分派任务、检测卡住、自动重规划
- Manager **不与用户对话**：把整个任务封装成黑盒，给一个目标，跑到给一个结果
- 内置 **Plan / Ledger / StallDetection / Replan** 流程

### 1.2 工作模式的实际诉求

工作模式不是"无人值守的多智能体协作"，而是 **人机协作（HITL，Human-in-the-Loop）**：

| 诉求 | Magentic 行为 | 工作模式期望 |
|------|--------------|------------|
| 需求补齐 | 不存在（直接给目标） | 多轮对话直到明确 |
| 计划生成 | Manager 自动制定，立即执行 | 显示给用户，**等用户确认才开始** |
| 计划修改 | Replan 由 Manager 触发 | 用户用自然语言改 |
| 用户插话 | 不支持 | 可以暂停、可以改方向 |
| 工具授权 | 走 RequestInfoEvent | 走 RequestInfoEvent ✅ |
| 计划复用 | 不存在 | 从模板/历史对话加载 |

**结论**：Magentic 解决的是"自动化协调"问题，工作模式解决的是"对话式任务执行"问题。两者目标不同，不应套用。

### 1.3 选定方案

```text
┌─────────────────────────────────────────────────────┐
│ 主 Agent: ChatClientAgent（普通智能体）              │
│  ├─ Instructions: 通过提示词引导对话流程              │
│  ├─ Tools: 计划工具 + 派发工具 + 验收工具 + ask_user │
│  └─ 包装成单节点 Workflow（获得 Checkpoint/HITL 能力）│
└─────────────────────────────────────────────────────┘
                       ↓ AsAIFunction
┌─────────────────────────────────────────────────────┐
│ 子智能体（部门 / 员工）                                │
│  ├─ 复用 Cortana 现有 AIAgentFactory.BuildSubAgent  │
│  └─ 通过 AsAIFunction 注入到主 Agent 的工具集        │
└─────────────────────────────────────────────────────┘
```

**好处**：

- 主 Agent 是普通 `ChatClientAgent`，可以复用 Cortana 现有的 `AIAgentFactory.Build()` 模式
- 用工具调用驱动流程，每个工具的语义是明确的（避免 Manager 行为不可控）
- 通过 `RequestInfoEvent` 自然支持暂停（等用户输入），通过 Checkpoint 支持恢复
- 子智能体仍可用 `AsAIFunction` 复用现有 `BuildWithSubAgents` 机制

## 二、智能体构建（动态、AOT 安全、提示词可替换）

### 2.1 设计原则

1. **每次任务临时构建**：不做单例缓存（提示词换了立即生效）
2. **AOT 安全**：所有工具用源生成器友好的方式注册（`AIFunctionFactory.Create` + 强类型签名）
3. **提示词外部化**：通过 `IPromptProvider` 加载，支持本地 / 数据库 / 网络

### 2.2 IPromptProvider 接口

```csharp
namespace Netor.Cortana.AI.WorkMode.Prompts;

/// <summary>
/// 提示词提供器。支持从多种来源加载提示词，按优先级链式查找。
/// 设计目标：未来可以无缝替换为远程加载，无需改业务代码。
/// </summary>
public interface IPromptProvider
{
    /// <summary>
    /// 按 key 加载提示词文本。
    /// 约定 key 命名空间："work_mode.<role>"，如 "work_mode.general_manager"。
    /// </summary>
    Task<string> GetPromptAsync(string key, CancellationToken ct = default);

    /// <summary>
    /// 是否支持指定 key（用于 CompositePromptProvider 的优先级判断）。
    /// </summary>
    Task<bool> HasPromptAsync(string key, CancellationToken ct = default);
}
```

### 2.3 内置实现

| 实现 | 用途 | 优先级 |
|------|------|--------|
| `LocalFilePromptProvider` | 从 `./prompts/<key>.md` 读 | 兜底 |
| `DatabasePromptProvider` | 从 `SystemSettings` 表读（用户可在设置页改） | 中 |
| `RemotePromptProvider` | 从 HTTP API 读（v1.1+ 实现） | 高（最优先） |
| `CompositePromptProvider` | 按优先级链式查找 | 组合器 |

**注册示例**：

```csharp
public static class PromptServiceExtensions
{
    public static IServiceCollection AddPromptProviders(this IServiceCollection services)
    {
        services.AddSingleton<LocalFilePromptProvider>();
        services.AddSingleton<DatabasePromptProvider>();
        // services.AddSingleton<RemotePromptProvider>();  // v1.1+

        services.AddSingleton<IPromptProvider>(sp =>
        {
            // 优先级从高到低
            var providers = new IPromptProvider[]
            {
                // sp.GetRequiredService<RemotePromptProvider>(),
                sp.GetRequiredService<DatabasePromptProvider>(),
                sp.GetRequiredService<LocalFilePromptProvider>(),
            };
            return new CompositePromptProvider(providers);
        });

        return services;
    }
}
```

```text
│   ├── work_mode.general_manager.md       ← 总经理（需求补齐 + 计划编排）
```

### 2.5 总经理 Agent 构建器

```csharp
namespace Netor.Cortana.AI.WorkMode;

/// <summary>
/// 工作模式主 Agent（"总经理"）构建器。
/// 每次任务启动时构建一个新实例，不做缓存，让提示词修改立即生效。
/// </summary>
public sealed class GeneralManagerAgentBuilder
{
    private readonly AIAgentFactory _agentFactory;
    private readonly IPromptProvider _promptProvider;
    private readonly WorkModeToolset _toolset;
    private readonly ILogger<GeneralManagerAgentBuilder> _logger;

    public GeneralManagerAgentBuilder(
        AIAgentFactory agentFactory,
        IPromptProvider promptProvider,
        WorkModeToolset toolset,
        ILogger<GeneralManagerAgentBuilder> logger)
    {
        _agentFactory = agentFactory;
        _promptProvider = promptProvider;
        _toolset = toolset;
        _logger = logger;
    }

    /// <summary>
    /// 构建总经理 Agent。
    /// </summary>
    /// <param name="taskId">当前任务 ID（注入到工具上下文，让工具知道操作哪个任务）</param>
    /// <param name="provider">使用的厂商（默认走当前选中的）</param>
    /// <param name="model">使用的模型</param>
    /// <param name="agent">使用的智能体配置（决定 temperature 等参数）</param>
    /// <param name="subAgentMentions">用户在 InputAreaView 里 @ 的子智能体（作为部门工具注入）</param>
    public async Task<AIAgent> BuildAsync(
        string taskId,
        AiProviderEntity provider,
        AiModelEntity model,
        AgentEntity agent,
        IReadOnlyList<AgentMention> subAgentMentions,
        CancellationToken ct = default)
    {
        // 1. 加载提示词（动态，每次都从 Provider 拿最新）
        var instructions = await _promptProvider.GetPromptAsync(
            "work_mode.general_manager", ct);

        // 2. 构建工具集（注入 taskId 上下文）
        var tools = _toolset.BuildTools(taskId);

        // 3. 临时改写 agent 实体的 Instructions（不入库，仅本次有效）
        var transientAgent = agent with
        {
            Instructions = instructions,
        };

        // 4. 复用 Cortana 现有的 AIAgentFactory
        //    BuildWithSubAgents 会把 mentions 通过 AsAIFunction 注入为子智能体工具
        if (subAgentMentions.Count > 0)
        {
            return _agentFactory.BuildWithSubAgents(
                transientAgent, provider, model,
                [.. subAgentMentions],
                _agentFactory.ProviderService,
                _agentFactory.ModelService,
                additionalTools: tools);  // 把工作模式工具一并注入
        }
        else
        {
            return _agentFactory.Build(transientAgent, provider, model,
                additionalTools: tools);
        }
    }
}
```

> **注意**：`AIAgentFactory.Build` / `BuildWithSubAgents` 当前签名没有 `additionalTools` 参数。**实施时需扩展现有方法**（增加可选参数 `IList<AIFunction>? additionalTools = null`，在组装 `ChatClientAgentOptions.ChatOptions.Tools` 时合并），保持向后兼容。

### 2.6 提示词模板（work_mode.general_manager.md）

```markdown
你是公司的总经理（General Manager），负责把用户的工作目标拆解为可执行的工作计划，并协调智能体团队完成。

## 工作模式定位（重要）

这是一个"一人公司"系统：用户是唯一的决策者和审批人，AI 是全部"员工"。
你不是辅助用户，你是替用户把活干掉。用户给你目标，你自己把信息查清楚、把计划列出来、把活干完。

## 你的工作流程

### 阶段 1 — 需求补齐（先查后问，不要逆序）
**重要**：不要一上来就追问用户。优先用工具自己查信息：
1. 先调用调查类工具（搜知识库、读用户当前 workspace 的相关文件、查历史任务的相关产出等）
2. 把能从工具拿到的信息整理出来
3. 只在**用户必须做决策**的点才停下来问——例如：
   - 多种合理路径让用户选（A 方案 vs B 方案）
   - 用户偏好（受众、风格、深度）你查不到
   - 高风险的方向需要用户确认
4. 一次只问一两个最关键的决策点，不要把用户当问卷调查表

错误示范：
- 用户："帮我做销售月报"
- 总经理："数据来源是？时间范围是？给谁看？输出格式是？" ← 不要这样

正确示范：
- 用户："帮我做销售月报"
- 总经理：[调用 search_workspace 找到 erp_config.json] [调用 query_recent_completed_task 找到上次做过类似月报] "我看到工作区里 ERP 配置完整，上次做过 4 月月报。要不就基于上次的方案做 5 月的，给老板看的高层版？还是要换格式？"
3. 信息足够后，整理一份不超过 5 行的需求摘要，让用户确认。

### 阶段 2 — 计划生成
1. 优先尝试加载已有计划：
   - 用户提到"用上次的方案 / 用 X 模板"时，调用 `load_plan_from_template`。
   - 用户提到"参考刚才在专家模式聊的内容"时，调用 `load_plan_from_chat_history`。
   - 用户提到"按会议讨论的"时，调用 `load_plan_from_groupchat`。
2. 没有可复用的计划时，自己拆解：3-5 个主步骤，每个主步骤 2-4 个子步骤，每个步骤都要有验收标准。
3. 计划制定完成后，调用 `set_plan` 工具保存到任务，然后用 Markdown 把计划展示给用户。**不要在没保存到 set_plan 的情况下就说"我已经制定好了"**。

### 阶段 3 — 计划确认与修改
1. 等待用户明确确认（如"开始""可以""执行"）。模糊的反馈（"嗯""好"）继续追问。
2. 用户提出修改时（"把第三步改成 X"），生成完整新计划，再次调用 `set_plan` 覆盖，再展示。
3. 不要"部分修改"——每次修改都输出完整的最新计划。

### 阶段 4 — 执行
1. **每个主步骤开始前必须调用 `check_pending_user_input` 工具**，看用户在执行过程中有没有插话（"立刻停 / 改计划 / 加个 X"）。有插话先按用户意思处理。
2. 评估当前主步骤的子步骤之间是否可以并行：
   - 有依赖（B 用 A 的结果）→ 用 `dispatch_step` 串行
   - 无依赖、可独立 → 用 `dispatch_parallel` 并行（明显提速）
   - 单个子步骤本身又包含 5+ 细操作 → 用嵌套子工作流 `dispatch_nested_workflow`
3. **每个产生具体产出的子步骤完成后，必须先调用 `self_evaluate` 自评**：
   - verdict = pass → 进入下一步
   - verdict = marginal → 最多再快速改一次
   - verdict = fail → 根据 suggestions 改进，重新产出，再 self_evaluate
   - 自评迭代上限 5 次。5 次仍 fail 调 `ask_user`。
4. 子步骤的最终产出过 `verify_step` 工具：
   - 通过 → 进入下一步
   - 不通过 → `send_back` 让部门带反馈重做
5. 同一步骤连续失败 3 次后，调用 `ask_user` 询问用户怎么处理（重做 / 跳过 / 改计划）。

### 阶段 5 — 完成
1. 所有步骤完成后，调用 `final_report` 提交最终报告。
2. 报告应包含：完成了什么、关键产物（含文件路径）、遇到的问题与解决方式、后续建议。

## 工作原则

- **替用户把活干掉**：你是一人公司里的全部员工，用户给你目标，把信息查清楚、把活干完，不要把决策都推给用户。
- **先查后问**：用工具查清楚后再问用户，不要一上来就追问。
- **不啰嗦**：必须问用户的时候，一次问一两个最关键的决策点。
- **结构化产出**：计划、验收结论、最终报告都用 Markdown。
- **诚实汇报**：失败就说失败，不要硬凑结果。
- **自评先行**：产出先自己看一眼再交给用户/下一步，不让用户当第一审稿人。
- **不打扰**：自评迭代、瞬时失败重试、子智能体内部细节，**不要每次都跟用户报告**，只在用户问起或主步骤完成时说。

## 可用工具

{tools_summary}

## 当前会话上下文

{session_context}
```

> 注：`{tools_summary}` 和 `{session_context}` 由 `IPromptProvider` 在加载时做模板替换（实现细节在 §三）。

## 三、工具设计

工作模式的全部能力通过工具暴露给主 Agent。所有工具用 `AIFunctionFactory.Create` 创建，**强类型参数 + Description 特性**，AOT 安全。

### 3.1 计划工具（核心）

#### set_plan

```csharp
[Description("保存当前任务的工作计划。每次修改都要调用一次，覆盖旧计划。")]
public async Task<string> SetPlanAsync(
    [Description("任务 ID")] string taskId,
    [Description("计划主步骤列表，每个主步骤包含若干子步骤")] WorkPlan plan,
    CancellationToken ct = default)
{
    await _taskService.UpdatePlanAsync(taskId, plan, ct);
    _publisher.Publish(Events.OnWorkPlanUpdated, new WorkPlanUpdatedArgs(taskId, plan));
    return $"计划已保存：{plan.MainSteps.Count} 个主步骤，{plan.MainSteps.Sum(s => s.SubSteps.Count)} 个子步骤";
}

public sealed record WorkPlan(IReadOnlyList<WorkPlanMainStep> MainSteps);
public sealed record WorkPlanMainStep(string Title, IReadOnlyList<WorkPlanSubStep> SubSteps);
public sealed record WorkPlanSubStep(string Title, string AcceptanceCriteria);
```

> **AOT 注意**：`WorkPlan` 等 record 必须在 `JsonSerializerContext` 里注册（参考 Cortana 项目里 `WebSocketJsonContext` 的模式）。

#### get_plan

```csharp
[Description("读取当前任务的工作计划。")]
public async Task<WorkPlan?> GetPlanAsync(
    [Description("任务 ID")] string taskId,
    CancellationToken ct = default)
{
    var task = await _taskService.GetByIdAsync(taskId, ct);
    return task?.CurrentPlan;
}
```

### 3.2 计划加载工具（复用）

#### load_plan_from_template

```csharp
[Description("从工作流模板加载计划。模板是用户保存的可复用计划。")]
public async Task<WorkPlan?> LoadPlanFromTemplateAsync(
    [Description("模板名称或 ID（模糊匹配）")] string templateNameOrId,
    CancellationToken ct = default)
{
    var template = await _templateService.FindBestMatchAsync(templateNameOrId, ct);
    if (template is null) return null;

    await _templateService.IncrementUseCountAsync(template.Id, ct);
    return template.Plan;
}

[Description("列出可用的工作流模板。")]
public async Task<IReadOnlyList<WorkPlanTemplateSummary>> ListPlanTemplatesAsync(
    [Description("关键词过滤（可空，表示列全部）")] string? keyword,
    [Description("分类过滤（可空）")] string? category,
    CancellationToken ct = default)
{
    return await _templateService.SearchAsync(keyword, category, take: 20, ct);
}
```

#### load_plan_from_chat_history

```csharp
[Description("从专家模式（Chat 模式）的对话历史中提取执行计划。" +
             "适用于：用户在普通对话里讨论了某个工作，想直接转成可执行的工作计划。")]
public async Task<WorkPlan?> LoadPlanFromChatHistoryAsync(
    [Description("源对话 Session ID。空则用当前会话的最近一次专家模式对话。")] string? sourceSessionId,
    CancellationToken ct = default)
{
    sourceSessionId ??= await _sessionService.GetLatestChatSessionIdAsync(ct);
    if (sourceSessionId is null) return null;

    var messages = await _chatHistoryService.GetMessagesAsync(sourceSessionId, ct);
    if (messages.Count == 0) return null;

    // 用专门的 plan_extractor agent 提取
    var extractor = await _planExtractorBuilder.BuildAsync(ct);
    var prompt = FormatMessagesForExtraction(messages);
    var response = await extractor.RunAsync(
        new ChatMessage(ChatRole.User, prompt),
        cancellationToken: ct);

    return TryParsePlan(response.Messages.Last().Text);
}
```

#### load_plan_from_groupchat

类似 `load_plan_from_chat_history`，但源是 GroupChat 模式的会话（`OrchestrationMessage` 表里 GroupChat 子模式的对话）。

> **关键点**：`plan_extractor` 是另一个**动态构建**的 ChatClientAgent，提示词从 `IPromptProvider.GetPromptAsync("work_mode.plan_extractor")` 加载。这确保提示词调优不需要改代码。

### 3.3 子智能体派发（同步 vs 背景两种模式）

子智能体（"部门"）以工具形式注入到主智能体。工作模式提供**两种调用模式**，主智能体根据预期耗时选择。

#### 模式 A：同步调用（短任务）

复用 Cortana 现有的 `AIAgentFactory.BuildWithSubAgents` 机制——把子智能体包成同步 `AIFunction`，主智能体 await 等结果。

```csharp
// AIAgentFactory.BuildWithSubAgents 已有逻辑（无需新写）：
// foreach (var mention in mentions)
// {
//     var subAgent = BuildSubAgent(mention.Agent, ...);
//     var agentFunction = AIFunctionFactory.Create(InvokeAgentWithAttachmentsAsync, ...);
//     subAgentFunctions.Add(agentFunction);
// }
// 工具名形如 agent_<id>，主 Agent 直接 await 调用。
```

**适用条件**：

- 子智能体预期 < 30 秒完成
- 简单查询、信息整合、文本转换、格式化等
- 不涉及递归调用其他长任务工具

**风险**：如果子智能体内部不小心调了长工具或思考很久，主智能体会被阻塞，造成 AF Workflow superstep 不结束、Checkpoint 不写盘。

#### 模式 B：背景调用（长任务，[LONG] 工具）

通过 `IBackgroundJobExecutor`（详见 [16 文档 §八](./16-长任务可靠性与重试策略.md)）启动子智能体到主进程内 Task 中，立即返回 `sub_task_id`。主智能体后续主动 poll 进度。

```csharp
// 工具一：启动（每个 @ 提及的子智能体都生成一个 [LONG] start_subagent_<id> 工具）
[Description("[LONG] 启动子智能体「研究员」做长时间研究/分析。立即返回 sub_task_id，不等结果。")]
public async Task<string> StartResearcherSubAgentAsync(
    [Description("研究问题或任务描述")] string query,
    [Description("附件路径数组（可空）")] string[]? attachmentPaths,
    CancellationToken ct)
{
    var input = new SubAgentJobInput(
        AgentId: "researcher",
        Query: query,
        AttachmentPaths: attachmentPaths ?? []);

    return await _executor.StartAsync(new BackgroundJobStartRequest(
        TaskId: _currentTaskId,
        OwnerName: "研究员",
        InputJson: JsonSerializer.Serialize(input, WorkModeJsonContext.Default.SubAgentJobInput),
        Metadata: null), ct);
}

// 工具二：等待进度（通用，所有背景子智能体共用）
[Description(
    "[LONG] 等待背景子智能体的进展。最多等 max_seconds 秒（建议 30-60，不要超过 60）。" +
    "状态：running 表示还在跑（再调一次继续等），completed 拿 result，failed 拿 error。")]
public async Task<BackgroundJobStatus> WaitForSubAgentAsync(
    [Description("子智能体的 sub_task_id")] string subTaskId,
    [Description("最多等待秒数（30-60）")] int maxSeconds,
    CancellationToken ct)
{
    if (maxSeconds < 5) maxSeconds = 5;
    if (maxSeconds > 60) maxSeconds = 60;
    return await _executor.WaitAsync(subTaskId, TimeSpan.FromSeconds(maxSeconds), ct);
}

// 工具三：取消
[Description("[LONG] 取消一个背景子智能体。已经完成的不会撤销。")]
public Task CancelSubAgentAsync(
    [Description("子智能体的 sub_task_id")] string subTaskId,
    CancellationToken ct)
    => _executor.CancelAsync(subTaskId, ct);
```

**适用条件**：

- 子智能体预期超过 30 秒
- 涉及长工具调用（视频处理、批量数据分析、大量文件读写）
- 用户希望"启动这件事，主线继续做别的"

**优势**：

- 主智能体不被阻塞，可在 wait_for 之间穿插别的工具
- 每个 wait_for 自然形成 superstep 边界，Checkpoint 频繁落盘
- 应用崩溃时丢失最多 60 秒的子智能体决策，不丢已完成的工具产出

#### 模式选择规则（写入主智能体 Instructions）

```markdown
## 子智能体调用模式选择

每次需要调用子智能体（"部门"）时，先判断预期耗时：

- 短任务（< 30 秒，如简单格式转换、单次查询）→ 用 agent_<id>(args) 同步调用
- 长任务（>= 30 秒，如完整研究报告、批量处理）→ 用 [LONG] start_subagent_<id> + wait_for_subagent

判断不准时，**优先用背景模式**——背景模式对短任务也有效，只是多 1-2 秒开销。

不要：
- 在循环里反复 await 同步 agent_<id>（容易把整个工作流阻塞）
- 在 wait_for_subagent 里指定 max_seconds > 60（破坏 Checkpoint 节奏）
- 启动后忘记 wait/cancel（资源泄漏，DB 里残留 running 记录）
```

### 3.7 dispatch_parallel（并行派发，长任务必备）

工作模式不限于"一步一步串行"——网站开发的"前端开发"和"后端 API"完全可以并行做。提供 `dispatch_parallel` 工具：

```csharp
[Description(
    "并行派发多个独立的步骤给不同的部门智能体，所有结果同时返回。" +
    "用于：步骤之间没有依赖关系、可以同时进行。" +
    "如果步骤间有依赖（B 要用 A 的结果），用 dispatch_step 串行调用。")]
public async Task<IReadOnlyList<DispatchResult>> DispatchParallelAsync(
    [Description("任务 ID")] string taskId,
    [Description("要并行派发的步骤列表，每个含部门、标题、验收标准、上下文")]
        IReadOnlyList<DispatchTarget> targets,
    CancellationToken ct)
{
    // 1. 写日志：并行块开始
    var blockId = Guid.NewGuid().ToString("N")[..8];
    await _logService.AppendAsync(taskId, new WorkExecutionLog
    {
        LogType = WorkExecutionLogType.ParallelBlockStart,
        Content = JsonSerializer.Serialize(
            new ParallelBlockStartRecord(blockId, [.. targets.Select(t => t.StepTitle)]),
            WorkModeJsonContext.Default.ParallelBlockStartRecord),
    }, ct);

    _publisher.Publish(Events.OnWorkParallelBlockStart,
        new WorkParallelBlockStartArgs(taskId, blockId, [.. targets.Select(t => t.StepTitle)]));

    // 2. 并行调用所有目标
    var results = await Task.WhenAll(
        targets.Select(t => DispatchOneAsync(taskId, blockId, t, ct)));

    // 3. 写日志：并行块结束
    await _logService.AppendAsync(taskId, new WorkExecutionLog
    {
        LogType = WorkExecutionLogType.ParallelBlockEnd,
        Content = JsonSerializer.Serialize(
            new ParallelBlockEndRecord(blockId, results.Length, results.Count(r => r.Success)),
            WorkModeJsonContext.Default.ParallelBlockEndRecord),
    }, ct);

    return results;
}

public sealed record DispatchTarget(
    string Department,
    string StepTitle,
    string AcceptanceCriteria,
    string Context);

public sealed record DispatchResult(
    string StepTitle,
    bool Success,
    string Output,
    string? Error);
```

在提示词里加入并行使用规则：

```markdown
## 并行派发使用规则

**何时用 dispatch_parallel**：

- 多个步骤之间没有数据依赖（B 不需要 A 的结果）
```

### 3.9 嵌套子工作流（深度任务）

像"网站开发→实现登录功能"这种深度场景，子步骤本身又是一个完整工作流。用 AF 的 `Workflow.AsAIAgent()` 实现嵌套：

```csharp
[Description(
    "对一个复杂的子步骤，启动一个嵌套子工作流来分解执行。" +
    "嵌套子工作流有自己的总经理 Agent、自己的计划、自己的子步骤。" +
    "用于：单个子步骤本身需要多步细粒度操作（如\"实现登录功能\"内部含设计 API、写代码、测试等）。")]
public async Task<string> DispatchNestedWorkflowAsync(
    [Description("父任务 ID")] string parentTaskId,
    [Description("嵌套子任务的目标")] string nestedGoal,
    [Description("嵌套子任务的验收标准")] string acceptanceCriteria,
    CancellationToken ct)
{
    // 1. 创建子任务（指向父任务）
    var nestedTaskId = Guid.NewGuid().ToString("N");
    await _taskService.CreateNestedAsync(parentTaskId, nestedTaskId, nestedGoal, ct);

    // 2. 构建嵌套总经理 Agent（用同一份提示词，复用 GeneralManagerAgentBuilder）
    var parentTask = await _taskService.GetByIdAsync(parentTaskId, ct);
    var nestedManager = await _generalManagerBuilder.BuildAsync(
        nestedTaskId, parentTask.Provider, parentTask.Model, parentTask.Agent,
        parentTask.Mentions, ct);

    // 3. 包装成嵌套 Workflow，转为 AIAgent
    var nestedWorkflow = AgentWorkflowBuilder.BuildSequential(nestedManager);
    var nestedAgent = nestedWorkflow.AsAIAgent(
        name: $"嵌套子工作流-{nestedGoal[..Math.Min(20, nestedGoal.Length)]}",
        description: nestedGoal);

    // 4. 调用嵌套 Agent（同步等待最终结果）
    var msg = new ChatMessage(ChatRole.User,
        $"目标：{nestedGoal}\n验收标准：{acceptanceCriteria}");
    var response = await nestedAgent.RunAsync([msg], cancellationToken: ct);

    // 5. 返回最终产出（嵌套子工作流的 final_report 内容）
    return response.Messages.Last().Text ?? "";
}
```

## 四、Workflow 包装与 HITL

### 4.1 为什么要包装成 Workflow

虽然主 Agent 是单个 `ChatClientAgent`，但我们要把它包装成 `Workflow`，**为了拿到 AF 框架自带的 Checkpoint 和 RequestInfoEvent 能力**：

```csharp
// 单 Agent → Workflow（用 AF 内置的 Sequential Builder，最简方式）
var workflow = AgentWorkflowBuilder.BuildSequential(generalManagerAgent);
```

这样工作模式自动获得：

- **Checkpoint**：每个 superstep 自动保存 → 应用重启可恢复
- **RequestInfoEvent**：`ask_user` / `ApprovalRequiredAIFunction` 触发后自然暂停
- **事件流**：所有过程通过 `WorkflowEvent` 暴露

### 4.2 Checkpoint 存储（自定义 ICheckpointStore）

AF 提供 `JsonCheckpointStore` 抽象类（见 04 文档 §2.2）。我们实现一个 SQLite 后端：

```csharp
namespace Netor.Cortana.AI.WorkMode.Checkpointing;

/// <summary>
/// SQLite 实现的 ICheckpointStore，把 Workflow Checkpoint 存到 WorkflowCheckpoints 表。
/// </summary>
public sealed class SqliteCheckpointStore : JsonCheckpointStore
{
    private readonly CortanaDbContext _db;

    public SqliteCheckpointStore(CortanaDbContext db) => _db = db;

    protected override Task<JsonElement?> LoadAsync(string key, CancellationToken ct)
    {
        var json = _db.ExecuteScalar<string>(
            "SELECT Payload FROM WorkflowCheckpoints WHERE [Key] = @Key",
            cmd => cmd.Parameters.AddWithValue("@Key", key));

        if (string.IsNullOrEmpty(json)) return Task.FromResult<JsonElement?>(null);

        using var doc = JsonDocument.Parse(json);
        return Task.FromResult<JsonElement?>(doc.RootElement.Clone());
    }

    protected override Task SaveAsync(string key, JsonElement value, CancellationToken ct)
    {
        var json = value.GetRawText();
        var now = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
        _db.Execute("""
            INSERT INTO WorkflowCheckpoints ([Key], Payload, UpdatedAt) VALUES (@Key, @Payload, @UpdatedAt)
            ON CONFLICT([Key]) DO UPDATE SET Payload = excluded.Payload, UpdatedAt = excluded.UpdatedAt;
            """, cmd =>
        {
            cmd.Parameters.AddWithValue("@Key", key);
            cmd.Parameters.AddWithValue("@Payload", json);
            cmd.Parameters.AddWithValue("@UpdatedAt", now);
        });
        return Task.CompletedTask;
    }
}
```

> 表结构见 [10-数据模型与持久化设计.md](./10-数据模型与持久化设计.md) §三。

### 5.4 恢复

```csharp
public async Task ResumeAsync(string taskId, string? userResponse, CancellationToken ct)
{
    var task = await _taskService.GetByIdAsync(taskId, ct);
    if (string.IsNullOrEmpty(task.RunId))
        throw new InvalidOperationException("任务没有 RunId，无法恢复");

    var workflow = await BuildWorkflowAsync(task, ct);
    var run = await InProcessExecution.ResumeAsync(
        workflow, task.RunId,
        new RunOptions { CheckpointManager = new CheckpointManager(_checkpointStore) },
        cancellationToken: ct);

    // 如果是回应 HITL 请求（ask_user / ApprovalRequest）
    if (userResponse is not null)
    {
        var pending = await _hitlService.GetPendingRequestAsync(taskId, ct);
        if (pending is not null)
        {
            await run.SendResponseAsync(pending.CreateResponse(userResponse));
            await _hitlService.ClearPendingRequestAsync(taskId, ct);
        }
    }

    // 继续监听事件
    await foreach (var evt in run.WatchAsync().WithCancellation(ct))
    {
        await _eventDispatcher.HandleAsync(taskId, evt, ct);
        if (evt is WorkflowOutputEvent or WorkflowErrorEvent) break;
        if (evt is RequestInfoEvent reqEvt2)
        {
            await _hitlService.PersistPendingRequestAsync(taskId, run.RunId, reqEvt2.Request, ct);
            break;
        }
    }
}
```

### 5.5 状态语义对齐

**AF Workflow 的状态是唯一真相**，Cortana 端不维护独立的复杂状态机：

| AF Workflow 状态 | Cortana 端表示 |
|------------------|---------------|
| Running（事件流活跃） | `WorkTasks.IsActive = 1` |
| Idle（HITL 暂停，等响应） | `WorkTasks.IsActive = 1` + `WorkTasks.PendingRequestId != null` |
| Completed（产出 WorkflowOutputEvent） | `IsActive = 0` + `CompletedAt != null` |
| Failed（产出 WorkflowErrorEvent） | `IsActive = 0` + `ErrorMessage != null` |

> **不要**再设计 `Clarifying / Planning / Executing` 这种语义状态——这些应当由"主 Agent 的对话历史"表达，不应作为外部状态机字段。
