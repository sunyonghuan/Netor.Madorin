# 06 - 事件系统与通信

> 事件流是连接"无状态服务端"与"长任务"和"实时 UI"的关键

## 一、事件系统总览

### 1.1 事件基类层次

```
WorkflowEvent (abstract)
├── ExecutorEvent (executor 范围事件)
│   ├── ExecutorInvokedEvent       — 执行器开始
│   ├── ExecutorCompletedEvent     — 执行器完成
│   └── ExecutorFailedEvent        — 执行器失败
├── SuperStepEvent                  — Pregel/BSP 超步事件
├── WorkflowStartedEvent            — 工作流启动
├── WorkflowOutputEvent             — 工作流输出
├── WorkflowErrorEvent              — 工作流错误
├── WorkflowWarningEvent            — 警告
├── AgentResponseEvent              — 智能体完整响应
├── AgentResponseUpdateEvent        — 智能体流式增量
├── RequestInfoEvent                — 请求外部信息（HITL/审批）
└── Magentic 专有
    ├── MagenticPlanEvent
    ├── MagenticProgressEvent
    └── MagenticReplanEvent
```

### 1.2 事件流接口

```csharp
public interface IRunEventStream
{
    void Start();
    void SignalInput();                        // 新输入到达
    Task StopAsync();
    Task<RunStatus> GetStatusAsync();
    IAsyncEnumerable<WorkflowEvent> TakeEventStreamAsync(
        bool blockOnPendingRequest = false);
}
```

### 1.3 实现：`StreamingRunEventStream`

源码：`src\Microsoft.Agents.AI.Workflows\Execution\StreamingRunEventStream.cs`

- 基于 `System.Threading.Channels` 的无界 channel
- 后台 run-loop 推进 superstep
- 支持从 checkpoint 恢复，自动重发挂起请求
- 集成 `Activity`（OpenTelemetry）

## 二、关键事件详解

### 2.1 `AgentResponseUpdateEvent`（流式增量）

```csharp
public sealed class AgentResponseUpdateEvent : WorkflowEvent
{
    public string ExecutorId { get; }
```

**用途**：把模型流式 Token 转发给前端。

### 2.2 `RequestInfoEvent`（外部输入请求）

```csharp
public sealed class RequestInfoEvent : WorkflowEvent
{
    public RequestInfo Request { get; }
}

public sealed class RequestInfo
{
    public string RequestId { get; }       // 用于配对响应
    public string ExecutorId { get; }
    public object Data { get; }            // ToolApprovalRequestContent / 自定义

    public bool TryGetDataAs<T>(out T? data);
    public RequestResponse CreateResponse(object responseData);
}
```

**用途**：
- 工具授权（`ToolApprovalRequestContent`）
- 业务确认（自定义类型）
- 信息补全（询问用户参数）

### 2.3 `RequestResponse`（回应外部输入）

```csharp
// 客户端拿到 RequestInfo 后处理，通过 run 发送回应
await run.SendResponseAsync(request.CreateResponse(myData));
```

### 2.4 Magentic 专有事件

```csharp
// 计划生成时
public sealed class MagenticPlanEvent : WorkflowEvent
{
    public string Plan { get; }           // 文本形式的执行计划
}

// 每轮进度更新
public sealed class MagenticProgressEvent : WorkflowEvent
{
    public string Ledger { get; }          // 进度账本（JSON / 文本）
}

// 检测到卡住，重新规划
public sealed class MagenticReplanEvent : WorkflowEvent
{
    public string Reason { get; }
    public string NewPlan { get; }
}
```

**用途**：让前端实时显示"老板视角"的：计划 / 进展 / 重规划。

## 三、客户端消费模式

### 3.1 服务端 SSE 转发

```csharp
[HttpGet("/tasks/{taskId}/events")]
public async Task Stream(string taskId, CancellationToken ct)
{
    Response.ContentType = "text/event-stream";

    var run = await InProcessExecution.ResumeAsync(workflow, taskId, checkpointStore);

    await foreach (var evt in run.WatchAsync().WithCancellation(ct))
    {
        var json = JsonSerializer.Serialize(new
        {
            type = evt.GetType().Name,
            data = evt
        });

        await Response.WriteAsync($"event: {evt.GetType().Name}\n");
        await Response.WriteAsync($"data: {json}\n\n");
        await Response.Body.FlushAsync(ct);

        if (evt is WorkflowOutputEvent or WorkflowErrorEvent) break;
    }
}
```

### 3.2 客户端 SSE 消费

```typescript
const es = new EventSource(`/tasks/${taskId}/events`);

es.addEventListener('MagenticPlanEvent', (e) => {
  const evt = JSON.parse(e.data);
  showPlanUI(evt.data.plan);
});

es.addEventListener('AgentResponseUpdateEvent', (e) => {
  const evt = JSON.parse(e.data);
  appendStreamingText(evt.data.update);
});

es.addEventListener('RequestInfoEvent', (e) => {
  const evt = JSON.parse(e.data);
  showApprovalDialog(evt.data.request);
});
```

### 3.3 WebSocket 双向

```csharp
// 服务端
[WebSocketRoute("/ws/tasks/{taskId}")]
public async Task WebSocket(WebSocket socket, string taskId)
{
    var run = await InProcessExecution.ResumeAsync(workflow, taskId, checkpointStore);

    // 转发事件给客户端
    var forwardTask = Task.Run(async () =>
    {
        await foreach (var evt in run.WatchAsync())
        {
            await socket.SendJsonAsync(evt);
        }
    });

    // 接收客户端响应（用于 RequestInfoEvent 的回应）
    while (socket.State == WebSocketState.Open)
    {
        var msg = await socket.ReceiveJsonAsync<ClientMessage>();
        if (msg.Type == "approval_response")
        {
            await run.SendResponseAsync(
                msg.RequestId,
                new ToolApprovalResponseContent(msg.Approved));
        }
    }
}
```

## 四、A2A 协议（跨进程智能体通信）

### 4.1 用途
让不同进程/服务器/语言的智能体能"互相调用"。

### 4.2 客户端（调用远端智能体）

源码：`src\Microsoft.Agents.AI.A2A\A2AAgent.cs`

```csharp
// 远端智能体的 AgentCard（描述符）
var resolver = new A2ACardResolver(new Uri("https://other-service/.well-known/agent.json"));
var card = await resolver.GetAgentCardAsync();

// 创建本地代理
AIAgent remoteAgent = card.AsAIAgent();

// 像本地智能体一样调用
var response = await remoteAgent.RunAsync("帮我处理这个");
```

### 4.3 暴露为远端智能体（服务端）

```csharp
// Program.cs
builder.Services.AddAIAgent("Worker", instructions, chatClient);

var app = builder.Build();

// 暴露 A2A 端点
app.MapA2AAgent("/agents/worker", "Worker");

app.Run();
```

### 4.4 协议特性
- **基于 HTTP/JSON**
- **支持流式响应（SSE）**
- **支持长时间任务**（taskId + 轮询/重连）
- **上下文延续**（contextId）

### 4.5 关键源码
- `src\Microsoft.Agents.AI.A2A\`
- `src\Microsoft.Agents.AI.Hosting.A2A.AspNetCore\`
- 示例：`samples\02-agents\A2A\`（4 个）

### 4.6 Cortana 集成场景
```
┌─────────────────┐         A2A           ┌────────────────┐
│  Cortana 主程序  │ ────────────────────→ │  视觉模型进程   │
│  (总经理)        │ ←──────────────────── │  (员工)        │
└─────────────────┘                       └────────────────┘
       │                                          
       │  A2A                                     
       ▼                                          
┌─────────────────┐                               
│  语音服务进程    │                               
│  (员工)         │                               
└─────────────────┘                               
```

这样 Cortana 已规划的"语音服务独立进程"、"视觉模型功能接入"都可以用 A2A 编排。

## 五、声明式工作流（YAML）

### 5.1 用途
让非开发者也能定义编排，或动态加载工作流。

### 5.2 示例（概念）

```yaml
# 总经理工作流
kind: workflow
name: general-manager-flow
description: 老板提需求，总经理协调部门完成

start: planning

steps:
  planning:
    agent: PlannerAgent
    inputs: [user_request]
    outputs: [plan]
    next: dispatch

  dispatch:
    type: handoff
    targets:
      - { agent: SalesDept, condition: "plan.domain == 'sales'" }
      - { agent: TechDept,  condition: "plan.domain == 'tech'"  }
      - { agent: HRDept,    condition: "plan.domain == 'hr'"    }
    next: verify

  verify:
    agent: VerifierAgent
    inputs: [output]
    on_pass: report
    on_fail: planning  # 退回重新规划

  report:
    agent: ReporterAgent
    inputs: [output]
    outputs: [final_report]
```

### 5.3 关键源码
- `src\Microsoft.Agents.AI.Workflows.Declarative\`
- `src\Microsoft.Agents.AI.Workflows.Declarative.Foundry\`

### 5.4 Power Fx 表达式
框架嵌入了 Microsoft Power Fx 引擎，YAML 中可以写表达式（与 Excel 兼容）。

## 八、通信架构推荐（Cortana 落地）

### 8.1 三层通信

```
┌──────────────────────────────────────────────────────┐
│ Layer 3: Client ←→ Cortana 主程序                     │
│   - SSE / WebSocket（双向）                            │
│   - 用于：流式响应 / 审批 / 进度展示                    │
└──────────────────────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│ Layer 2: Cortana 主程序内 Workflow                    │
│   - IRunEventStream                                    │
│   - WorkflowEvent                                      │
│   - 用于：总经理 ↔ 部门 / 部门 ↔ 员工                  │
└──────────────────────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│ Layer 1: 主程序 ↔ 独立进程（语音/视觉/计算）           │
│   - A2A 协议                                           │
│   - 用于：跨进程的"远端员工"                            │
└──────────────────────────────────────────────────────┘
```
