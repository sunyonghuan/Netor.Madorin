# 14 - 实施路线图与验收标准

> 工作模式分阶段开发计划、阶段验收标准、风险与应对
>
> **核心**：基于 ChatClientAgent + AF Workflow + 已有 UI 控件，AOT 安全交付

---

## 0. 通用实施原则（所有阶段都要遵守）

### 0.1 演示代码"晚清理"原则

`WorkModeView.axaml.cs` 当前的 `LoadDemoConversation()` 及相关辅助方法（`MakeThinkCard` / `MakeToolCard` / `MakeAcceptanceCard` / `MakeArchiveCard` / `MakeSubStepCompleted` / `MakeContentBlock`）以及 `ApprovalPopup.DecisionMade` 演示订阅 — 这些代码生成的界面布局是**当前最满意的视觉基线**。

**原则**：

- **阶段 0-5 不删除任何演示代码**。可以注释掉调用入口（让默认不再加载演示数据），但**保留方法本体**作为死代码。
- 演示代码的作用：每次新增功能时，可以临时切回演示模式对照视觉效果是否一致，作为视觉回归测试。
- 集中清理推迟到**阶段 6**，且需要先用真实任务跑一遍确认 `WorkModeViewController` 的输出与演示数据视觉一致后再清理。
- 清理时由项目维护者选择策略（删除 / 独立文件 / `#if DEBUG`），文档不强制方案。

**禁止行为**：

- 任何阶段直接删除 `LoadDemoConversation` 或其辅助方法
- 删除已有控件的事件订阅（即使现在不用，未来真实链路可能需要相同的事件接入点）

### 0.2 AOT 安全前置

每个阶段完成后必须跑一次 `dotnet publish -c Release -p:PublishAot=true`，新引入的反射或不安全调用必须在当前阶段消化掉，不能留到阶段 6 集中处理。

### 0.3 现有代码扩展前置写测试

修改 `AIAgentFactory.Build` / `BuildWithSubAgents` / `AiChatHostedService` 等共享代码前，先写覆盖现有路径的单元测试，避免影响专家模式 / 群聊模式。

## 一、实施总览

| # | 阶段 | 时长 | 里程碑 |
|---|------|------|--------|
| 0 | 数据层与基础设施 | 1 周 | 数据库（含 `WorkBackgroundJobs`）/ 提示词 / 路由骨架就绪 / `FailureClassifier` + `IBackgroundJobExecutor` 接口 |
| 1 | 主 Agent + 计划生成 + 工具重试 | 2 周 | 用户能与总经理对话、看到生成的计划；瞬时失败自动重试 |
| 2 | MVP 执行链路 + 自评循环 | 2.5 周 | 计划确认后跑出第一个完整任务，含子智能体（同步）派发、`self_evaluate` 自评、心跳 |
| 3 | HITL + 软抢占 + 崩溃恢复 | 1.5 周 | 工具授权、ask_user、`TaskResumePromptCard`、软抢占识别 |
| 4 | 计划复用 + 长任务编排 | 2.5 周 | 模板/从对话提取、`dispatch_parallel`、嵌套子工作流、**子智能体背景执行框架**（[16 文档 §八](./16-长任务可靠性与重试策略.md)） |
| 5 | 死循环检测 + 体验完善 | 1.5 周 | `DeadlockDetector`、左侧任务列表、错误展示 |
| 6 | AOT 验收 + 演示代码清理 | 0.5 周 | AOT 编译通过、关键路径压测、统一清理演示代码 |

**总计**：约 11.5 周（约 2.5 个月）

> 阶段 4 是 v1.0 最复杂的阶段（长任务编排集大成），其他阶段时长保持稳定。

### 6.3 风险

| 风险 | 应对 |
|------|------|
| AI 提取的 JSON 格式不稳定 | 用 Structured Output（如 OpenAI `response_format`）；模型不支持时降级用正则 + JsonNode 容错 |
| 模板搜索"模糊匹配"不准 | 阶段 4 用 LIKE，v1.1 引入向量检索 |
| AI 误用同步 `agent_<id>` 调用长任务子智能体导致阻塞 | 提示词强约束 + 子智能体类型上元数据标记（`Agents.Description` 含"长时间"等关键词时强制走背景） |
| 并行派发时 UI 列宽自适应问题 | 复用现有 `Grid` 自适应；窄屏降级竖向堆叠（[09 文档 §11.2](./09-界面交互设计.md)） |
| 嵌套子工作流递归过深 | 运行时检查 `ParentTaskId` 链长度，超过 2 直接报错给 AI |
| `IBackgroundJobExecutor` 实现里的 Task 未捕获异常 | 顶层 try/catch + `MarkFailedAsync`，`Dispose` 时取消所有 _running |

## 十一、后续迭代（v1.1+）

阶段 0-6 完成后，进入维护与迭代：

| 版本 | 时间 | 目标 |
|------|------|------|
| v1.1 | 完成后 1 个月 | **WS 广播**：所有 `work.*` 事件通过 WebSocket 推给插件（仿专家模式 conversation 事件机制），让"记忆插件"等订阅 |
