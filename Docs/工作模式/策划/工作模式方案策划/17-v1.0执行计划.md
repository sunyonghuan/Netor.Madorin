# Cortana 工作模式 v1.0 执行计划

## Context

Cortana 项目的工作模式（Work Mode）UI 控件已就绪、文档体系（09-16 共 7 篇）已定稿，现在需要进入代码实施阶段。本计划基于已经定稿的全部架构决策，给出 7 个阶段的具体落地步骤、文件路径、复用点和验收标准。

**核心架构**（已落定）：

- 一人公司模式，主智能体是普通 `ChatClientAgent`（非 Magentic），通过 `[LONG]` 命名约定的工具集驱动
- AOT 安全是基础规范（无反射 / 无 Binding / 全部走 JsonSerializerContext 源生成）
- 长任务编排分两层：插件自治（已有）+ 主软件托管（新建 `IBackgroundJobExecutor` 框架）
- AF Workflow 状态作为唯一真相，Cortana 端只用 `IsActive` 布尔字段
- 用户插话用输入队列（软抢占）+ HITL（不取消 Workflow）

**关键既有能力**（从探索阶段确认）：

- AF v1.7.0 已引用，含 `Microsoft.Agents.AI.Workflows`
- `ChatHistoryDataProvider.AppendAssistantMessageAsync` 已存在（[Providers/ChatHistoryDataProvider.cs:291](e:/Netor.me/Cortana/Src/Netor.Cortana.AI/Providers/ChatHistoryDataProvider.cs#L291)）
- `WorkflowCheckpoints` 表已建好但**无代码引用**（[CortanaDbContext.cs:432](e:/Netor.me/Cortana/Src/Netor.Cortana.Entitys/CortanaDbContext.cs#L432)），可直接服务 AF `ICheckpointStore`
- 插件 `[LONG]` 模式已有典范：`PowerShellProvider` + `SessionRegistry`（[BuiltIn/PowerShell/](e:/Netor.me/Cortana/Src/Netor.Cortana.Plugin/BuiltIn/PowerShell/)）
- `AIAgentFactory` 三个 `Build*` 方法[AIAgentFactory.cs:135/197/579](e:/Netor.me/Cortana/Src/Netor.Cortana.AI/AIAgentFactory.cs#L135) 待扩展 `additionalTools`

## 风险与应对

| 风险 | 严重度 | 应对 |
|---|---|---|
| 提示词调优不达预期 | 高 | 每阶段尾留 1-2 天调优；用户验收回调闭环 |
| AF Workflow 单 Agent 包装行为偏离预期 | 中 | 阶段 0 末提前跑 sample 验证 |
| `ApprovalRequiredAIFunction` 集成问题 | 中 | 阶段 3 开始前用 sample 验证 |
| AOT 编译报反射警告无法消除 | 中 | 阶段 0 起每次 PR 都跑 AOT 检查 |
| `BuildWithSubAgents` 加 `additionalTools` 破坏现有功能 | 中 | 加默认值 null；写覆盖单测；先在 dev 分支验证不影响专家模式 |
| UI 控件性能问题（大量卡片） | 低 | 阶段 5 末压测；超阈值改虚拟化 |
| 子智能体背景 Task 未捕获异常导致主进程崩溃 | 中 | 顶层 try/catch + `MarkFailedAsync`；`Dispose` 取消所有 _running |
| AF Run "继续输入"机制不明确 | 中 | 阶段 0 验证；不可行则改用每次新建 Run + ChatHistoryProvider 共享上下文 |

## 不在 v1.0 范围（v1.1+ 路线）

- WS 广播 work.* 事件给插件（仿 conversation 桥接）
- 远程提示词加载（`RemotePromptProvider`）
- 模板向量检索
- 自定义部门智能体（用户在工作模式 Tab 内创建）
- 长操作"轮询型工具"模式（参考 `BackgroundAgentsProvider`）
- 任务衍生任务（链式创建）

明确不做：

- 多用户/多角色审批链
- 审批转发/IM 集成
- 团队协作（多人共享任务）
- 任务族（多活跃任务并存）
- 长任务硬抢占
