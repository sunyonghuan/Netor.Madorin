# 12 - 输入路由与任务调度设计

> 用户输入如何被分发到普通对话 / 新任务 / 活跃任务的不同处理路径
>
> **核心**：依赖 AF Workflow 自身状态作为真相，路由器只做"分发"不做"状态机"

---

## 一、为什么没有"状态机"

上一版本设计了 `WorkTaskStatus { Idle / Clarifying / Planning / PlanReview / Executing / Paused ...}`，这是错误设计：

| 旧设计假设 | 实际情况 |
|----------|---------|
| 我们能精确知道 AI 处于哪个阶段 | AI 的对话进度是"软"状态，由提示词引导，没有硬切换点 |
| 状态切换由代码触发 | 状态切换由 AI 自己决定（调用 `set_plan` / `dispatch_*` / `final_report` 工具） |
| 用户输入要按状态分类处理 | 不需要——交给 AI 通过对话历史判断 |
| 暂停用 CTS 取消 | 错误，CTS 取消 = Workflow Failed，无法 Resume |

**新方案**：

- AF Workflow 状态（`Running` / `Idle (HITL等待)` / `Completed` / `Failed`）是**唯一真相**
- Cortana 端只用一个布尔字段 `WorkTasks.IsActive` 区分"任务还活着 vs 已经结束"
- `PendingRequestId IS NOT NULL` 表示"任务挂在 HITL 上等用户回应"
- 所有"现在是不是该追问需求 / 该生成计划 / 该开始执行"的判断**由 AI 自己做**（提示词约束）

路由器只做一件事：**根据当前会话的活跃任务情况决定调用哪个执行器**。

## 二、路由决策树

```text
用户在 WorkModeView 提交输入
  ↓
WorkModeInputRouter.RouteAsync(sessionId, userInput)
  ↓
查询 WorkTasks WHERE SessionId=? AND IsActive=1 ORDER BY LastActiveAt DESC LIMIT 1
  ↓
┌─ 命中活跃任务?
│
├─ 是 ─→ 任务有 PendingRequestId?
│         │
│         ├─ 是（HITL 等待中） ─→ WorkflowExecutor.ResumeAsync(taskId, userInput)
│         │                       └─ 把用户输入作为 RequestResponse 提交给 Workflow
│         │
│         └─ 否（执行中） ─→ WorkflowExecutor.EnqueueUserInputAsync(taskId, userInput)
│                            └─ 写入 WorkPendingInputs 队列
│                            └─ 主 Agent 在下次决策点通过 check_pending_user_input 工具消费
│
└─ 否（无活跃任务） ─→ IntentClassifier.ClassifyAsync(userInput)
                        │
                        ├─ NewTask ─→ 创建 WorkTasks 记录 → WorkflowExecutor.ExecuteAsync(taskId, userInput)
                        │
                        └─ NormalChat ─→ IAiChatEngine.SendMessageAsync(userInput)
                                          └─ 走专家模式现有路径（不创建任务）
```

## 三、WorkModeInputRouter

### 3.1 接口

```csharp
namespace Netor.Cortana.AI.WorkMode;

public interface IWorkModeInputRouter
{
    Task RouteAsync(string userInput, CancellationToken ct = default);
}
```

### 3.2 实现

```csharp
public sealed class WorkModeInputRouter : IWorkModeInputRouter
{
    private readonly WorkTaskService _taskService;
    private readonly IWorkflowExecutor _executor;
    private readonly IIntentClassifier _intentClassifier;
    private readonly IAiChatEngine _chatEngine;
    private readonly ChatHistoryDataProvider _chatHistory;
    private readonly ICurrentSessionResolver _sessionResolver; // 拿当前 ChatSession.Id
    private readonly IPublisher _publisher;
    private readonly ILogger<WorkModeInputRouter> _logger;

    public async Task RouteAsync(string userInput, CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(userInput)) return;

        var sessionId = await _sessionResolver.GetCurrentSessionIdAsync(ct);

        // 用户输入先写入 ChatMessages（与专家模式一致，AI 能看到)
        // 注意：不要重复写入——如果走 NewTask 路径，由 ExecuteAsync 内部统一写
        // 这里仅在"非新任务"路径写入
        var activeTask = await _taskService.GetActiveTaskAsync(sessionId, ct);

        if (activeTask is not null)
        {
            // 路径 A / B：有活跃任务
            await HandleActiveTaskAsync(activeTask, userInput, ct);
            return;
        }

        // 路径 C / D：无活跃任务
        var intent = await _intentClassifier.ClassifyAsync(userInput, ct);
        if (intent == UserIntent.NewTask)
        {
            await CreateAndExecuteNewTaskAsync(sessionId, userInput, ct);
        }
        else
        {
            // 普通对话：直接走专家模式引擎（用户消息会被它写入 ChatMessages）
            await _chatEngine.SendMessageAsync(userInput, ct);
        }
    }

    private async Task HandleActiveTaskAsync(WorkTask task, string userInput, CancellationToken ct)
    {
        // 把用户消息写入 ChatMessages（让对话历史完整）
        await _chatHistory.AppendUserMessageAsync(task.SessionId, userInput, ct);

        if (!string.IsNullOrEmpty(task.PendingRequestId))
        {
            // 路径 A：任务挂在 HITL 上，把输入作为响应提交
            _logger.LogInformation(
                "Task {TaskId} resumed with pending request {RequestId}",
                task.Id, task.PendingRequestId);
            await _executor.ResumeAsync(task.Id, userInput, ct);
            return;
        }

        // 路径 B：任务正在执行（Workflow 还在跑）
        // 区分软抢占 vs 普通插话
        var isPreempt = IsSoftPreemption(userInput);

        await _executor.EnqueueUserInputAsync(task.Id, userInput, ct);

        if (isPreempt)
        {
            // 软抢占：标记任务有"高优先级"输入待处理
            // 总经理 Agent 在每次工具调用结束（不等下一个主步骤开始）就检查 check_pending_user_input
            await _taskService.SetPreemptionFlagAsync(task.Id, true, ct);
            _publisher.Publish(Events.OnWorkPreemptRequested,
                new WorkPreemptRequestedArgs(task.Id, userInput));

            _logger.LogInformation(
                "Task {TaskId} received soft-preempt input: {Input}",
                task.Id, userInput);
        }
        else
        {
            _logger.LogInformation(
                "Task {TaskId} received user input mid-execution, enqueued",
                task.Id);
        }
    }

    /// <summary>
    /// 软抢占识别：用户的输入是否要求 AI 立即停下当前动作。
    /// 命中关键词时返回 true。
    /// </summary>
    private static bool IsSoftPreemption(string input)
    {
        // 中文关键词
        ReadOnlySpan<string> ZhPreemptKeywords = new[]
        {
            "立刻", "马上", "立即", "赶紧", "紧急",
            "别管", "停下", "停一下", "暂停", "等等",
            "不用做", "不要做", "先不要", "改方向",
            "回滚", "撤销", "取消",
        };

        foreach (var k in ZhPreemptKeywords)
        {
            if (input.Contains(k, StringComparison.Ordinal)) return true;
        }
        return false;
    }

    private async Task CreateAndExecuteNewTaskAsync(string sessionId, string userInput, CancellationToken ct)
    {
        var taskId = Guid.NewGuid().ToString("N");
        var workspace = await _sessionResolver.GetCurrentWorkspaceIdAsync(ct);
        var (provider, model, agent, mentions) = await _sessionResolver.GetCurrentAgentContextAsync(ct);

        var sourceTaskId = await _taskService.GetMostRecentCompletedTaskIdAsync(sessionId, ct);

        var task = new WorkTask
        {
            Id = taskId,
            SessionId = sessionId,
            WorkspaceId = workspace,
            Title = "",                          // 后续由 AI 调用 set_plan 时回填
            InitialInput = userInput,
            IsActive = true,
            Provider = provider.Id,
            Model = model.Id,
            AgentId = agent.Id,
            MentionsJson = SerializeMentions(mentions),
            SourceTaskId = sourceTaskId,
            CreatedAt = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds(),
            UpdatedAt = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds(),
            LastActiveAt = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds(),
        };

        await _taskService.CreateAsync(task, ct);
        await _chatHistory.AppendUserMessageAsync(sessionId, userInput, ct);

        _publisher.Publish(Events.OnWorkTaskCreated, new WorkTaskCreatedArgs(taskId, sessionId));

        // 异步启动执行（不阻塞当前调用，让 UI 即时返回）
        _ = Task.Run(async () =>
        {
            try
            {
                await _executor.ExecuteAsync(taskId, userInput, CancellationToken.None);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Background execution failed for task {TaskId}", taskId);
                await _taskService.MarkFailedAsync(taskId, ex.Message, CancellationToken.None);
            }
        });
    }

    private static string SerializeMentions(IReadOnlyList<AgentMention> mentions)
    {
        var dto = mentions.Select(m => new AgentMentionDto(m.Agent.Id, m.Agent.Name)).ToList();
        return JsonSerializer.Serialize(
            (IReadOnlyList<AgentMentionDto>)dto,
            WorkModeJsonContext.Default.IReadOnlyListAgentMentionDto);
    }
}

public sealed record AgentMentionDto(string AgentId, string AgentName);
```

### 3.3 ICurrentSessionResolver（新建）

路由器需要知道"当前 SessionId / Workspace / 选中的 Provider/Model/Agent / @ 的子智能体"。这些信息现在散落在 `AiChatHostedService` 的私有字段里。

新建一个轻量解析器，把这些信息暴露出来：

```csharp
public interface ICurrentSessionResolver
{
    Task<string> GetCurrentSessionIdAsync(CancellationToken ct);
    Task<string> GetCurrentWorkspaceIdAsync(CancellationToken ct);
    Task<(AiProviderEntity Provider, AiModelEntity Model, AgentEntity Agent, IReadOnlyList<AgentMention> Mentions)>
        GetCurrentAgentContextAsync(CancellationToken ct);
}
```

实现类可以：

- 通过 `AiChatHostedService` 暴露的（新增的）公共属性读取
- 或独立维护当前选中状态（订阅 `Events.OnAiProviderChange / OnAiModelChange / OnAgentChange`）

> 实施时优先方案 1（避免重复维护状态）。需要在 `AiChatHostedService` 上加 internal 访问器。

## 四、IntentClassifier

### 4.1 接口

```csharp
public interface IIntentClassifier
{
    Task<UserIntent> ClassifyAsync(string userInput, CancellationToken ct);
}

public enum UserIntent { NewTask, NormalChat }
```

### 4.2 实现策略：规则优先 + AI 兜底

```csharp
public sealed class IntentClassifier : IIntentClassifier
{
    private readonly IPromptProvider _promptProvider;
    private readonly AIAgentFactory _agentFactory;
    private readonly ICurrentSessionResolver _sessionResolver;
    private readonly ILogger<IntentClassifier> _logger;

    // 关键词规则（先做兜底，便宜快）
    private static readonly string[] NewTaskKeywords =
    {
        "帮我做", "帮我生成", "帮我写", "帮我整理", "帮我分析", "帮我创建",
        "做一份", "生成一份", "做一个", "生成一个", "整理一份",
        "分析一下", "统计一下", "导出", "制作",
    };

    private static readonly string[] ChatKeywords =
    {
        "你好", "你是谁", "怎么用", "什么是", "解释一下", "为什么",
    };

    public async Task<UserIntent> ClassifyAsync(string userInput, CancellationToken ct)
    {
        // 1. 规则匹配（短路）
        if (NewTaskKeywords.Any(k => userInput.Contains(k, StringComparison.Ordinal)))
            return UserIntent.NewTask;

        if (ChatKeywords.Any(k => userInput.Contains(k, StringComparison.Ordinal)))
            return UserIntent.NormalChat;

        // 2. 文本太短，按聊天处理（避免误启动任务）
        if (userInput.Trim().Length < 8)
            return UserIntent.NormalChat;

        // 3. AI 兜底：用动态构建的轻量分类 Agent
        try
        {
            var classifier = await BuildClassifierAgentAsync(ct);
            var prompt = userInput;
            var response = await classifier.RunAsync(
                new ChatMessage(ChatRole.User, prompt),
                cancellationToken: ct);

            var text = response.Messages.Last().Text?.Trim() ?? "";
            return text.StartsWith("NewTask", StringComparison.OrdinalIgnoreCase)
                ? UserIntent.NewTask : UserIntent.NormalChat;
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "IntentClassifier AI fallback failed, defaulting to NormalChat");
            return UserIntent.NormalChat;
        }
    }

    private async Task<AIAgent> BuildClassifierAgentAsync(CancellationToken ct)
    {
        var instructions = await _promptProvider.GetPromptAsync(
            "work_mode.intent_classifier", ct);

        var (provider, model, _, _) = await _sessionResolver.GetCurrentAgentContextAsync(ct);

        // 用一个临时的轻量 AgentEntity（不入库）
        var transientAgent = new AgentEntity
        {
            Id = $"intent_classifier_{Guid.NewGuid():N}"[..16],
            Name = "意图分类器",
            Instructions = instructions,
            Temperature = 0,           // 确定性输出
            MaxTokens = 16,            // 只需要 NewTask / NormalChat 两个 token
        };

        // 复用 AIAgentFactory.BuildSubAgent 的逻辑（不带历史/工具）
        return _agentFactory.BuildLightweightAgent(transientAgent, provider, model);
    }
}
```

> `BuildLightweightAgent` 是对现有 `BuildSubAgent` 的公开包装。或者直接复用 `BuildSubAgent`（实施时确认其访问权限）。

### 4.3 提示词文件 work_mode.intent_classifier.md

```markdown
你是一个意图分类器。判断用户的话是"想发起一个工作任务"还是"普通聊天"。

## 输出格式

只输出一个单词，二选一：
- `NewTask` — 用户在请求执行一个具体工作（如生成报告、分析数据、写代码、整理文件等）
- `NormalChat` — 用户在闲聊、提问、确认状态、表达情绪等

## 判断标准

NewTask 的特征：
- 包含动词 + 对象（"做 X""生成 X""分析 X"）
- 隐含交付物（报告、文档、代码、图表）
- 提及数据源、范围、形式

NormalChat 的特征：
- 知识性问题（"什么是 X""为什么 X"）
- 情绪表达（"谢谢""你好""可以"）
- 状态确认（"你在做什么""收到没"）
- 短输入（少于 8 个字）

## 示例

输入：帮我做一份销售月报
输出：NewTask

输入：什么是机器学习？
输出：NormalChat

输入：再做一份 5 月的
输出：NewTask

输入：嗯
输出：NormalChat
```

### 4.4 边界情况

| 场景 | 路由结果 | 备注 |
|------|---------|------|
| 用户输入"再做一份 5 月的"（无活跃任务，但有完成的旧任务） | NewTask | 新任务通过 `SourceTaskId` 关联到旧任务，总经理 Agent 加载旧 Plan 作为参考 |
| 用户输入"嗯"（无活跃任务） | NormalChat | 路由到专家模式 |
| 用户输入"你好" | NormalChat | 同上 |
| 用户输入太长（>500 字） | 优先调用 AI 分类（规则可能误判） | |
| 意图分类失败（API 超时等） | 默认 NormalChat | 不要冒然创建任务 |

## 五、活跃任务的并发约束

**约束**：每个 ChatSession 同时最多有一个活跃任务。

**保证方式**：

```csharp
public async Task CreateAsync(WorkTask task, CancellationToken ct)
{
    using var tx = _db.BeginTransaction();
    try
    {
        // 检查是否已有活跃任务
        var existing = _db.ExecuteScalar<long>(
            "SELECT COUNT(*) FROM WorkTasks WHERE SessionId = @S AND IsActive = 1",
            cmd => cmd.Parameters.AddWithValue("@S", task.SessionId));

        if (existing > 0)
            throw new InvalidOperationException(
                $"Session {task.SessionId} already has an active task");

        // 插入新任务
        _db.Execute(/* INSERT WorkTasks ... */);

        tx.Commit();
    }
    catch
    {
        tx.Rollback();
        throw;
    }
}
```

**为什么这样设计**：

- 用户在工作模式 Tab 里的"思路"是单线程的，让 AI 同时做多个任务会让对话上下文混乱
- 实现时简单（不用考虑多任务并发的状态共享）
- 用户想做多任务可以新建 Session

## 六、应用启动时的恢复

> **决策已确认**（2026-05-29）：应用崩溃后重启**不自动续跑**长任务。重启时把活跃任务标记为 `IsOrphaned=1`，UI 加载会话时检测到并展示恢复决策卡片，由用户选择"继续"或"放弃"。详细流程见 [16 文档 §三](./16-长任务可靠性与重试策略.md#三layer-1应用崩溃恢复)。

```csharp
public sealed class WorkModeStartupService : IHostedService
{
    private readonly WorkTaskService _taskService;
    private readonly ILogger<WorkModeStartupService> _logger;

    public async Task StartAsync(CancellationToken ct)
    {
        // 找所有"上次未正常关闭"的活跃任务
        var orphanedCandidates = await _taskService.GetActiveTasksAsync(ct);

        foreach (var task in orphanedCandidates)
        {
            // 不区分有无 PendingRequest，统一标记为 Orphaned 等用户决策
            // - PendingRequest 非空：上次 HITL 等待中，重启后等用户回应
            // - PendingRequest 为空：上次执行中崩溃，等用户选"继续/放弃"
            await _taskService.MarkOrphanedAsync(task.Id, ct);

            _logger.LogInformation(
                "Task {TaskId} marked orphaned (last activity: {Time})",
                task.Id, task.LastActiveAt);
        }
    }

    public Task StopAsync(CancellationToken ct) => Task.CompletedTask;
}
```

### 6.1 用户决策路径

UI 加载会话时（`WorkModeViewController.LoadSessionAsync`），如果检测到最近一个任务 `IsOrphaned=1`：

1. 在消息流末尾追加一个 `TaskResumePromptCard` 控件
2. 卡片显示：任务标题、上次活动时间、最后一个执行步骤
3. 两个按钮：
   - **继续执行** → 调用 `ContinueOrphanedAsync`，按 HITL/普通两种情况分别恢复
   - **放弃任务** → 调用 `AbandonOrphanedAsync`，标记为 Cancelled

详细的 `TaskResumePromptCard` 与决策实现见 [16 文档 §3.4 / §3.5](./16-长任务可靠性与重试策略.md#34-ui-端恢复展示)。

## 七、用户主动操作

### 7.1 取消任务

UI 上提供"取消任务"按钮（实施阶段未必首版，但要预留接口）：

```csharp
public async Task CancelAsync(string taskId, CancellationToken ct)
{
    await _taskService.MarkCancelledAsync(taskId, ct);
    // 不需要 cancel Workflow（它已经挂在 HITL 上或没在跑）
    // 但要清掉 pending request 避免后续误响应
    await _taskService.ClearPendingRequestAsync(taskId, ct);

    _publisher.Publish(Events.OnWorkTaskCancelled, new WorkTaskCancelledArgs(taskId));
}
```

### 7.2 切换工作目录 / 模型

用户切换 workspace 或 provider/model 时：

- 现有活跃任务**保持不变**（任务在创建时已锁定 Provider/Model 字段）
- 新创建的任务才用新选择

> 这避免了"任务跑到一半，模型被换掉，结果不一致"的问题。

## 八、与专家模式输入的边界

**专家模式 Tab** 和 **工作模式 Tab** 共享 ChatSession，但提交路径不同：

| Tab | 提交路径 | 输入处理 |
|-----|----------|---------|
| 专家模式 | `IAiChatEngine.SendMessageAsync` | 直接调用普通聊天 Agent |
| 工作模式 | `WorkModeInputRouter.RouteAsync` | 走路由判断 |

**关键**：

- 用户在专家模式说的话不会触发工作模式任务（即使内容像"帮我做 X"）
- 用户在工作模式说话即使没有任务也可能走专家模式聊天（IntentClassifier 判断为 NormalChat 时）
- 两个 Tab 的对话内容**互通**（同一 ChatSession，用户切 Tab 不会丢上下文）
