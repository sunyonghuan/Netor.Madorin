## 一、为什么要做这件事

### 1.1 当前状态的问题

工作模式提示词目前**全部以 EmbeddedResource 烧进 DLL**：

| 提示词 | 文件位置 | 加载方式 |
|--------|---------|---------|
| 总经理 | [prompts/work_mode/general_manager.md](../../Src/Netor.Cortana.AI/prompts/work_mode/general_manager.md) | EmbeddedResource → `Assembly.GetManifestResourceStream` |
| 意图分类器 | [prompts/work_mode/intent_classifier.md](../../Src/Netor.Cortana.AI/prompts/work_mode/intent_classifier.md) | **未声明 EmbeddedResource，且代码中未加载**（IntentClassifier 当前只用关键词，未使用此提示词） |
| Magentic 动态创建模板 | [Resources/Prompts/Magentic.DynamicCreation.md](../../Src/Netor.Cortana.AI/Resources/Prompts/Magentic.DynamicCreation.md) | EmbeddedResource → [MagenticDynamicCreationInstructionsProvider.LoadTemplate](../../Src/Netor.Cortana.AI/Providers/MagenticDynamicCreationInstructionsProvider.cs#L66) |

**问题**：用户想调整提示词必须重新编译应用。在产品线投入生产后，提示词调优是高频活动（每周可能会调整一次），重新编译发版的成本不可接受。

### 1.3 设计目标

| 目标 | 实现 |
|------|------|
| 用户改提示词不重编译 | `<UserData>/prompts/` 路径优先 |
| 默认提示词随发版更新 | EmbeddedResource 作为兜底 |
| 不破坏当前行为 | 用户没创建文件时 = 现状 |
| 不写"首装释放"逻辑 | 用户主动覆盖模型，避免版本同步问题 |
| 统一两套模式 | 工作模式 + 会议模式 共用同一条加载链路 |

## 二、目标架构

### 2.1 查找链路

```text
GetPromptAsync("work_mode.general_manager")
  ↓
CompositePromptProvider
  ↓
1) LocalFilePromptProvider
     读 <UserData>/prompts/work_mode/general_manager.md
     找到? → 返回内容（用户覆盖层）
  ↓ 没找到
2) EmbeddedResourcePromptProvider
     读 Netor.Cortana.AI.prompts.work_mode.general_manager.md
     找到? → 返回内容（默认值）
  ↓ 没找到
返回 null（调用方降级处理或抛异常）
```

**关键决策**：移除 `DatabasePromptProvider` 出默认链路。`v1.0` 用不上数据库版本，简化心智模型；如果后续要做远程提示词中心或多租户提示词管理，可以再单独评估。

### 2.2 用户主动覆盖模型

不做"首装释放"。用户想改提示词时：

1. 用户在 `<UserData>/prompts/work_mode/general_manager.md` 创建一个文件，写入自己的提示词
2. 重启应用 → `LocalFilePromptProvider` 读到，覆盖 EmbeddedResource 默认值
3. 用户想恢复默认值 → 删除该文件 → 自动回退

好处：
- `<UserData>/prompts/` 目录里只有用户改过的，一目了然
- 不需要版本同步（"释放后又升级默认提示词怎么办"）
- 用户如果改坏了，删除即可恢复

### 2.3 命名约定

[LocalFilePromptProvider](../../Src/Netor.Cortana.AI/WorkMode/Prompts/LocalFilePromptProvider.cs#L24-L25) 已有规则：

```text
"work_mode.general_manager"  →  <PromptsDirectory>/work_mode/general_manager.md
"work_mode.intent_classifier" →  <PromptsDirectory>/work_mode/intent_classifier.md
"meeting.host"                →  <PromptsDirectory>/meeting/host.md
"meeting.compaction"          →  <PromptsDirectory>/meeting/compaction.md
```

新的 `EmbeddedResourcePromptProvider` 用相同名字 → 资源名转换：

```text
"work_mode.general_manager"  →  Netor.Cortana.AI.prompts.work_mode.general_manager.md
"meeting.host"               →  Netor.Cortana.AI.prompts.meeting.host.md
```

#### 3.1.1 EmbeddedResourcePromptProvider

新建 `Src/Netor.Cortana.AI/WorkMode/Prompts/EmbeddedResourcePromptProvider.cs`：

```csharp
using System.Reflection;

namespace Netor.Cortana.AI.WorkMode.Prompts;

/// <summary>
/// 从 Assembly EmbeddedResource 加载提示词（默认兜底层）。
/// 资源命名规则：name "work_mode.general_manager" → "Netor.Cortana.AI.prompts.work_mode.general_manager.md"
/// </summary>
public sealed class EmbeddedResourcePromptProvider : IPromptProvider
{
    private readonly Assembly _assembly;
    private readonly string _resourceNamePrefix;

    /// <param name="assembly">承载提示词资源的程序集</param>
    /// <param name="resourceNamePrefix">资源名前缀，如 "Netor.Cortana.AI.prompts."</param>
    public EmbeddedResourcePromptProvider(Assembly assembly, string resourceNamePrefix = "Netor.Cortana.AI.prompts.")
    {
        _assembly = assembly ?? throw new ArgumentNullException(nameof(assembly));
        _resourceNamePrefix = resourceNamePrefix ?? throw new ArgumentNullException(nameof(resourceNamePrefix));
    }

    public Task<string?> GetPromptAsync(string name, CancellationToken cancellationToken = default)
    {
        if (string.IsNullOrWhiteSpace(name))
            return Task.FromResult<string?>(null);

        var resourceName = _resourceNamePrefix + name + ".md";
        using var stream = _assembly.GetManifestResourceStream(resourceName);
        if (stream is null)
            return Task.FromResult<string?>(null);

        using var reader = new StreamReader(stream);
        return Task.FromResult<string?>(reader.ReadToEnd());
    }
}
```

## 六、风险与回归点

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 用户文件编码问题（BOM / GBK） | 低 | 中 | `File.ReadAllTextAsync` 默认 UTF-8 不带 BOM；如果用户用 Windows 记事本另存为 UTF-8 with BOM，`StreamReader` 应该能识别。提供文档说明用 UTF-8 |
| 用户写了语法错误的 markdown | 中 | 低 | 提示词不需要严格 markdown 语法；模型会容错。如果用户写空文件 → `LocalFilePromptProvider` 返回空字符串 → 主 Agent 退化为无提示行为，需要约定"空文件 = 占位，不作为有效覆盖" |
| EmbeddedResource 资源名拼错 | 中 | 高 | csproj `LogicalName` 与代码里的资源名严格一致；启动时调一次 `EmbeddedResourcePromptProvider` 验证关键提示词加载成功，失败时大字日志报警 |
| AOT 构建丢失 EmbeddedResource | 低 | 高 | `Assembly.GetManifestResourceStream` 在 AOT 下完全合法；`<EmbeddedResource>` 与 trimming 无关。验收阶段必跑 `dotnet publish -p:PublishAot=true` |
| 同步 GetAwaiter().GetResult() 在 UI 线程构造时死锁 | 低 | 中 | `GeneralManagerAgentBuilder` 由 DI 容器在后台构造，不会跑在 UI 线程；如果将来场景变化，改成 lazy 初始化 |

### 关键回归测试用例

1. **默认行为不变**：删除 `<UserData>/prompts/` 整个目录 → 启动应用 → 工作模式正常
2. **用户覆盖生效**：在 `<UserData>/prompts/work_mode/general_manager.md` 写入显式不同的内容（如 "你是测试机器人"）→ 重启 → 总经理首次回复体现新提示词的效果
3. **空文件处理**：创建一个空的 `<UserData>/prompts/work_mode/general_manager.md` → 重启 → 主 Agent 提示词为空字符串（按当前 `LocalFilePromptProvider` 行为；如果不能接受，需要在 LocalFilePromptProvider 增加"空文件视作 null"逻辑）
4. **AOT 构建**：`dotnet publish -p:PublishAot=true` 通过，启动后提示词正常加载
5. **意图分类器提示词**：csproj 已声明 EmbeddedResource，但 `IntentClassifier` 暂不接入；`_promptProvider.GetPromptAsync("work_mode.intent_classifier")` 应能返回非 null
