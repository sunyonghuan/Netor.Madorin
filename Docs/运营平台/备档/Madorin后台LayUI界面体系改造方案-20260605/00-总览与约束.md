# 00. 总览与约束

## 目标

将 `Netor.Cortana.Platform.Admin` 后台从混合 Razor 静态表格、Bootstrap 风格和零散页面跳转，改造成基于 LayUI 2.x 标准组件的后台管理体系。

本次不是单纯换皮，而是按当前项目已经存在的账户、资源、审核、分类、创作者、订阅、下载、订单、交易、结算、设置等功能重新组织界面、数据接口和操作流程。

外壳和菜单也属于验收范围：后台不能只保留旧版通用 LayUI 侧栏，应呈现清晰的 Madorin 运营工作台，包括待办队列、用户钱包、资源市场、订单流水、订阅下载、创作者结算、系统运维等业务视角。

## 硬性约束

1. 不使用 `Netor.Operates.LayuiHelpers`。该库当前不完善、不完整，暂时不能作为界面改造基础。
2. 所有界面、表单、控件都采用 Razor `.cshtml` 编写。
3. Razor 只输出 LayUI 标准结构、class、属性和模板，不引入 React/Vue/SPA。
4. 主列表统一使用 LayUI 官方 `table.render()`。
5. 新增、修改、查看统一从右侧抽屉打开。
6. 关联明细统一从底部抽屉打开，例如用户交易记录、订单交易流水、资源版本、下载记录。
7. 筛选项必须绑定数据库字段和关联数据，不能只做关键词和状态。
8. 保留现有控制器业务能力，不因界面重构丢失发布、审核、充值、改密、结算、批量处理等功能。
9. 菜单入口必须尽量指向真实页面、真实筛选参数或真实抽屉操作，不能只做装饰性导航。

## LayUI 依据

- 官方文档：<https://layui.dev/docs/2/>
- 本地资源：`wwwroot/lib/layui`
- 本地 `layui.min.js` 版本：`2.12.0`

如果后续需要使用本地 2.12.0 不支持的 LayUI 能力，应先升级静态资源，再执行对应改造。

## 改造边界

本轮规划只确定后台界面与数据接口体系：

- Razor 页面结构。
- LayUI table 数据接口。
- 右侧抽屉和底部抽屉交互。
- 列表筛选维度。
- 公共 JS/CSS 能力。
- 分阶段执行计划。

不在本轮做：

- 重构业务服务层。
- 调整数据库结构。
- 引入前端框架。
- 依赖不完整 helper 库生成控件。
