# 08. 验收标准

完成后必须满足：

1. 所有列表页使用 LayUI table 对接数据接口。
2. 所有新增、修改、查看都在右侧抽屉完成。
3. 用户交易记录等关联列表从底部抽屉打开。
4. 所有页面、表单、控件都由 Razor 编写，并使用 LayUI 标准样式。
5. 不依赖 `Netor.Operates.LayuiHelpers`。
6. 筛选项覆盖当前数据库字段和关键关联数据。
7. 批量操作、危险操作都有 `layer.confirm`。
8. 表单保存成功后关闭抽屉并刷新父表格。
9. 页面不再混用 Bootstrap 表格和表单样式。
10. 浏览器控制台无明显 JS 错误。
11. 现有业务能力不丢失，控制器中的发布、审核、结算、充值、改密、批量处理等功能继续可用。
12. 后台外壳、Logo 区、侧栏菜单和工作台快捷入口需要和旧版通用 LayUI 后台有明显区分。
13. 菜单按业务场景组织，并提供待审核、待支付、待结算、新增资源、新增分类、存储配置等真实入口。
14. 通过菜单 query 参数进入列表页时，筛选控件应自动带入对应值，LayUI table 应按这些条件请求数据。

## 首个样板验收

`Accounts` 模块完成后应满足：

1. 用户主列表由 `layui.table.render()` 渲染。
2. 筛选覆盖用户、钱包、订单、订阅、下载、创作者维度。
3. 查看、编辑、充值、改密全部右侧抽屉。
4. 用户交易记录从底部抽屉打开。
5. 交易记录支持交易号、订单号、第三方流水号、支付状态、支付方式、金额范围、支付时间、订单状态、资源类型、异常交易等筛选。
6. 保存或操作成功后刷新父表格，不整页跳转。
