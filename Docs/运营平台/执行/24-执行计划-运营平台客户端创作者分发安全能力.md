## 26 文档评审反馈（2026-06-03 追记）

桌面端应用商店方案（23 / 26 文档）评审过程中，定位到本计划遗留的若干风险，按"风险 + 计划修复时间窗"记录如下，避免以"100%"状态封箱后被遗忘：

- 25-Step3 客户端签名校验闭环已修订为"已废弃"。本计划的资源分发链路签名机制将由 26-Step1 一次性删除，完整性单纯依靠 SHA256 + HTTPS（决议依据：客户端商店只需要"包没有被改过"的语义，HTTPS + 哈希已经覆盖；对称签名让客户端持有密钥反而引入风险，非对称签名带来密钥轮换/重签等运维负担均不必要）。
- `PackageRiskService.DangerousExtensions` 包含 `.dll`，会让所有 dotnet 插件包被驳回。当前 admin 直接发布路径绕过审核（已在本计划修复），所以 demo 阶段未暴露；创作者上传走完整审核会触发。修复计划：26-Step2 按 AssetType 分流白名单。
- `ApiTokenService` 是 stateless HMAC，账号被禁用后已签发 token 仍生效。修复计划：26-Step2 在 `GetCurrentAccountAsync` 中追加账号状态校验，禁用账号统一返回 401。
- `Program.cs` 缺少全局 camelCase 序列化策略。客户端按 23-§9 设计的 camelCase 请求会被 PascalCase record 反序列化失败。修复计划：26-Step2 启用全局 camelCase。
- 平台 Web 端缺少忘记密码、重置密码、账号中心三个页面。桌面端商店方案明确"账号自助一律跳 Web"，前置依赖必须在桌面端商店上线前补齐。修复计划：26-Step2。
- `/api/v1/assets/{id}/download` 永远走平台代理流，大模型包（含 voice 系插件 ≥ 200MB）会消耗平台带宽。第一阶段允许，后续版本基于 `AssetVersion.StorageProvider == "S3"` + `PublicBaseUrl` 做 302 直链。

以上各项**不在本计划（24）的回滚范围内**，本计划保持当前状态归档。所有修复点统一进入 26 计划跟踪。
