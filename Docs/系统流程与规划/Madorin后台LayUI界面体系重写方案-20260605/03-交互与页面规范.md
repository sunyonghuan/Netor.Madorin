# 03. 交互与页面规范

## 页面外壳

1. 后台布局使用 `layui-layout-admin`。
2. 左侧为业务导航，但必须保持 LayUI 标准 `layui-nav-tree` 和 `layui-bg-black` 深色侧栏样式，不再自定义成非 LayUI 视觉。
3. 顶部提供折叠、刷新、当前工作区、全屏、用户菜单、退出。
4. 内容区顶部提供工作台快捷入口，入口必须落到真实页面或抽屉。
5. 页面主体以列表、筛选、表格、批量操作为主，保持后台工具属性。

## 列表页

每个列表页统一结构：

```text
页面指标
筛选表单
LayUI table 卡片
行操作模板
批量操作区
页面脚本
```

要求：

1. 表格使用 `table.render()`。
2. 数据接口返回 `LayuiTableResult<T>`。
3. 默认工具栏保留筛选列、导出、打印等 LayUI 标准能力。
4. 列表高度使用稳定尺寸，避免筛选展开后表格跳动失控。
5. URL query 参数必须能回填筛选表单。

## 右侧抽屉

适用：

1. 新增资源、新增分类、新增设置。
2. 编辑用户、改状态、充值、改密。
3. 查看账户、资源、分类、创作者、订单、结算、设置详情。

要求：

1. 通过 `mode=drawer` 使用 `_DrawerLayout.cshtml`。
2. 保存成功后关闭抽屉并刷新父表格。
3. 表单使用 `layui-form`、`layui-form-pane`、`layui-input`、`layui-select`、`layui-textarea`。
4. 表单底部使用 sticky 操作区。

## 底部抽屉

适用：

1. 用户交易记录。
2. 订单支付流水。
3. 订阅下载记录。
4. 创作者名下资源。
5. 创作者结算记录。

要求：

1. 底部抽屉内仍使用 LayUI table。
2. 支持独立筛选，不依赖父页面筛选状态。
3. 底部抽屉高度默认 70% 到 78%，保留上下文。

## 操作反馈

1. 危险操作使用 `layer.confirm`。
2. 审核、结算等需要备注的操作使用 `layer.prompt`。
3. 批量操作必须校验选中行。
4. 成功后使用 `layer.msg`，并刷新当前 table。
5. 失败场景要保留服务端 ModelState 或 HTTP 错误提示。

## 可访问性与响应式

1. 图标按钮必须有 `aria-label` 或明确文字。
2. 移动端侧栏改为覆盖式展开。
3. 抽屉宽度在窄屏下使用接近全屏宽度。
4. 筛选表单在 1200、960、640 断点下逐级减少列数。
