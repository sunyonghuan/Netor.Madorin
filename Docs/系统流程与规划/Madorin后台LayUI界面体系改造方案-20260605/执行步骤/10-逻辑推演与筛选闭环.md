# 10. 逻辑推演与筛选闭环

## 目标

在界面体系完成后，从真实后台使用链路推演潜在逻辑问题，重点检查筛选字段、查询条件、抽屉操作、批量操作和运行期 EF 查询是否闭合。

## 推演结论

1. ID 字段当前以字符串传递，不存在 LayUI/JavaScript 长整型精度丢失风险。
2. 右侧抽屉表单通过 `mode=drawer` 传回 POST，`_ViewStart` 和控制器 `DrawerSuccess` 能形成保存后关闭抽屉并刷新父表格的闭环。
3. 部分列表存在“控制器支持筛选，但界面没有入口”的缺口，会导致文档中的完整筛选能力没有充分暴露。
4. 钱包余额、创作者结算金额筛选需要把空集合按 0 处理，否则 `最小值=0` 或 `最大值` 类筛选会意外排除无钱包、无结算记录的数据。
5. 资源列表的审核状态筛选应和表格展示的“最新审核状态”一致，不能按任意历史审核记录匹配。

## 本轮处理

1. `Accounts/Index.cshtml` 补齐用户编号范围、订单上限、订阅上限、下载上限、登录次数上限、注册 IP 筛选入口。
2. `Assets/Index.cshtml` 补齐下载上限、版本数量最小值筛选入口。
3. `Creators/Index.cshtml` 补齐已结算金额上限筛选入口。
4. `AccountsController.TableData` 钱包余额筛选改为 `Sum(...) ?? 0m` 后再比较。
5. `CreatorsController.TableData` 待结算、已结算金额筛选改为 `Sum(...) ?? 0m` 后再比较。
6. `AssetsController.TableData` 审核状态筛选改为按最新审核记录判断。
