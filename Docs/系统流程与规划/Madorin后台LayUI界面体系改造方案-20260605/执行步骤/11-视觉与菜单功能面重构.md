# 11. 视觉与菜单功能面重构

## 背景

用户反馈当前后台“界面并没有什么改变，菜单功能设置几乎没变过”。复查后确认前序执行偏重 LayUI table、抽屉、筛选和数据接口，后台外壳与菜单信息架构仍接近旧版通用 LayUI 管理界面。

## 调整目标

1. 让后台进入后的第一视觉明显变成 Madorin 运营工作台。
2. 左侧菜单按真实业务场景重组，而不是只按控制器模块平铺。
3. 常用操作和待办入口要落到现有页面、筛选条件或右侧抽屉。
4. 保持 Razor `.cshtml` 和 LayUI 标准 class，不使用 `Netor.Operates.LayuiHelpers`。

## 已执行

1. `_Layout.cshtml` 调整 Logo 区和顶部当前工作区展示。
2. 新增 `_WorkspacePartial.cshtml`，统一输出待审核、待支付、待结算、新增资源、新增分类、存储配置等快捷入口。
3. `_NavPartial.cshtml` 重构为待办队列、用户与钱包、资源市场、订单与权益、创作者经营、系统运维六类业务菜单。
4. 菜单新增多个真实筛选入口，例如资源待审核、创作者待审核、有余额用户、有待审资源、待支付订单、待确认流水、待结算收益。
5. `site.js` 新增 URL query 参数自动灌入 LayUI 筛选表单能力，保证菜单入口能实际影响 table 数据请求。
6. `site.css` 将旧深色通用侧栏改为白色运营导航，增加工作台快捷区、Logo 标识、业务导航分组和响应式折叠态。

## 验收

1. 后台外壳视觉不再像旧版默认 LayUI 深色侧栏。
2. 菜单入口能覆盖当前项目已有账户、资源、审核、分类、创作者、订单、交易、订阅、下载、结算、设置功能。
3. 新增资源、新增分类、新增设置仍通过右侧抽屉打开。
4. 待办类菜单通过 query 参数进入列表，并自动填充筛选表单。
5. 构建通过后，使用 HTTP 或浏览器验证首页、资源审核、订单、结算、资源新增抽屉等入口。
