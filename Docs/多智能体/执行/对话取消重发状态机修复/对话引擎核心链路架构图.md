## 一、文档定位

把 Cortana 平台对话引擎涉及的**所有数据与控制链路**画出来，让读者一眼看清 v7.3 方案实施后的落地架构：

- 一次"用户输入 → AI 流式输出 → 取消 → 重发"的完整路径上有多少条链路在协作
- 每条链路在哪个组件 publish、哪个组件 subscribe、走什么协议（IPublisher / IAiOutputChannel / PluginBus topic / DB 表 / AF 钩子）
- 哪些链路是**专家模式独有**、哪些**跨模式共享**、哪些**完全隔离**

**对照阅读**：本文档画**落地架构"是什么"**（结构），[README.md](README.md) 写**改造"为什么 + 怎么改 + 改完接得通吗"**（决策与修复）。两份文档配合使用，README 是决策档，本文档是结构档。

**当前定位**：本文档与 README 同属 `Docs/已完成功能规划/对话取消重发状态机修复/`。当前代码的阶段 1-5 主路径已经落地，因此本文档不再是纯“待实施目标态”，而是“已落地主路径 + 已归档验收边界”的结构档。

## 二、核心组件清单（与图对应）

按代码所在程序集分组，每行标注职责简介。

### 2.1 输入层（Input Sources）

| 组件 | 程序集 | 职责 |
| --- | --- | --- |
| `ChatInputVm` | UI | 专家模式输入框 VM；调 `IAiChatEngine.SendMessageAsync` / `CancelCurrentTaskAsync` |
| `WebSocketInputChannel` | Networks | 外部插件通过 WebSocket 推送的输入；调 `chatEngine.Stop()` 中断 |
| `IVoiceCoordinator` / `SpeechRecognitionService` / `VoicePipelineCoordinator` | Voice | 语音输入 + 唤醒词；调 `chatEngine.CancelCurrentTask()` 截断 |

### 2.2 引擎层（Engine Core）

| 组件 | 程序集 | 职责 |
| --- | --- | --- |
| `IAiChatEngine` | Entitys（接口） | UI/Networks/Voice 共用的对话引擎契约 |
| `AiChatHostedService` | AI | `IAiChatEngine` 实现；2082 行（重构后 ≤ 200 行）；专家模式 turn 编排入口 |
| `ChatTurnExecutor`（v7.3 新增） | AI | 拆分后的 turn 执行器；负责取消/事件/持久化的 turn 内统一编排 |
| `ChatTurnCancellationRegistry`（v7.3 新增） | AI | turnId → CTS 字典 |
| `ChatAgentResolver`（v7.3 新增） | AI | "下一轮默认配置"（Provider/Agent/Model）字段所有者；监听 ToolContextVersionService |
| `ChatSessionService`（v7.3 新增） | AI | session 生命周期（NewSession/ResumeSession/CurrentId） |
| `ChatMessagePersistence`（v7.3 新增） | AI | turn 取消时的 SavePartialResponse 薄包装（转调 ChatHistoryDataProvider） |
| `WorkflowExecutor` | AI | 工作模式执行器；`ExecuteAsync(taskId, ...)` 按 taskId 隔离 |
| `MeetingExecutor` | AI | 会议模式执行器；`ExecuteAsync(meetingId, ...)` 按 meetingId 隔离 |

### 2.3 AF 钩子层（AF Kit Extensions）

| 组件 | 程序集 | 职责 |
| --- | --- | --- |
| `AIAgentFactory` | AI | 装配 AF AIAgent；注入 `ChatHistoryProvider` / 工具 / Skills |
| `ChatHistoryDataProvider` | AI | AF 钩子重写：`ProvideChatHistoryAsync`（推理前从 DB 拉历史）/ `StoreChatHistoryAsync`（完成时持久化）/ `SavePartialResponseAsync`（取消时部分持久化）/ `AppendWorkflowFinalReport`（工作模式 finalReport 回灌） |
| `CompactionSegmentService` | AI | 历史压缩段落存储（`CompactionSegments` 表） |
| `IChatCompactionClientResolver` | AI | 压缩用小模型的解析器 |
| `ToolContextVersionService` | AI | 工具上下文版本号；插件加载/卸载时递增 |

### 2.4 输出通道层（Output Channels）

| 组件 | 程序集 | 接口 | 职责 |
| --- | --- | --- | --- |
| `UiChatOutputChannel` | UI | `IAiOutputChannel` + `IRealtimeProcessOutput` | 专家模式 UI 流式渲染；v7.3 后按 turnId 路由 |
| `WebSocketChatOutputChannel` | Networks | `IAiOutputChannel` | 转发到 PluginBus `conversation` topic 给外部插件 |
| `TtsPluginOutputChannel` | Voice | `IAiOutputChannel` | TTS 语音播报（按时间序，非 per-turn） |
| `VoiceChatOutputChannel` | Voice | `IAiOutputChannel` | 唤醒词驱动语音对话 |
| `NonExpertSuppressingRealtimeOutput` | UI | `IRealtimeProcessOutput` | 工作/会议模式实时事件抑制器（`NonExpertProcessScope.Active` 整把丢弃） |

### 2.5 事件总线层（Event Bus）

| 组件 | 程序集 | 职责 |

### 2.6 持久化层（Persistence）

| 组件 | 程序集 | 表 |

### 2.7 工作 / 会议模式专属

```text
 │                                                                              │   Completed(Status=Cancelled)       │              │
```

```text
 │                                                                              ▼                                     │              │
```

**关键点**：

- 取消唯一入口是 `ChatTurnExecutor.CancelCurrentTurnAsync`；4 个外部入口（IAiChatEngine.Stop / CancelCurrentTask / CancelCurrentTaskAsync / ChatInputVm.CancelAsync）全部转发到这里
- `Registry.CancelAsync(turnId)` 只 cancel 该 turn 的 CTS，立即返回（不等 AF 结束）
- 旧 turn 的 catch 块用 `ChatTurnContext` 局部捕获的 session/agent 调 SavePartialResponse — 不依赖任何 service-level 字段
- `OnConversationTurnCompleted` 由 `IsCompletionPublished` 守卫保证只发一次

```text
            ┌──────────────────────────────────────┐
            │       (turn 不存在；空闲态)          │
            └──────────────────────┬───────────────┘
                                   │
                                   │ 用户发消息
                                   │ ChatTurnExecutor.ExecuteTurnAsync

                                   ▼

            │ Created                              │

            └──────────────────────┬───────────────┘
                                   │
                                   │ AF.RunStreamingAsync 开始
                                   │

            ┌──────────────────────────────────────┐

            │ - foreach chunk: channel.OnToken     │

               │                 │
               ▼                 ▼
   ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
   │  Completing      │    │  Cancelling      │    │  Failing         │
   │  AF 钩子自动调   │    │  CTS.Cancel()    │    │  catch (Exception)│
   │  StoreChat...    │    │  → AF stream     │    │  publish Failed  │
   │  ↓               │    │    抛 OperCanceled│    │  ↓               │
   │  publish Completed│   │  ↓               │    │  publish Completed
   │  (Succeeded)     │    │  catch 块:        │    │  (Failed)        │
   │  (守卫保证一次)   │    │  - SavePartial   │    │                  │
   └────────┬─────────┘    │    Response      │    │                  │
            │              │  - publish        │    │                  │
            │              │    Completed      │    │                  │
            │              │    (Cancelled)    │    │                  │

            │              └────────┬─────────┘    └────────┬─────────┘
            │                       │                       │
            └───────────────────────┴───────────────────────┘
                                    │
                                    │ finally
                                    │ Registry.TryUnregister(turnId)
                                    │ ChatTurnContext.Dispose
                                    │
                                    ▼
            ┌──────────────────────────────────────┐
            │ Done                                 │
            │ (turn 不存在；回到空闲态)             │
            └──────────────────────────────────────┘

兜底分支：5s 超时（ZombieKiller）
            ┌──────────────────────────────────────┐
            │  超过 5s 仍未到达 Done 态             │
            │  → 后台 ZombieKiller 强制 Cts.Dispose │
            │  → publish Completed(Failed,         │
            │     ErrorMessage="zombie killed")    │
            │  → 守卫保证只发一次                   │
            │  → Registry.TryUnregister            │
            └──────────────────────────────────────┘
```

**状态不变量**：

- 任意时刻，单个 turnId **要么在 Registry 内**（Streaming/Cancelling/Completing/Failing），**要么不在**（Created 之前 / Done 之后）
- 任意 turn 的 `OnConversationTurnCompleted` 事件**有且只有一次**发布（守卫保证）
- 多个 turnId 可以同时存在 — 旧 turn 处于 Cancelling 时，新 turn 已经 Created（这是 v7.3 取消立即返回的核心保证）

## 八、读图指引

### 8.1 想理解"取消"为什么这么复杂

看 §5.1 链路 ① 序列图。专家模式的取消涉及 6 个组件协作（VM → IAiChatEngine → ChatTurnExecutor → Registry → ChatTurnContext → AF stream），且有 4 个外部入口和 60s LRU 守卫。

### 8.2 想理解"取消后 AI 还能看到刚才那段"为什么自动成立

看 §5.4 链路 ④ 路径 B + §5.3 链路 ③ 联动 — 部分回复落进 ChatMessages 表，下一轮 AF 钩子 ProvideChatHistoryAsync 自然读到。

### 8.3 想理解"工作模式不会被破坏"是什么意思

看 §七 跨模式协作矩阵。工作模式在控制流（取消注册表 / 流式事件 / 历史持久化）上与专家模式完全隔离；只在数据流（Factory / ToolContextVersionService / 默认配置）上通过共享或转发协作。

### 8.4 想理解"接口为什么要破坏性变更而不是默认转发"

看 §5.2 链路 ② 序列图的"channel 首行 turnId 守卫"。如果接口允许默认转发兼容旧实现，这个守卫就成了可选项 — 然而它正是 v7.3 实现"截"语义的核心。让所有 channel 实现强制处理 turnId 是接口契约的硬要求，不是性能优化。

### 8.5 想看 publish 事件触发点会不会丢

看 §5.7 链路 ⑦ SessionCreated 联动。每个 publish 点都标注了 publisher 的实际位置（哪个组件的哪个方法）。v7.3 阶段 3.4 把 NewSessionAsync 迁到 ChatSessionService 时，publish 代码也跟着迁 — 跟随业务行为而不是停留在原位置。
