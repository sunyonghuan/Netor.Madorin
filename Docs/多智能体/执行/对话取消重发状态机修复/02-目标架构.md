## 四、修复目标

### 4.1 不做什么

- ❌ 不引入"插话""排队"功能（专家模式不需要）
- ❌ 不动数据库表结构
- ❌ 不改 `IAiChatEngine` 接口（UI/Networks/Voice 调用零感知）
- ❌ **不动现有压缩链路**（CompactionSegments / ChatHistoryDataProvider 钩子机制保留）
- ❌ 不新增 ChatHistoryReplayService（v6 想法作废，AF 钩子已经做了）

### 4.2 做什么

1. 把 15 种职责拆成职责单一的组件
2. 引入 `ChatTurnContext` 让 turn 成为一等公民贯穿所有跨组件调用
3. 引入 `ChatTurnCancellationRegistry` 按 turnId 隔离 CTS
4. 输出通道按 turnId 过滤实现"截"
5. 让 `Change*` 不再清空字段实现"留"主路径
6. VM 改事件驱动消除乐观更新

### 5.2 ChatTurnContext = "Turn 一等公民"

```csharp
internal sealed record ChatTurnContext(
    string TurnId,              // ← 串起所有跨组件调用的标识
    string SessionId,
    AgentSession Session,       // ← 启动时快照（不读字段）
    AIAgent Agent,              // ← 启动时快照（Change* 不影响旧 turn）
    AiProviderEntity Provider,  // ← 启动时快照
    AiModelEntity Model,
    AgentEntity AgentEntity,
    string UserInput,
    IReadOnlyList<AttachmentInfo> Attachments,
    IReadOnlyList<AgentMention> Mentions,
    string AssistantMessageId,  // ← 持久化主键，跟 turn 同生命周期
    CancellationTokenSource Cts,
    long StartTimestampUtc);
```

`ChatTurnExecutor.ExecuteTurnAsync` 进入时一次性快照所有依赖到 record。后续：

- 调持久化 → `_persistence.SavePartialResponse(context, fullResponse)`，**不读字段**
- 调实时事件 → `_realtimePublisher.PublishToken(context, token)`，**不读字段**
- 调输出通道 → `channel.OnTokenAsync(context.TurnId, token, ...)`

**新 turn 修改任何字段都不影响旧 turn 的 catch 块** — "留"主路径成立。

### 5.3 输出通道按 turnId 过滤

`IAiOutputChannel` 接口**破坏性变更** — 所有方法首参加 `string turnId`，旧签名删除（详见 [05-兼容性与决策.md §8.2](05-兼容性与决策.md)）：

```csharp
public interface IAiOutputChannel
{
    Task OnTokenAsync(string turnId, string token, string sessionId, CancellationToken ct);
    Task OnDoneAsync(string turnId, string sessionId, CancellationToken ct);
    Task OnCancelledAsync(string turnId);
    Task OnErrorAsync(string turnId, string message, CancellationToken ct);
}
```

`IRealtimeProcessOutput.OnProcessEventAsync` **签名不变** — `RealtimeProcessEvent.TurnId` 字段已经存在，实现端按字段做路由即可（详见 [05-兼容性与决策.md §8.2](05-兼容性与决策.md) "实现端责任"段）。`PowerShellProvider:309` 等插件调用方零改动。

`UiChatOutputChannel` 内部用 `ConcurrentDictionary<turnId, TurnRenderState>` 替代实例字段：

```csharp
public Task OnTokenAsync(string turnId, string token, ...)
{
    if (_cancelledTurnIds.Contains(turnId)) return Task.CompletedTask;  // ← "截"
    var state = _activeTurns.GetOrAdd(turnId, _ => CreateTurnState());
    // 累加到该 turn 自己的 buffer / 渲染到该 turn 的 presenter
}

public Task OnCancelledAsync(string turnId)
{
    _cancelledTurnIds.Add(turnId);
    if (_activeTurns.TryRemove(turnId, out var state))
    {
        // 该 turn 的气泡已经在 MessageList.Items 里，不删除（"留"）
        state.Dispose();  // 只清 buffer/presenter 引用
    }
}
```

`_cancelledTurnIds` 用 60s LRU 防止无限增长。

### 5.4 取消语义端到端

```text
T0    用户点击 Stop
T0+ε  Registry.CancelAsync(turnId) → CTS.Cancel() 立即返回
T0+ε  channel.OnCancelledAsync(turnId) → _cancelledTurnIds.Add → 「截」完成
T0+ε  publish OnConversationTurnCompleted(Status=Cancelled, turnId, ...)
      VM 收到 Completed 看 Status → IsRunning=false
      走马灯停 / 按钮切换 / 输入框可用 → 「停」对用户完成

T0+ε~Δ  旧 turn 在 HTTP/MCP 慢慢跑完
        await foreach 收到 cancel → catch 块
        ① _persistence.SavePartialResponseAsync(context, fullResponse)
           ← 用 context 局部变量；不读字段；写入 ChatMessages 表 → 「留」完成
        ② publish OnConversationTurnCompleted(Cancelled) 已在 T0+ε 发过，这里不重发
        finally Registry.TryUnregister(turnId)

T0+δ  用户已开始打字（任意 δ ≥ T0+ε）→ 完全独立
T0+T  用户发新消息 → 新 turnId 注册到 Registry → 完全独立运行
        AF 在 RunStreamingAsync 前调 ChatHistoryDataProvider.ProvideChatHistoryAsync
        从 DB 拉到包括"刚才被打断那段"的完整历史 → AI 看到上下文 → 硬要求 #5 成立

T0+5s  兜底：ZombieKiller 扫超时未释放的 CTS 强制 Dispose
       + publish OnConversationTurnCompleted(Status=Failed, ErrorMessage="zombie killed: ...")
       （复用现有事件，不新增类型；同时 LogWarning 便于观测）
       注：受同一 turnId 的去重守卫保护，若 catch 块已发过 Cancelled，此处自动跳过
```

5 条硬要求逐项对照：

| # | 要求 | 对应实现 |
| --- | --- | --- |
| 1 | 动效立即停 | publish OnConversationTurnCompleted(Cancelled) → VM 改 IsRunning |
| 2 | 流式输出立即停 | `_cancelledTurnIds.Add(turnId)` → 后续 OnTokenAsync 守卫拦截 |
| 3 | 已生成内容必须保留 | catch 块用 context 局部捕获的 session 调 SavePartialResponse |
| 4 | 旧 turn 不再产生新内容 | `_cancelledTurnIds` 守卫 + 5s ZombieKiller 兜底 |
| 5 | 新消息基于已有上下文继续 | AF 钩子 `ProvideChatHistoryAsync` 自动从 DB 读到部分回复，**前提是阶段 2 的"留"修好** |
