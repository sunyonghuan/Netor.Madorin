# 更新日志

本目录记录 Madorin 项目的代码、构建、配置和文档更新。每次完成一组可独立说明的变更后，新增一份更新记录，不直接覆盖历史记录。

## 文件命名

推荐使用以下格式：

```text
YYYY-MM-DD-主题.md
```

例如：

```text
2026-07-17-品牌发布与界面性能优化.md
```

同一天存在多组互不相关的更新时，在日期后增加两位序号：

```text
2026-07-17-01-品牌发布优化.md
2026-07-17-02-插件链路修复.md
```

涉及正式版本发布时，可以在主题中增加版本号：

```text
2026-07-17-v1.3.11-版本更新.md
```

命名要求：

- 日期使用项目所在地时间，格式固定为 `YYYY-MM-DD`。
- 主题使用简短、明确的中文描述，避免使用“杂项”“临时修改”等无法检索的名称。
- 文件名不使用路径分隔符和特殊控制字符；版本号使用字母 `v` 加语义化版本号。
- 一份记录对应一次完整更新；后续补充应直接修改原记录，不重复创建同名记录。

## 内容要求

每份更新记录至少包含以下内容：

1. 更新日期、版本号或当前开发阶段。
2. 更新概述，说明本次变更解决的问题或达到的目标。
3. 变更明细，按功能、界面、构建、配置、文档等类别分组。
4. 兼容性、迁移步骤、配置变化或用户可见影响。
5. 验证结果，包括构建、测试、发布检查或明确的未验证项。
6. 风险、遗留问题和后续计划。
7. 关联文档、提交记录或发布包信息。

## 编写规则

- 只记录已经完成或已经明确进入当前更新范围的内容，不把未实施的设想写成已完成。
- 用户可感知的变化优先使用结果描述，技术实现细节放在变更明细中。
- 删除、重命名和兼容性变化必须单独说明，避免升级后无法追溯。
- 验证未执行时写明“未验证”及原因，不使用模糊表述替代验证结果。
- 历史记录不随目录重组改写；路径变化只在必要时补充新的关联路径。

## 更新记录模板

新建记录时可复制以下结构：

```markdown
# 更新记录：{主题}

- 更新日期：YYYY-MM-DD
- 版本号：vX.Y.Z / 开发阶段
- 关联提交：{commit}

## 更新概述

## 变更明细

### 功能与代码

### 构建与发布

### 配置与资源

### 文档

## 兼容性与迁移

## 验证结果

## 风险与后续计划

## 关联资料
```
