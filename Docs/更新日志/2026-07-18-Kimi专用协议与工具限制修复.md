# 更新记录：Kimi 专用协议与工具限制修复

- 更新日期：2026-07-18
- 版本号：开发阶段
- 关联提交：`fd82216`

## 更新概述

本次更新完成 Kimi 专用协议接入，并修复 Kimi 多轮工具调用中的请求兼容问题。针对 Kimi 当前工具数量上限，新增可配置的工具数量限制与用户提醒机制，避免工具过多时模型接口直接拒绝请求。

## 变更明细

### 功能与代码

- 新增 `KimiProviderDriver`，协议 ID 为 `Kimi`，显示名为 `Kimi 专用协议`。
- 新增 `KimiOverrideHandler`，在请求发送前适配 Kimi 专用字段：
  - 自动注入顶层 `thinking`。
  - 为带 `tool_calls` 的 assistant 消息补齐 `partial = true`。
  - 清理空文本 content part，修复 `Invalid request: text content is empty`。
- 新增 `ProviderToolLimitContextProvider`，在 AI 上下文最终组装阶段按提供商能力限制工具数量。
- 扩展 `AiProviderDriverDefinition`，支持声明默认工具上限。
- Kimi 默认最大工具数量为 128。

### 配置

- 新增系统设置：`AI.Provider.Kimi.MaxTools`。
- 新增环境变量覆盖：`CORTANA_KIMI_MAX_TOOLS`。
- 设置值小于等于 0 时关闭工具数量限制。

### 用户体验

- 当工具数量超过上限时，软件会自动裁剪本轮工具列表，而不是直接让请求失败。
- 系统会向用户显示提醒，说明工具数量超限、部分工具被临时停用，并建议禁用不需要的插件/MCP 或只挂载当前任务所需工具。

### 文档

- 更新 `Docs/Bug修复/执行/Kimi专用协议接入执行计划.md`，记录修复完成状态、验证结果和配置说明。
- 新增本更新日志记录。

## 兼容性与迁移

- 不需要数据库迁移，继续使用文本型 `AiProviders.ProviderType`。
- 已有 Kimi 提供商配置不受影响。
- 如果 Kimi 后续取消工具数量限制，只需将 `AI.Provider.Kimi.MaxTools` 或 `CORTANA_KIMI_MAX_TOOLS` 设置为 `0`。

## 风险与后续计划

- 当前工具裁剪采用稳定顺序保留前 N 个工具。后续如需要更精细的工具优先级，可在工具元数据中补充来源、类别和优先级后进一步优化。
- Kimi 官方工具数量限制如果变化，可先通过配置调整，无需改动代码。
