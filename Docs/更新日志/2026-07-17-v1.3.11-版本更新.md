# 更新记录：Madorin v1.3.11 正式发布

- 更新日期：2026-07-17
- GitHub 发布日期：2026-09-13
- 版本号：v1.3.11
- GitHub Release 标签：`v1.3.11-r2`（`v1.3.11` 受仓库不可变 Release 限制，不能复用）
- 发布提交：`f8a7f99`（`完善品牌发布、界面性能与更新日志`）
- 上一版本：v1.3.10（`d3f800e`）
- 发布范围：Windows x64 Native AOT 桌面端

## 更新概述

v1.3.11 是 v1.3.10 之后的正式补丁版本，面向 Windows x64 用户交付。本版本把双品牌发布流程整理成按品牌分目录管理，并修复高频 PowerShell 输出把主界面调度队列打满、过程卡片无限增长导致卡顿的问题。同时为文件写入/编辑类内置工具补齐 Native AOT 源生成序列化配置，降低裁剪发布后工具参数反序列化失败的风险。

一句话：**本版本让双品牌打包更规范，让长命令输出时界面更跟得上，并让 AOT 发布包里的文件工具更稳。**

本版本不引入新的对话协议、不改数据库结构、不要求用户迁移配置。从 v1.3.10 覆盖安装即可。

## 用户可见变化

- 关于窗口、文件属性中的版本号从 `1.3.10` 变为 `1.3.11`。
- 主程序与 NativeHost 使用统一的 `brand.ico` / `brand.png`，不再混用旧的 `logo.200.ico`。
- 执行会产生大量实时输出的 PowerShell 命令时，主界面更不容易卡顿，输入框仍可响应。
- 实时过程卡片在输出超过约 256 KB 后会截断显示，并提示完整内容已记录在执行结果中，避免超长输出把聊天区撑死。
- 过程卡片自动滚动改为最多约 200ms 一次，用户向上翻看历史输出时不会被每一行新输出强行拽回底部。

## 变更明细

### 1. 版本号

桌面端项目版本已从 `1.3.10` 提升到 `1.3.11`：

```text
Src/Netor.Cortana.UI/Netor.Cortana.UI.csproj
  Version / InformationalVersion : 1.3.10 -> 1.3.11
  AssemblyVersion / FileVersion  : 1.3.10.0 -> 1.3.11.0
```

本发布包对应产品版本 `v1.3.11`，源码标签 `v1.3.11` 指向提交 `f8a7f99`。GitHub 因不可变 Release 限制无法在 `v1.3.11` 上创建 Release，因此实际上传使用标签 `v1.3.11-r2`，仍指向同一提交。

### 2. 双品牌发布目录与统一入口

品牌配置、图标和 Logo 改为按品牌 ID 分目录存放，不再把多个品牌的 JSON 平铺在 `Build/brands/` 根目录。

当前结构：

```text
Build/brands/
  publish.ps1                 统一发布入口，按 -Brand 选择品牌
  README.md                   品牌目录、字段和新增品牌步骤
  madorin/
    madorin.json              品牌身份与构建配置
    brand.ico / brand.png     应用图标与 Logo
  sreamx/
    sreamx.json
    brand.ico / brand.png
```

主要行为：

- 推荐入口改为 `Build/brands/publish.ps1 -Brand madorin`。
- 发布前把当前品牌的 `brand.ico` / `brand.png` 同步到 UI `Assets` 和 NativeHost 目录。
- 无论发布成功或失败，脚本都会按字节级备份恢复默认品牌资源，避免源码目录残留其它品牌图标。
- `ui.brand.publish.ps1` 默认配置路径改为 `brands\madorin\madorin.json`。
- 新增 `Build/ui.brands.publish.ps1`，可按同一版本号连续发布 Madorin 和 SreamX。
- 新增品牌时必须同时提供 `{brand}.json`、`brand.ico`、`brand.png`。

品牌 JSON 继续控制显示名、程序集名、发布目录、zip 包名前缀、官网 Host 和平台 API 默认地址。Madorin 品牌包名仍为 `Madorin`，产物文件名为：

```text
Madorin-v1.3.11-win-x64.zip
Madorin-v1.3.11-win-x64.sha256
```

### 3. 图标与资源路径统一

UI 和 NativeHost 的默认图标路径从旧文件名收敛到统一品牌资源名：

| 位置 | v1.3.10 | v1.3.11 |
|------|---------|---------|
| UI `ApplicationIcon` | `Assets\logo.200.ico` | `Assets\brand.ico` |
| NativeHost `ApplicationIcon` | `logo.200.ico` | `brand.ico` |
| UI Logo | 旧 Logo 资源 | `Assets\brand.png` |

发布脚本按品牌覆盖这些文件，因此同一套源码可以打出 Madorin 和 SreamX 两套外观不同的安装包。

### 4. 打包时排除历史 zip / sha256

`Build/ui.package.ps1` 在收集发布目录文件时，会跳过源目录中已经存在的 `.zip` 和 `.sha256`。避免把上一次打包产物再次打进新的 zip，导致包体膨胀或校验文件套娃。

### 5. PowerShell 高频输出不再打满 UI 调度队列

v1.3.10 中，PowerShell 每输出一行就会：

1. 写一条 Information 日志；
2. 立即发布一条实时过程事件；
3. 在 UI 线程 `Dispatcher.Post` 一次；
4. 过程卡片立即 `ScrollToBottom()`。

长命令或循环输出会在短时间内产生数千次 UI 调度，表现为主窗口卡住、输入框打字延迟、滚动条疯狂跳动。

v1.3.11 拆成三层缓冲：

1. **有界 Channel（容量 10000）**  
   PowerShell stdout/stderr 先写入 Channel，不再逐行直接 publish。Channel 满时静默丢弃新行，避免内存无限堆积。
2. **后台 pump 批量合并**  
   独立任务按「最多 100ms 或最多 200 行」合并成一块后再发布过程事件。Dispatcher 投递次数大约下降 1 到 2 个数量级。
3. **日志降级**  
   `PowerShellExecutor` 的逐行输出日志从 `LogInformation` 降为 `LogTrace`，避免日志 sink 成为第二个放大器。

命令结束时会 `TryComplete()` Channel 并等待 pump 排空，正常结束的输出不会因为批量窗口而丢失最后几行。取消执行时未排空的剩余块按取消语义丢弃。

### 6. 实时过程卡片滚动节流与内容上限

`UiChatOutputChannel` 处理过程事件时改为 `DispatcherPriority.Background`，让用户输入、点击等交互优先于逐块输出刷新。

过程卡片在 `running` 状态下的自动滚动增加 200ms 节流：

- 高频输出时不再每一行都触发 `ScrollViewer` 布局失效。
- 仍尊重用户向上滚动查看历史的行为（沿用原 `AutoScrollToBottom` 逻辑）。
- 过程完成、失败、取消等终态仍立即滚到底部，避免漏看结果。

单张过程卡片新增约 256 KB（128K 字符）内容上限：

- 超过上限后停止追加到界面缓冲区。
- 刷新时在卡片末尾显示截断提示：`输出已截断（超过 256 KB），完整内容已记录在执行结果中`。
- 目的是避免 `TextBlock` 全量重排成本随输出无限增长。

### 7. 文件工具 Native AOT 序列化补齐

文件浏览器内置工具在注册 `AIFunctionFactory.Create` 时，为以下工具显式传入源生成 `JsonSerializerOptions`：

- `sys_write_file`
- `sys_write_large_file`
- `sys_edit_file`
- `sys_delete_file`

`FileBrowserToolJsonContext` 额外注册 `bool?`，覆盖这些工具里常见的可选布尔参数（例如 `backup`）。Native AOT / 裁剪发布后，工具参数不再依赖运行时反射去发现这些类型，降低「工具能列出来但参数反序列化失败」的风险。

## 兼容性与迁移

- 不需要数据库迁移，不需要清理本地 `cortana.db`。
- 已有工作区、会话、插件、模型配置可直接沿用。
- 从 v1.3.10 升级：覆盖解压到原目录即可；建议先备份个人数据目录。
- 直接调用品牌发布脚本时，配置路径必须改为 `Build/brands/{brand}/{brand}.json`，旧路径 `Build/brands/{brand}.json` 已失效。
- 推荐统一使用 `Build/brands/publish.ps1 -Brand {brand}`，不要再直接传扁平 JSON 路径。
- 新增品牌必须同时提供 `{brand}.json`、`brand.ico`、`brand.png`；`resourceAssemblyName` 必须与 `desktopAssemblyName` 一致，否则 Avalonia 资源会加载失败。
- PowerShell 逐行输出日志默认不再出现在 Information 级别。需要逐行排查命令输出时，把日志级别调到 Trace。
- Channel 满时会丢弃新输出行。当前缓冲是 10000 行，正常命令几乎不会触发；极端刷屏场景下界面可能少显示中间若干行，完整结果仍以命令执行结果为准。
- 过程卡片界面截断不影响工具返回给模型的执行结果文本。

本版本**不包含**标签之后才合入的能力，例如：

- Kimi 专用协议与工具数量限制（`fd82216`，晚于 v1.3.11）
- 品牌发布图标缓存修复（`d310ded`，晚于 v1.3.11）
- 模型选择与管理交互增强（`370a1dd`，晚于 v1.3.11）

这些内容会在后续版本发布说明中单独记录，避免把未打进本 zip 的改动写成已发布。

## 风险与后续计划

- 品牌资源同步依赖发布脚本的 `finally` 恢复。若进程被强制杀掉，源码目录可能短暂留下其它品牌图标，下次发布前应核对 `Assets/brand.ico` 与 `Assets/brand.png`。
- Channel `DropWrite` 在极端刷屏时会丢弃中间输出行。若后续要保证「界面与结果完全一致」，需要改成阻塞写入或落盘旁路，而不是继续加大缓冲。
- 过程卡片 256 KB 截断只影响界面展示。如果后续要把完整输出提供给用户复制，应走执行结果或独立日志，而不是继续撑大 TextBlock。
- 文件工具目前只给写入/编辑/删除类补了源生成选项。读取类工具若在 AOT 下出现参数反序列化问题，按同样方式补 `JsonSerializerContext`。
- 标签 `v1.3.11` 之后已有 Kimi 协议、模型选择交互、图标缓存等提交，它们不属于本 zip，应在后续版本单独发布。
