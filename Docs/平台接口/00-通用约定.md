## 2. 通信与数据格式

### 2.1 地址与媒体类型

| 项目 | 当前实现 |
| --- | --- |
| 开发配置端口 | `appsettings.json` 中 `Server:HttpPort = 5190` |
| 示例服务地址 | `http://localhost:5190`；实际地址由运行配置和部署决定 |
| 普通业务前缀 | `/api/v1` |
| 非版本化前缀 | `/api` |
| JSON 请求 | `Content-Type: application/json` |
| JSON 成功响应 | `application/json`，通常带 `charset=utf-8` |
| 显式业务错误 | `application/problem+json` |
| 上传请求 | `multipart/form-data; boundary=...` |
| 下载成功响应 | `application/zip`，响应体为 ZIP 原始字节流 |

程序仅在 `Server:HttpPort > 0` 时调用 `UseUrls("http://*:{port}")`。开发启动配置同时列有 HTTP/HTTPS 地址，但不能据此认定部署环境已经启用 HTTPS。

### 2.2 身份认证

需登录的接口携带以下请求头：

```http
Authorization: Bearer <accessToken>
```

| 参数 | 位置 | 传输类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| `Authorization` | Header | `string` | 需登录接口为是 | `Bearer ` 加登录接口返回的完整 `accessToken` |

Token 是自定义 HMAC-SHA256 签名令牌，客户端应作为不透明字符串保存和回传。当前没有刷新令牌、注销或撤销令牌接口。登录签发的有效期为签发时刻起 30 天。

每次认证同时检查 Token 和数据库账号：账号必须存在且 `Status == 0`。缺少 Token、Token 无效/过期、账号不存在或账号被禁用时，受保护接口通常返回 `401` 空响应。登录时账号被禁用则返回 `403 ProblemDetails`；部分服务层分支也可能返回 `403`。

### 2.3 类型表示规则

| 文档写法 | C# 类型 | JSON 类型或传输格式 | 约束 |
| --- | --- | --- | --- |
| `string` | `string` | JSON string | 不自动代表非空字符串；非空要求见具体字段 |
| `string / null` | `string?` | JSON string 或 null | 可空；空字符串与 null 不同 |
| `int32` | `int` | JSON number，整数 | -2147483648 至 2147483647 |
| `int64` | `long` | JSON number，整数 | -9223372036854775808 至 9223372036854775807 |
| `byte` | `byte` | JSON number，整数 | 0 至 255 |
| `decimal` | `decimal` | JSON number | 十进制金额；不固定输出小数位，不输出为字符串 |
| `boolean` | `bool` | JSON boolean | `true` / `false` |
| `date-time` | `DateTimeOffset` | JSON string | ISO 8601，包含时区偏移；`*Utc` 表示 UTC 时间 |
| `EnumName` | 对应枚举，底层 `int` | JSON number，整数 | [枚举与状态值](./00-通用约定.md#3-枚举与状态值)列出合法业务取值 |
| `ModelName` | 对应 record | JSON object | 字段见[数据模型索引](./README.md#数据模型索引)中的同名模型 |
| `ModelName[]` | `IReadOnlyList<T>` / `List<T>` | JSON array | 元素类型为对应模型；空列表为 `[]` |
| `JsonValue / null` | `JsonElement?` | 任意合法 JSON 值或 null | 具体边界见 [manifest 类型与结构边界](./00-通用约定.md#25-manifest-的确定类型与结构边界) |
| `binary` | 上传文件 / `Stream` | multipart 文件部分或原始字节流 | 不使用 JSON 字节数组或 Base64 包装 |

JSON 属性使用 camelCase，例如 C# `AccessToken` 对应 `accessToken`。当前没有配置 `JsonStringEnumConverter`，因此 JSON 枚举使用整数；**非版本化市场列表的 `type` 是字符串**，这是服务显式调用 `ToString()` 的结果。

除特别说明外，成功对象直接作为响应根对象返回，没有统一的 `code/message/data` 包装。列表接口可能直接返回根数组，只有资源分页、客户端同步和更新检查有专用对象包装。

JSON 输出默认保留值为 null 的 DTO 属性。响应表的“可空”以 C# 声明为准；非可空字符串仍可能是 `""`，它不是数据库完整性保证。`int64` 字段在 JavaScript 中需要留意安全整数范围，金额字段需要按业务精度处理。

### 2.4 必填、缺失与默认值

本文区分“调用契约要求”与“当前代码检查”：

- 非可空请求字段按调用契约必须提交；可空请求字段可以省略或提交 null。
- `string` 非可空声明本身不等于服务端已验证非空，当前 JSON 配置没有启用 `RespectNullableAnnotations`、`RespectRequiredConstructorParameters`，也没有统一 DTO 验证管线。
- 请求 JSON 缺字段时可能被绑定为 null 或值类型默认值。没有显式检查的字段，不能承诺会得到稳定的 `400`；例如 `installedAssets` 为 null 可能引发未处理异常。
- [各功能文档的请求模型字段表](./README.md#数据模型索引)明确给出代码执行的非空检查、规范化及缺省处理。请按表提交完整有效数据，不依赖反序列化宽松行为。
- 路由路径参数均为非空路径段。Query 中的非可空 `page`、`pageSize` 必须实际提供；代码里的 `<= 0` 修正不是“省略参数的默认值”。

服务注入参数、`HttpContext` 和 `CancellationToken` 不是客户端参数，不需要在 HTTP 请求中发送。

### 2.5 manifest 的确定类型与结构边界

| 字段 | 确定的传输类型 | 当前结构保证 |
| --- | --- | --- |
| 提交请求 `manifestJson` | `string / null` | 字符串内容为 JSON 文本；空白或 null 替换为 `"{}"` |
| 响应 `manifest` | `JsonValue / null` | 将版本中的 `ManifestJson` 反序列化为 `JsonElement` 后嵌入响应 |

`manifestJson` 在请求中必须写成字符串，例如 `"{\"name\":\"demo\"}"`；响应中的 `manifest` 则是 JSON 值，例如 `{"name":"demo"}`，不再是转义字符串。

当前 API 没有为 manifest 定义统一 DTO 或 JSON Schema，也没有在提交入口统一验证 JSON 内容。因此只能确定它是 **object、array、string、number、boolean 或 null 的联合类型**，不能把内部业务字段编造成固定契约。空白存储内容返回 null；存储了非法 JSON 时，读取它的接口可能出现未处理异常。客户端只有在验证具体资源清单格式后，才能读取其中字段。

### 2.6 错误响应

显式 `Results.Problem(...)` 使用 `ProblemDetails`，字段如下：

| JSON 字段 | C# 类型 | JSON 类型 | 可空/可缺失 | 说明 |
| --- | --- | --- | --- | --- |
| `type` | `string?` | `string` | 是 | 错误类型 URI；框架可根据状态码填充 |
| `title` | `string?` | `string` | 是 | HTTP 状态标题；框架可填充 |
| `status` | `int?` | `number (int32)` | 是 | 本项目显式业务错误设置为对应 HTTP 状态码 |
| `detail` | `string?` | `string` | 是 | 业务错误描述；多数显式校验使用中文，上传接口也可能直接返回存储层异常原文，语言和内容不固定 |
| `instance` | `string?` | `string` | 是 | 错误实例标识；本项目没有显式设置 |
| 其他扩展字段 | `object?` | 任意 JSON 值 | 是 | 若框架或部署管线提供扩展，位于对象根部；不能假定存在 |

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.4",
  "title": "Forbidden",
  "status": 403,
  "detail": "当前账号没有该资源的有效订阅。"
}
```

上例只用于说明格式；`type` 和 `title` 的具体文字不作为稳定业务标识。

| 场景 | HTTP 状态 | 响应体 |
| --- | --- | --- |
| 显式业务校验失败 | `400` | `ProblemDetails` |
| `Results.Unauthorized()` | `401` | 空；不是 JSON null 或 `{}` |
| 显式无权限 | `403` | `ProblemDetails` |
| `Results.NotFound()` | `404` | 空；不能按 ProblemDetails 强制反序列化 |
| 显式资源/包冲突 | `409` | `ProblemDetails` |
| 请求绑定失败，如缺 Query、非法 JSON | 通常 `400` | 框架生成，当前程序未统一为 ProblemDetails |
| JSON 请求媒体类型不支持 | 通常 `415` | 框架生成，格式不固定 |
| 请求体超出服务器有效限制 | 可为 `413` 或框架错误 | 由服务器、表单及代理限制决定 |
| 未处理异常 | 通常 `500` | 当前没有统一错误处理器，内容取决于运行环境 |

虽然序列化上下文注册了验证错误类型，当前接口并未显式返回 `ValidationProblemDetails`，不能据此约定所有 `400` 都带 `errors` 字典。客户端应先判断状态码及 Content-Type，再决定读取 JSON、文本、空体或文件流。

### 2.7 接口与字段表阅读规则

各功能文档中的“无请求体”表示不需要 JSON Body；“无其他参数”表示没有业务 Query/Form 参数。需登录接口始终额外要求 `Authorization: string` Header。接口说明列出端点显式返回的业务状态；通用框架错误见[错误响应](#26-错误响应)。

DTO 字段表按功能分布在各文档中，具体位置见[数据模型索引](./README.md#数据模型索引)。响应表中的“可空”为 `是` 表示允许 JSON null；请求表的“必填”是调用契约要求，实际检查和默认值另行注明。JSON `number` 的整数位宽或十进制精度由 C# 列确定。

## 4. 当前契约边界与对接注意事项

以下是当前实现边界，不代表已修改程序。本文对能够由代码确定的类型已经明确列出；未建立结构约束或校验的部分如实说明。

### 4.1 已确定的公共行为

| 事项 | 当前规则 |
| --- | --- |
| ID 与 slug | ID 是不透明 string，不承诺 UUID 格式。仅部分接口接受 slug，见各路径参数说明 |
| 当前版本 | 优先 CurrentVersionId；为空或无法匹配时，回退版本 TimeStamp 倒序第一条；没有版本则为 null/对应错误 |
| 列表中的版本 ID | ApiAssetListItem.currentVersionId 使用资源记录原值，currentVersionName 来自回退选定版本，两者不能保证始终配对 |
| 有效授权 | 订阅 Active 且 expiresAtUtc > 当前时间；公开授权/同步同时要求资源 Published |
| 免费期限 | durationDays <= 0 并非时间上的永久，而是从基准时间加 20 年 |
| 付费续期 | 已有有效订阅时，从其到期时间继续增加期限；否则从当前时间开始 |
| 下载哈希 | 内置 Local/S3 存储计算 SHA256 并输出小写十六进制；成功下载前必须通过完整性校验 |
| 下载时间戳 | ApiDownloadRecord.timeStamp 为 Unix 秒级 int64，前端转 Date 时乘以 1000 |
| 时间戳依据 | Netor.Database.Abstractions 8.1.2 的 XML 注释将 Base.TimeStamp 定义为“创建时间(秒)”；仓库 AssetsController 也用 FromUnixTimeSeconds 读取此基类值 |
| 订单金额币种 | 收费方案有 currency，当前订单列表/详情/支付 DTO 没有 currency；不能从响应字段中读取不存在的币种 |
| 远端 IP | 下载记录来自 Connection.RemoteIpAddress；API 未显式注册 ForwardedHeaders，代理场景可能记录代理 IP |

### 4.2 实体层长度约束

接口请求 DTO 没有对应的 DataAnnotations 自动验证。以下来自实体 `StringLength`，用于明确持久化边界，不能理解为超长必然返回字段级 `400`；是否强制还取决于数据库提供方和实际表结构。

| API 字段 | 对应实体属性 | 声明最大长度 |
| --- | --- | --- |
| 创作者 `displayName` | CreatorProfile.DisplayName | 128 |
| 创作者 `bio` | CreatorProfile.Bio | 512 |
| 资源提交 `name` | Asset.Name | 128 |
| 资源提交 `slug` | Asset.Slug | 160 |
| 资源 `developerName` | Asset.DeveloperName | 128 |
| 资源提交 `shortDescription` | Asset.ShortDescription | 256 |
| 资源提交 `tags` | Asset.Tags | 512 |
| 资源 `iconUrl` / `coverUrl` | Asset.IconUrl / CoverUrl | 各 512 |
| 资源提交 `versionName` | AssetVersion.VersionName | 32 |
| 资源提交 `packageHash` | AssetVersion.PackageHash | 128 |
| 资源提交 `storageProvider` | AssetVersion.StorageProvider | 32 |
| 资源提交 `filePath` | AssetVersion.FilePath | 1024 |
| 资源提交 `currency` | PricingPlan.Currency | 16 |
| 收费方案 `name` | PricingPlan.Name | 64 |

`description`、`releaseNotes`、`manifestJson` 没有在上述实体声明 StringLength。没有统一的字段级格式错误对象和业务错误码。

### 4.3 尚未固定或未校验的部分

| 项目 | 当前现状 | 客户端对接要求 |
| --- | --- | --- |
| manifest 内部字段 | JsonElement 动态 JSON，没有统一 DTO/Schema | 按具体资源格式单独校验，不能假定所有资源都有同一组字段 |
| 必填 JSON 字段 | 没有统一 required/nullability 强制验证 | 按本文必填列发送，不依赖缺失值自动默认行为 |
| 提交数值范围 | 未统一拒绝负 packageSize/price、未定义 AssetType 等 | 发送有效枚举、真实包大小与合理非负金额 |
| 包提交校验 | 检查路径前缀和提供方配置，不在提交时重算哈希/大小或统一验证文件存在 | 使用上传接口原始结果；不能把提交成功等同于包可下载 |
| 分类与 slug 冲突 | 分类外键和并发唯一冲突可能在数据库层失败 | 使用有效 categoryId；不能将所有失败视为既定 400/409 |
| 错误体 | 显式 ProblemDetails、空 401/404、框架错误并存 | 按 HTTP 状态和 Content-Type 分别处理 |
| 分页 | 仅 `/api/v1/assets` 有分页；没有搜索、排序等参数 | 不向其他列表假设 page/pageSize 有效 |
| 更新判断 | 版本名相同即不更新；不比较版本大小 | 始终提交已安装 versionName，不把结果理解为严格 SemVer 升级判定 |
| 支付 | 模拟支付直接变更订单和授权，没有真实收款验证 | 对接时明确该端点的实际效果 |
| 幂等性 | 付费下单没有幂等键；下载 GET 会计数、写记录 | 重试时考虑重复订单和重复下载记录 |
| 上传容量 | 端点 200 MiB 请求限制不等于最终有效文件上限 | 结合表单、宿主、代理限制确认实际上传容量 |
| 标签、说明、版本格式 | tags 是 string；描述无统一富文本格式；版本名不强制 SemVer | 不自行假定标签数组、固定分隔符或版本语法 |

### 4.4 本项目当前没有提供的接口
