# 插件清单与能力声明

Native / Process 插件包根目录必须直接包含 `plugin.json`。宿主在启动插件前读取清单，用它确定运行时、入口文件、能力申请、设置字段和 PluginBus 事件契约。

## 一、plugin.json

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 插件唯一 ID，必填 |
| `name` | string | 显示名称，必填 |
| `version` | string | 插件版本 |
| `description` | string | 插件说明 |
| `runtime` | string | 新插件使用 `native` 或 `process`；`dotnet` 仅保留历史兼容 |
| `minHostVersion` | string | 最低宿主版本 |
| `abstractionsVersion` | string | 历史托管插件兼容字段 |
| `tags` | string[] | 分类标签 |
| `capabilities` | string[] | 历史能力字段 |
| `providedCapabilities` | string[] | 插件提供给宿主的能力，优先读取 |
| `requiredHostCapabilities` | object[] | 插件申请宿主提供的能力 |
| `settingsSchema` | object[] | 设置界面字段定义，不包含配置值 |
| `publishedOps` | object[] | 插件声明会发布的事件 op |
| `subscribedOps` | object[] | 插件声明会订阅的事件 op |
| `libraryName` | string | Native DLL 文件名；`runtime=native` 时必填 |
| `command` | string | Process 启动命令；`runtime=process` 时必填，相对路径基于插件目录 |

当前宿主校验至少要求 `id`、`name` 以及对应运行时的 `libraryName` / `command`。插件仍应提供稳定的语义版本和说明。

示例：

```json
{
  "id": "document_helper",
  "name": "Document Helper",
  "version": "1.0.0",
  "description": "Document tools",
  "runtime": "process",
  "command": "DocumentHelper.exe",
  "minHostVersion": "1.0.0",
  "tags": ["document"],
  "capabilities": ["document.parse"],
  "providedCapabilities": ["document.parse"],
  "requiredHostCapabilities": [
    {
      "id": "host.fs.workspace.read.v1",
      "purpose": "document.load",
      "required": true,
      "reason": "读取工作区中的文档。"
    }
  ],
  "settingsSchema": [
    {
      "key": "api_key",
      "label": "API Key",
      "type": "secret",
      "required": true,
      "sensitive": true,
      "scope": ["user"],
      "restartRequired": true
    }
  ],
  "publishedOps": [
    { "op": "document.index.updated.v1", "description": "索引已更新" }
  ],
  "subscribedOps": [
    { "op": "workspace.event.publish", "reason": "工作区切换后刷新索引" }
  ]
}
```

使用官方 C# SDK 时，Generator 负责输出清单；其他实现应在构建阶段生成或校验清单。

## 二、get_info

`get_info` 是插件启动后的动态元数据接口。Native 通过 `cortana_plugin_get_info` 返回 JSON；Process 通过 `get_info` 响应的 `data` 字符串返回 JSON。

当前返回结构包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` / `name` / `version` / `description` | string | 插件基础信息 |
| `instructions` | string? | 可选 AI 指令片段 |
| `tags` | string[]? | 分类标签 |
| `capabilities` | string[]? | 历史能力字段 |
| `providedCapabilities` | string[]? | 插件提供的能力 |
| `requiredHostCapabilities` | object[]? | 宿主能力申请 |
| `settingsSchema` | object[]? | 设置 schema |
| `tools` | object[] | 工具列表 |

`runtime`、`command`、`libraryName`、`minHostVersion`、`publishedOps` 和 `subscribedOps` 当前只从 `plugin.json` 读取，不属于 `get_info` 返回结构。

## 三、能力

`providedCapabilities` 表示插件提供什么能力。`capabilities` 是兼容字段；新清单应让两者保持一致。

常用值：

| capability | 用途 |
| --- | --- |
| `voice.kws` | 关键词唤醒 |
| `voice.stt` | 语音识别 |
| `voice.tts` | 语音合成 |
| `conversation.v1` | 对话 topic 能力声明 |
| `workflow.v1` | 工作模式 topic 能力声明 |
| `meeting.v1` | 会议 topic 能力声明 |
| `memory.v1` | 长期记忆能力 |

能力 ID 是宿主与插件约定的稳定 token，不是工具名，也不是事件 op。

## 四、宿主能力申请

`requiredHostCapabilities` 每项包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 宿主能力 ID |
| `purpose` | string? | 具体用途 token |
| `required` | boolean | 核心功能是否依赖该能力 |
| `reason` | string? | 面向用户的授权说明 |

声明只表示申请，不表示已经授权。`required: false` 的能力不可用时，插件应降级；`required: true` 的能力不可用时，应对相关操作返回清晰错误。

## 五、设置 schema

`settingsSchema` 每项支持：

- `key`、`label`、`description`
- `type`：`string`、`secret`、`number`、`boolean`、`enum`、`path`、`json`
- `defaultValue`、`required`、`sensitive`
- `scope`、`options`
- `validation.min`、`validation.max`、`validation.minLength`、`validation.maxLength`、`validation.pattern`
- `restartRequired`

`settingsSchema` 只定义界面和存储规则。真实配置值由宿主在 `init.extensions` 中注入。敏感值不得写入 `plugin.json`、日志或工具结果。

## 六、事件契约

`publishedOps` 和 `subscribedOps` 是 PluginBus 1.4.0 的静态声明：

```json
{
  "publishedOps": [
    { "op": "voice.stt.final.v1", "description": "最终识别文本" }
  ],
  "subscribedOps": [
    { "op": "voice.tts.started.v1", "reason": "播放期间暂停识别" }
  ]
}
```

- 发布声明用于宿主弱校验；未声明的发布只记录警告，当前不会强制拒绝。
- 订阅声明用于清单和审计；运行时是否接收事件仍由 WebSocket `subscribe` 帧决定。
- op 首段决定 topic 路由，例如 `voice.stt.final.v1` 路由到 `voice`。
- RPC 和控制 op 不能作为 `type: "event"` 发布。

完整运行时协议见 [插件事件总线开发指南.md](插件事件总线开发指南.md)。

## 七、C# 示例（使用官方 SDK）

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin;

[Plugin(
    Id = "document_helper",
    Name = "Document Helper",
    Version = "1.0.0",
    Capabilities = ["document.parse"])]
[RequiredHostCapability(
    Id = "host.fs.workspace.read.v1",
    Purpose = "document.load",
    Required = true,
    Reason = "读取工作区中的文档。")]
[PluginSetting(
    Key = "api_key",
    Label = "API Key",
    Type = PluginSettingType.Secret,
    Required = true,
    Sensitive = true,
    Scope = ["user"],
    RestartRequired = true)]
[PublishesEvent("document.index.updated.v1", Description = "索引已更新")]
[SubscribesEvent("workspace.event.publish", Reason = "工作区切换后刷新索引")]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
    }
}
```

Process 使用 `Netor.Cortana.Plugin` 命名空间；Native 使用 `Netor.Cortana.Plugin.Native`。这些 Attribute 均叠加在唯一的 `[Plugin]` 入口类上。
