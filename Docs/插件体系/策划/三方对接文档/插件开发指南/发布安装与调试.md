# 发布安装与调试

Native / Process 插件按完整目录或 zip 包发布。MCP Server 使用连接配置，不走插件包安装流程。

## 一、插件包结构

插件根目录必须直接包含 `plugin.json`，不能再额外嵌套一层同名目录。

Process 示例：

```text
your-process-plugin/
  plugin.json
  YourProcessPlugin.exe
  YourProcessPlugin.dll
  YourProcessPlugin.deps.json
  models/
  templates/
```

Native 示例：

```text
your-native-plugin/
  plugin.json
  YourNativePlugin.dll
  models/
```

发布物应包含运行所需的全部依赖和资源，不依赖开发机源码目录。

## 二、通用验证

发布前至少完成：

1. `plugin.json` 是有效 JSON，`id`、`name`、`runtime` 和入口字段正确。
2. `command` / `libraryName` 指向包内实际文件。
3. `get_info` 可调用，工具列表与清单能力一致。
4. `init` 可接受真实目录和 PluginBus 扩展字段。
5. 每个工具至少验证一条成功路径。
6. 有输入约束的工具至少验证一条失败或边界路径。
7. `destroy`、stdin 关闭或宿主退出时能释放后台服务和文件句柄。
8. stdout 不混入日志，敏感配置不出现在日志和工具结果中。

非 C# 实现还应直接做通道冒烟：Process 验证四种单行 JSON 请求；Native 验证导出入口、UTF-8、返回指针和 `free`。

## 三、C# Process 发布

```powershell
dotnet build .\Samples\YourProcessPlugin\YourProcessPlugin.csproj
dotnet run --project .\Samples\YourProcessPlugin\YourProcessPlugin.csproj -- --self-test

.\skills\plugin-development\scripts\publish-process-plugin.ps1 `
  -ProjectDir 'Samples\YourProcessPlugin' `
  -SkipDeploy `
  -CreateZip
```

发布模式：

| 参数 | 模式 |
| --- | --- |
| 默认 | win-x64 JIT self-contained |
| `-FrameworkDependent` | 依赖目标机器 .NET 10 Runtime |
| `-Aot` | Native AOT exe |

`-FrameworkDependent` 与 `-Aot` 不能同时使用。脚本会校验发布目录中存在 exe 和 `plugin.json`，并默认把 zip 输出到 `Realases/PluginPackages`。

当前共享脚本只复制发布目录根级文件，不会自动递归复制 `models/`、`templates/` 等子目录。带资源的插件必须扩展打包步骤并检查最终 zip。

## 四、C# Native 调试与发布

Native Debugger 是类库，不能把它的 csproj 当作可执行项目并传入发布 DLL。应运行脚手架生成的 Debug Console：

```powershell
dotnet build .\Samples\YourNativePlugin\YourNativePlugin.csproj
dotnet run --project .\Samples\YourNativePlugin\Debug\YourNativePlugin.Debug.csproj
```

完成工具验证后执行 AOT 发布：

```powershell
.\skills\plugin-development\scripts\publish-native-plugin.ps1 `
  -ProjectDir 'Samples\YourNativePlugin' `
  -SkipDeploy `
  -CreateZip
```

Native AOT 需要 Visual Studio“使用 C++ 的桌面开发”工作负载。Debug Console 通过不代表 AOT 发布通过，最终 DLL 还要核对导出入口。

当前 Native 发布脚本只组装 Native DLL 和 `plugin.json`；其他资源同样需要显式加入 staging。

## 五、AOT 约束

C# Native 项目应启用：

```xml
<PublishAot>true</PublishAot>
<JsonSerializerIsReflectionEnabledByDefault>false</JsonSerializerIsReflectionEnabledByDefault>
```

自定义工具返回类型和事件 payload 必须注册到 `JsonSerializerContext`。发布时应处理所有 trim/AOT 警告，不能只验证普通 `dotnet build`。

## 六、zip 结构

安装器接受两种 zip：

- zip 根目录直接包含 `plugin.json` 和运行文件。
- zip 根目录只有一个插件目录，该目录直接包含 `plugin.json`。

不允许 `plugin.json` 位于更深层级。安装器会校验 zip、JSON 和安装后的目录结构。

## 七、安装与更新

安装目录必须由宿主的 `sys_get_user_plugins_directory` 返回，不手工拼接。更新已加载插件的顺序为：

1. `sys_list_loaded_plugins`
2. `sys_unload_plugin(dirName)`
3. 调用插件安装脚本覆盖安装
4. `sys_reload_plugin(dirName)`
5. 再次查询已加载插件并验证工具

仓库内安装入口：

```powershell
.\skills\plugin-development\subskills\publish-install\scripts\install-plugin-package.ps1 `
  -PackageType plugin `
  -SourcePath '<plugin.zip>' `
  -InstallDirectory '<sys_get_user_plugins_directory 返回值>' `
  -Force
```

不要在插件仍加载时直接覆盖 DLL 或 exe。重载完成后需要切换一次智能体，使工具上下文刷新。
