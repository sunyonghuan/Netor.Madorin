# 插件事件总线开发指南

PluginBus 1.4.0 事件总线（pub-sub）开发指南。

适用于 Native / Process 两种插件通道；MCP 通道不参与事件总线。

## 一、什么时候用事件总线

事件总线用于**一对多、单向、不等响应**的状态变化通知。典型场景：

- 语音插件触发唤醒或识别 → 字幕、桌宠、状态指示器联动
- 文件插件感知工作区变更 → 索引、AI 辅助插件级联处理
- 记忆插件刷新索引 → 上下文检索插件重载

**不适合事件总线**的场景：

| 场景 | 应选 | 原因 |
|---|---|---|
| 需要等结果（RPC） | `model.capability.request` / `memory.context.supply.request` | 同步请求-响应，需要 `requestId` 关联 |
| 一对一聊天数据流 | `conversation.chat.message.send` / `system.notice` | 控制平面，不属于 pub-sub |
| 跨进程会话续传 | 不要复用事件总线 | 事件总线不持久、不重放 |

## 二、协议形态（PluginBus 1.4.0）

事件帧使用统一信封式 `type: "event"`：

```json
{
  "type": "event",
  "op": "voice.kws.detected.v1",
  "sourcePluginId": "voice_kws_sherpa",
  "payload": {
    "text": "小娜",
    "sessionId": "..."
  }
}
```

| 字段 | 说明 |
|---|---|
| `type` | 固定 `"event"` |
| `op` | 事件 op，权威标识。形如 `{namespace}.{name}.v{n}`，`{namespace}` 必须等于 topic（详见 §四） |
| `sourcePluginId` | 推荐填，等于 `plugin.json.id`；宿主用于弱声明校验，不作安全依据 |
| `payload` | 业务负载，`JsonElement`，必须 JSON-serializable |

宿主侧由 `PluginBusBroadcastDispatcher` 接收并按订阅关系转发，单帧 ≤ 1MB，hopCount 上限 8 跳。

## 三、声明事件契约

### 3.1 发布方：`[PublishesEvent]`

在入口类（`Startup`）上叠加 attribute，每个 op 一条：

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin;

namespace Cortana.Plugins.Voice.Stt.Sherpa;

[Plugin(
    Id = "voice_stt_sherpa",
    Name = "Sherpa ONNX 语音识别",
    Version = "0.1.2",
    Capabilities = ["voice.stt"])]
[PublishesEvent("voice.stt.partial.v1", Description = "实时识别中文本")]
[PublishesEvent("voice.stt.final.v1", Description = "最终识别文本")]
[PublishesEvent("voice.stt.stopped.v1", Description = "识别会话已停止")]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<SttPluginBusClient>();
    }
}
```

| attribute 字段 | 必填 | 用途 |
|---|---|---|
| `Op`（构造参数） | ✅ | 事件 op，全小写 + 点号分隔 + `.v{n}` 版本号 |
| `Description` | 否 | 事件用途说明，运维审计用，非校验依据 |

**约束**：

- 必须叠加在 `[Plugin]` 入口类上
- 每个 op 一条 attribute；同 op 重复叠加由 Generator 去重
- op 必须出现在 `[PublishesEvent]` 中，否则宿主收到时仅 LogWarning（不强拒，详见 §六）

### 3.2 订阅方：`[SubscribesEvent]`

```csharp
[Plugin(
    Id = "subtitle_overlay",
    Name = "字幕浮层",
    Version = "1.0.0")]
[SubscribesEvent("voice.stt.partial.v1", Reason = "实时显示识别中文本")]
[SubscribesEvent("voice.stt.final.v1", Reason = "确认最终字幕")]
[SubscribesEvent("voice.tts.subtitle.v1", Reason = "显示 TTS 字幕")]
public static partial class Startup
{
}
```

| attribute 字段 | 必填 | 用途 |
|---|---|---|
| `Op`（构造参数） | ✅ | 要订阅的事件 op |
| `Reason` | 否 | 订阅理由，运维审计用 |

### 3.3 Generator 输出

构建后 `plugin.json` 自动生成两个字段（对象数组）：

```json
{
  "publishedOps": [
    { "op": "voice.stt.partial.v1", "description": "实时识别中文本" }
  ],
  "subscribedOps": [
    { "op": "voice.tts.subtitle.v1", "reason": "显示 TTS 字幕" }
  ]
}
```

不要手工维护这两个字段。

## 四、op 命名规范

op 命名格式：`{topic}.{name}.v{n}`，例如 `voice.stt.partial.v1`。

**op 首段必须等于 topic**——宿主 BroadcastDispatcher 按 `op.Split('.')[0]` 直接路由到对应 topic 的订阅者集合，不维护别名表。

| 已有 topic | 用途 | 命名空间约束 |
|---|---|---|
| `voice` | 语音三件套（KWS / STT / TTS） | `voice.{name}.v{n}` |
| `conversation` | 对话流（含 `conversation.chat.*`） | `conversation.{name}.v{n}` |
| `memory` | 记忆 RPC + 未来事件 | plugin→plugin 事件必须用 `memory.event.{name}.v{n}` 子命名空间，避开 `memory.context.supply.*` RPC |
| `model` | 模型能力 RPC + 未来事件 | plugin→plugin 事件必须用 `model.event.{name}.v{n}` 子命名空间，避开 `model.capability.*` RPC |
| `workflow` | 工作模式事件 | `workflow.{name}.v{n}` |
| `meeting` | 会议模式事件 | `meeting.{name}.v{n}` |
| `workspace` | 工作区状态变更（宿主广播，只读） | `workspace.{name}.v{n}` |

**版本号**：op 末尾 `.v{n}` 是契约版本号。新增向下兼容字段不升号；删除/重命名字段或调整语义必须升号（`voice.stt.partial.v1` → `voice.stt.partial.v2`），新老插件并存期由消费方自行选择订阅哪一版。

## 五、SDK 用法

### 5.1 PluginBusClient（共享 SDK）

`Netor.Cortana.Plugin.Process` 包提供 `PluginBusClient`，Native 与 Process 通道都可用。两种构造方式：

```csharp
// 不带 sourcePluginId（事件帧不带该字段，弱声明校验时由 source 兜底）
new PluginBusClient(settings, logger);

// 推荐：传 plugin.json 的 id（弱声明校验更友好）
new PluginBusClient(settings, sourcePluginId: "voice_stt_sherpa", logger);
```

注册到 DI 容器：

```csharp
public static void Configure(IServiceCollection services)
{
    services.AddLogging();
    services.AddSingleton<PluginBusClient>(sp => new PluginBusClient(
        sp.GetRequiredService<PluginSettings>(),
        sourcePluginId: "voice_stt_sherpa",
        sp.GetService<ILogger<PluginBusClient>>()));

    services.AddSingleton<SttPluginBusClient>();
}
```

`PluginBusClient` 实现 `IHostedService`，由插件宿主自动 Start/Stop。`StartAsync` 是占位，连接按需懒建立——首个 `PublishEventAsync` / `SubscribeEventAsync` 调用时再连。

### 5.2 发布事件：`PublishEventAsync`

```csharp
public Task PublishEventAsync(
    string op,
    JsonElement payload,
    CancellationToken cancellationToken = default)
```

**约束**：

- 严格 AOT，参数只接 `JsonElement`，不接 `T payload`（避免反射序列化）
- 调用方负责把业务对象先序列化为 `JsonElement`，必须自带 `JsonSerializerContext`
- 空 op 抛 `ArgumentException`
- 连接缺失（`PluginBusEndpoint` 未配置）时静默跳过——插件不要假设事件一定送达

### 5.3 类型化包装范式（推荐）

直接用 `PluginBusClient` 容易写错 op 字符串。生产代码建议为每个发布方做一层类型化包装。Sherpa STT 实例：

```csharp
using System.Text.Json;
using Netor.Cortana.Plugin.PluginBus;

namespace Cortana.Plugins.Voice.Stt.Sherpa;

/// <summary>
/// STT 插件的 PluginBus 类型化包装：通过共享 SDK 客户端发布 voice.stt.{partial,final,stopped}.v1。
/// </summary>
public sealed class SttPluginBusClient(PluginBusClient bus)
{
    public Task PublishPartialAsync(string text, string? sessionId, CancellationToken cancellationToken = default)
        => PublishAsync("voice.stt.partial.v1", text, sessionId, cancellationToken);

    public Task PublishFinalAsync(string text, string? sessionId, CancellationToken cancellationToken = default)
        => PublishAsync("voice.stt.final.v1", text, sessionId, cancellationToken);

    public Task PublishStoppedAsync(string? sessionId, CancellationToken cancellationToken = default)
        => PublishAsync("voice.stt.stopped.v1", null, sessionId, cancellationToken);

    private Task PublishAsync(string op, string? text, string? sessionId, CancellationToken cancellationToken)
    {
        var payload = JsonSerializer.SerializeToElement(
            new SttPluginBusEventPayload { Text = text, SessionId = sessionId },
            PluginJsonContext.Default.SttPluginBusEventPayload);
        return bus.PublishEventAsync(op, payload, cancellationToken);
    }
}
```

事件 payload POCO（`PluginBus/SttPluginBusEvent.cs`）：

```csharp
internal sealed record SttPluginBusEventPayload
{
    [JsonPropertyName("text")]
    public string? Text { get; init; }

    [JsonPropertyName("sessionId")]
    public string? SessionId { get; init; }
}
```

注册到插件自己的 `PluginJsonContext`（AOT 强约束）：

```csharp
[JsonSerializable(typeof(SttPluginBusEventPayload))]
internal partial class PluginJsonContext : JsonSerializerContext;
```

工具方法内部使用包装：

```csharp
[Tool(Name = "voice_stt_emit_partial", Description = "向宿主发送一条 STT partial 事件。")]
public async Task<string> EmitPartial(
    [Parameter(Name = "text", Description = "识别中的临时文本。")] string text,
    [Parameter(Name = "session_id", Description = "可选会话标识。", Required = false)] string? sessionId)
{
    var status = state.SetPartial(text);
    await pluginBus.PublishPartialAsync(text, sessionId).ConfigureAwait(false);
    return Serialize(SttToolResult.Success("STT partial 已发送。", status));
}
```

### 5.4 订阅事件：`SubscribeEventAsync`

```csharp
public Task SubscribeEventAsync(
    string op,
    Func<JsonElement, Task> handler,
    CancellationToken cancellationToken = default)
```

**行为**：

- 重复订阅同一 op 会覆盖旧 handler
- 首次调用时向宿主发送 `subscribe` 帧（`topics` 取所有已订阅 op 的首段，`subscribedOps` 即所有已注册 op）
- handler 在后台接收循环里串行调用；handler 内部抛异常仅记录日志，不终止接收循环

订阅示例：

```csharp
public sealed class SubtitleSubscriber(PluginBusClient bus, ISubtitleView view)
{
    public async Task StartAsync(CancellationToken ct)
    {
        await bus.SubscribeEventAsync(
            "voice.stt.partial.v1",
            payload =>
            {
                var text = payload.TryGetProperty("text", out var t) ? t.GetString() : null;
                view.UpdatePartial(text ?? string.Empty);
                return Task.CompletedTask;
            },
            ct).ConfigureAwait(false);

        await bus.SubscribeEventAsync(
            "voice.stt.final.v1",
            payload =>
            {
                var text = payload.TryGetProperty("text", out var t) ? t.GetString() : null;
                view.CommitFinal(text ?? string.Empty);
                return Task.CompletedTask;
            },
            ct).ConfigureAwait(false);
    }
}
```

**handler 内 payload 处理建议**：

- 用 `JsonElement.TryGetProperty` 读字段，不要假设字段存在
- 大 payload 字段（如二进制）应避免在 handler 内长时间持有
- handler 不要做阻塞操作；后台投递有 1 秒超时，超时连接会被宿主清理

## 六、宿主行为参考

插件作者只需理解三件事，便于排查链路问题：

1. **op 必须显式声明**：发布方 `plugin.json.publishedOps` 缺该 op 时宿主 LogWarning，但仍转发；建议把所有发布的 op 都通过 `[PublishesEvent]` 声明
2. **路由按 op 首段**：`op.Split('.')[0]` 等于 topic，决定哪些订阅者收到
3. **受保护 op 黑名单**：宿主对已有 RPC / 控制 op 设置黑名单（`conversation.chat.message.send` / `conversation.chat.generation.stop` / `model.capability.request` / `memory.context.supply.*` 等）；若插件误标这些 op 为 `type=event`，宿主立即 LogWarning 拒收，**不**会路由

宿主完整设计详见 [插件事件广播策划文档](../../已完成功能规划/插件事件广播/README.md)。

## 七、限制与注意事项

| 限制 | 说明 |
|---|---|
| 单帧 ≤ 1MB | 宿主 BroadcastDispatcher 入口校验，超过即丢弃 + LogWarning |
| hopCount ≤ 8 | 防事件循环；超过即丢弃 |
| 1 秒投递超时 | 慢/死订阅者由宿主主动清理（移除订阅 + 关闭连接），订阅插件应避免在 handler 内长阻塞 |
| 不保证 ordering | v1 多帧并发投递可能错序送达；订阅方应按"总是用最新值覆盖"模式编写（如 partial 字幕直接覆盖显示，不假设按顺序累积） |
| fire-and-forget | 业务侧不等订阅方响应；事件丢失（订阅方未连接、超时、payload 解析失败）插件**无法感知** |
| 不持久化 | 宿主重启即清空，事件不重放 |

## 八、AOT 强约束

整个软件 AOT 编译，事件总线相关代码必须满足：

- `PublishEventAsync` 参数只接 `JsonElement`，调用方自带 `JsonSerializerContext` 序列化
- 所有事件 payload POCO 必须在插件自己的 `JsonSerializerContext` 中注册
- 不要在 handler 内反射，不要 `JsonSerializer.Deserialize<T>(string)` 反射重载
- 插件自身 csproj 必须 `<PublishAot>true</PublishAot>` + `<JsonSerializerIsReflectionEnabledByDefault>false</JsonSerializerIsReflectionEnabledByDefault>`

发布前验证：`dotnet publish` 0 个 trim warning、0 个 AOT warning。

## 十、宿主广播事件（Host → Plugin）

以下事件由宿主主动推送，插件只需订阅，不能也无需发布。

### 10.1 `workspace.event.publish` — 工作区目录变更

用户切换工作目录时，宿主通过 `workspace` topic 广播此事件。进程插件若持有工作目录（用于文件监听、路径拼接、索引等），必须订阅此事件并更新本地状态。

**payload 结构：**

```json
{
  "path": "D:/MyWorkspace"
}
```

**订阅方式：**

```csharp
await bus.SubscribeEventAsync(
    "workspace.event.publish",
    payload =>
    {
        var path = payload.TryGetProperty("path", out var p) ? p.GetString() : null;
        if (path is not null)
            myService.UpdateWorkspacePath(path); // 重建文件监听、刷新索引等
        return Task.CompletedTask;
    }, ct).ConfigureAwait(false);
```

在入口类声明订阅：

```csharp
[SubscribesEvent("workspace.event.publish", Reason = "工作目录变更时同步本地路径")]
public static partial class Startup { ... }
```

**注意事项：**

- 该 op 由宿主发出，插件的 `publishedOps` 中不要声明它
- Native 插件通过 `IPluginContext.WorkspaceDirectory`（computed property，每次读取均为最新值）获取当前工作目录，无需订阅此事件
- 进程插件无法访问 `IPluginContext`，必须依赖此事件感知目录变更；若插件在 `InitializeAsync` 阶段缓存了启动时的工作目录，需在此事件中更新缓存
