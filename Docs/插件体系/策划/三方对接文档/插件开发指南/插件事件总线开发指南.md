# 插件事件总线开发指南

PluginBus 1.4.0 使用 WebSocket 在宿主和 Native / Process 插件之间传递消息。事件通道用于单向、一对多、无需响应的状态通知；MCP 通道不参与该总线。

## 一、连接

宿主通过 `init` 注入以下连接信息：

- `extensions.pluginBusEndpoint`：当前端点通常为 `ws://localhost:{port}/internal`
- `extensions.pluginBusProtocol`：`cortana.plugin-bus`
- `extensions.pluginBusVersion`：当前为 `1.4.0`
- `extensions.pluginBusPort`

未提供端点时，可以在 `wsPort > 0` 的情况下使用 `ws://localhost:{wsPort}/internal`。

连接建立后，宿主会发送 `connected` 控制帧。客户端应忽略不认识的控制帧，并在收到 `ping` 时回复：

```json
{"type":"pong"}
```

## 二、发布事件

最小发布帧：

```json
{
  "type": "event",
  "op": "voice.stt.final.v1",
  "sourcePluginId": "voice_stt",
  "payload": {
    "text": "识别结果",
    "sessionId": "session-001"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | string | 固定为 `event` |
| `op` | string | 事件标识，路由时优先于 `eventType` 和 `type` |
| `sourcePluginId` | string? | 建议填 `plugin.json.id`，只用于弱声明校验 |
| `payload` | 任意 JSON | 业务负载；SDK 以 `JsonElement` 承载 |
| `hopCount` | integer? | 插件首次发布可省略；宿主转发前递增 |

宿主会保留原帧字段，只重写或补充 `hopCount`。订阅方因此可以按同一结构读取 `type`、`op` 和 `payload`。

## 三、订阅事件

客户端发送 `subscribe` 帧：

```json
{
  "type": "subscribe",
  "protocol": "cortana.plugin-bus",
  "version": "1.4.0",
  "topics": ["voice", "workspace"],
  "subscribedOps": [
    "voice.stt.final.v1",
    "workspace.event.publish"
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | string | 固定为 `subscribe` |
| `protocol` | string | 必须为 `cortana.plugin-bus`；不匹配时宿主返回错误 |
| `version` | string | 客户端协议版本；当前宿主接收但不据此拒绝连接 |
| `topics` | string[] | 粗粒度订阅；缺省时宿主使用 `conversation` |
| `subscribedOps` | string[] | 精确 op 过滤；缺省或空数组表示接收 topic 下全部 op |

宿主成功处理后返回 `subscribed` 控制帧。重复发送会覆盖该连接原有的 topic 和 op 集合。

## 四、路由规则

宿主从 op 第一个点号前提取 topic：

```text
voice.stt.final.v1 -> voice
workspace.event.publish -> workspace
```

事件只发送给同时满足以下条件的连接：

1. 已订阅该 topic。
2. `subscribedOps` 为空，或包含该完整 op。
3. 不是原始发布连接。

插件自定义事件建议使用 `{topic}.{domain}.{name}.v{n}`，并把不兼容的 payload 变化升级为新版本。宿主当前不强制校验 `.v{n}` 后缀，但路由始终取 op 首段。

`connected` 控制帧当前列出 `conversation`、`memory`、`model`、`plugin`、`workflow`、`meeting` 和 `workspace`。订阅注册表也接受 `voice`；宿主广播分发器会按首段正常路由，并额外桥接已知语音 op。

## 五、禁止作为事件发布的 op

下列请求/响应或控制 op 受宿主保护，不能使用 `type: "event"` 发布：

- `conversation.chat.message.send`
- `conversation.chat.generation.stop`
- `system.notice`
- `conversation.history.replay`
- `workflow.history.replay`
- `meeting.history.replay`
- `model.capability.request`
- `model.capability.response`
- `memory.context.supply.request`
- `memory.context.supply.response`
- `memory.context.supply.error`

需要响应时使用对应请求/响应协议，不走事件广播。

## 六、清单声明

发布方在 `plugin.json.publishedOps` 声明：

```json
{
  "publishedOps": [
    { "op": "voice.stt.final.v1", "description": "最终识别文本" }
  ]
}
```

订阅方在 `plugin.json.subscribedOps` 声明：

```json
{
  "subscribedOps": [
    { "op": "voice.stt.final.v1", "reason": "显示最终字幕" }
  ]
}
```

清单声明和运行时订阅作用不同：

- 发布声明缺失时，宿主记录警告但仍转发。
- 订阅清单用于发现和审计，不会自动建立 WebSocket 订阅。
- 运行时必须发送 `subscribe` 帧才能接收事件。
- 当前 `get_info` 不返回 `publishedOps` / `subscribedOps`。

## 七、限制

| 限制 | 当前行为 |
| --- | --- |
| 帧大小 | 超过 1 MB 时丢弃并记录警告 |
| hopCount | 达到 8 时丢弃 |
| 单订阅者发送超时 | 1 秒；超时连接会被移除和关闭 |
| 可靠性 | 不确认、不持久化、不重放 |
| 顺序 | 不保证跨事件投递顺序 |
| 发布结果 | 发布方无法获知各订阅方是否处理成功 |

高频状态事件应采用“最新值覆盖”模式。需要可靠完成信号时，另行设计工具调用或请求/响应协议。

## 八、宿主事件

### workspace.event.publish

工作区变化时，宿主向 `workspace` topic 广播：

```json
{
  "type": "event",
  "protocol": "cortana.plugin-bus",
  "version": "1.4.0",
  "topic": "workspace",
  "op": "workspace.event.publish",
  "source": "host",
  "eventType": "workspace.changed",
  "payload": {
    "Path": "D:/MyWorkspace",
    "ID": "<event-id>"
  }
}
```

当前 payload 由 `WorkspaceChangedArgs` 直接序列化，字段名区分大小写。消费方必须读取 `Path`，不能读取 `path`；`ID` 是事件基类字段，值可能为空或由事件系统填充，不应用作工作区路径。

只接收该事件的插件应在 `subscribedOps` 中声明，并发送：

```json
{
  "type": "subscribe",
  "protocol": "cortana.plugin-bus",
  "version": "1.4.0",
  "topics": ["workspace"],
  "subscribedOps": ["workspace.event.publish"]
}
```

## 九、C# 示例（Process 官方 SDK）

Process 宿主会注册 `Netor.Cortana.Plugin.Process` 包中的 `PluginBusClient`。它使用 Process 版 `PluginSettings`，首次发布或订阅时按需连接。

### 清单声明

```csharp
[PublishesEvent("voice.stt.final.v1", Description = "最终识别文本")]
[SubscribesEvent("workspace.event.publish", Reason = "工作区变化后刷新索引")]
public static partial class Startup
{
}
```

### 发布

```csharp
var payload = JsonSerializer.SerializeToElement(
    new SttPayload("识别结果", "session-001"),
    PluginJsonContext.Default.SttPayload);

await bus.PublishEventAsync("voice.stt.final.v1", payload);
```

### 订阅

```csharp
await bus.SubscribeEventAsync(
    "workspace.event.publish",
    payload =>
    {
        if (payload.TryGetProperty("Path", out var value))
        {
            workspaceState.Update(value.GetString() ?? string.Empty);
        }

        return Task.CompletedTask;
    },
    stoppingToken);
```

重复订阅同一 op 会覆盖旧 handler。所有 handler 在该客户端的接收循环中串行执行；handler 异常只记录日志，不终止循环。

发布 payload 的自定义类型必须注册到插件自己的 `JsonSerializerContext`：

```csharp
[JsonSerializable(typeof(SttPayload))]
internal partial class PluginJsonContext : JsonSerializerContext;
```

## 十、Native 接入

事件线协议同样适用于 Native 插件，但 `Netor.Cortana.Plugin.Process` 中的 `PluginBusClient` 构造函数依赖 Process 版 `PluginSettings`，不能直接注入 Native 版 `Netor.Cortana.Plugin.Native.PluginSettings`。

当前 Native SDK 没有等价的内置 PluginBus 客户端。Native 插件需要使用 `PluginSettings.PluginBusEndpoint` 自行实现 WebSocket 发布、订阅、ping/pong 和重连，或提供一个显式适配层；不能把 Process 客户端当作 Native 内置服务使用。
