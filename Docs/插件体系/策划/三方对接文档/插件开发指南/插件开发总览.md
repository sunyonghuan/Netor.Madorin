# 插件开发总览

## 一、插件通道

| 通道 | 交付物 | 宿主调用方式 | 适用场景 |
| --- | --- | --- | --- |
| Native | `plugin.json` + 原生 DLL | 加载 DLL 并调用固定导出入口 | 本地高性能、快速启动、Native AOT |
| Process | `plugin.json` + 可执行程序及依赖 | stdin/stdout 单行 UTF-8 JSON | 进程隔离、JIT、模型、外部 SDK、长任务 |
| MCP | MCP Server 连接配置 | stdio / SSE / Streamable HTTP | 已有 MCP 服务、远程工具、标准生态接入 |

Native 和 Process 的宿主接口只约束交付物与运行时行为。能够生成兼容原生 DLL 的工具链可以实现 Native 插件；能够启动为子进程并读写标准输入输出的语言可以实现 Process 插件。MCP Server 按 MCP 规范实现。

新开发通常优先选择 Native 或 MCP。只有需要 JIT、反射、动态编译、复杂依赖隔离或独立崩溃边界时，再选择 Process。

## 二、运行时契约

### Process

宿主启动 `plugin.json.command` 指定的程序。请求和响应均为一行一个 JSON 对象：

1. `get_info`：获取插件与工具元数据。
2. `init`：注入目录、端口和扩展参数。
3. `invoke`：按完整工具名调用工具。
4. `destroy`：释放资源，响应后退出进程。

完整字段见 [Process插件开发指南.md](Process插件开发指南.md)。

### Native

宿主加载 `plugin.json.libraryName` 指定的 DLL，并查找以下入口：

- 必需：`cortana_plugin_get_info`、`cortana_plugin_invoke`、`cortana_plugin_free`
- 可选：`cortana_plugin_init`、`cortana_plugin_destroy`

所有字符串均为以 NUL 结尾的 UTF-8 字符串。插件返回的字符串由插件分配，宿主读取后调用 `cortana_plugin_free` 释放。完整签名见 [Native插件开发指南.md](Native插件开发指南.md)。

### MCP

MCP 不使用 Madorin 的 `plugin.json`、Native ABI 或 Process 消息循环。宿主保存 MCP Server 的传输方式、命令或 URL、参数、环境变量和认证配置，然后按 MCP 协议发现与调用工具。

## 三、清单与动态元数据

Native / Process 插件包根目录必须直接包含 `plugin.json`。它负责静态发现、运行时选择、启动文件定位、能力与设置声明。

插件启动后，宿主还会调用 `get_info` 获取动态元数据和工具列表。当前实现中：

- `plugin.json` 包含 `runtime`、`command` / `libraryName`、`publishedOps`、`subscribedOps`，以及分类属性与 `tools` 清单。
- `get_info` 包含插件基础信息、能力、设置 schema 和运行时 `tools`。
- `publishedOps` / `subscribedOps` 当前只来自 `plugin.json`，不在 `get_info` 返回结构中。
- `category`、`riskLevel`、`tags`、`searchHints`、`idempotent` 的继承与覆盖见 [插件与工具分类属性.md](插件与工具分类属性.md)。

具体字段见 [插件清单与能力声明.md](插件清单与能力声明.md)。

## 四、开发流程

Native / Process 的通用流程：

1. 选择通道并实现对应运行时契约。
2. 准备 `plugin.json`。
3. 实现 `get_info`，声明工具名、参数和能力。
4. 处理 `init` 注入的运行时配置。
5. 实现工具调用和资源释放。
6. 逐个验证工具的成功路径和失败路径。
7. 按插件包结构发布并生成 zip。
8. 安装更新时先卸载已加载插件，再安装并重载。

使用官方 C# SDK 时，Generator 会生成 `plugin.json`、`get_info`、工具路由和通道适配代码，开发者只维护 Attribute、依赖注册和业务实现。

## 五、C# 示例（使用官方 SDK）

### Process 入口

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin;

namespace Your.Process.Plugin;

[Plugin(
    Id = "your_process_plugin",
    Name = "Your Process Plugin",
    Version = "1.0.0",
    Description = "提供示例 Process 工具。",
    Tags = ["sample"],
    Capabilities = ["sample.process"])]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<SampleService>();
    }
}
```

### Native 入口

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin.Native;

namespace Your.Native.Plugin;

[Plugin(
    Id = "your_native_plugin",
    Name = "Your Native Plugin",
    Version = "1.0.0",
    Description = "提供示例 Native 工具。",
    Tags = ["sample"],
    Capabilities = ["sample.native"])]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<SampleService>();
    }
}
```

C# 入口必须是 `public static partial class`，一个项目只能声明一个 `[Plugin]`。

## 六、能力与事件

- `providedCapabilities`：插件提供给宿主的能力。
- `requiredHostCapabilities`：插件申请宿主提供的能力，不代表已经授权。
- `publishedOps`：插件可能发布的 PluginBus 事件。
- `subscribedOps`：插件计划订阅的 PluginBus 事件。
- `settingsSchema`：宿主设置界面字段定义，不包含真实配置值。

PluginBus 事件是单向、一对多、无响应的通知。需要请求结果时使用对应的请求/响应 op，例如 `model.capability.request` / `model.capability.response`，不要把 RPC 帧标记为 `type: "event"`。

## 七、运行时配置

`init.args` 的 JSON 对象包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `dataDirectory` | string | 插件专属数据目录 |
| `workspaceDirectory` | string | 初始化时的工作区目录 |
| `pluginDirectory` | string | 插件包根目录 |
| `wsPort` | integer | 宿主 WebSocket 端口 |
| `extensions` | object<string, string> | 字符串扩展字段 |

当前宿主注入的扩展键包括 `pluginBusEndpoint`、`pluginBusPort`、`pluginBusPath`、`pluginBusProtocol`、`pluginBusVersion`、`pluginConfigJson` 和 `hostCapabilityGrantsJson`。Process 插件若长期缓存工作区目录，还应订阅 `workspace.event.publish` 处理后续变更。

官方 C# SDK 会把上述内容映射为 `PluginSettings`。Native SDK 直接提供 `PluginBusEndpoint` / `PluginBusProtocol` / `PluginBusVersion` / `PluginBusPort`；Process SDK 当前通过兼容属性 `ConversationFeedEndpoint` / `ConversationFeedProtocol` / `ConversationFeedVersion` / `ConversationFeedPort` 暴露对应值，完整扩展仍可从 `Extensions` 读取。

## 八、验证要求

| 通道 | 本地验证 | 发布验证 |
| --- | --- | --- |
| Native C# | 脚手架生成的 Debug Console，逐个调用工具 | Native AOT 发布成功，DLL 导出入口完整 |
| Process C# | `dotnet run -- --self-test`，先 `InitAsync()` 再逐个调用工具 | 目标发布模式可启动，stdin/stdout 冒烟通过 |
| 其他 Native / Process 实现 | 按协议完成 `get_info`、`init`、`invoke`、`destroy` 冒烟 | 清单、入口、编码、退出码和资源释放正确 |
| MCP | 配置校验、连接和工具发现 | 目标环境可连接，认证信息可用 |
