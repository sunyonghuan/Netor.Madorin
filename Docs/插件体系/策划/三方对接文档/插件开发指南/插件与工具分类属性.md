# 插件与工具分类属性

本文说明 Native / Process 插件在 `[Plugin]`、`[Tool]` 上新增的分类属性，以及 Generator 如何把它们写进发布产物 `plugin.json`。

适用通道：Native、Process。MCP 不使用 `plugin.json`，本文不适用。

相关文档：

- [插件清单与能力声明.md](插件清单与能力声明.md)：`plugin.json` 全量字段、能力与设置 schema
- [工具声明与参数规范.md](工具声明与参数规范.md)：工具名、参数类型与 `invoke`

## 一、目的

宿主把工具交给模型时，上下文里只有工具，没有插件。模型看不到「这是哪个插件」，也看不到「这一组工具属于哪一类」。

分类信息必须能落到每个工具上，才能：

- 按类别分组
- 按风险过滤或提示
- 按关键词搜索
- 按标签聚合

开发者不需要给每个工具重复填写。默认写在插件上，个别例外再覆盖。Generator 在构建和发布时生成标准 `plugin.json`，不要手写 `tools` 数组。

## 二、三层写法

| 层 | 开发者做什么 | 效果 |
| --- | --- | --- |
| 零配置 | 不写分类字段 | Generator 仍输出完整 `tools`（名字、描述、参数 schema）；清单里没有分类字段 |
| 插件默认 | 在 `[Plugin]` 上写一次 | 该插件下所有工具都用这套值 |
| 工具覆盖 | 只在个别方法的 `[Tool]` 上写要改的字段 | 只改这一个工具；未写的字段仍用插件默认值 |

没写就是没有。不要为了「完整」去猜 `RiskLevel` 或编造 `SearchHints`。

## 三、属性一览

插件级写在入口类的 `[Plugin]` 上。工具级写在**方法**上的 `[Tool]`。类上的 `[Tool]` 只表示这是工具类，分类属性以方法级为准。

可继承、可覆盖的字段：

| C# 属性 | 类型 | plugin.json | 插件级 | 工具级 | 未写时 |
| --- | --- | --- | --- | --- | --- |
| `Category` | `string?` | `category` | 默认值 | 可覆盖 | 不出现 |
| `RiskLevel` | `ToolRiskLevel?` | `riskLevel` | 默认值 | 可覆盖 | 不出现 |
| `Idempotent` | `bool?` | `idempotent` | 默认值 | 可覆盖 | 不出现 |
| `Tags` | `string[]` | `tags` | 默认值 | 可覆盖 | 空则不出现 |
| `SearchHints` | `string[]` | `searchHints` | 默认值 | 可覆盖 | 空则不出现 |

工具自身字段，不能靠继承：

| C# 来源 | plugin.json | 说明 |
| --- | --- | --- |
| `[Tool(Name = ...)]` 或方法名转 snake_case | `name` | 短工具名，不含插件 ID 前缀 |
| `[Tool(Description = ...)]` | `description` | 面向模型和用户的用途说明 |
| 方法参数与 `[Parameter]` | `inputSchema` | 一层 JSON Schema，不展开嵌套对象 |

C# 命名空间：

- Native：`Netor.Madorin.Plugin.Native`
- Process：`Netor.Madorin.Plugin`

## 四、插件级属性

在入口类上声明一次，作为该插件全部工具的默认值。

```csharp
[Plugin(
    Id = "my_plugin",
    Name = "My Plugin",
    Version = "1.0.0",
    Description = "开发辅助工具",
    Category = "development",
    RiskLevel = ToolRiskLevel.Low,
    Idempotent = false,
    Tags = ["development", "automation"],
    SearchHints = ["build", "deploy"])]
public static partial class Startup
{
}
```

### 1. Category

插件所属分组，一个插件通常只写一个值。建议使用稳定的小写短横线 token，例如：

- `file-system`
- `database`
- `development`
- `voice`
- `network`

`Category` 不是封闭枚举。选定后应保持稳定，避免后续改名导致宿主分组失效。

### 2. Tags

多标签，用于交叉分类。与 `Category` 的区别：

- `Category`：一个主分组
- `Tags`：多个辅助标签，例如 `["sql", "postgres"]`

所有工具默认继承插件级 `Tags`。只有某个工具明显不属于这组标签时，才在工具上覆盖。

### 3. SearchHints

搜索关键词，按插件功能和常见说法填写，写在插件上即可。例如文件插件可写 `["file", "read", "write", "directory"]`。

建议：

- 用用户或模型可能搜到的词，含同义词
- 不要堆砌实现细节或内部类名
- 大多数工具共用同一组关键词；只有行为明显不同的工具才单独覆盖

### 4. Idempotent

是否幂等：相同参数重复调用，效果与调用一次相同，可以安全重试。

- 查询、列表、按确定路径覆盖写入：通常为 `true`
- 每次调用都新建记录、启动进程、发送不可去重的请求：通常为 `false`
- 拿不准就不要写，不要猜

### 5. RiskLevel

插件默认风险级别。取值见第六节。多数工具风险接近时，在插件上写一个默认值；个别更高风险的工具再覆盖。

默认值应按插件里**最常见**的操作来选，而不是按最危险的那个工具来抬高全部工具。危险操作留给工具级覆盖。

## 五、工具级覆盖

只覆盖真正不同的字段。未写的字段继承插件默认值，不会在该工具的 JSON 对象里重复出现。

```csharp
[Tool]
public sealed class FileTools
{
    [Tool(Description = "列出目录中的文件。")]
    public string ListFiles(string path) => path;

    [Tool(
        Description = "格式化磁盘。此操作不可恢复。",
        RiskLevel = ToolRiskLevel.Destructive,
        SearchHints = ["format", "erase", "wipe"])]
    public string FormatDisk(string device) => device;
}
```

上例中 `list_files` 不写分类字段，全部继承插件默认值。`format_disk` 只覆盖 `RiskLevel` 和 `SearchHints`；若插件还声明了 `Category`、`Tags`、`Idempotent`，该工具仍继承这些值。

覆盖是字段级的，不是整份替换。不要为了覆盖风险级别而把插件的 `Tags`、`SearchHints` 再抄一遍。

## 六、ToolRiskLevel

`[Plugin]` 和 `[Tool]` 使用同一枚举。Generator 按枚举成员名写入 JSON，例如 `"Low"`、`"Destructive"`。

| 值 | 说明 | 适用场景 | 示例 |
| --- | --- | --- | --- |
| `Low` | 低风险（只读操作） | 读取文件、查询数据、列表操作 | `read_file`、`list_directory`、`get_user_info` |
| `SensitiveRead` | 敏感读取 | 读取密码、密钥、私有数据 | `read_credentials`、`get_api_key`、`read_env` |
| `Write` | 写操作（可逆） | 创建或修改文件、写入数据库 | `write_file`、`create_directory`、`update_record` |
| `Destructive` | 破坏性操作（不可逆） | 删除文件、清空数据、格式化 | `delete_file`、`drop_table`、`format_disk` |
| `Process` | 进程操作 | 启动或停止进程、执行命令 | `run_command`、`kill_process`、`spawn_process` |
| `PowerShell` | PowerShell 脚本执行 | 执行 PowerShell 脚本 | `run_powershell`、`execute_script` |
| `Network` | 网络操作 | HTTP 请求、网络连接 | `http_request`、`download_file`、`connect_to_server` |

选择规则：

- 一个工具只标最贴切的一项，不要叠多个风险级别。
- 读私密内容用 `SensitiveRead`，不要用 `Low` 敷衍。
- 删除、清空、格式化用 `Destructive`，不要用 `Write`。
- 执行外部命令用 `Process` 或 `PowerShell`，不要标成普通 `Write`。
- 出网请求用 `Network`，即使请求体是只读查询。

## 七、继承与清单存储

生效顺序：

```text
工具显式值 → 插件默认值 → 未写则没有
```

`plugin.json` 采用紧凑存储：

- 插件级字段写在清单根上。
- 工具对象默认只含 `name`、`description`、`inputSchema`。
- 只有覆盖了的字段才出现在对应工具对象上。

给模型看的工具列表需要完整分类信息时，由宿主按上面的顺序合并，而不是要求清单把插件字段复制到每一个 tool。

工具 JSON 里的 `name` 是短名（snake_case）。宿主 `invoke` 仍使用完整工具名 `{plugin_id}_{short_name}`，见 [工具声明与参数规范.md](工具声明与参数规范.md)。

## 八、场景

### 场景 1：简单插件（零配置）

只声明插件分类。工具不写风险、标签、关键词。

```csharp
[Plugin(Id = "file_helper", Name = "File Helper", Version = "1.0.0", Category = "file-system")]
public static partial class Startup { }

[Tool]
public sealed class FileTools
{
    [Tool(Description = "读取文件内容。")]
    public string ReadFile(string path) => path;

    [Tool(Description = "写入文件内容。")]
    public string WriteFile(string path, string content) => path;

    [Tool(Description = "删除文件。")]
    public string DeleteFile(string path) => path;
}
```

生成的工具项只有 `name`、`description`、`inputSchema`。插件根上有 `"category": "file-system"`。

### 场景 2：统一风险级别

数据库写入插件的工具风险接近，全部写在插件上。

```csharp
[Plugin(
    Id = "db_helper",
    Name = "DB Helper",
    Version = "1.0.0",
    Category = "database",
    RiskLevel = ToolRiskLevel.Write,
    Tags = ["database", "sql"])]
```

`insert_record`、`update_record`、`delete_record` 都继承 `Write` 和上述标签。若删除不可恢复，应把 `delete_record` 单独覆盖为 `Destructive`。

### 场景 3：个别工具高风险

插件默认低风险，只有破坏性工具覆盖。

```csharp
[Plugin(
    Id = "disk_helper",
    Name = "Disk Helper",
    Version = "1.0.0",
    Category = "file-system",
    RiskLevel = ToolRiskLevel.Low)]
public static partial class Startup { }

[Tool]
public sealed class DiskTools
{
    [Tool(Description = "列出文件。")]
    public string ListFiles(string path) => path;

    [Tool(Description = "读取文件。")]
    public string ReadFile(string path) => path;

    [Tool(
        Description = "格式化磁盘。此操作不可恢复。",
        RiskLevel = ToolRiskLevel.Destructive,
        SearchHints = ["format", "erase", "wipe"])]
    public string FormatDisk(string device) => device;
}
```

对应清单中，`list_files` 和 `read_file` 不带 `riskLevel`；`format_disk` 带 `"riskLevel": "Destructive"` 和自己的 `searchHints`。

## 九、plugin.json 产物

使用官方 C# SDK 时，构建和发布后由 Generator 写出清单，不要手写 `tools`。字段为 camelCase。

```json
{
  "id": "my_plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "description": "开发辅助工具",
  "category": "development",
  "riskLevel": "Low",
  "idempotent": false,
  "tags": ["development", "automation"],
  "searchHints": ["build", "deploy"],
  "tools": [
    {
      "name": "create_file",
      "description": "Create a file",
      "inputSchema": {
        "type": "object",
        "properties": {
          "path": { "type": "string", "description": "文件路径。" }
        },
        "required": ["path"]
      }
    },
    {
      "name": "delete_all",
      "description": "Delete everything",
      "inputSchema": { "type": "object", "properties": {} },
      "riskLevel": "Destructive",
      "searchHints": ["delete", "remove", "cleanup"]
    }
  ],
  "runtime": "native",
  "libraryName": "MyPlugin.dll",
  "minHostVersion": "1.0.0"
}
```

`inputSchema` 由现有参数生成。无参数时为 `{ "type": "object", "properties": {} }`。参数类型仍是 `string` / `integer` / `number` / `boolean`。

## 十、编写约束

- 不要手写 `plugin.json` 里的 `tools`、`category`、`riskLevel`、`searchHints`。用 Attribute，交给 Generator。
- 分类字段优先写在 `[Plugin]`。只有个别工具例外时才在方法的 `[Tool]` 上覆盖。
- 类上的 `[Tool]` 不要填分类属性；填了也不会作为工具覆盖值。
- `Category`、`Tags`、`SearchHints` 一旦对外使用，应保持稳定。
- `SearchHints` 写给搜索用，不是再写一遍 `Description`。
- 未确定的 `RiskLevel` / `Idempotent` 留空，不要猜。
- 工具参数保持扁平。分类属性解决的是分组和搜索，不改变 `invoke` 参数协议。

## 十一、宿主读取

宿主反序列化 `plugin.json` 时：

- 旧插件没有 `tools` 或分类字段，仍可加载。
- `tools` 缺省视为空数组。
- 工具对象缺少 `category` / `riskLevel` / `tags` / `searchHints` / `idempotent` 表示继承插件根上的同名字段，而不是空值覆盖。

把工具交给模型前，宿主应按第七节合并出每个工具的最终分类属性。
