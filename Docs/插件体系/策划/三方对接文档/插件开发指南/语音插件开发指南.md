# 语音插件开发指南

语音插件通过能力声明提供 KWS、STT 或 TTS，通过 PluginBus 事件向宿主 UI 和其他插件报告状态。语音引擎、模型格式和音频库由插件自行选择；宿主只依赖清单、工具和事件契约。

## 一、能力

| 能力 | capability | 典型工具 |
| --- | --- | --- |
| 关键词唤醒 | `voice.kws` | 启动、停止、状态、关键词配置 |
| 语音识别 | `voice.stt` | 启动、停止、状态、识别配置 |
| 语音合成 | `voice.tts` | 合成播放、停止、状态、模型配置 |

一个插件可以只实现一种能力。需要独立进程、JIT 或复杂原生依赖时通常使用 Process；能生成兼容 Native DLL 时也可以使用 Native。

## 二、资源与目录

模型和运行资源放在插件包内，并以 `pluginDirectory` 为基准解析：

```text
your-voice-plugin/
  plugin.json
  <plugin entry>
  models/
    KWS/
    STT/
    TTS/
  config/
```

- `pluginDirectory`：只读程序、模型和模板。
- `dataDirectory`：插件生成的数据、缓存和用户配置。
- `workspaceDirectory`：初始化时的工作区路径；需要跟踪切换时订阅 `workspace.event.publish`。

不要依赖当前进程工作目录，也不要把模型绝对路径写入清单。

## 三、语音事件

宿主当前识别以下 PluginBus op：

| op | 建议 payload | 宿主桥接行为 |
| --- | --- | --- |
| `voice.kws.detected.v1` | `sessionId` 可选 | 发布唤醒信号 |
| `voice.stt.partial.v1` | `text`，`sessionId` 可选 | 发布 STT 临时文本 |
| `voice.stt.final.v1` | `text`，`sessionId` 可选 | 发布 STT 最终文本 |
| `voice.stt.stopped.v1` | `sessionId` 可选 | 发布 STT 停止信号 |
| `voice.tts.started.v1` | `sessionId` 可选 | 发布 TTS 开始信号 |
| `voice.tts.subtitle.v1` | `text`，`sessionId` 可选 | 发布 TTS 字幕 |
| `voice.tts.completed.v1` | `sessionId`、`reason` 可选 | 发布 TTS 完成信号 |
| `voice.tts.greeting_ready.v1` | 自定义 | 只记录 Debug，不桥接 UI |
| `voice.tts.error.v1` | `text`、`reason` 可选 | 记录 Warning，不桥接 UI |

所有 `voice.*` 事件仍会按普通 PluginBus 规则转发给其他订阅插件。宿主桥接只消费上表需要的字段；其他 payload 字段会原样保留给插件订阅方。

宿主会为没有版本后缀的旧 voice op 在 UI 桥接时补 `.v1`，但 PluginBus 精确订阅仍按原始 op 匹配。新插件必须直接发布带 `.v1` 的标准 op。

## 四、payload

文本事件：

```json
{
  "type": "event",
  "op": "voice.stt.final.v1",
  "sourcePluginId": "voice_stt",
  "payload": {
    "text": "识别结果",
    "sessionId": "session-001"
  }
}
```

信号事件：

```json
{
  "type": "event",
  "op": "voice.tts.completed.v1",
  "sourcePluginId": "voice_tts",
  "payload": {
    "sessionId": "session-001",
    "reason": "completed"
  }
}
```

`text` 应为字符串。宿主桥接兼容读取 `payload.data` 或帧根级 `text` / `data`，但新插件只使用 `payload.text`。

TTS `reason` 建议值：

| 事件 | reason | 说明 |
| --- | --- | --- |
| completed | `completed` | 自然播放完成 |
| completed | `stopped` | 主动停止 |
| completed | `cancelled` | 后台任务取消 |
| completed | `error` | 错误收尾 |
| error | `model_not_ready` | 模型不可用 |
| error | `synthesis_failed` | 合成失败 |
| error | `synthesis_empty` | 没有生成音频 |
| error | `playback_failed` | 播放失败 |

模型不可用时发布 `voice.tts.error.v1`，不要伪造 started、subtitle、completed 或 greeting_ready 生命周期。

## 五、协同建议

| 插件 | 发布 | 可订阅 | 处理建议 |
| --- | --- | --- | --- |
| KWS | `voice.kws.detected.v1` | TTS started/completed | TTS 播放期间抑制自唤醒 |
| STT | partial/final/stopped | KWS detected、TTS started/completed | 唤醒后监听，TTS 播放期间暂停或降敏 |
| TTS | started/subtitle/completed/error | 通常无 | 由工具或对话编排驱动朗读 |

TTS 不应默认订阅 `voice.stt.final.v1` 并直接朗读。STT 最终识别文本是用户输入，不等于模型回复。

事件 handler 只做状态切换或写入内部队列，不在 PluginBus 接收循环中执行长时间识别、合成或播放。

## 六、清单声明

STT 清单示例：

```json
{
  "capabilities": ["voice.stt"],
  "providedCapabilities": ["voice.stt"],
  "publishedOps": [
    { "op": "voice.stt.partial.v1", "description": "实时识别文本" },
    { "op": "voice.stt.final.v1", "description": "最终识别文本" },
    { "op": "voice.stt.stopped.v1", "description": "识别会话停止" }
  ],
  "subscribedOps": [
    { "op": "voice.kws.detected.v1", "reason": "唤醒后开始监听" },
    { "op": "voice.tts.started.v1", "reason": "播放期间暂停识别" },
    { "op": "voice.tts.completed.v1", "reason": "播放结束后恢复识别" }
  ]
}
```

清单声明不会自动建立订阅。插件运行时仍需发送 `subscribe` 帧或调用 Process SDK 的 `SubscribeEventAsync`。

## 七、C# 示例（Process 官方 SDK）

### 入口声明

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin;

[Plugin(
    Id = "voice_stt",
    Name = "Voice STT",
    Version = "1.0.0",
    Capabilities = ["voice.stt"])]
[PublishesEvent("voice.stt.partial.v1", Description = "实时识别文本")]
[PublishesEvent("voice.stt.final.v1", Description = "最终识别文本")]
[PublishesEvent("voice.stt.stopped.v1", Description = "识别会话停止")]
[SubscribesEvent("voice.kws.detected.v1", Reason = "唤醒后开始监听")]
[SubscribesEvent("voice.tts.started.v1", Reason = "播放期间暂停识别")]
[SubscribesEvent("voice.tts.completed.v1", Reason = "播放结束后恢复识别")]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<SttEngine>();
        services.AddSingleton<SttEventPublisher>();
        services.AddHostedService<SttCoordinator>();
    }
}
```

Process 插件宿主已经注册 `PluginBusClient`，插件不要重复注册。

### 类型化发布器

```csharp
internal sealed record SttPayload(
    [property: JsonPropertyName("text")] string? Text,
    [property: JsonPropertyName("sessionId")] string? SessionId);

public sealed class SttEventPublisher(PluginBusClient bus)
{
    public Task PublishFinalAsync(
        string text,
        string? sessionId,
        CancellationToken cancellationToken = default)
    {
        var payload = JsonSerializer.SerializeToElement(
            new SttPayload(text, sessionId),
            PluginJsonContext.Default.SttPayload);

        return bus.PublishEventAsync(
            "voice.stt.final.v1",
            payload,
            cancellationToken);
    }
}
```

这里的 `CancellationToken` 是插件内部服务方法参数，不是 `[Tool]` 参数。

```csharp
[JsonSerializable(typeof(SttPayload))]
internal partial class PluginJsonContext : JsonSerializerContext;
```

### 订阅协调器

```csharp
public sealed class SttCoordinator(
    PluginBusClient bus,
    SttEngine engine) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        await bus.SubscribeEventAsync(
            "voice.tts.started.v1",
            _ =>
            {
                engine.Suppress();
                return Task.CompletedTask;
            },
            stoppingToken);

        await bus.SubscribeEventAsync(
            "voice.tts.completed.v1",
            _ =>
            {
                engine.Resume();
                return Task.CompletedTask;
            },
            stoppingToken);

        await Task.Delay(Timeout.Infinite, stoppingToken);
    }
}
```

Native 插件遵循相同事件 JSON，但当前 Native SDK 没有内置等价 `PluginBusClient`；接入方式见 [插件事件总线开发指南.md](插件事件总线开发指南.md)。

## 八、状态与错误

状态工具应区分“用户希望监听”和“引擎实际运行”：

- `isListening`：插件状态机是否处于监听意图。
- `engineRunning`：音频线程或推理引擎是否实际运行。
- `deviceCount`：可用音频设备数量。
- `lastError`：最近一次失败原因。

只要 `engineRunning=false`、`deviceCount=0` 或存在不可恢复 `lastError`，调用方就不应把插件视为正在正常监听。

## 九、发布检查

- `plugin.json` 的能力和事件声明完整。
- 模型与词表位于发布目录，路径以 `pluginDirectory` 为基准。
- 共享发布脚本不会自动递归打包模型目录，生成 zip 前已显式复制并核对资源。
- 无模型、无设备、合成失败和播放失败均有明确工具结果与 error 事件。
- 高频 partial 事件不会阻塞识别线程。
- started/completed 成对，异常路径不会让其他插件永久处于抑制状态。
- Process 插件完成 `--self-test`；Native 插件完成 Debug Console 和 AOT 发布验证。
