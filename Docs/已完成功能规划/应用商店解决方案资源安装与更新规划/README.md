# 应用商店解决方案资源安装与更新规划

## 文档状态

本文档原属于未来版本策划，用于记录应用商店解决方案资源的产品语义、安装语义和更新语义。当前实现已按本文档核心语义推进完成，本文档现在同时作为“语义说明”和“当前实现对齐记录”使用。

执行进度、验证命令和涉及文件记录在同目录的 `执行计划(应用商店解决方案资源安装与更新).md` 中。

会员后台和管理后台需要同步调整的功能策划记录在同目录的 `会员后台与管理后台同步改造策划.md` 中。

会员后台和管理后台同步改造的执行拆解记录在同目录的 `执行计划(会员后台与管理后台同步改造).md` 中。

## 背景

应用商店早期曾把 `AssetType.Solution` 当作普通资源包处理：下载 ZIP 后整体解压到用户数据目录的 `solutions/{slug}` 下，并要求包根目录存在 `solution.json`。

这个定义不符合产品语义。应用商店里的“解决方案”不是单独一种可运行资源，而是一套由插件、技能、智能体组合出来的完整工作方案。解决方案包需要解决的不只是首次安装问题，还包括后续插件、技能、智能体的版本更新、关系记录和卸载边界。

当前实现已经不再把解决方案作为单一运行目录处理，而是读取 `solution.json` 后把包内插件、技能、智能体分别安装到对应目录，并在解决方案目录保留安装记录。

## 产品定义

解决方案包是复合资源包，用于把一组插件、技能和智能体整理成一个可下载、可安装、可更新的工作方案。

一个解决方案不要求同时包含插件、技能和智能体三类资源。它可以只包含其中一种，也可以包含其中两种或三种。例如：

- 只包含插件：用于分发一组系统能力扩展。
- 只包含技能：用于分发一组提示词、流程或知识操作规范。
- 只包含智能体：用于分发一组角色化工作智能体。
- 包含插件和技能：插件提供工具能力，技能提供使用方式。
- 包含技能和智能体：智能体引用配套技能完成工作。
- 包含插件、技能和智能体：形成完整端到端工作方案。

解决方案包至少应包含一种可安装子资源，空解决方案只能作为无效包处理。

## 安装语义

安装解决方案时，不能只把整个 ZIP 解压到 `solutions/{solutionSlug}`。安装器应读取 `solution.json`，识别包内包含的插件、技能、智能体资源，并分别安装到对应目录：

- 插件安装到用户插件目录：`plugins/{pluginSlug}`
- 技能安装到用户技能目录：`skills/{skillSlug}`
- 智能体安装到用户智能体目录：`agents/{agentSlug}`

解决方案自身只在用户解决方案目录保留安装记录和方案说明：

- `solutions/{solutionSlug}/solution.json`
- `solutions/{solutionSlug}/installed-assets.json`
- 可选的 README、实施说明、版本记录、授权信息

如果解决方案中没有某一类资源，对应安装流程直接跳过，不视为错误。

## 更新语义

应用商店资源更新不能只按外层 ZIP 覆盖目录处理。插件、技能、智能体都需要独立版本判断和独立更新记录。

单独安装的插件、技能、智能体更新时，应按各自资源类型处理：

- 插件更新：校验 `plugin.json`、版本号、兼容性和运行时加载要求；先执行插件卸载或停用流程，确保进程、文件句柄、工具注册、事件订阅和运行时实例释放完成，再替换插件目录，最后重新加载插件并刷新工具能力。
- 技能更新：校验 `skill.md` 及附带资源，可以直接覆盖技能目录，覆盖完成后由技能目录监听服务推进工具上下文版本，下次对话自动重建技能上下文。
- 智能体更新：校验智能体清单和提示词资源，可以直接覆盖智能体目录，覆盖完成后触发智能体索引刷新。

插件更新不能等同于普通文件覆盖。插件可能存在独立进程、Native 依赖、运行时配置、工具注册和被当前会话引用的状态，因此更新顺序应是：

- 标记插件进入更新状态，阻止新的调用进入。
- 卸载或停用旧插件，释放进程、程序集、Native 句柄和订阅关系。
- 删除或备份旧插件目录。
- 解压并安装新版本插件。
- 重新加载插件声明、配置和工具列表。
- 更新失败时恢复旧版本或记录插件不可用状态。

技能目录虽然可以直接覆盖，但技能不只是 `skill.md`。技能包内可以包含图片、脚本、文档、模板、示例数据、配置片段等资源。更新技能时应以整个技能目录作为一个完整资源单元处理，覆盖后依赖 `SkillDirectoryWatcherService` 监听用户技能目录变化并推进工具上下文版本，避免只更新 Markdown 而遗漏配套文件。

解决方案更新时，应以 `solution.json` 和当前 `installed-assets.json` 为依据，比较新旧版本的子资源清单：

- 新增子资源：安装到对应插件、技能或智能体目录，并写入解决方案安装记录。
- 已存在子资源：按子资源版本策略更新，不能只因为外层解决方案更新就盲目覆盖。
- 移除子资源：从解决方案记录中移除关系；是否删除本地资源，需要判断该资源是否被用户单独安装、被其他解决方案引用或被用户修改。
- 版本回退：应保留上一次安装记录，后续可用于回滚或故障恢复。

解决方案的更新记录应能回答这些问题：

- 当前解决方案版本是多少？
- 本次解决方案安装或更新了哪些插件、技能和智能体？
- 每个子资源的 slug、版本、安装路径和来源是什么？
- 某个子资源是由哪个解决方案带入的，还是用户单独安装的？
- 更新失败时，哪些子资源已变更，哪些仍保持旧版本？

当前实现已经在解决方案目录的 `installed-assets.json` 中保留子资源安装记录和历史操作记录。历史记录用于表达安装、更新、移除、失败等操作，以及旧版本、新版本、结果和失败信息。

## 卸载语义

卸载解决方案时，不能只删除 `solutions/{solutionSlug}` 目录。安装器应读取解决方案的 `installed-assets.json`，找到该解决方案安装或带入的插件、技能、智能体资源，并按资源类型执行卸载。

解决方案卸载的基本语义是：删除该解决方案带入的全部资源，同时删除解决方案自身的安装记录和说明文件。

不同资源类型的卸载方式不同：

- 插件卸载：必须先执行插件卸载或停用流程，确保插件进程停止、工具注册移除、事件订阅解除、运行时实例释放完成，再删除插件目录。
- 技能卸载：可以删除技能目录，删除后由技能目录监听服务推进工具上下文版本。
- 智能体卸载：可以删除智能体目录，删除后触发智能体索引刷新。

如果某个插件、技能或智能体同时被其他解决方案引用，或者用户曾单独安装同名资源，卸载当前解决方案时不能直接删除该资源。此时应只移除当前解决方案的引用关系，并在安装记录中保留来源判断。

## 建议包结构

```text
solution.json
README.md
plugins/
  google-search-plugin/
    plugin.json
    ...
skills/
  market-research/
    skill.md
    ...
agents/
  marketing-director/
    agent.json
    prompt.md
    ...
```

`plugins/`、`skills/`、`agents/` 目录都应是可选目录。包内只需要包含本解决方案实际需要的资源类型。

插件、技能、解决方案包允许包含运行所需的脚本、可执行文件和 Native 依赖。平台风控不应把这些文件类型直接作为插件、技能、解决方案的阻断项；智能体包仍按较严格的普通资源规则处理。

## solution.json 建议字段

```json
{
  "id": "netor.solution.marketing-launch",
  "slug": "marketing-launch",
  "name": "新品营销启动解决方案",
  "version": "1.0.0",
  "description": "包含营销智能体、搜索插件和市场调研技能的一套启动方案。",
  "assets": {
    "plugins": [
      {
        "slug": "google-search-plugin",
        "version": "1.0.0",
        "path": "plugins/google-search-plugin"
      }
    ],
    "skills": [
      {
        "slug": "market-research",
        "version": "1.0.0",
        "path": "skills/market-research"
      }
    ],
    "agents": [
      {
        "slug": "marketing-director",
        "version": "1.0.0",
        "path": "agents/marketing-director"
      }
    ]
  }
}
```

如果某类资源不存在，可以省略该数组，也可以保留为空数组。安装器需要按实际存在的资源处理。

## installed-assets.json 建议字段

```json
{
  "solutionSlug": "marketing-launch",
  "solutionVersion": "1.0.0",
  "installedAtUtc": "2026-06-11T00:00:00Z",
  "assets": [
    {
      "type": "plugin",
      "slug": "google-search-plugin",
      "version": "1.0.0",
      "path": "plugins/google-search-plugin",
      "installedPath": "plugins/google-search-plugin",
      "source": "solution"
    }
  ],
  "history": [
    {
      "type": "plugin",
      "slug": "google-search-plugin",
      "operation": "install",
      "previousVersion": null,
      "newVersion": "1.0.0",
      "result": "success",
      "message": null,
      "recordedAtUtc": "2026-06-11T00:00:00Z"
    }
  ]
}
```

该文件是解决方案目录下的安装记录，不是插件、技能、智能体的运行目录副本。

## 当前实现对齐结论

截至 2026-06-11，对插件、技能、智能体和解决方案安装更新卸载链路的对齐结论如下：

- 应用商店插件覆盖安装已具备先卸载再替换的基础顺序。`PackageInstallService.ReplaceInstalledDirectoryAsync` 在目标插件目录已存在时，会先调用 `pluginActivationService.Unload(directoryName)`，再移动旧目录、替换新目录，最后重新加载插件。
- `pluginActivationService.Unload` 会进入 `PluginLoader.UnloadPlugin`，再由 `UnloadPluginByPath` 释放 Native/Process 插件宿主并发布插件变更事件。因此现有覆盖更新不是单纯文件覆盖。
- 插件首次安装时，目标目录不存在，不需要卸载旧插件；写入目录后会加载新插件。
- 设置页插件删除入口已满足先卸载再删除目录：先调用 `PluginLoader.UnloadPlugin`，再删除插件目录，并清理全局插件记录和智能体绑定。
- 应用商店模块已补充独立 `UninstallAsync`，卸载普通插件时会先停用插件运行态，再删除目录。
- `PackageInstallService` 已对 `AssetType.Solution` 使用专用复合资源安装流程：读取 `solution.json`，枚举可选的 `plugins`、`skills`、`agents` 子资源，并分别安装到用户插件、技能、智能体目录。
- 解决方案目录只保留 `solution.json`、`installed-assets.json` 和包根级说明文件，不保留作为运行资源的插件、技能、智能体副本。
- 解决方案更新已支持新增、变更、移除子资源；插件子资源更新必须先卸载或停用旧插件再替换目录。
- 解决方案卸载已支持读取 `installed-assets.json` 并删除该解决方案带入的可删除子资源；插件删除前先停用运行态。
- 技能安装、更新和卸载通过目录写入触发 `SkillDirectoryWatcherService`，由该服务推进工具上下文版本；智能体安装和删除则显式发布 `Events.OnAgentChange`。
- 共享资源已具备保护逻辑：当同名子资源被其他解决方案引用，或作为用户单独安装资源存在时，卸载当前解决方案不会直接删除该资源目录。
- 更新和卸载测试已覆盖插件先卸载再替换、插件先卸载再删除、解决方案新增/移除子资源、共享资源不误删等关键路径。
- 应用商店交互已支持解决方案类型筛选、安装、更新、卸载状态展示；解决方案详情会展示包内插件、技能、智能体清单，更新列表会区分“方案更新”和“单资源更新”。
- 会员后台与管理后台同步改造已完成第一阶段核心能力；`Netor.Cortana.Platform.Web`、`Netor.Cortana.Platform.Admin` 构建通过，平台测试已覆盖解决方案清单解析、结构校验和风控边界。

## 后续增强边界

当前实现已经完成核心安装、更新、卸载语义。后续仍可继续增强以下能力：

- 用户本地修改策略：子资源如果被用户修改，解决方案更新时应提示、保留或生成冲突记录。
- 回滚策略：当前安装失败会记录部分成功和失败状态，后续可以进一步支持一键恢复到上一版解决方案子资源集合。
- 子资源版本比较策略：当前以解决方案清单与安装记录比较为主，后续可以增加更严格的语义版本比较和兼容性检查。
- 技能刷新显式化：当前技能目录变更依赖 `SkillDirectoryWatcherService` 的文件监听能力，后续可以补充和智能体事件一致的显式刷新入口。
- 平台详情增强：平台 Web 资源详情、市场卡片、我的订阅和我的下载已展示解决方案包内资源结构；后续可以继续补充更细的版本差异和安装状态回传。
