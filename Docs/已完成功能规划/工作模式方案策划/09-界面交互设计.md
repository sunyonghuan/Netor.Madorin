# 09 - 界面交互设计

> 工作模式（Work Mode）的 UI / UX 规范
> 实现栈：Avalonia 11 (.axaml)，已有组件位于 [Src/Netor.Cortana.UI/](../../../Src/Netor.Cortana.UI/)

## 一、全局原则（不可违反）

| # | 原则 | 说明 |
|---|------|------|
| 1 | **零交互按钮**（仅 1 个例外） | 整个对话流程中禁止出现确认按钮、单选框、表单等交互元素。**唯一例外**：工具/沙盒授权浮窗 |
| 2 | **阶段隐式化** | 不显示"阶段 1/4""需求确认中"等标号、标题、进度条。状态切换无视觉断点 |
| 3 | **永续无限滚动** | 消息流像专家模式一样持续向下追加，**不清空、不分页、不结束**。任务完成后接着聊下个任务，上下文连贯，除非用户手动开新任务 |
| 4 | **居中布局** | 所有消息（用户气泡 / AI 内容 / 卡片 / 时间线）全部居中对齐，铺在中间列 |
| 5 | **无身份标签** | 不显示用户/AI 头像、姓名、角色标签 |
| 6 | **Markdown 渲染** | 用户输入和 AI 回复均通过现有 Markdown 控件渲染 |
| 7 | **卡片标题禁用 emoji** | 所有折叠卡片标题禁止 emoji 表情。折叠图标用项目资源里的箭头图片，**放在标题左边**，通过 RotateTransform 旋转 |
| 8 | **输入区完全复用专家模式** | 不修改 [InputAreaView.axaml](../../../Src/Netor.Cortana.UI/Controls/InputAreaView.axaml)。边框、颜色、间距、动画、`#` 文件引用、`@` 智能体引用、附件/厂商/模型选择、走马灯流光全部保留 |

## 二、四阶段流程

四阶段构成一次"任务循环"，结束后自然回到对话模式等待下一句话；新任务从对话开始。**整个会话由多个循环串联组成，不会终结**。

```
            ┌──────────────────────────────────────────────┐
            ↓                                              │
        [对话(空闲)]                                       │
            │ 用户提需求                                    │
            ↓                                              │
       [需求识别+引导] ←──┐                                 │
            │ 摘要         │ 用户："不对/再改"               │
            ↓             │                                │
       [需求确认]──────────┘                                │
            │ 用户："对/OK/确认"                            │
            ↓                                              │
        [出计划] ←─────┐                                   │
            │           │ 用户提修改意见                    │
            ↓           │                                  │
       [计划确认]───────┘                                   │
            │ 用户："开始/可以/执行"                        │
            ↓                                              │
       [时间线执行]                                         │
            │ ┌─ Critic 通过      → 下一步                  │
            │ ├─ Critic 失败      → 当前步内调试 (新增卡片) │
            │ ├─ 发现上一步逻辑错  → 退到上一步 (历史不改)  │
            │ ├─ 工具授权请求      → 浮窗滑入               │
            │ └─ 用户插话/停止     → 暂停 → 路由判断意图     │
            ↓                                              │
       [汇总卡片 + 总结消息]                                │
            ↓                                              │
            └──────────────────────────────────────────────┘
                          自动回到[对话(空闲)]
```

### 2.1 阶段 1：需求识别与引导（对话）

- **触发**：用户在空闲状态输入需求
- **AI 行为**：通过对话**自适应识别领域**后追问关键点（数据源、范围、受众、形式、约束）
- **可见信息**：
  - AI 消息**前置**思维卡片（折叠态，标题"思考"）
  - AI 消息**前置**工具调用卡片（折叠态，标题"调用工具 xxx"）
  - AI 主体内容（Markdown 平铺）
- **退出**：AI 整理需求摘要 → 用户输入确定语义（"对""确认""OK""可以""开始"等）
- **不显示阶段编号**

### 2.2 阶段 2：计划编写（对话）

- **AI 行为**：基于需求生成结构化 Plan（主步骤 + 子步骤）
- **可见信息**：同阶段 1（思维/工具卡片 + Markdown）
- **循环**：用户提修改意见 → AI 修改 → 重新列出**完整计划** → 直到用户确认
- **退出**：用户输入"开始/可以/执行"等确定语义
- **关键**：计划阶段就要列出所有主步骤，便于阶段 3 渐次点亮

### 2.3 阶段 3：任务执行（时间线）

- **作为单一 `TimelineBlock` 控件插入消息流**（执行结束后整块"凝固"为历史的一部分）
- **主步骤**：左侧灰色圆点 + 标题，按计划渐次出现
- **子步骤**：每个主步骤下挂折叠卡片（默认展开，完成后自动折叠）
- **思维/工具/验收卡片**：**嵌在子步骤卡片内部**（不在外面单独出现）
- **完成态**：主步骤完成后自动折叠其下所有子步骤卡片，主步骤标题行保留可见
- **失败处理**：
  - Critic 失败 → 当前子步骤内追加重试卡片，**不修改历史卡片**
  - 上一步逻辑错 → 退到上一步骤，**历史卡片保持不变**，在当前位置追加新卡片继续
- **不显示阶段编号、不显示总进度条**

### 2.4 阶段 4：工作汇总 + 回到对话

- **汇总卡片**（标题"完成总结"，**默认展开**）：
  - 总结正文（Markdown）
  - 每个主步骤作为子折叠卡片（默认折叠）
- **紧接 AI 总结消息**（Markdown 平铺）：用自然语言收尾，提示用户可以继续提需求
- **自动进入对话模式**：消息流不清空，输入框等待下一句

## 三、视觉规格

### 3.1 消息列容器

```
MessageList (StackPanel)
├── HorizontalAlignment: Stretch
├── 内层 ContentPresenter HorizontalAlignment: Center
└── 每条消息 Margin: 0,8,0,0    (上下间距 8px)

注：所有消息项靠"间距"而非"MaxWidth"约束视觉边界
    避免窗口缩小时文字被遮挡
```

### 3.2 用户气泡

```
Border
├── Background: UserBubbleBrush (#30343B)            (复用现有资源)
├── BorderBrush: UserBubbleBorderBrush (#3A4452)     (复用现有资源)
├── BorderThickness: 1
├── CornerRadius: 3
├── Padding: 12,8,12,8
├── Margin: 16,4,16,8      ← 距左右边各 16px,距上 4px,距下 8px
├── HorizontalAlignment: Stretch    ← 铺满中间列,不设 MaxWidth
└── Content:
    └── MarkdownRenderer (复用现有控件)
```

**禁止设置 MaxWidth**：上一版本因 MaxWidth 导致缩小窗口时文字被遮挡。靠 Margin 控制视觉边界。

### 3.3 AI 内容（平铺）

```
ContentPresenter
├── 无 Border, 无 Background, 无 CornerRadius
├── Margin: 16,4,16,8      ← 与用户气泡相同间距,保持节奏
├── HorizontalAlignment: Stretch
└── Content:
    └── StackPanel (Vertical)
        ├── 思维卡片 (折叠卡片,可 0~N 个)
        ├── 工具卡片 (折叠卡片,可 0~N 个)
        └── MarkdownRenderer (主体内容)
```

### 3.4 折叠卡片（思维 / 工具 / 验收 / 子步骤 / 汇总 / 主步骤）

```
Border (Card)
├── BorderBrush: AiBubbleBorderBrush (#3c3c3c)
├── BorderThickness: 1
├── CornerRadius: 3
├── Background: #1e1e1e (略深于 AI 区底色)
├── Margin: 0,4,0,4
└── 内部结构:
    └── DockPanel
        ├── Header (DockPanel.Dock=Top) [可点击展开/折叠]
        │   ├── Image #ArrowImage (Dock=Left, 16x16)    ← 箭头图片在标题"左边"
        │   │   ├── Source: 项目资源 arrow_right.png    (复用现有)
        │   │   └── RenderTransform: RotateTransform Angle=0
        │   │       折叠态: Angle=0   (指右)
        │   │       展开态: Angle=90  (指下)
        │   │       Transitions: DoubleTransition Duration=0:0:0.15
        │   ├── TextBlock (标题文本,无 emoji)
        │   └── TextBlock (右侧状态: 完成 / 失败 / 运行中 等,可选)
        └── ContentArea (DockPanel.Dock=Bottom)
            ├── IsVisible 绑定到展开状态
            ├── Padding: 24,8,12,12  (左缩进对齐标题文字,跳过箭头)
            └── Content: 根据卡片类型注入不同内容
```

**箭头旋转动画**：参考 [RealtimeProcessCard.axaml.cs](../../../Src/Netor.Cortana.UI/Controls/RealtimeProcessCard.axaml.cs) `ArrowImage` 的实现模式。

### 3.5 卡片标题词典（统一规范）

| 卡片类型 | 标题 |
|---------|------|
| 思维卡片 | `思考` 或 `思考 - <主题>` |
| 工具卡片 | `调用工具 <function_name>` |
| 验收卡片 | `验收` 或 `验收 - <反馈摘要>` |
| 子步骤卡片 | `<子步骤名>`（来自计划） |
| 主步骤(时间线圆点) | `<主步骤名>`（来自计划） |
| 汇总卡片 | `完成总结` |

### 3.6 时间线（TimelineBlock）

```
TimelineBlock (UserControl,作为消息列一项插入)
├── Margin: 16,8,16,8
├── HorizontalAlignment: Stretch
└── 内部:
    └── StackPanel (Vertical)
        └── 每个主步骤一行 Grid:
            ├── 左列: 圆点 + 竖线
            │   ├── Ellipse (12x12)
            │   │   ├── Fill: #5A5A5A (统一灰色,不分状态)
            │   │   ├── Stroke: #3c3c3c
            │   │   └── StrokeThickness: 1
            │   └── Rectangle (2px 宽,垂直竖线)
            │       └── Fill: #3c3c3c    (连接到下一个圆点)
            └── 右列: 主步骤标题行 + 子步骤卡片列表
                ├── TitleRow:
                │   ├── TextBlock: 主步骤名
                │   └── TextBlock: 右侧状态文字
                │       状态文字: "运行中" / "已完成" / "等待中"
                │       (纯文字,无颜色区分,统一前景色)
                └── StackPanel: 子步骤卡片列表
                    └── 每个子步骤是一个折叠卡片
                        └── 展开后内容: 思维/工具/验收卡片串行
```

**关键**：圆点统一灰色，不用颜色区分状态。状态通过右侧文字（运行中/已完成/等待中）传达。
**层级限制**：主步骤不做折叠卡片，避免出现"主步骤卡片 → 子步骤卡片 → 明细卡片"的三层卡片嵌套。时间线内只保留两层卡片：子步骤卡片 + 子步骤内部的思维/工具/验收卡片。

### 3.6.1 时间线行为

| 触发 | 行为 |
|------|------|
| 主步骤启动 | 圆点 + 主步骤标题行渐现，子步骤区域显示 |
| 主步骤完成 | 主步骤容器继续可见，其下子步骤卡片保持列表状态并自动折叠，标题行右侧显示"已完成" |
| Critic 失败 | 在当前子步骤卡片内**追加**新的工具/验收卡片，**不修改之前的卡片** |
| 上一步逻辑错(退步) | 在当前主步骤标题下**追加**新子步骤卡片，已有子步骤卡片保持不动 |
| 全部完成 | 时间线整块"凝固"，紧随其后插入"完成总结"汇总卡片 |

```
ApprovalFloatPopup (UserControl)

├── HorizontalAlignment: Stretch
├── Margin: 16,8,16,4    (与气泡同间距)
├── Background: #2D2D30
├── BorderBrush: #FF8C00 (工作模式主色调,与 InputMarquee 一致)
├── BorderThickness: 1

│   └── DoubleTransition Property=Opacity Duration=0:0:0.22 (0→1)
└── 内部:
    └── StackPanel
        ├── TextBlock: "工具授权" (标题)
        ├── 详情区:
        │   ├── 工具名:       send_email
        │   ├── 参数列表:     to / subject / attachment 等
        │   └── 风险提示:     "发送邮件不可逆"
        ├── 按钮栏: WrapPanel 或 Grid (2x2)
        │   ├── Button "确认授权"           [本次允许]
        │   ├── Button "本次会话全部允许"   [Session 内此工具自动通过]
        │   ├── Button "永远允许"           [持久化到用户配置]
```

- 退出：反向播放后从 Tree 移除

## 四、上下文与会话管理

### 4.1 全局 Session 贯穿所有任务

```
ChatClientAgentSession  (整个会话期间唯一)
├── ChatHistory   (无限连贯的对话历史,跨任务)
└── StateBag
    ├── tasks: Dictionary<string, TaskState>
    │   ├── "task_001": {
    │   │     plan, ledger, status: completed,
    │   │     createdAt, completedAt, summary
    │   │   }
    │   ├── "task_002": { ..., status: in_progress }
    │   └── "task_003": { ... }
    ├── currentTaskId: string?         (当前活动任务,可空)
    ├── globalApprovals: Dictionary    ("永远允许"的工具规则)
    └── sessionApprovals: Dictionary   (本次会话允许的工具)
```

### 4.2 任务边界判定（AI 路由判断）

总经理智能体在每次用户发言时通过路由 LLM 判断意图，分支：

| 用户意图 | 框架行为 |
|---------|---------|
| 解释/补充信息 | 接收信息，继续当前阶段 |
| 追问执行细节 | 答复后继续 |
| 修改某个子步骤 | 在当前主步骤内追加新子步骤卡片 |
| 修改整体方案 | 回到阶段 2（重新出计划） |
| 改需求 | 回到阶段 1（重谈需求） |
| 提出新任务 | 收尾当前任务（如未完成） → 阶段 1 |
| 自然结束 | 进入空闲态 |

**判定不通过 UI 显式提示**，AI 直接以对话方式承接：
- 例：用户说"再做一份 5 月的" → AI 自动识别为新任务，开始新的需求确认（甚至跳过，因为可参考上一个任务的 Plan）

### 4.3 暂停与恢复

- **触发暂停**：用户在执行中发送消息 / 点击输入框旁的停止按钮
- **暂停后**：当前正在运行的子智能体收到 `CancellationToken`，停止
- **路由判断**：AI 解析用户消息意图（参见上表）
- **恢复**：根据意图决定继续点 / 修改点 / 重启点

### 4.4 任务历史的折叠

任务完成后，时间线整块固化为消息流中的历史项。新任务的时间线作为**新的 TimelineBlock** 插入消息流后续位置。

## 六、关键交互细节

### 6.1 折叠动画

参考 [RealtimeProcessCard.axaml.cs](../../../Src/Netor.Cortana.UI/Controls/RealtimeProcessCard.axaml.cs) 现成模式：

```csharp
// 折叠/展开切换时
ArrowImage.RenderTransform = new RotateTransform(_isExpanded ? 90 : 0);
// 加 Transitions 自动过渡
```

### 6.2 卡片标题点击区域

整个 Header（箭头 + 标题 + 状态文字）都可点击，触发折叠/展开。点击区域要有 hover 高亮（参考 `selector-item` 样式）。

### 6.3 用户气泡内的 Markdown

用户输入可能包含 `#文件引用`、`@智能体引用`。Markdown 渲染时这些片段应高亮（参考 `chat-input` 内的 token 显示风格）。

### 6.4 AI 内容中的工具卡片流式更新

工具卡片在调用过程中可能产生流式输出（如 Shell 命令的 stdout），复用 `RealtimeProcessCard` 的 `_contentBuffer/_flushTimer` 模式做节流刷新。

### 6.5 时间线圆点不变色，那怎么传达状态？

- 圆点统一灰色
- 状态通过主步骤标题行**右侧文字**传达（"运行中"、"已完成"、"等待中"）
- 运行中的主步骤标题行或当前子步骤卡片可加 `InputMarqueeBorder` 同款的霓虹流光（可选，弱化）
- 不要让色彩成为状态信号

### 6.6 授权浮窗的按钮排布

按钮使用 Avalonia 默认 Button 样式 + 现有 `selector-item` 风格，4 个按钮用 `WrapPanel` 或 `Grid` 2x2 排列，避免窄屏被压成一列。

### 6.7 滚动行为

- 新消息追加时自动滚到底部（复用 [ChatView](../../../Src/Netor.Cortana.UI/Controls/ChatView.axaml) 的 `MessageScroller` + `ScrollToBottomBtn`）
- 用户手动上滑后，停止自动滚动；底部出现"回到底部"按钮
- 时间线折叠子步骤卡片时，**不触发自动滚动**（否则用户看不清折叠效果）

### 6.8 左侧工作记录

- 工作模式页面内部不再放独立任务列表。
- 工作任务历史统一接入主窗口左侧面板的“工作记录”Tab。
- 点击工作记录中的任务时，工作模式主消息区从持久化任务和执行日志恢复任务概览、计划、时间线和最终报告。
- 历史恢复时可以省略工具调用的参数和成功结果正文，但必须恢复主步骤标题、子步骤标题、工具名、验收状态和失败错误。

## 七、状态机（ViewModel 实现指引）

```csharp
public enum WorkModeState
{
    Idle,                  // 空闲对话
    RequirementGathering,  // 阶段1
    PlanDrafting,          // 阶段2
    Executing,             // 阶段3
    Paused,                // 用户暂停中
    Summarizing,           // 阶段4
}

public sealed class WorkModeVm : ObservableObject
{
    public WorkModeState State { get; private set; }
    public ObservableCollection<MessageItem> Messages { get; }   // 消息流
    public ApprovalRequestVm? PendingApproval { get; }           // 当前授权请求(可空)
    public TimelineVm? CurrentTimeline { get; }                  // 当前任务时间线(可空)

    public async Task SubmitUserMessageAsync(string text);
    public async Task StopAsync();                               // 输入框停止按钮
    public void ApproveTool(ApprovalKind kind);                  // 4 个按钮之一
}

public sealed class MessageItem
{
    public MessageRole Role;          // User / Ai / TimelineBlock / SummaryCard
    public string? Markdown;
    public IList<FoldableCardVm>? PrependedCards;  // AI 消息前置的思维/工具卡片
    public TimelineVm? Timeline;
    public SummaryCardVm? Summary;
}
```

**关键不变量**：
- 消息一旦加入 `Messages`，**永不修改 / 删除**
- 时间线内的卡片可以"追加"，但已有的卡片不修改
- 状态切换不引发 UI 重排，纯靠追加新消息项

## 八、与 AF 框架的连接

| UI 行为 | AF 框架对应 |
|---------|-----------|
| 提交用户消息 | `AIAgent.RunStreamingAsync(msg, session)` |
| 思维过程显示 | 监听 `AgentResponseUpdateEvent`（reasoning content） |
| 工具调用显示 | 监听 `FunctionCallContent` / `FunctionResultContent` |
| 用户确认进入下一阶段 | 总经理智能体路由判断（自定义 `GroupChatManager`） |
| 时间线主步骤推进 | 监听 `MagenticProgressEvent` / `ExecutorInvokedEvent` |
| 时间线子步骤完成 | 监听 `ExecutorCompletedEvent` / `AgentResponseEvent` |
| Critic 验收失败 | Critic Agent 输出 "VERDICT: FAIL" → 路由重试 |
| 工具授权浮窗触发 | 监听 `RequestInfoEvent` + `ToolApprovalRequestContent` |
| 浮窗按钮回填 | `run.SendResponseAsync(request.CreateResponse(...))` |
| 暂停 | 触发 `CancellationToken` + 保存 Checkpoint |
| 恢复 | `InProcessExecution.ResumeAsync(workflow, runId, checkpointStore)` |

## 十一、长任务可靠性的 UI 配套（v1.0 增补）

> 工作模式定位"一人公司"，支持视频剪辑（6-8 小时）、网站开发（30+ 小时）等长任务。
> 这一章为长任务相关的 UI 元素补充视觉规格。详见 [16 文档](./16-长任务可靠性与重试策略.md)。

### 11.1 进度横条（顶部固定）

工作模式 Tab 的消息区**顶部**固定一个"进度横条"（在欢迎面板之上、消息流之上）：

```text
┌─────────────────────────────────────────────────────────────────┐
│ 实现登录功能 (12/35)              预计 8 小时后完成            ███████░░░░░ 34%
└─────────────────────────────────────────────────────────────────┘
```

视觉规格：

- 高度：32px（消息流可见区减少 32px）
- 背景：`#252526`，下边框 `#3c3c3c`
- 左侧：当前子步骤标题 + 进度（已完成/总数）
- 右侧：预计完成时间
- 底部 4px 进度条：`#FF8C00` 填充，`#3c3c3c` 背景
- 任务空闲（无活跃任务）时**整体隐藏**，回到欢迎面板状态

### 11.2 并列主步骤（dispatch_parallel 配套）

`TimelineBlock` 在并行块内同时展示多个主步骤：

```text
●━━━ 主步骤 1（已完成）
│
●━━━ [并行块 · 3 列]
│  ┌───────────────────┬───────────────────┬───────────────────┐
│  │ 主步骤 2A         │ 主步骤 2B         │ 主步骤 2C         │
│  │ 状态: 运行中       │ 状态: 运行中       │ 状态: 已完成       │
│  │ ├─ 子步骤 2A.1     │ ├─ 子步骤 2B.1     │ ├─ 子步骤 2C.1     │
│  │ └─ 子步骤 2A.2     │                    │                    │
│  └───────────────────┴───────────────────┴───────────────────┘
│
●━━━ 主步骤 3（等待中，并行块全部完成才开始）
```

视觉规格：

- 并行块左侧仍是单个圆点（区别于多列圆点的混乱）
- 圆点右侧用一个浅色边框（`#3c3c3c`，1px）包裹整个并行块
- 边框右上角小字："并行 · 3 列"
- 列与列之间 16px 间距，每列宽度均分剩余空间
- 列内部完全是普通主步骤的展开形式（标题行 + 子步骤卡片列表）
- 窄屏（< 800px）时降级为竖向堆叠（保留每列的子步骤区，去掉左右并列）

### 11.3 嵌套子工作流下钻

主步骤标题行右侧，如果该主步骤通过 `dispatch_nested_workflow` 创建了嵌套子工作流，显示一个"展开"图标：

```text
●━━━ 实现登录功能（运行中）  ⤢ 展开嵌套
```

点击 ⤢ 图标，**在当前位置原地展开**（不弹新窗口、不切页面）：

```text
●━━━ 实现登录功能（运行中）  ⤡ 收起嵌套
│   ┌─ 嵌套子工作流：实现登录功能 ─────────────────────┐
│   │ ●━━━ 设计 API 契约（已完成）                     │
│   │ ●━━━ 写 Controller（已完成）                     │
│   │ ●━━━ 写 Service（运行中）                        │
│   │ ●━━━ 写 Repository（等待中）                     │
│   │ ●━━━ 写单元测试（等待中）                        │
│   │ ●━━━ 调试通过（等待中）                          │
│   │ ●━━━ 提交代码（等待中）                          │
│   └─────────────────────────────────────────────────┘
```

嵌套区域：

- 比父级时间线缩进 24px
- 左右边框 `#3c3c3c`，1px
- 顶部有标题"嵌套子工作流：{Goal}"
- 内部完整复用 `TimelineBlock` 控件（递归用法）
- v1.0 嵌套深度 = 2（不允许嵌套里再嵌套）

应用崩溃后重启，UI 加载会话末尾如果检测到 `IsOrphaned=1` 的任务，追加这张卡片：

```text

│                                                         │
│ 任务：实现登录功能                                       │

│ 最后一步：写 Service - 自评迭代 2/5                      │
│                                                         │
│        [继续执行]              [放弃任务]                │
└─────────────────────────────────────────────────────────┘
```

视觉规格：

- 与 `SummaryCard` 类似的边框 + 内边距
- 边框 `#FF8C00`（强调色）+ 1px
- 标题行用 ⚠ + "上次任务未正常结束"（这是工作模式里允许的 emoji 唯一例外，因为是关键决策点）

### 11.5 自评循环视觉

子步骤的自评循环不在主时间线展开（避免噪音），改为：

- 当前子步骤卡片右侧状态文字显示"自评迭代 (3/5)"
- 卡片展开后内部追加内嵌的"自评 - 第 N 次"折叠卡片（默认折叠）
- 用户感兴趣点开看具体的 issues / suggestions

```text
┌─────────────────────────────────────────────┐
│ ▶ 销售月报排版                  自评迭代 (3/5)
└─────────────────────────────────────────────┘

展开后：
┌─────────────────────────────────────────────┐
│ ▼ 销售月报排版                  自评迭代 (3/5)
│   ▶ 调用工具 export_pdf            完成
│   ▶ 自评 - 第 1 次                 fail (62)
│   ▶ 调用工具 export_pdf            完成
│   ▶ 自评 - 第 2 次                 marginal (78)
│   ▶ 调用工具 export_pdf            完成
│   ▶ 自评 - 第 3 次                 pass (91)
└─────────────────────────────────────────────┘
```

### 11.6 重试中的视觉反馈

任意工具调用如果触发了自动重试（来自 `RetryingFunctionWrapper`），工具卡片右侧状态文字显示"重试中 (2/5)"：

- 不弹任何浮窗
- 不打断正在显示的内容
- 重试成功后状态恢复为"完成"
- 重试上限到达后状态变为"失败"

### 11.7 软抢占已收到反馈

[12 文档](./12-输入路由与状态机设计.md) 软抢占识别命中后，当前正在跑的主步骤标题行旁追加一个标签：

```text
●━━━ 写 Service（运行中 · 已收到打断指令）
```

不打断当前正在跑的工具，但给用户视觉反馈"输入被收到了，会在最近的工具结束后处理"。

### 11.8 死循环检测命中

[16 文档 §七](./16-长任务可靠性与重试策略.md) 死循环检测命中后，会触发 `ask_user`，UI 上会自然出现一条总经理 AI 消息：

```text
我注意到自己在 [当前子步骤] 上反复尝试 5 次都没成功，问题可能出在 ...。
请问你想：
A. 让我换个思路再试
B. 跳过这一步继续后面的
C. 修改计划
```

不需要专门的 UI 控件，复用 ask_user 的对话流即可。但**重试中和死循环命中**两种状态在工具卡片上要明显区分：

- 重试中（瞬时） = 黄色"重试中 (2/5)"
- 死循环（已停下问用户） = 橙色"已停下等指令"
