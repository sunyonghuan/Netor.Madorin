# 03 - 编排模式（多智能体协作核心）

> AF 工作流引擎提供 6 种开箱即用的编排模式
> 源码：`E:\OpenSourse\agent-framework-main.v1.6.0\dotnet\src\Microsoft.Agents.AI.Workflows\`

## 一、工作流引擎概览

### 1.1 核心类型

```csharp
// 节点 - 智能体或自定义代码
public abstract class Executor { /* 处理输入 → 产生输出 */ }
public abstract class Executor<TIn, TOut> : Executor { ... }

// 边 - 节点间数据流
public class Edge { /* Source → Target，可带条件 */ }

// 工作流（编译后产物）
public sealed class Workflow { ... }

// 构建器
public class WorkflowBuilder
{
    public WorkflowBuilder AddEdge<TIn>(Executor source, Executor target);
    public WorkflowBuilder AddFanOutEdge<TIn>(Executor source, IEnumerable<Executor> targets);
    public WorkflowBuilder AddFanInEdge<TIn>(IEnumerable<Executor> sources, Executor target);
    public WorkflowBuilder SetStartExecutor(Executor start);
    public Workflow Build();
}

// 执行
public static class InProcessExecution
{
    public static Task<TResult> RunAsync<TResult>(Workflow workflow, object input, ...);
    public static IAsyncEnumerable<WorkflowEvent> RunStreamingAsync(Workflow workflow, object input, ...);
}
```

### 1.2 执行模型
- **Superstep 模型**（类似 Pregel/BSP）：每一步内所有 Executor 并行执行，步与步之间同步
- **消息驱动**：每个 Edge 传递一条消息
- **事件流**：执行中持续产生 `WorkflowEvent`

### 1.3 智能体作为 Executor

```csharp
// 框架自动提供把 AIAgent 包装为 Executor 的能力
var agentExecutor = agent.AsExecutor();
// 内部：Executor<ChatMessage, ChatMessage>
```

## 二、模式 1：Sequential（顺序流水线）

### 2.1 适用场景
**线性多步骤任务** — 翻译 → 校对 → 润色

### 2.2 构建

```csharp
var workflow = AgentWorkflowBuilder.BuildSequential(
    frenchAgent,    // 第一步：法语翻译
    spanishAgent,   // 第二步：西班牙语翻译
    englishAgent    // 第三步：英语翻译
);

var result = await InProcessExecution.RunAsync<List<ChatMessage>>(
    workflow,
    new ChatMessage(ChatRole.User, "Hello"));
```

## 四、模式 3：GroupChat（群聊轮转）

### 4.1 适用场景
**多个智能体围绕一个主题反复交流，直到达成共识或满足条件**

### 4.2 核心：`GroupChatManager`

```csharp
public abstract class GroupChatManager
{
    public int IterationCount { get; protected set; }
    public int MaximumIterationCount { get; set; } = 40;

    // 关键：决定下一个发言者
    public abstract ValueTask<AIAgent?> SelectNextAgentAsync(
        IReadOnlyList<ChatMessage> history);

    // 关键：决定是否终止
    public virtual ValueTask<bool> ShouldTerminateAsync(
        IReadOnlyList<ChatMessage> history);

    // 在传给下一个智能体前过滤历史
    public virtual ValueTask<IReadOnlyList<ChatMessage>> UpdateHistoryAsync(
        IReadOnlyList<ChatMessage> history);

    public virtual void Reset();
}
```

### 4.3 内置：`RoundRobinGroupChatManager`

```csharp
var workflow = AgentWorkflowBuilder
    .CreateGroupChatBuilderWith(agents => new RoundRobinGroupChatManager(agents)
    {
        MaximumIterationCount = 5,
    })
    .AddParticipants(qaEngineer, devopsEngineer)
    .Build();
```

### 4.4 自定义 Manager（**我们要做这个**）

```csharp
public sealed class GeneralManagerChat : GroupChatManager
{
    private readonly AIAgent _critic;     // 验收员
    private readonly AIAgent _planner;    // 规划员

    public override async ValueTask<AIAgent?> SelectNextAgentAsync(
        IReadOnlyList<ChatMessage> history)
    {
        // 用一个"路由"LLM 决定谁发言
        var route = await _planner.RunAsync(
            $"根据下面对话决定下一个发言者（planner/worker/critic）: {history.Last()}");
        return Resolve(route.Messages.Last().Text);
    }

    public override async ValueTask<bool> ShouldTerminateAsync(
        IReadOnlyList<ChatMessage> history)
    {
        // 让 Critic 判断是否达标
        var verdict = await _critic.RunAsync($"是否达标？历史:{history}");
        return verdict.Messages.Last().Text.Contains("PASS");
    }
}
```

## 五、模式 4：Handoff（智能体接力）

### 5.1 适用场景
**前台分诊 → 转交专家** — 一个入口智能体分析意图，把控制权交给最匹配的下游智能体

### 5.2 工作原理
框架会把"转交"操作变成**特殊工具调用**，例如 `handoff_to_LegalAgent()`，当 LLM 调用这个工具时，框架检测并切换 Executor。

### 5.3 构建

```csharp
var workflow = AgentWorkflowBuilder
    .CreateHandoffBuilderWith(intakeAgent)               // 入口
    .WithHandoffs(intakeAgent, [legalAgent, financeAgent, techAgent])  // intake → 任一专家
    .WithHandoffs([legalAgent, financeAgent, techAgent], intakeAgent)  // 专家可回 intake
    .EnableReturnToPrevious()                            // 允许返回前一个智能体
    .WithHandoffInstructions("当用户问题超出你的领域时，请转交给合适的同事")
    .Build();
```

### 5.4 关键类型

```csharp
public readonly record struct HandoffTarget(AIAgent Target, string? Reason);

public sealed record HandoffState
{
    public TurnToken TurnToken { get; init; }
    public string? RequestedHandoffTargetAgentId { get; init; }
    public string? PreviousAgentId { get; init; }
}
```

### 5.6 在业务模型中的角色
**总经理把任务交给某个部门**（部门接手后可以再交回，也可以转给其他部门）。

## 六、模式 5：Magentic（**与我们业务模型最匹配**）

### 6.1 适用场景
**Manager 协调多个专家完成一个复杂任务**，Manager：
- 制定 Plan
- 维护 Progress Ledger
- 检测卡住 / 死循环
- 必要时重规划（Replan）

### 6.2 构建

```csharp
var workflow = new MagenticWorkflowBuilder(managerAgent)
    .AddParticipants([researcherAgent, coderAgent, writerAgent])
    .WithMaxRounds(10)        // 最多 10 轮
    .WithMaxStalls(3)         // 最多 3 次卡住
    .Build();

// 监听事件
await foreach (var evt in InProcessExecution.RunStreamingAsync(workflow, "完成一份市场分析报告"))
{
    switch (evt)
    {
        case MagenticPlanEvent planEvt:
            Console.WriteLine($"计划：{planEvt.Plan}");
            break;
        case MagenticProgressEvent progressEvt:
            Console.WriteLine($"进展：{progressEvt.Ledger}");
            break;
        case MagenticReplanEvent replanEvt:
            Console.WriteLine($"重规划：{replanEvt.NewPlan}");
            break;
    }
}
```

### 6.3 核心机制

| 阶段 | Manager 做什么 |
|------|--------------|
| **Plan** | 分析任务 → 拆分为子任务 → 选择参与者 |
| **Ledger** | 每轮维护"已完成 / 进行中 / 待办"清单 |
| **Stall Detection** | 检测是否同一动作反复执行无进展 |
| **Replan** | 卡住超过阈值时，重新生成 Plan |
| **Completion** | 验收完整性，提取最终答案 |

### 6.4 关键源码
- `src\Microsoft.Agents.AI.Workflows\Specialized\Magentic\` 整个目录
- 示例：`samples\03-workflows\Orchestration\Magentic\`

### 6.5 **这就是我们的"总经理"**

```
老板提需求 → 总经理(Magentic Manager)
            ├── 制定工作计划 (Plan)
            ├── 安排部门做事 (Researcher/Coder/Writer)
            ├── 跟踪进度 (Ledger)
            ├── 发现卡住 → 重新规划
            └── 验收 → 汇报报表给老板
```

## 七、模式 6：WriterCritic（**验收-重做循环**）

### 7.1 适用场景
**有质量门禁的任务** — Writer 写内容，Critic 评分，不达标退回。**这是问题 3 的标准答案**。

### 7.2 工作流图

```
开始 ──→ Writer ──→ Critic ──┬─→ (Pass)  ─→ 输出
                              └─→ (Fail)  ─→ Writer（带 Critic 的修改意见）
                                   ↑ 循环
```

### 7.3 关键技术：`ConditionalEdge`

```csharp
public class WorkflowBuilder
{
    public WorkflowBuilder AddEdge<TIn>(
        Executor source,
        Executor target,
        Func<TIn, bool>? condition = null);  // 只有满足条件才走这条边
}
```

### 7.4 示例代码模式

```csharp
var builder = new WorkflowBuilder();
builder.SetStartExecutor(writerAgent.AsExecutor());

// Writer → Critic（无条件）
builder.AddEdge<ChatMessage>(writerAgent.AsExecutor(), criticAgent.AsExecutor());

// Critic → 输出（如果 Pass）
builder.AddEdge<ChatMessage>(
    criticAgent.AsExecutor(),
    outputExecutor,
    msg => msg.Text.Contains("PASS"));

// Critic → Writer（如果 Fail，循环）
builder.AddEdge<ChatMessage>(
    criticAgent.AsExecutor(),
    writerAgent.AsExecutor(),
    msg => !msg.Text.Contains("PASS"));

var workflow = builder.Build();
```

### 7.5 关键源码
- 示例：`samples\03-workflows\_StartHere\07_WriterCriticWorkflow\`

### 7.6 在业务模型中的角色
**部门完成工作 → 自检 → 不达标 → 重做** — 完美对应"循环执行直到合格"。

## 八、模式组合（嵌套与子工作流）

### 8.1 子工作流

工作流可以嵌套 — 父工作流的一个 Executor 内部运行另一个工作流：

```csharp
// 子工作流（部门内部）
var departmentWorkflow = AgentWorkflowBuilder.BuildSequential(workerA, workerB);

// 父工作流（总经理协调多个部门）
var orgWorkflow = new MagenticWorkflowBuilder(generalManager)
    .AddParticipants([
        departmentWorkflow.AsAIAgent("部门A"),    // 子工作流作为参与者
        departmentWorkflow.AsAIAgent("部门B"),
    ])
    .Build();
```

### 8.2 关键源码
- `samples\03-workflows\_StartHere\05_SubWorkflows\`

### 8.3 我们的三层嵌套设计

```
Level 1: Magentic 工作流
  ├── Manager: 总经理 (GeneralManagerAgent)
  └── Participants:
      ├── Level 2: 部门 A 工作流 (GroupChat)
      │     ├── Manager: 部门主管
      │     └── Participants: 员工 A1, A2, A3
      ├── Level 2: 部门 B 工作流 (Sequential + WriterCritic)
      │     ├── Writer: 员工 B1
      │     ├── Critic: 员工 B2
      └── ...
```

## 九、流程图速查

### 9.1 各模式选择决策树

```
要解决什么？
├── 一条直线流程 → Sequential
├── 多个并行视角后汇总 → Concurrent
├── 多人讨论 → GroupChat
├── 分诊 + 专家接力 → Handoff
├── 复杂任务+智能规划+卡住重规划 → Magentic ★
├── 内容生成 + 质量门禁循环 → WriterCritic ★
└── 上述组合 → 嵌套（子工作流）
```

### 9.2 业务问题与编排模式映射

| 我们的业务问题 | 推荐模式 |
|-------------|---------|
| 总经理拆解任务 | **Magentic**（Manager 思路） |
| 任务验证 + 退回重做 | **WriterCritic** + Magentic |
| 部门内员工协作 | **GroupChat** 或 **Sequential** |
| 部门转交 | **Handoff** |
| 多部门并行 + 汇总 | **Concurrent** + Magentic |
