# 会议模式阶段 0-1 对齐检查

> 检查时间：2026-05-31

## 总结

阶段 0 和阶段 1 的主线已经与文档对齐：HITL 公共层、提示词加载链路、会议数据表、实体服务、事件契约、会议提示词资源、启动孤儿清理均已落地，并通过 `dotnet build Netor.Cortana.slnx --no-restore` 验证。

## 已对齐

- `HitlTools` 已迁移到 `Netor.Cortana.AI.Hitl`，构造参数改为 `IHitlContext` + `IHitlNotifier`。
- 工作模式通过 `WorkTaskHitlContext` + `WorkHitlNotifier` 适配公共 HITL 层，旧 `HitlPendingRequestSnapshot` 位置保留兼容类型。
- `IPromptProvider` 已接入 DI，默认链路为 `LocalFilePromptProvider -> EmbeddedResourcePromptProvider`。
- `GeneralManagerAgentBuilder` 已改为异步加载提示词，工作模式提示词可由本地文件覆盖、EmbeddedResource 兜底。
- 会议模式 5 张表、关键索引、实体与 Service 已落地。
- `Events.cs` 已追加会议模式事件与 Args 契约。
- `MeetingJsonContext` 已注册会议模型和公共 HITL snapshot。
- `prompts/meeting/host.md`、`compaction.md`、`participant_header.md` 已加入 EmbeddedResource。
- `MeetingStartupService` 已注册为 `IHostedService`，启动时把遗留活跃会议标记为已散会。

## 已补齐

- `MeetingMessageService` 已补充文档中阶段 1/2 会用到的异步方法：
  - `AppendSummaryAsync`
  - `GetLatestSummaryAsync`
  - `AppendPartialAsync`
- `MeetingMessageService` 已补充 `ListBySequence`，保留原有 `ListBySequenceRange` 与 `ListCompleteBySequence`。
- `MeetingMessageService.Append` 已改为在同一 SQLite 事务连接内完成 `Sequence` 分配和插入，避免事务语义与文档不一致。
- `CortanaDbContext` 已补充有返回值的事务 helper，供后续需要同连接事务的服务复用。

## 有意偏离

- 文档里写 `WorkTaskService` / `MeetingSessionService` 可直接实现 `IHitlContext`。当前代码没有让 `Entitys` 层引用 `AI` 层接口，而是在 AI 层放 adapter。这是为了保持分层依赖方向正确。
- `MeetingPendingInputService` 当前只提供实体级 `Drain` 和 `PeekUnconsumed`。文档里的 `DrainAsUserMessages` 需要依赖 `Microsoft.Extensions.AI.ChatMessage`，后续应在 AI 层 `MeetingHistoryProvider` 或 adapter 中完成转换，避免数据层依赖 AI 包。
