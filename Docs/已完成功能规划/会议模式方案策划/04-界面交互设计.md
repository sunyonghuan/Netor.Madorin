# 04 - 界面交互设计

> 会议模式 UI/UX 规范
> 实现栈：Avalonia 11 (.axaml)，code-behind，AOT 安全
> 视觉基调：**仿专家模式**（头像 + 名字 + 时间 + 气泡）

## 一、全局原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **零浮窗交互** | 所有问询、确认、总结都以普通气泡形式插入消息流，通过输入框作答 |
| 2 | **仿专家模式视觉** | 每条发言带 40x40 头像 + 名字 + 时间戳 + Markdown 气泡（参考 [ChatView.AddMessageBubble](../../../Src/Netor.Cortana.UI/Controls/ExpertMode/ChatView.axaml.cs#L190)） |
| 3 | **左右对齐区分身份** | user 右对齐；agent / host 左对齐 |
| 4 | **思考/工具卡嵌入气泡内** | 不作为独立卡片漂浮在气泡外（与工作模式 TimelineBlock 不同） |
| 5 | **输入区复用** | [InputAreaView](../../../Src/Netor.Cortana.UI/Controls/ExpertMode/InputAreaView.axaml) 直接复用，新增 `Meeting` 模式的多选改造 |
| 6 | **AOT 安全** | 全 code-behind，无 Binding，无反射 |

#### 提交前数量校验（修复缺陷 22）

老板按发送前 UI 必须做参会者数量校验，避免 backend 才发现错误：

```csharp
// MeetingInputArea.OnSendClick 内
private const int MinParticipants = 2;
private const int MaxParticipants = 8;

private void OnSendClick(object? sender, RoutedEventArgs e)
{
    var selectedAgents = _meetingInputVm.SelectedAgents;
    if (selectedAgents.Count < MinParticipants)
    {
        ShowValidationError($"会议至少需要 {MinParticipants} 位参会者(当前 {selectedAgents.Count} 位)");
        return;
    }
    if (selectedAgents.Count > MaxParticipants)
    {
        ShowValidationError($"会议建议不超过 {MaxParticipants} 位参会者(当前 {selectedAgents.Count} 位),可能影响讨论质量");
        // 仅警告,允许继续
    }

    // 校验通过 → 提交主题给 MeetingExecutor
    _meetingInputVm.SubmitTopic();
}
```

UI 显示位置：智能体多选按钮下方红色文字（仿 [InputAreaView ValidationErrorText](../../../Src/Netor.Cortana.UI/Controls/ExpertMode/InputAreaView.axaml#L37) 模式），点 Send 按钮校验失败时显示。

> **关键**：UI 校验是**用户体验防线**，不是数据正确性防线。Backend `MeetingExecutor.ExecuteAsync` 仍然有相同校验（详见 [02 §1.2](./02-AF编排集成.md)），双重保护。

### 3.5 Model 锁定反馈（修复缺陷 26）

会议进行中（`MeetingSessions.Status IN (0, 1)`），输入区的 Model / Provider 按钮**仍可点击**（保持视觉一致性），但点击行为改为弹出 toast 提示：

```text
当前会议已锁定模型 [Claude 4.7]，本次切换不生效。
下次新建会议时使用您选择的新模型。
```

实现：

```csharp
// InputAreaView.OnModelSelectorClick 的 Meeting 模式分支
private void OnModelSelectorClick_Meeting(object? sender, RoutedEventArgs e)
{
    var activeMeeting = _meetingInputVm.ActiveMeeting;
    if (activeMeeting?.Status is MeetingStatus.InProgress or MeetingStatus.AwaitingUser)
    {
        ShowToast(
            $"当前会议已锁定模型 [{activeMeeting.ModelName}],本次切换不生效。" +
            "下次新建会议时使用您选择的新模型。");
        return;    // 仍打开 popup 让用户选,但 popup 选择只对下次会议生效
    }

    // 无活跃会议 → 正常打开模型 popup
    ModelPopup.IsOpen = true;
}
```

**关键约束**：

- 用户**仍能选**新模型（Popup 正常打开），选择被记到 ChatInputVm 的全局状态
- 当前活跃会议**不受影响**（`MeetingExecutor.ExecuteAsync` 内部读 `session.Model` 而不是输入区状态）
- 用户结束会议（用 `/end` 或主持人 confirm_meeting_end 走完流程）后再新建的会议使用新模型
- 详见 [03 §3.1 Provider/Model 锁定语义](./03-数据模型与持久化.md)

### 4.2 各角色视觉规格

| 角色 | 头像 | 名字 | 气泡颜色 | 对齐 | 备注 |
|------|------|------|---------|------|------|
| **user** | UserAvatarBitmap | "我" | UserBubbleBrush | **右** | 与专家模式完全一致 |
| **agent** | AgentEntity.Avatar 或 AiAvatarBitmap | AgentEntity.Name | AiBubbleBrush | **左** | 复用专家模式 |
| **host - normal** | 主持人专属图标（小议长锤） | "主持人" | AiBubbleBrush | 左 | 与 agent 同色，靠头像区分 |
| **host - summary** | 同上 | "主持人 · 会议总结" | AiBubbleBrush + 整体淡紫底色 (`#1A06CFF`) | 左 | 视觉上是会议的"重点段落" |
| **host - inquiry** | 同上 | "主持人 · 征询您的意见" | AiBubbleBrush + **左侧 3px 紫色色条** | 左 | 同时触发 StatusHintBar 紫色加亮 |

**关键约束**（修复缺陷 13 视觉侧）：

- `host - normal` / `host - summary` / `host - inquiry` 三种视觉**完全由 `MeetingMessageEntity.MessageRole` 决定**：
  - `MessageRole=normal` → host - normal
  - `MessageRole=summary` → host - summary（必须由主持人调 `output_summary` 工具触发，详见 [02 §三.4](./02-AF编排集成.md)）
  - `MessageRole=inquiry` → host - inquiry（必须由主持人调 `ask_user` 工具触发，详见 [02 §三](./02-AF编排集成.md)）
- **不允许**用主持人 markdown 内容关键词匹配（"会议总结" / "请问"）来切换视觉——会被 LLM 用词不规范带偏
- `output_summary` 工具发布 `meeting.summary.draft` 事件，但视觉切换的真相是 `MessageRole=summary` 的 MeetingMessages 落库

**部分消息附加角标**（修复缺陷 14 视觉侧）：当 `MeetingMessageEntity.IsPartial=1` 时，气泡右上角加 "未完成" 灰色 chip + tooltip 显示 ErrorMessage。详见 §5.5。

### 5.3 用户提交输入的分流

在 `InputAreaView` 的 `UserMessageSubmitted` 事件回调里：

```csharp
private async void OnMeetingUserSubmit(string text)
{
    var meetingId = _currentMeetingId;
    if (string.IsNullOrEmpty(meetingId)) return;

    var session = _sessions.GetById(meetingId);
    if (session is null) return;

    // 用户消息立即显示在 UI（不等 backend 确认）
    AddUserBubble(text);

    if (!string.IsNullOrEmpty(session.PendingRequestId))
    {
        // HITL 挂起态 → Resume
        await _executor.ResumeAsync(meetingId, text);
    }
    else
    {
        // 普通插话 → 入队
        await _executor.EnqueueInterruptAsync(meetingId, text);
    }
}
```

### 5.4 Tab 切换语义（修复缺陷 16）

**场景**：用户在会议进行中切到对话模式 / 工作模式 Tab，会议在后台继续跑（事件持续产出），用户切回时期望看到完整的最新状态。

**关键决策**：

- **MeetingView 实例在 Tab 切换时保留**（`IsVisible=Collapsed`，不销毁不重建）
- **MeetingViewController 的事件订阅与 Tab 可见性解耦**——切走时仍处理事件、更新内部 `_bubbles` 字典；只在 IsVisible=true 时调 `ScrollToBottom`、播放走马灯动画
- 切回 Meeting Tab → 不需要重建任何 UI 状态（已经在内存里）
- 只有从左侧"会议记录"列表点开**另一个会议** → 走 `LoadMeetingHistoryAsync` 路径完整重建

```csharp
public sealed class MeetingViewController
{
    private bool _isVisible;

    public void SetVisibility(bool isVisible)
    {
        _isVisible = isVisible;
        if (isVisible)
        {
            // 切回时:仅滚动到最新位置,不重建状态
            _view.ScrollToBottom();
        }
    }

    private void OnMeetingMessageDelta(MeetingMessageDeltaArgs args)
    {
        Avalonia.Threading.Dispatcher.UIThread.Post(() =>
        {
            if (!_bubbles.TryGetValue(args.MessageId, out var bubble)) return;
            bubble.MarkdownBuffer.Append(args.DeltaText);
            bubble.MarkdownRenderer.Markdown = bubble.MarkdownBuffer.ToString();

            // 只在 Tab 可见时滚动,避免后台运算开销
            if (_isVisible) _view.AutoScrollToBottom();
        });
    }
}
```

**关键约束**：

- 后台跑的会议事件**必须**在切走期间继续被处理（更新 `_bubbles` 字典 + 写库），否则切回时丢失中间消息
- 走马灯 / 状态提示行 / 滚动行为都按 `_isVisible` 联动，不影响数据正确性
- 主窗口 Tab 切换通知 `MeetingViewController.SetVisibility`

### 5.5 重试与部分消息的 UI 反馈（修复缺陷 14 + 20 视觉侧）

**`meeting.llm.retrying`（缺陷 20）**：

- StatusHintBar 文字临时变 "网络抖动,正在重试...（第 N/M 次）"，颜色 `#F0A030`（橙色提示）
- 走马灯频率加快显示活动状态

- 该气泡不再接收 delta 事件，新一轮发言（同 speaker 或换人）会创建新的 BubbleHandle

每行 chip 字段：

| 字段 | 来源 | 视觉 |
|------|------|------|
| 状态徽标 | `MeetingSessions.Status` | 进行中=绿点 / 已结束=灰点 / 已散会=暗灰点 |
| 主题 | `MeetingSessions.Topic`（截断） | 主标题 |
| 参会者数 | `ParticipantsJson.Count` + 1（含主持人） | "X位" |
| 时间 | `UpdatedAt` | 相对时间 |

点击行 → 触发 `MeetingViewController.LoadMeetingHistoryAsync(meetingId)`，详见 [03-数据模型与持久化.md §10](./03-数据模型与持久化.md)。

### 6.4 进行中 / 已归档的视觉差异

| 会议状态 | 输入区 | StatusHintBar | MembersStrip |
|---------|--------|---------------|------------|
| 进行中 (Status=0) | 可输入 | "X 正在发言…" | 显示，不可编辑 |
| 等待回复 (Status=1) | 可输入，走马灯紫色加亮 | "主持人在等您回复" | 显示，不可编辑 |
| 已归档 (Status=2) | **可输入** | "本轮会议已归档，可继续讨论、保存记录或开启下一轮" | 显示，保持历史上下文 |
| 已散会 (Status=3) | 可输入历史续接指令 | "会议已散会，可输入指令基于历史继续" | 显示，保持历史上下文 |

会议归档表示本轮总结已经写入历史，不表示会话被锁死。归档后用户仍可继续输入，例如要求主持人把会议记录保存到文档、补充新意见，或基于上一轮结论开启第二轮会议；下一次输入应作为当前会议历史上的续接指令进入调度流程。

### 6.5 用户主动取消（活跃会议中）

- 在会议进行中，用户输入 "结束会议" / "取消" 等明确指令 → AI 路由层（`MeetingIntentClassifier`，类似 [WorkModeIntent](../../../Src/Netor.Cortana.AI/WorkMode/WorkModeInputRouter.cs)）识别为 `CancelMeeting` 意图
- → MeetingExecutor 调用 `cancellationRegistry.Cancel(meetingId)` + UPDATE Status=3
- publish `meeting.cancelled` (Reason="user_cancel")
- UI 显示一条系统消息："会议已取消"

> v1.0 不做意图分类器，简化处理：用户输入 `/end` 命令直接走取消路径；非 `/end` 的所有输入都按"插话或回复征询"处理。意图分类可作为 v1.1 增强。

## 九、与工作模式 UI 的差异对照

| 维度 | 工作模式 | 会议模式 |
|------|---------|---------|
| 视觉基线 | 时间线 + 折叠卡片（隐式阶段） | 头像气泡群聊（仿专家模式） |
| 身份标签 | **无**（无头像无名字） | **有**（必须能区分谁说话） |
| 思考/工具位置 | 嵌在子步骤卡片内 | 嵌在气泡 markdown 上方 |
| 总结展现 | SummaryCard（独立控件） | host - summary 气泡（整体淡紫底） |
| HITL 挂起视觉 | ApprovalFloatPopup 浮窗 | host - inquiry 气泡 + 走马灯加亮 + 状态提示文字 |
| 输入区状态 | 走马灯橙色 | 走马灯紫色 + StatusHintBar 文字 |

会议模式**有意打破**工作模式的"无身份标签"原则——群聊语义必须能区分谁在说话。但保持一致的：3px 圆角、Markdown 渲染、AOT 安全、消息流永续滚动。
