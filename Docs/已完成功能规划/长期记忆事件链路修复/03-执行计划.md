# 03-执行计划

## 一、整体节奏

按"先打通管道，再补开关，最后修历史回放"的顺序，把变化分成 3 个逻辑阶段。每个阶段保持改动范围独立，便于后续按文件/阶段单独回滚。

```
Stage 1：扩 WorkTaskCompletedArgs + 改发布点 + AllowMemoryIngest
         (修复问题 1 + 问题 3 实时部分)

Stage 2：扩 Meeting 两个 args + 改 3 个发布点
         (修复问题 2)

Stage 3：PluginBusWorkflowHistoryDispatcher 换表 + WorkflowExportRecord 加字段
         (修复问题 4 + 问题 3 历史部分)
```

每 stage 可独立验证；本轮按用户要求先对齐文档再推进实现，不强制在当前工作树中拆分提交。

## 四、Stage 3：工作模式历史回放换表

### 4.1 步骤

1. 编辑 [Src/Netor.Cortana.Networks/WebSockets/PluginBusWorkflowHistoryDispatcher.cs](../../../Src/Netor.Cortana.Networks/WebSockets/PluginBusWorkflowHistoryDispatcher.cs)：
   - 注入 `AgentService`（如尚未注入）
   - SQL 改为 `SELECT ... FROM WorkTasks WHERE (LastActiveAt > @Since OR (LastActiveAt = @Since AND Id > @LastId)) AND CompletedAt IS NOT NULL AND ErrorMessage IS NULL AND IFNULL(FinalReport, '') <> '' ORDER BY LastActiveAt, Id LIMIT @queryLimit`
   - 字段映射改写：
     - `Id` ← `WorkTasks.Id`
     - `Title` ← `WorkTasks.Title`
     - `WorkspaceId` ← `WorkTasks.WorkspaceId`
     - `SourceSessionId` ← `WorkTasks.SessionId`
     - `ManagerAgentName` ← `agentService.GetByName(WorkTasks.AgentName)?.Name ?? WorkTasks.AgentName`
     - `ManagerAgentId` ← `WorkTasks.AgentName`
     - `Summary / FinalReport` ← `WorkTasks.FinalReport`
     - `Status` ← `"completed"`（SQL 已过滤失败 / 空报告任务）
     - `CompletedAt` ← `WorkTasks.CompletedAt`
     - `StartedAt / LastActiveTimestamp` ← `WorkTasks.CreatedAt / LastActiveAt`
     - `TraceId` ← `""`（`WorkTasks` schema 无此字段，记忆插件容忍空值）
     - `AllowMemoryIngest` ← `agentService.GetByName(WorkTasks.AgentName)?.AllowWorkflowMemory ?? true`
2. 编辑 [Src/Netor.Cortana.Networks/WebSockets/Serialization/WebSocketJsonContext.cs](../../../Src/Netor.Cortana.Networks/WebSockets/Serialization/WebSocketJsonContext.cs)：
   - `WorkflowExportRecord` record 增加 `bool AllowMemoryIngest` 字段
3. 本轮按用户要求不执行编译构建；改用 grep/static review 确认序列化契约和调用点

### 4.2 验证

- 编译通过
- 准备一份预先存在的 `WorkTasks` 数据（运行 Stage 1 之前的旧任务也行）
- 重启应用
- 看 Memory 插件日志：`workflow.history.replay` 的 `since=0` 请求应返回 ≥1 条；条数与 `SELECT COUNT(*) FROM WorkTasks WHERE CompletedAt IS NOT NULL AND ErrorMessage IS NULL AND IFNULL(FinalReport, '') <> ''` 一致
- 检查回放后 `observation_records` 表对应行的 `AgentId` 非空
- 准备同毫秒 `LastActiveAt` 的多条 WorkTasks 历史记录时，`workflow.history.replay` 不应漏行
- 单元覆盖：`PluginBusWorkflowHistoryDispatcherTests.ReplayAsync_DoesNotSkipTasksWithSameLastActiveAtAcrossBatches`
- 单元覆盖：`PluginBusWorkflowHistoryDispatcherTests.ReplayAsync_ExportsAgentDisplayNameAndMemorySwitch`
- 单元覆盖：`PluginBusWorkflowHistoryDispatcherTests.ReplayAsync_SkipsFailedAndEmptyReportTasks`

### 4.3 回滚

只回滚 Stage 3 对应文件即可。`OrchestrationTask` 表本身没有任何代码写入，回滚后回到"历史回放始终为空"的现状，不会引入数据损坏。
