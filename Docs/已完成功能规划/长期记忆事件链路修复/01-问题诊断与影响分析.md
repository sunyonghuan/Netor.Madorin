# 01-问题诊断与影响分析

## 一、整体结论

记忆系统的"管道"已经修通——订阅、握手、协议路由、批次摄取、historyDispatcher 都到位。问题集中在**"管道里流的水"**：实时事件 payload 字段过简，使下游处理直接退化或失效。

## 二、问题清单

### 问题 1：工作模式实时事件进库即丢弃（P0）

**事件定义**：[Src/Netor.Cortana.Entitys/Events.cs:670](../../../Src/Netor.Cortana.Entitys/Events.cs)

```csharp
public record WorkTaskCompletedArgs(string TaskId, string FinalReport) : EventArgs;
```

**发布点**：[Src/Netor.Cortana.AI/WorkMode/ProjectLead/ProjectLeadService.cs:93-95](../../../Src/Netor.Cortana.AI/WorkMode/ProjectLead/ProjectLeadService.cs)

```csharp
await publisher.PublishAsync(
    Events.OnWorkTaskCompleted,
    new WorkTaskCompletedArgs(taskId, finalReport)).ConfigureAwait(false);
```

**Memory 插件接收**：[Plugins/Src/Cortana.Plugins.Memory/Services/MemoryWorkflowEventHandler.cs:191-209](../../../Plugins/Src/Cortana.Plugins.Memory/Services/MemoryWorkflowEventHandler.cs)
插件期望从 payload 读 `managerAgentId / managerAgentName / sourceSessionId / completedAt / traceId / allowMemoryIngest`，因 host 不发，全部读不到。

**致命卡点**：[Plugins/Src/Cortana.Plugins.Memory/Processing/MemoryProcessingService.cs:112](../../../Plugins/Src/Cortana.Plugins.Memory/Processing/MemoryProcessingService.cs)

```csharp
if (string.IsNullOrWhiteSpace(observation.AgentId) || string.IsNullOrWhiteSpace(observation.Content))
    return;
```

`AgentId` 为空 → 后台扫描器直接跳过 → 不生成 `MemoryFragment` → 不生成抽象 → 召回时也召不到。

**实际影响**：工作模式任务完成后写入 `observation` 表的记录，永远停留在原始观察阶段，从未升格为长期记忆片段。**用户感知**：工作模式怎么跑都不会"记住"。

### 问题 2：会议模式实时事件元数据残缺（P1）

**事件定义**：[Src/Netor.Cortana.Entitys/Events.cs:781-809](../../../Src/Netor.Cortana.Entitys/Events.cs)

```csharp
public record MeetingMessageCompletedArgs(
    string MeetingId,
    string MessageId,
    string SpeakerId,
    string SpeakerKind,
    string ContentMd,
    string MessageRole,
    bool AwaitingUserReply) : EventArgs;

public record MeetingCompletedArgs(string MeetingId, string FinalSummary) : EventArgs;
```

**发布点**（三处，均不带 session/topic/workspace 等上下文）：

- [Src/Netor.Cortana.AI/MeetingMode/MeetingStreamProcessor.cs:294-295](../../../Src/Netor.Cortana.AI/MeetingMode/MeetingStreamProcessor.cs)（meeting.completed）
- [Src/Netor.Cortana.AI/MeetingMode/MeetingStreamProcessor.cs:423-432](../../../Src/Netor.Cortana.AI/MeetingMode/MeetingStreamProcessor.cs)（message.completed）
- [Src/Netor.Cortana.AI/MeetingMode/Tools/MeetingControlTools.cs:71-80](../../../Src/Netor.Cortana.AI/MeetingMode/Tools/MeetingControlTools.cs)（summary 角色）

**Memory 插件期望**：[Plugins/Src/Cortana.Plugins.Memory/Services/MemoryMeetingEventHandler.cs:120-198](../../../Plugins/Src/Cortana.Plugins.Memory/Services/MemoryMeetingEventHandler.cs)
读不到 `sessionId / topic / hostAgentId / model / createdAt / endedAt / workspaceId / participantsJson` 等。

**实际影响**（实时路径）：

- 会议片段抽取出来后 `SourceSessionIdsJson` 是 `[""]`，无法回链源会议
- `Topic` 为空 → 记忆处理阶段只能从正文推断主题，会议级聚类和召回归因精度下降
- `WorkspaceId` 退化到全局兜底 → 跨工作区可能污染
- `meeting.completed` 缺 `HostAgentId` 时 `AgentId` 为空，会触发问题 1 同样的处理 guard，最终总结无法升格为长期记忆片段
- `meeting.message.completed` 的 summary 路径会回退到 `SpeakerId`，通常不会被 guard 丢弃，但仍缺 `SessionId / WorkspaceId / Topic / Model` 等上下文

历史回放路径不受影响（`PluginBusMeetingHistoryDispatcher` 直接 join `MeetingSessions + MeetingMessages` 表，字段齐全），所以表现为"重启后正常，跑久了越来越乱"。

### 问题 3：`AllowWorkflowMemory` 开关永远不生效（P1）

**配置完整性**：

- `AgentEntity.AllowWorkflowMemory` 字段已就位
- AgentManifest 序列化已带
- UI 设置项已暴露给用户
- Memory 插件读取逻辑：[Plugins/Src/Cortana.Plugins.Memory/Services/MemoryWorkflowEventHandler.cs:222-237](../../../Plugins/Src/Cortana.Plugins.Memory/Services/MemoryWorkflowEventHandler.cs)

```csharp
private static bool IsMemoryIngestAllowed(JsonElement payload)
{
    if (payload.TryGetProperty("allowMemoryIngest", out var prop) && prop.ValueKind == JsonValueKind.False)
        return false;
    return true;  // 默认放行
}
```

**断点**：实时事件 args 不带 → 历史回放 `WorkflowExportRecord` 也不带（[Src/Netor.Cortana.Networks/WebSockets/Serialization/WebSocketJsonContext.cs:181-200](../../../Src/Netor.Cortana.Networks/WebSockets/Serialization/WebSocketJsonContext.cs)） → 永远走默认 `true`。

**实际影响**：UI 上把开关关掉**没用**，工作记录还是会被记。当前因为问题 1 让记录其实根本进不了 fragment 阶段，所以这个 bug 暂时被另一个 bug 顶住；**问题 1 修好的瞬间，问题 3 立刻成为可见缺陷**。

### 问题 4：`OrchestrationTask` 表是空表，工作模式历史回放永远 0 行（P0）

**Schema 定义**：[Src/Netor.Cortana.Entitys/CortanaDbContext.cs:352-381](../../../Src/Netor.Cortana.Entitys/CortanaDbContext.cs) 创建 `OrchestrationTask` 表，字段齐全（含 `ManagerAgentId / SourceSessionId / TraceId / WorkspaceId / Status / CompletedAt`）。

**运行时数据写入**：grep 全代码库，仅 [Src/Netor.Cortana.Entitys/Services/WorkTaskService.cs](../../../Src/Netor.Cortana.Entitys/Services/WorkTaskService.cs) 对 **`WorkTasks`** 表做 `INSERT/UPDATE`。`OrchestrationTask` 表**从未被写入过**。

**回放查询**：[Src/Netor.Cortana.Networks/WebSockets/PluginBusWorkflowHistoryDispatcher.cs](../../../Src/Netor.Cortana.Networks/WebSockets/PluginBusWorkflowHistoryDispatcher.cs) `SELECT FROM OrchestrationTask`。

**实际影响**：工作模式握手时的 `workflow.history.replay` 永远返回 0 条；问题 1 的"重启就修复"自愈手段也对工作模式失效——长期下来工作模式的长期记忆**完全是空的**。

## 三、问题之间的耦合关系

```
问题 1（args 字段缺失） ─┬─ 把实时事件丢给后台处理时被 guard 挡掉
                          └─ 同时让问题 3 的开关读不到值

问题 4（OrchestrationTask 空表） ── 让原本能"重启回放补救"的兜底也失效

问题 2（会议 args 字段缺失） ── 仅在实时路径有效；历史回放正常 → 间歇性表现

问题 3（开关失效） ── 依附于问题 1，问题 1 修完它就外露
```

## 四、读图速查

| 模式 | 实时入库 | 抽取片段 | 历史回放 | 长期记忆是否生效 |
|---|---|---|---|---|
| 对话 / 专家 | ✓ | ✓ | ✓ | ✓ 完整 |
| 工作模式 | ✓（数据残缺） | ✗ guard 挡掉 | ✗ 表为空 | **完全失效** |
| 会议模式 | ✓（数据残缺） | ⚠ 元数据丢失 | ✓ | **召回错乱** |

## 五、不做的事项

- 不修 `LongMemoryContextProvider` 在 Workflow / Meeting 模式下读不到 `StateBag.agentid` 早退的问题。该问题与本次"事件链路缺字段"是不同维度，且涉及对 AF 工作流 / 会议主持人 Session 注入上下文键值，需要单独评审，不并入本次方案。
- 不增加"记忆 → host UI 反向推送"。按用户确认，记忆系统是内部循环，不暴露 UI。
