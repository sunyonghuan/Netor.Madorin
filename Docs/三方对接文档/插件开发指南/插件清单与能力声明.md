# 插件清单与能力声明

## 一、plugin.json 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 插件唯一 ID |
| `name` | string | 显示名称 |
| `version` | string | 插件版本 |
| `description` | string | 插件说明 |
| `instructions` | string | 可选 AI 指令片段 |
| `tags` | string[] | 分类标签 |
| `capabilities` | string[] | 历史兼容能力字段 |
| `providedCapabilities` | string[] | 首选能力字段，表示插件提供给宿主/模型层的能力 |
| `requiredHostCapabilities` | array | 插件希望宿主提供的能力申请 |
| `publishedOps` | array | 插件会通过 PluginBus 事件总线发布的事件 op 对象数组（PluginBus 1.4.0），由 `[PublishesEvent]` 生成；元素结构 `{ op, description? }` |
| `subscribedOps` | array | 插件会通过 PluginBus 事件总线订阅的事件 op 对象数组（PluginBus 1.4.0），由 `[SubscribesEvent]` 生成；元素结构 `{ op, reason? }` |
| `settingsSchema` | array | 插件设置界面 schema |
| `runtime` | string | `native` / `process` |
| `command` | string | Process 插件启动命令 |
| `libraryName` | string | Native 插件库文件名 |
| `minHostVersion` | string | 最低宿主版本 |

Native / Process 的这些字段由 `[Plugin]`、`[RequiredHostCapability]`、`[PluginSetting]`、`[PublishesEvent]`、`[SubscribesEvent]` 自动生成，不要手写维护副本。

## 二、能力声明

`[Plugin].Capabilities` 是“插件提供给宿主或模型层”的能力，例如：

```csharp
[Plugin(
    Id = "memory_helper",
    Name = "Memory Helper",
    Version = "1.0.0",
    Capabilities = ["memory.extract"])]
public static partial class Startup
{
}
```

常见能力：

| capability | 宿主用途 |
| --- | --- |
| `voice.kws` | 语音唤醒 |
| `voice.stt` | 语音识别 |
| `voice.tts` | 语音合成 |
| `conversation.v1` | 对话事件 |
| `workflow.v1` | 工作模式事件 |
| `meeting.v1` | 会议模式事件 |
| `memory.v1` | 长期记忆供应 |

### 事件契约声明（PluginBus 1.4.0）

`[Plugin].Capabilities` 描述"我提供什么能力"。如果插件还会通过 PluginBus 事件总线**发布**或**订阅**事件，必须额外声明事件契约——这是宿主弱声明校验和运维审计的依据，与 `Capabilities` 不复用同一字段。

发布事件用 `[PublishesEvent]`，每个 op 一条：

```csharp
[Plugin(
    Id = "voice_stt_sherpa",
    Capabilities = ["voice.stt"])]
[PublishesEvent("voice.stt.partial.v1", Description = "实时识别中文本")]
[PublishesEvent("voice.stt.final.v1", Description = "最终识别文本")]
[PublishesEvent("voice.stt.stopped.v1", Description = "识别会话已停止")]
public static partial class Startup
{
}
```

订阅事件用 `[SubscribesEvent]`：

```csharp
[Plugin(
    Id = "subtitle_overlay")]
[SubscribesEvent("voice.stt.partial.v1", Reason = "实时显示识别中文本")]
[SubscribesEvent("voice.tts.subtitle.v1", Reason = "显示 TTS 字幕")]
public static partial class Startup
{
}
```

| attribute | 必填字段 | 可选字段 | 生成到 plugin.json |
| --- | --- | --- | --- |
| `[PublishesEvent]` | `Op` | `Description` | `publishedOps[]` |
| `[SubscribesEvent]` | `Op` | `Reason` | `subscribedOps[]` |

约束：

- 必须叠加在 `[Plugin]` 入口类上
- op 命名 `{topic}.{name}.v{n}`，op 首段必须等于已有 topic（详见 [插件事件总线开发指南.md §四](插件事件总线开发指南.md)）
- 不要把"我发布的事件"和"我订阅的事件"和 `Capabilities` 混成同一个字段

完整事件总线机制、SDK 用法、限制条件见 [插件事件总线开发指南.md](插件事件总线开发指南.md)。

## 三、宿主能力申请

如果插件要调用宿主授权的大模型、访问工作区、访问文件或申请其他宿主能力，应使用 `[RequiredHostCapability]`：

```csharp
[RequiredHostCapability(
    Id = "host.llm.invoke.v1",
    Purpose = "summary.generate",
    Required = true,
    Reason = "需要调用宿主授权的大模型生成摘要。")]
public static partial class Startup
{
}
```

生成字段：

- `id`
- `purpose`
- `required`
- `reason`

规则：

- `Required = true` 表示核心路径依赖该能力。
- `Required = false` 表示可降级的增强能力。
- `Reason` 要写成用户和宿主能看懂的说明，不要写内部实现细节。

## 四、设置 schema

如果要在宿主设置界面生成配置项，使用 `[PluginSetting]`：

```csharp
[PluginSetting(
    Key = "api_key",
    Label = "API Key",
    Description = "第三方服务访问密钥",
    Type = PluginSettingType.Secret,
    Required = true,
    Sensitive = true,
    Scope = ["user"],
    RestartRequired = true)]
public static partial class Startup
{
}
```

`PluginSettingType` 当前支持：

- `String`
- `Secret`
- `Number`
- `Boolean`
- `Enum`
- `Path`
- `Json`

`validation` 支持最小值、最大值、长度和正则规则。`DefaultValue` 由 Generator 按类型写入 JSON，不要自己拼引号。

## 五、运行时注入

插件运行时统一通过 `PluginSettings` 获取：

- `DataDirectory`
- `WorkspaceDirectory`
- `PluginDirectory`
- `WsPort`
- `PluginBusEndpoint`
- `PluginBusProtocol`
- `ConversationFeedEndpoint`
- `ConversationFeedProtocol`
- `ConversationFeedVersion`
- `ConversationFeedPort`
- `Extensions`

示例：

```csharp
public sealed class WorkspaceTools(PluginSettings settings)
{
    [Tool(Description = "返回运行时上下文")]
    public object GetContext()
        => new
        {
            settings.DataDirectory,
            settings.WorkspaceDirectory,
            settings.PluginDirectory,
            settings.Extensions
        };
}
```

## 六、约束

- 不要把 `Capabilities` 和 `[RequiredHostCapability]` 混成一个字段。
- 不要手工维护 `providedCapabilities`、`requiredHostCapabilities`、`settingsSchema`。
- 不要把敏感值写进日志。
- 不要自己解析原始 `init` JSON。
