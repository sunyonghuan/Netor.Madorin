# 插件开发总览

## 一、选择插件通道

| 通道 | 适用场景 | 项目形态 | 宿主加载方式 |
| --- | --- | --- | --- |
| Native | Native AOT、本地轻量工具、快速启动、严格部署体积 | AOT `.dll` | 宿主加载原生 DLL，调用 Generator 导出的入口 |
| Process | 需要进程隔离、完整 .NET JIT 生态、模型/外部 SDK、长任务服务 | `.exe` | 宿主启动子进程，通过 stdin/stdout 单行 JSON 协议调用工具 |
| MCP | 已有外部 MCP Server、跨语言工具、远程服务 | stdio / sse / streamable-http 配置 | 宿主通过 MCP 配置连接，不生成 `plugin.json`，不走 zip 插件安装 |

新开发优先选择 Native 或 MCP。只有确实需要 JIT、反射、动态编译、复杂 native 依赖隔离时，再选择 Process。

## 二、基本流程

Native / Process 插件：

1. 用脚手架创建项目。
2. 在入口类声明 `[Plugin]`。
3. 按需叠加 `[RequiredHostCapability]` 和 `[PluginSetting]`。
4. 在 `Configure(IServiceCollection services)` 中注册依赖。
5. 在 `Tools/` 中编写 `[Tool]` 类和工具方法。
6. 构建项目，确认 Generator 输出 `plugin.json` 和工具路由。
7. 完成本地调试和每个工具的最小调用验证。
8. 使用发布脚本生成发布目录或 zip 包。
9. 运行时安装/更新使用仓库安装脚本，不手工复制覆盖已加载插件。

MCP 通道：

1. 明确传输方式：本地命令行用 stdio，HTTP 服务用 sse 或 streamable-http。
2. 校验 Command / Arguments / Url / 环境变量 / 认证信息。
3. 在宿主设置界面或数据库录入连接配置。
4. 连接后确认远程工具能被自动发现。

## 三、项目入口

Process 插件入口：

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin;

namespace Your.Process.Plugin;

[Plugin(
    Id = "your_process_plugin",
    Name = "Your Process Plugin",
    Version = "1.0.0",
    Description = "提供示例 Process 工具。",
    Tags = ["sample"],
    Capabilities = ["sample.process"])]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<SampleService>();
    }
}
```

Native 插件入口：

```csharp
using Microsoft.Extensions.DependencyInjection;
using Netor.Cortana.Plugin.Native;

namespace Your.Native.Plugin;

[Plugin(
    Id = "your_native_plugin",
    Name = "Your Native Plugin",
    Version = "1.0.0",
    Description = "提供示例 Native 工具。",
    Tags = ["sample"],
    Capabilities = ["sample.native"])]
public static partial class Startup
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<SampleService>();
    }
}
```

入口类必须是 `public static partial class`，一个项目只能有一个 `[Plugin]` 入口。

## 四、能力声明

`[Plugin].Capabilities` 表示插件“提供给宿主或模型层”的能力。生成产物会同时包含历史兼容字段 `capabilities` 和首选字段 `providedCapabilities`。

```csharp
[Plugin(
    Id = "your_voice_stt",
    Name = "Your STT Plugin",
    Version = "1.0.0",
    Capabilities = ["voice.stt"])]
public static partial class Startup
{
}
```

常用能力：

| capability | 用途 |
| --- | --- |
| `voice.kws` | 关键词唤醒 |
| `voice.stt` | 语音识别 |
| `voice.tts` | 语音合成 |
| `memory.v1` | 长期记忆供应 |
| `conversation.v1` | 对话事件订阅 |
| `workflow.v1` | 工作模式事件订阅 |
| `meeting.v1` | 会议模式事件订阅 |

插件需要使用宿主提供的能力时，不要写进 `Capabilities`，而是使用 `[RequiredHostCapability]`。例如调用宿主授权的大模型：

```csharp
[RequiredHostCapability(
    Id = "host.llm.invoke.v1",
    Purpose = "summary.generate",
    Required = true,
    Reason = "需要调用宿主授权的大模型生成摘要。")]
public static partial class Startup
{
}
```

## 五、事件总线（PluginBus 1.4.0）

如果插件需要在多个组件之间共享状态变化（一对多、不等响应），通过 PluginBus 事件总线声明：

```csharp
[Plugin(
    Id = "voice_stt_sherpa",
    Capabilities = ["voice.stt"])]
[PublishesEvent("voice.stt.partial.v1", Description = "实时识别中文本")]
[PublishesEvent("voice.stt.final.v1", Description = "最终识别文本")]
[SubscribesEvent("voice.tts.subtitle.v1", Reason = "实时显示 TTS 字幕")]
public static partial class Startup
{
}
```

`[PublishesEvent]` / `[SubscribesEvent]` 由 Generator 写入 `plugin.json` 的 `publishedOps` / `subscribedOps` 对象数组，由宿主做弱声明校验。运行时通过共享 SDK `PluginBusClient.PublishEventAsync(op, JsonElement)` 发布、`SubscribeEventAsync(op, handler)` 订阅。

事件总线不是 RPC——发布方不等响应、单向、一对多。需要等结果时仍走 `model.capability.request` 等同步通道（详见 §七）。

完整说明、op 命名规范、SDK 用法、限制与 AOT 约束见 [插件事件总线开发指南.md](插件事件总线开发指南.md)；语音三件套实战案例见 [语音插件开发指南.md](语音插件开发指南.md) §六。

## 六、工具声明

工具类和方法都要标记 `[Tool]`：

```csharp
[Tool]
public sealed class WeatherTools(WeatherService service)
{
    [Tool(Name = "get_weather", Description = "查询指定城市天气。")]
    public string GetWeather(
        [Parameter(Name = "city", Description = "城市名称。")] string city)
    {
        return service.Get(city);
    }
}
```

Generator 会把完整工具名加上插件 ID 前缀。例如插件 ID 是 `weather_plugin`，方法工具名是 `get_weather`，宿主侧完整工具名是 `weather_plugin_get_weather`。如果你在 `Name` 中已经写了此前缀，Generator 不会重复添加。

## 六、运行时配置

插件运行时统一通过 `PluginSettings` 读取宿主注入上下文，不解析原始 `init` JSON。

常用字段：

| 字段 | 用途 |
| --- | --- |
| `DataDirectory` | 插件专属数据目录 |
| `WorkspaceDirectory` | 当前工作区目录 |
| `PluginDirectory` | 插件安装目录 |
| `WsPort` / `PluginBusPort` | 宿主 PluginBus 端口 |
| `PluginBusEndpoint` | PluginBus WebSocket 端点，通常为 `ws://localhost:{port}/internal` |
| `PluginBusProtocol` | PluginBus 协议，当前为 `cortana.plugin-bus` |
| `Extensions` | 宿主扩展参数，例如授权摘要、插件 ID、端点兼容字段 |

Process 示例：

```csharp
public sealed class RuntimeTools(PluginSettings settings)
{
    [Tool(Description = "返回插件运行上下文。")]
    public string GetContext()
        => $"data={settings.DataDirectory}; workspace={settings.WorkspaceDirectory}";
}
```

## 七、宿主 LLM 能力

插件可以申请 `host.llm.invoke.v1`，再通过 PluginBus 的 `model` topic 发送 `model.capability.request`。宿主会按用户授权、模型设置和审计规则代理调用大模型，插件不直接读取模型密钥。

完整说明见 [宿主LLM模型能力调用.md](宿主LLM模型能力调用.md)。

## 八、调试门禁

| 通道 | 调试方式 | 最低要求 |
| --- | --- | --- |
| Native | 脚手架生成的 `Debug\*.Debug.csproj` + `PluginDebugRunner` | `dotnet build` 成功；REPL 能发现插件；每个工具至少调用一次 |
| Process | `dotnet run -- --self-test` + Generator 生成的 `{PluginClass}Debugger` | 先 `InitAsync()`；每个工具至少调用一次；失败返回非 0 |
| MCP | 连接配置校验和服务可达性验证 | 配置可用；远程工具可发现 |

发布前必须先通过本地调试。Native Debug Console 只验证开发态托管程序集，最终仍要执行 AOT 发布验证。
