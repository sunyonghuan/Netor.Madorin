# 语音插件开发指南

这篇文档描述 KWS / STT / TTS 语音插件的开发方式、PluginBus 事件总线集成和模型目录约定。

PluginBus 1.4.0 起，语音事件统一走 `type=event` 信封式，op 字段加 `.v{n}` 版本号；通用事件总线机制详见 [插件事件总线开发指南.md](插件事件总线开发指南.md)。

## 一、插件能力

| 能力 | capability | 插件负责 |
| --- | --- | --- |
| 关键词唤醒 | `voice.kws` | 监听麦克风，识别唤醒词并发送唤醒事件 |
| 语音识别 | `voice.stt` | 监听或接收音频，输出 partial / final 文本 |
| 语音合成 | `voice.tts` | 接收文本，合成语音，发送字幕和播放状态 |

一个插件可以只提供一种能力，也可以同时提供多种能力。

## 二、项目结构

```text
Your.Voice.Plugin/
  Your.Voice.Plugin.csproj
  Program.cs
  Startup.cs
  Tools/                       # [Tool] 类
  Runtime/                     # 运行时状态、配置、引擎包装
  Engine/                      # ONNX / Melo 等具体推理引擎封装
  Audio/                       # 音频采集、播放、重采样
  Diagnostics/                 # 自检、诊断入口，按需添加
  PluginBus/                   # 事件总线类型化包装
    YourPluginBusClient.cs     # 类型化包装，依赖共享 PluginBusClient
    YourPluginBusEvent.cs      # 事件 payload POCO
  Serialization/
    PluginJsonContext.cs       # JsonSerializerContext，注册 payload + tool result
  models/
    KWS/                       # 关键词唤醒模型
    STT/                       # 语音识别模型
    TTS/                       # 语音合成模型
```

模型文件放在插件目录内，运行时优先通过 `PluginSettings.PluginDirectory` 解析；仅当该值为空时才回退到 `AppContext.BaseDirectory`。

模型文件要求：

| 能力 | 默认目录 | 必需文件 |
| --- | --- | --- |
| KWS | `models/KWS` | `encoder(.int8).onnx`、`decoder(.int8).onnx`、`joiner(.int8).onnx`、`tokens.txt`、`keywords.txt` |
| STT | `models/STT` | `encoder(.int8).onnx`、`decoder(.int8).onnx`、`tokens.txt` |
| TTS | `models/TTS` | `model.int8.onnx`、`tokens.txt`、`lexicon.txt`、`dict/` |

## 六、KWS / STT / TTS 事件与协同

语音事件走 PluginBus 事件总线（1.4.0 信封式），WebSocket 端点 `ws://localhost:{port}/internal`，协议 `cortana.plugin-bus`。

宿主已经支持 plugin->plugin 的一对多事件转发。语音插件发布 `type=event` 帧后：

1. `WebSocketPluginBusServerService` 把事件交给 `PluginBusBroadcastDispatcher`。
2. `PluginBusBroadcastDispatcher` 从 op 首段提取 topic，例如 `voice.stt.partial.v1` 的 topic 是 `voice`。
3. 宿主查找订阅 `voice` topic 的客户端，再用订阅帧中的 `subscribedOps` 做精确过滤。
4. 宿主排除 source client，避免发布者收到自己的事件。
5. 对 `voice.*` 事件，宿主同时调用 `VoiceEventBridge` 桥接到 `IPublisher` / UI 事件；未映射的 voice op 只转发插件，不桥接 UI。

因此，KWS / STT / TTS 三个独立插件可以只通过 `[PublishesEvent]` / `[SubscribesEvent]` 和 `PluginBusClient.SubscribeEventAsync` 完成协同，不需要宿主为每条语音链路写硬编码串联逻辑。需要事件持久化、重放、强安全绑定或新的宿主 UI 事件时，才需要单独评审宿主改动。

### 6.1 op 清单

三件套实际发布的 op 与 attribute 声明：

| op | 发布方 | 用途 |
| --- | --- | --- |
| `voice.kws.detected.v1` | KWS | 检测到唤醒词 |
| `voice.stt.partial.v1` | STT | 实时识别中文本 |
| `voice.stt.final.v1` | STT | 最终识别文本 |
| `voice.stt.stopped.v1` | STT | 识别会话已停止 |
| `voice.tts.started.v1` | TTS | TTS 播放开始 |
| `voice.tts.subtitle.v1` | TTS | TTS 字幕 |
| `voice.tts.completed.v1` | TTS | TTS 播放完成 |
| `voice.tts.greeting_ready.v1` | TTS | 问候语 TTS 模型就绪 |
| `voice.tts.error.v1` | TTS | TTS 上报错误 |

所有 op 首段 `voice` 等于 topic，宿主 BroadcastDispatcher 按首段路由（详见事件总线指南 §四）。

### 6.2 三件套协同契约

语音三件套的推荐协同关系：

| 插件 | 发布 | 订阅 | 用途 |
| --- | --- | --- | --- |
| KWS | `voice.kws.detected.v1` | `voice.tts.started.v1`、`voice.tts.completed.v1` | 唤醒后通知 STT；TTS 播放期间抑制自唤醒，播放结束恢复 |
| STT | `voice.stt.partial.v1`、`voice.stt.final.v1`、`voice.stt.stopped.v1` | `voice.kws.detected.v1`、`voice.tts.started.v1`、`voice.tts.completed.v1` | 唤醒后进入准备或监听；TTS 播放期间暂停或降低识别敏感度，结束后恢复 |
| TTS | `voice.tts.started.v1`、`voice.tts.subtitle.v1`、`voice.tts.completed.v1`、`voice.tts.greeting_ready.v1`、`voice.tts.error.v1` | 默认不订阅 voice 事件 | 朗读由对话编排层或工具调用驱动，不把 STT final 直接等同为朗读内容 |

TTS 默认不订阅 `voice.stt.final.v1`。识别结果不等于要朗读的内容，是否朗读应由对话编排层决定，例如宿主调用 `voice_tts_speak`，或后续通过 `conversation.*` 事件驱动。

### 6.3 入口声明事件契约

```csharp

[PublishesEvent("voice.stt.partial.v1", Description = "实时识别中文本")]
[PublishesEvent("voice.stt.final.v1", Description = "最终识别文本")]
[PublishesEvent("voice.stt.stopped.v1", Description = "识别会话已停止")]
[SubscribesEvent("voice.kws.detected.v1", Reason = "唤醒后启动或准备一次语音识别会话")]

public static partial class Startup

    {
        services.AddLogging();
        services.AddSingleton<SttEngine>();
        services.AddSingleton<SttRuntimeState>();
        services.AddSingleton<SttPluginBusClient>();

```

KWS 入口应声明：

```csharp
[PublishesEvent("voice.kws.detected.v1", Description = "检测到唤醒词")]
[SubscribesEvent("voice.tts.started.v1", Reason = "TTS 播放期间避免系统朗读触发唤醒")]
```

`[PublishesEvent]` 由 Generator 写入 `plugin.json.publishedOps` 对象数组，`[SubscribesEvent]` 写入 `plugin.json.subscribedOps` 对象数组。运行时由宿主做弱声明校验和运维审计；转发时以插件实际发出的 `subscribe` 帧为准。详细 attribute 字段见 [插件事件总线开发指南.md §三](插件事件总线开发指南.md)。

### 6.4 类型化包装范式

直接调 `PluginBusClient.PublishEventAsync` 容易写错 op 字符串。三件套都做了一层类型化包装。

事件 payload POCO（`PluginBus/SttPluginBusEvent.cs`）：

```csharp
internal sealed record SttPluginBusEventPayload
{
    [JsonPropertyName("text")]
    public string? Text { get; init; }

    [JsonPropertyName("sessionId")]
    public string? SessionId { get; init; }
}
```

类型化包装（`PluginBus/SttPluginBusClient.cs`）应包住整次发布，避免后台 fire-and-forget 产生未观测异常。真实链路状态写入也可以放在包装层中，确保工具调试路径与引擎路径一致：

```csharp
using System.Text.Json;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Logging;
using Netor.Cortana.Plugin.PluginBus;

public sealed class SttPluginBusClient(
    PluginBusClient bus,
    IServiceProvider serviceProvider,
    ILogger<SttPluginBusClient> logger)
{
    public Task PublishPartialAsync(string text, string? sessionId, CancellationToken cancellationToken = default)
        => PublishAsync("voice.stt.partial.v1", text, sessionId, cancellationToken);

    public Task PublishFinalAsync(string text, string? sessionId, CancellationToken cancellationToken = default)
        => PublishAsync("voice.stt.final.v1", text, sessionId, cancellationToken);

    public Task PublishStoppedAsync(string? sessionId, CancellationToken cancellationToken = default)
        => PublishAsync("voice.stt.stopped.v1", null, sessionId, cancellationToken);

    private async Task PublishAsync(string op, string? text, string? sessionId, CancellationToken cancellationToken)
    {
        try
        {
            UpdateState(op, text);
            var payload = JsonSerializer.SerializeToElement(
                new SttPluginBusEventPayload { Text = text, SessionId = sessionId },
                PluginJsonContext.Default.SttPluginBusEventPayload);
            await bus.PublishEventAsync(op, payload, cancellationToken).ConfigureAwait(false);
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            logger.LogWarning(ex, "STT PluginBus 事件发布失败：{Op}", op);
        }
    }

    private void UpdateState(string op, string? text)
    {
        var state = serviceProvider.GetService<SttRuntimeState>();
        if (state is null)
        {
            return;
        }

        switch (op)
        {
            case "voice.stt.partial.v1" when text is not null:
                state.SetPartial(text);
                break;
            case "voice.stt.final.v1" when text is not null:
                state.SetFinal(text);
                break;
            case "voice.stt.stopped.v1":
                state.MarkStopped();
                break;
        }
    }
}
```

注册 payload POCO 到插件自己的 `PluginJsonContext`（AOT 强约束）：

```csharp
[JsonSerializable(typeof(SttPluginBusEventPayload))]
internal partial class PluginJsonContext : JsonSerializerContext;
```

### 6.5 在工具方法中调用

工具方法把发包当成普通异步调用：

### 6.6 插件内订阅服务

订阅实现放在插件自己的 `BackgroundService` 中。handler 只做轻量状态切换或投递内部队列，不直接执行长耗时识别、合成或播放。

```csharp
public sealed class SttVoiceCoordinator(
    PluginBusClient bus,
    SttRuntimeState state,
    SttEngine engine,
    ILogger<SttVoiceCoordinator> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        await bus.SubscribeEventAsync(
            "voice.kws.detected.v1",
            payload =>
            {
                var sessionId = payload.TryGetProperty("sessionId", out var s)
                    ? s.GetString()
                    : null;

                // 示例：进入准备态或启动一次监听，具体策略由插件状态机决定。
                logger.LogInformation("收到 KWS 唤醒事件，准备 STT 会话。SessionId={SessionId}", sessionId);
                return Task.CompletedTask;
            },
            stoppingToken).ConfigureAwait(false);

        await bus.SubscribeEventAsync(
            "voice.tts.started.v1",
            _ =>
            {
                // 示例：暂停识别或降低敏感度，避免把系统朗读识别成用户输入。
                logger.LogDebug("收到 TTS started，进入 STT 抑制策略。");
                return Task.CompletedTask;
            },
            stoppingToken).ConfigureAwait(false);

        await bus.SubscribeEventAsync(
            "voice.tts.completed.v1",
            _ =>
            {
                logger.LogDebug("收到 TTS completed，恢复 STT 策略。");
                return Task.CompletedTask;
            },
            stoppingToken).ConfigureAwait(false);

        await Task.Delay(Timeout.Infinite, stoppingToken).ConfigureAwait(false);
    }
}
```

Process 插件宿主已经统一注册 `PluginBusClient`，并以插件 `Id` 作为 `sourcePluginId`。插件只需要注入 `PluginBusClient` 调用 `SubscribeEventAsync`，不要重复注册共享客户端。

### 6.7 宿主侧链路

宿主 `PluginBusBroadcastDispatcher` 接收到 `voice.*` 事件后做两件事：

1. **桥接到宿主 `IPublisher`**：通过 `VoiceEventBridge` 把事件桥接到 `Events.OnSttPartial` / `Events.OnSttFinal` / `Events.OnTtsSubtitle` 等，UI 层（字幕、桌宠、状态指示器）订阅这些 EventHub 事件即可，零感知 PluginBus
2. **转发到其他订阅插件**：按 §6.1 op 路由到订阅 `voice` topic 且 `subscribedOps` 匹配的其他插件

`voice.tts.greeting_ready.v1` 是例外——它仅作为 TTS 自检信号，宿主收到后**不**触发 `IPublisher` / UI 事件，仅 LogDebug；但如果某个插件显式订阅该 op，宿主广播分发器仍会按普通 PluginBus 规则转发给该插件。

TTS 的 `voice.tts.completed.v1` 和 `voice.tts.error.v1` payload 可以带可选 `reason` 字段。建议值：

| op | reason | 含义 |
| --- | --- | --- |
| `voice.tts.completed.v1` | `completed` | 自然播放完成 |
| `voice.tts.completed.v1` | `stopped` | 用户或工具主动停止 |
| `voice.tts.completed.v1` | `cancelled` | 后台播放被取消 |
| `voice.tts.completed.v1` | `error` | 播放以错误收尾 |
| `voice.tts.error.v1` | `model_not_ready` | 模型文件缺失或不完整 |
| `voice.tts.error.v1` | `synthesis_failed` | 合成失败 |
| `voice.tts.error.v1` | `synthesis_empty` | 合成结束但没有可播放音频 |
| `voice.tts.error.v1` | `playback_failed` | 播放失败 |

模型缺失时，TTS 工具应返回 `model_not_ready` 并发布 `voice.tts.error.v1(reason=model_not_ready)`；不得伪造 started/subtitle/completed/greeting_ready 生命周期。

KWS/STT 的 `voice_*_status` 返回值应同时暴露工具层监听意图和引擎实际状态。`IsListening=true` 表示当前插件认为监听有效；`EngineRunning=false`、`LastError` 或 `DeviceCount=0` 表示麦克风线程没有实际运行，调用方应把它当作未监听处理。

### 9.2 订阅服务

```csharp
public sealed class SubtitleSubscriber(PluginBusClient bus, ISubtitleView view) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        await bus.SubscribeEventAsync(
            "voice.stt.partial.v1",
            payload =>
            {
                var text = payload.TryGetProperty("text", out var t) ? t.GetString() : null;
                view.UpdatePartial(text ?? string.Empty);
                return Task.CompletedTask;
            },
            ct).ConfigureAwait(false);

        await bus.SubscribeEventAsync(
            "voice.stt.final.v1",
            payload =>
            {
                var text = payload.TryGetProperty("text", out var t) ? t.GetString() : null;
                view.CommitFinal(text ?? string.Empty);
                return Task.CompletedTask;
            },
            ct).ConfigureAwait(false);

        await bus.SubscribeEventAsync(
            "voice.tts.subtitle.v1",
            payload =>
            {
                var text = payload.TryGetProperty("text", out var t) ? t.GetString() : null;
                view.ShowTtsSubtitle(text ?? string.Empty);
                return Task.CompletedTask;
            },
            ct).ConfigureAwait(false);

        await Task.Delay(Timeout.Infinite, ct).ConfigureAwait(false);
    }
}
```

### 9.3 注意事项

- handler 内必须非阻塞；后台投递有 1 秒超时，超时连接会被宿主主动清理
- partial 类高频事件（10 Hz 量级）订阅方应按"总是用最新值覆盖"模式编写，不能假设按顺序累积
- 订阅插件无法感知"事件丢失"（payload 解析失败、网络抖动、超时被清理）；不要把 final/completed 类终态事件作为唯一状态依据
- PluginBus 事件是一对多、单向、不等响应；需要明确结果的动作仍走工具调用或 RPC 型 op
- 三件套协同 handler 不应阻塞识别/播放主循环；需要长任务时投递到内部队列
- KWS/STT 对 TTS started/completed 的处理应是可恢复策略，避免 TTS 异常退出后永久停听
- TTS 默认不消费 STT final，避免把用户输入回声朗读；自动朗读应由对话编排层决定
