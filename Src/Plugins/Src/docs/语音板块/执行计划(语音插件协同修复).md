## 目标与边界

目标：

- 在不修改宿主程序的前提下，让 KWS / STT / TTS 三个语音插件通过现有 PluginBus plugin->plugin 一对多转发机制完成协同。
- 修复评审中确认的运行期 bug：重复 stopped/completed、TTS 模型未就绪误发真实生命周期、KWS/STT 状态不同步、fire-and-forget 异常不可观测等。
- 更新插件自身文档、模型 README、自检说明，使行为、事件契约和模型要求一致。

边界：

- 不改宿主 `PluginBusBroadcastDispatcher` / `PluginBusSubscriptionRegistry` / `VoiceEventBridge`。
- 不新增同步 RPC 语义；PluginBus 仍只用于一对多、单向、不等响应事件。
- TTS 默认不订阅 `voice.stt.final.v1`，朗读由对话编排层或工具调用驱动。
- 模型文件本体不纳入本次提交，只修正代码校验和 README 说明。

## 风险与回滚

- 如果订阅 handler 引入阻塞或长任务，可能导致 PluginBus 客户端被宿主 1 秒投递超时清理；回滚 handler 实现，保留 attribute 也不会影响发布路径。
- 如果 STT/KWS 抑制策略导致永久停听，优先回滚协同 `BackgroundService`，保留重复事件修复和状态同步修复。
- 如果 TTS completed 语义调整影响旧 UI，优先保持 `voice.tts.completed.v1` op 不变，只新增可选 `reason` 字段，不做破坏性字段删除。
- 如果 AOT/trim 出现新增 warning，先回滚新增反射或未注册 JSON 类型，补齐 `PluginJsonContext` 后再推进。
